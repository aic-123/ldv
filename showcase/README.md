# showcase —— 它确实做到了：真实参数、真实回执、真实账本

本目录是**成果展示**：每个能力配一组真实参数、真实的工具回执、真实的账本行。
不是截图，不是宣传语——`runs/` 里每一个 JSON 都是当天实跑落盘的返回体，
`corpus/` 是支撑这些返回的语料节点原件，`ledger/` 是它自己写的账。

## ① 推算：答案带可复算的依据

**输入**：`{"derive": {"运算":"*", "左":"name=声速", "右":"name=三", "字段":"数值"}}`

**输出**（[`runs/01_推算_声速乘三.json`](runs/01_推算_声速乘三.json)）：

```json
{"ok": true, "算式": "340.0 * 3.0 = 1020", "算得": 1020,
 "依据": [{"原文": "运算资格：arith/003（运算=乘）",
           "原文": "nat/046（声速）的 数值=340",
           "原文": "conc/025（三）的 数值=3"}]}
```

三个数，三个出处——任何人拿这三条去语料里核，结果都一样。

## ② 空结果：不被翻译成肯定句

订单系统返回空（`{"data": []}` 的同款场景，真库真查）：

```json
{"解读": {"结论": "空结果", "任务标签": "无此记录", "条数": 0,
          "空结果不算故障": "ok=1 但没有文档 = 账面就是这样，不是连不上"},
 "该集合字段": ["loanId", "bookId", "borrowerId", "borrowedAt", "dueDate"]}
```

它顺手把**这个集合真实的字段名**报出来——让你一眼看出是不是谓词写错了。
支撑语料：[`corpus/规程/conc__480.md`](corpus/规程/conc__480.md)（三分类交付格式）。

## ③ 失败：报失败码、报允许值、挂账

给一个带枚举校验的集合（`状态` 只许 `待还/已还/逾期`）：

**第 1 步**（[`runs/04a_第1步_写入成功.json`](runs/04a_第1步_写入成功.json)）：写入成功。

**第 2 步**塞了列表外的值（[`runs/04b_第2步_枚举越界.json`](runs/04b_第2步_枚举越界.json)）：

```json
{"解读": {"结论": "写入被拒", "任务标签": "参数校验失败",
          "已尝试": [{"单号": "L1002", "状态": "已还清"}],
          "允许值": {"状态": ["待还", "已还", "逾期"]},
          "错号": 121, "挂账": "已挂账 mongo_ledger.jsonl"},
 "弃答": "库拒了这次写入：提交 1 条、写进 0 条——Document failed validation
          ｜允许值：{'状态': ['待还', '已还', '逾期']}"}
```

这就是「第 2 步失败，已尝试参数 X，允许值 Y」的完整形态——**不重试、不前进、账上全有**。
账本原件：[`ledger/mongo_ledger.jsonl`](ledger/mongo_ledger.jsonl)。

## ④ 装配单：哪条判据靠哪块砖

把需求写成判据 ①②③，它逐条去找能管的规程，缺就如实标缺：

**输入**：`{"装配": {"名称": "订单退款空结果审计"}}`
**输出**（[`runs/05_装配单_订单退款空结果审计.json`](runs/05_装配单_订单退款空结果审计.json)）：
`状态: 可交付`，三条判据分别顶在《显式结构》《查不到就报查不到规程》《空结果报法规程》上，
每一格带分数与命中片段。判据从目标正文逐条取，**一条都不许省**。

## ⑤ 归因：评测满分、生产崩盘，错在哪一层

**输入**：评测 95 分，抽 20 条反馈只有 3 条属于检索/生成，其余是权限、跨系统聚合、同步延迟。

**输出**（[`runs/06_断层归因_成文.json`](runs/06_断层归因_成文.json)）——它给出的不是安慰，是一份**逐维度的对照表**：
权限（评测万能账号 vs 真实 403）、数据新鲜度（刚刷新 vs 昨天那份）、跨系统聚合（单系统 vs 拼两个库）、
延迟（只记对错 vs 用户第一秒就关掉）；结论**落在工程层**，不落在"模型需要微调"。
