# ldv

**从「结构」这个方向做的认知模型。**

它把一份语料装成一棵**分层划分树**，在上面做五件事：**记录**（建树）·
**检索**（在树上定位候选）· **推导**（从材料算谓词）· **推理**（找结构矛盾 +
回答「删了会怎样」）· **处置**（不够格的降权、忽略在支上，但**不删**）。
**五层都只产出结构，不产出答案。** 它不拿向量找相似段落——推理是结构的
（包含 / 可达 / 递归分割 / 反事实），不是语义的。

**A cognitive model built on partitioning: it reasons over structure, not similarity.**

> 定位是**约定**（不是定理）；它蕴含的可判承诺见 `§S1`–`§S7`
> （[`docs/形式化断言集.md`](docs/形式化断言集.md)，33 条，拿纸就能验）。
> 代码里的 `§K8`、`§I4` 这类号指 [`docs/`](docs/) 里的设计文档，可以逐条对上。

## 2. 它解决什么实际问题

每个问题都对应一组实测，不是设想：

**① 引导与事实在长会话/压缩后丢失。** agent 的系统提示与早期结论，在长会话
或上下文压缩后消失，行为当场崩塌（E1：丢失后 0.319 vs 在窗 0.987；E2：压缩后
裸 agent **0.00**）。放进 ldv 结构里的引导可跨任务取回（0.864），压缩后仍可追溯
（0.93）。**代价要说清**：这个优势来自「预先整理」，不是取回机制本身（E3）。

**② 「学到了」无法审计。** agent 说「我记住了/我学会了」，无法核对。ldv 的
使用记录是**账本**：只追加、不覆写、逐条落盘（`usage/*.md`）；曝光不算有用、
下钻才算、判错只能人授；遗忘 = 降权可回退，不删。阶段一 37 条机制判据 +
V13 对外接口 6/6 不可伪造。

**③ 检索过程不可解释。** 「为什么给我这几条」答不上。`chain()` 把「根 → 该支」
的路投影出来，`folded` 换成与人同单位的讲述（字段决策），`attention` 说明
「为什么它排前面」——全部是**事实**（次数/天数），零分数、零排名。

**④ 人脑检索会漏，且漏得没有凭据。** V17 出声思维实测：库主人自己找东西
**3/7 题漏检**且不自知。LDV 的无假阴保证答案集完备，现在答案头部带
**完备性声明**（「共 N 条，无遗漏」）。

**不解决的**：语义理解、内容生成、相似度匹配、「A 意味着 B」——见 §3 边界。

## 3. 与传统数据库 / RAG / 结构化记忆的区别

| 维度 | 关系数据库 | RAG（向量检索+生成） | 知识图谱/结构化记忆 | **LDV** |
|---|---|---|---|---|
| 组织单位 | 行/表（schema 固定或迁移） | 文本块 + 嵌入向量 | 三元组 + 本体 | **分层划分树**（谓词定义的划分单元） |
| 检索 | 精确匹配 / 索引扫描 | **相似度**（近邻） | 图遍历 / SPARQL | **划分收窄**（不相似、只覆盖） |
| 完备性 | 可证（SQL 语义） | **无保证**（召回率是经验数） | 查询本身可证，图谱完整性无保证 | **无假阴是判据**（§K8，破了就是红）+ 答案带完备性声明 |
| 学习 | 无 | 无（索引重建） | 无 | **有，但只到呈现次序**：使用记录→倾向→排序；遗忘=降权可回退；账本可审计 |
| 解释 | 查询计划 | 无（黑箱相似度） | 路径可读 | **链路投影 + 折叠视图 + 注意力事实** |
| 内容 | 存取，不产内容 | **产内容**（生成） | 存取 | **只产结构，不产内容**（§S1：输出可指回材料） |
| schema 演化 | 迁移脚本 | 重嵌入 | 本体工程 | **声明式**：缺谓词当场 `declare`（带来源），清空声明树逐字回原样 |

**一条把它们分开的硬边界**：LDV 的检索不做「像不像」，只做「在不在划分里」。
所以它**不会**给你语义近邻（那是 RAG 的活），也因此**不会**因表达方式不同而漏掉
划分内的项（那是 RAG 的痛点）。两者是互补位置，不是竞争位置。

## 5. 理论主张的收缩与待验证

**诚实清单。** 完整版在 [`exp/CLAIMS.md`](exp/CLAIMS.md)（能说/不能说逐条）。

### 已收缩（原主张 → 现在的说法）

| 原主张 | 收缩为 | 依据 |
|---|---|---|
| 「ldv 取回精度优于直给」 | **撤回**：E1 的 R-L 是「预先整理」的功劳；机制在信息在窗时为负税（−0.11） | E3 |
| 「ldv 的优势来自存储与取回机制」 | **优势来自整理**（E1/E3/E4 三角互证） | E3 |
| 「结构承载视角/意图」 | **结构是可审计的候选全集**；视角在检索事实里（V11/V15.2），结构不携带（S3-4 两轮红） | m1 |
| 「链长 5–10 = 想得比人深」 | **思考形状与人一致**（字段决策 2 vs 1.86）；差在讲述单位（二元步 vs 字段决策）——v0.1.55 已修 | m2 STOP_PROBE §7 + V16 |
| 「树的第一刀 = 人看处境的第一眼」 | **作废**：跨角色（中间少了 agent 层） | m2 T0 |
| 「历史实验的 C 组 1.00 可比」 | C 组是确定性脚本作答，与模型不可比 | E3 |

### 待验证（想做但还没做的，各需独立预注册）

- **多叉 split**：根治 repetition viscosity 的结构层正解（折叠只是呈现层模拟）——等折叠上线后的盲判数据
- **基本层级优先选键**：让树的第一刀落在 `type` 类大字段（V17 7/7 实测人如此）——触「照人答案改系统」红线，需改前/改后对照
- **意图槽**：需求原文随记录存储（V17-H4 降级后的方向）
- 折叠/attention 对**真实长期使用**的影响（现有验证都是单会话）
- 跨模型：主结论单模型（deepseek）；付费档第二模型因余额未完成

### 明确不声称（从第一天起）

任务正确性（建树质量对不对）· 线程安全（`--locked` 是可选壳）· 语义蕴含 ·
标量评分（协议禁词 `score/weight/priority/rating`）

## 6. 如何运行与集成

### 30 秒跑一遍（Python 3.13+，零依赖零配置）

```bash
git clone https://github.com/aic-123/ldv.git && cd ldv
python -m ldv.cli a        # 流程 A：三个插件上各建一棵划分树并跑检索
```

⚠️ Windows 先 `set PYTHONIOENCODING=utf-8 & set PYTHONUTF8=1`（否则中文输出
`UnicodeEncodeError`，且**和「有检查命中」长得一样**）。

### 验证（不需要 pytest）

```bash
python -m ldv.run_checks             # 97 断言（构建验收；三值：红/过/跳过，跳过≠通过）
python -m ldv.tests.run_tests        # 934 条（单元/对照/守卫/注入）
python -m ldv.tools.evidence_index check   # 证据无悬空、无孤儿
python -m ldv.tools.version_spots check    # 版本落点 7 处一致
```

### 编程集成（`entry.py`，只读入口）

```python
from entry import App
app = App(root="_data/<语料>/nodes")

r = app.query({"require": ["type=综述"]})
# r["n_answer"]/["n_branches"] 账平；r["attention"] 注意力事实；
# r["ordered_by"] 使用学习只到这里，答案集逐字不变

c = app.chain({"require": ["type=综述"]})
# c["chains"] 每支的路（相干/过路分开）；c["folded"] 折叠视图
# （筛选步数=字段决策；检索深度/到叶深度；兄弟分支可见）；
# c["答案完备性"] {"n_answer": N, "无遗漏": true}

app.drill(did, require)                    # 唯一写信号：下钻 = +1
app.drill(did, require, verdict="wrong", actor="human")   # 判错只能人授
```

### 服务与协议

```bash
python serve.py --port 8080        # HTTP：/ask /drill /agenda /healthz /readyz /metrics
python e2e_agent.py                # 端到端：真进程、真 HTTP、27 步（含重启与坏语料）
python -m ldv.cli --agenda-tick    # 议程：时钟推空闲档位（无守护进程）
```

MCP 工具（`orient / ask / drill / remember / next(idle=)`）见 `ldv-mcp/`。
对讲协议 `ldv-msg/1`（文件/HTTP 两层）见 `docs/服务化设计.md` §10。

### 语料

随仓库 36 项是**演示语料**（`filled_by` 逐项留痕，不代表真实材料）；
真实语料放 `_data/<名字>/nodes/`，`LDV_CORPUS=<名字>` 显式指定——
**找不到报错，不回落**（回落会让「打错字」与「指对了」长得一样）。

| 跨会话累积 | 记录累积、折算倾向，**不跨进答案集** | W5 探针；清空：`usage_store clear` |
