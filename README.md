# ldv

**分层方向视图。** 把检索系统的「方向」做成可插拔的分层结构 —— 一层比一层细，每一层只产出下层表达不出的东西。
**A pluggable layered direction view for retrieval systems.**

> **Layer = Direction** · **Deeper = Finer**
> 输出是**方向**，不是答案。押错了的代价是一次**漏**，而**用本身就是确认**。

家族位置：`Scaffold`（结构空间）→ `arena`（交互层分歧）→ `dce`（视图层分歧）→ **`ldv`（检索方向层）** → …

> 代码里那些 `§K8`、`§I4` 一样的号，指的是 [`docs/`](docs/) 里的设计文档 —— **可以逐条对上**。
> 那几份文档就是这个系统照着建的东西，一并放在仓库里，不用去别处找。

## ⚠️ 先说清楚成色

| 项 | 实际情况 |
|---|---|
| 是什么 | 检索系统的**分层方向视图**。输入是项 + 一个插件（三个方向：键集包含 / 锚点可达 / 序列前缀），输出是**一棵方向树** —— 每个方向带 `覆盖`，叶 = 该方向能表达的**分辨率下界** |
| 依赖 | **零第三方**（标准库 + 纯内存，不装任何东西） |
| 测试 | **59 条断言（红 0，跳过 1）· 236 条单元测试 · 30 条注入验伪，红 0** |
| 状态 | **接口已押定**（§I1–§I7 七个），内核冻结。**健全性两条路径都守住了；覆盖不漏在维护路径上还差一半**（见下） |
| 不做的 | 持久化 / 并发 / 曝光模型标定 / 全局目标函数 / 排序 / 打分 / 匹配 |
| 一句话的诚实版 | 接口押对了、内核冻结了，**但「押对」不等于「没问题」**：健全性在维护路径上的缺陷**两条出路都修好了**（`reach` 根记账 / `sequence` 出路 (4)）⇒ `B1` / `B16` 升级成**两条路径的真判据**；**覆盖不漏**（§1 第四行）在 `sequence` 维护路径上**仍破着**（16 漏 / 2 对），走 baseline 守卫 |

## 它只回答三句话

    这一层建不建？ 每个方向盖住什么？ 盖住的东西有没有漏？

三句话对应**三种不同性质**的东西 —— **只有第三句能红**：

| 问 | 谁答 | 性质 |
|---|---|---|
| 这一层建不建 | 内核按 §K2 | **度量**（判空次数）—— 判空越多，说明这个方向的形状越贴不上接口 |
| 每个方向盖住什么 | 插件按 §I1 命中 | **允许假阳**（§K8）—— 代价是性能，而性能**会累积** |
| 盖住的东西有没有漏 | 内核按 §I3 代价 分配归属 | **禁止假阴**（§K8）—— 破了就是**正确性**问题 |

### 不对称的那一条（§K8 是承重墙）

它只说了两句话，而两句的**处置完全不同**：

    假阳允许   → 代价是**性能**，而性能**会累积** ⇒ 必须**计量**
                 （十个度量里有三个在量它）
    假阴禁止   → 破了**正确性**             ⇒ 必须**红**（B1 守，**两条路径各一条**）

⇒ 「假阳率」不是一个质量指标，它是**结构在漏**的读数。一个假阳率 90% 的过滤器
不违反任何一条检查，却让整套结构白建 —— **所有方向都说「是」，等于没有方向。**

## 已经证明到哪一步

    ✅ 接口押定：三个「代价形状」完全不同的方向，一条接口都没动

       方向          假阳率   §K2判空   叶容量max/avg   方向数   它是什么
       ───────────────────────────────────────────────────────────────────────────────
       A 键集包含     50.1%      7       10 / 2.77      25     粗过滤器：只看节点自己，问得飞快
       B 锚点可达     29.0%      0        1 / 1.00      71     要遍历整张图，但切分点随手可得
       C 序列前缀      0.0%      8       10 / 3.27      16     命中把覆盖**算出来** ⇒ 说不出「是」而实际没有

       ⇒ 同一套 §K2，形状越自然，两个数都越小。**省方向 ⟺ 丢分辨率**

    ✅ 四条流程都能跑（A 运行 / B 维护 / C 构建验收 / D 自优化）
       账本（只追加）：初始 24 → B 38（结构 +14）→ A 49（展示 +10、查询时展开 +1）→ D 49（自优化不写账本）

    ✅ §K2 第二半有**外生**判据（`B17`）：叶容量 = 最大等价类
       那是该方向能表达的**分辨率下界**，任何 payload 设计都越不过去
       ⚠️ 前提是**每一项都走到了叶**（`滞留 == 0`）⇒ `B17` **只跑批建路径**。
          项停在**内部**节点时 `叶容量` 会掉到**下界以下**（实测 2 < 10）——
          那时下界改由 `最大停留数` 承担（32 ≥ 10）。**掉下去的是尺子的量程，不是分辨率**

    ✅ 两条「空转不许与通过长得一样」的守卫已落地（各自配一条可红的检查）
       `B18` **覆盖不漏 baseline 守卫**：新增的漏会红，**账上已冻结的漏不再发生**也会红
       `B19` **进步量守卫**（N=10，取 SP-GiST `longValuesOK` 前例）：十次展开没变小就报错
       ⇒ 判据的「尺子」与「守卫」是两件事：`B16` 改成了**外生覆盖 oracle**
          （不调插件、不调内核，只按语料独立复算）—— 实测三方向逐项一致

    ✅ **健全性两条路径都守住了**（三条判据各自注入验证）：

       `reach`    出路 (1) **根记账**：`insert` 先问 `命中(根, {x})`，**只有「否」是反证**
                  ⇒ 记 `out_of_scope`、不塞进结构（`是` 是允许的假阳，`未展开` 不许当「不在」）
                  维护路径越界 **128 / 328 → 0 / 33** —— 那 28 项从「静默错位」变成「一条显式的账」
       `sequence` 出路 (4) **项留在父方向**：下降**只进入「没有证明不收它」的子方向**；
                  每个子方向都证明不收 ⇒ 记 `stayed`、**停在父这一层**
                  维护路径越界 **36 / 176 → 0 / 86**（外部印证：X-tree 的 supernode，
                  "created during insertion **only if there is no other possibility**"）
       ⇒ `B1` / `B16` 因此**升级成两条路径各判一次**（各占一行、各自注入验证）

    ⛔ **覆盖不漏（§1 第四行）还差一半**：`sequence` 维护路径 **16 漏 / 2 对**。
       ⚠️ 出路 (1) / (4) 修的是**健全性**，不是它 —— 实测 (4) 落地前后漏项数
          **都是 16，一个数没动**。要修它得靠出路 (1) 的 catch-all（代价：永不细化）
       ⇒ 它继续走 `B18` baseline 守卫（冻结既有、对新增红）

    ✅ 两条**代价分开记账**，不合并（合并就把「声称盖不住」与「这一层表达不出来」当成一件事）：

       根覆盖之外   项**不在**任何方向的覆盖里（根下「否」）⇒ **范围**损失（项检索不到）
       滞留         项**在**父的覆盖里，但**没有子方向**表达得出来 ⇒ **划分**代价（项检索得到）

    ✅ 顺带修掉一把**会骗人的尺子**：`叶容量` 默认每一项都走到了叶，(4) 之后不成立
       同一份结构：`叶容量` **2**（看起来分辨率很高）而 `最大停留数` **34**（真相）
       ⇒ `最大停留数` 是 `叶容量` 的**推广**（项都走到叶时两者相等，批建路径三个方向实测相同）

## 换一份**公开数据集**跑：一条判据被证伪，一条检查是平方的

随仓库那 36 项语料是**手写的**，跑出来的绿只说明「手写那份上没问题」。
所以另取一份公开语料来撞 —— **OpenAlex** 的引用图切片（CC0，取法与丢弃明细见
`ldv/tools/intake_openalex.py`）：

    种子   2020–2021、被引 > 200，按被引降序取前 200（命中 77,043 篇）
    切片   共被引 ≥ 2 的闭包 ⇒ **3907 项 / 24156 边 / 丢弃 196223 条外部引用**
    子切片 共被引 ≥ 5 ⇒ 281 项 / 1008 边（套件默认用这一档，见下）

**两条独立数法**（一条走 markdown 往返，一条直接读原始 JSON）给出同一组数
⇒ 转换器没漏写节点、没漏写边。

### ① 一条判据被证伪：`B17` 在**真实**引用图上红了

设计文档 §7.2 写着「`reach` 在**合环图**上会把互相可达的两项劈成两个覆盖完全相同的
子方向 …… **真实语料是 DAG，所以这个缺口在语料上不露**」。

**后半句是错的。** 引用图**不是** DAG —— 论文互引（对引、勘误、综述与原文）会造出环：

    语料              项数    边     SCC ≥2 的个数   最大 SCC    `B17`(reach)
    ──────────────────────────────────────────────────────────────────────────
    随仓库那 36 项      36     47          0            1         跳过（退化）
    OpenAlex 子切片    281   1008          6            4         **红**（6 个类被拆开）

⇒ 「真实语料没有环」是个**没验过的前提**，碰到真数据就翻了。
人工小图可以被人说成「构造出来的边角情形」，公开语料不能。
⇒ 同一趟里 `B1`（两条路径）/ `B16`（两条路径）/ `B18` / `B19` **全是绿的**。

### ② 一条检查是**平方**的：`B8`

`B8`（失效局部）原来是「每检查第 k 项就重建内核、把前 k−1 项重插一遍」——
总插入次数 `n(n−1)/2`。36 项上是 0.05 s，**看不出来**：

    语料               n     改前                        改后
    ─────────────────────────────────────────────────────────────
    openalex-small    281   21 分钟没跑完（被杀）         0.7 s
    openalex         3907   61 分钟没跑完（被杀）         6.7 s

改成一个内核走到底、快照逐次前移。**判据内容一个字没动** ——
两个实现各自吐出「每一步的 `changed` 集合」的 trace，**12/12 逐字相同**
（含注入后变红那一档：`b160` 上都是 159 处越界）。见 `ldv/checks/structure.py`。

### ③ 剩下的墙，以及 `--no-probes`

`B8` 修完之后 `run_checks` 在 281 项上还要 ~13 分钟 —— 98% 花在**一条只报不判的度量**上：

    检查                  代价的形状                281 项实测
    ─────────────────────────────────────────────────────────
    `规范重建`（度量）     O(n) 次重建 × 每次 O(n)      **446 s**（reach）
    `B15`（判据）          3 次整建                      0.5 s
    `B8`（判据）           n 次插入                      0.2 s
    其余全部合计                                        < 2 s

⇒ 关键区别不是「贵不贵」，是**进不进退出码**：

    判据（进退出码）   B1–B19
    探针（只报不判）   十个度量

⇒ 所以有 `--no-probes`：**判据一条不少地全跑，只把贵的探针关掉**。
**关它是安全的** —— 度量不进退出码，关掉它**不可能把红变成绿**；
报告里会写明哪几行未跑（「没跑」与「跑了但没话说」不共用一行）：

    281 项：整趟 ~780 s  →  `--no-probes` **6.05 s**，而 `B17` 那条红照样露

⚠️ 另有一个 `--cap N`（只跑前 N 项），但它**连判据一起截**，会挡住结论：
   实测 `openalex-citations` 的环**全落在第 400 项之后**，所以 `--cap 160` 上
   `B17` 那条红**根本不会出现**。⇒ 要快用 `--no-probes`，别用 `--cap`。

### ④ `B18` 的基线没按语料分开 —— 也是这份料撞出来的

`B18`（覆盖不漏的 baseline 守卫）的基线是**在 36 项上冻的**（`sequence` 维护路径 16 漏）。
换到 281 项的切片上，那一格是 **183 漏** ⇒ 报出：

> `sequence|maintenance` **新增覆盖不漏：183 漏（baseline 16）**

**这句话是假的。** 没有任何东西变差，只是 baseline 换了参照物 ——
而「baseline 是别的语料的」与「新增违规」在输出里**长得一模一样**。
⇒ 已修：基线记**语料指纹**（项数 / 边数），对不上就报**跳过**并说清是换了语料。

⚠️ 顺带量出一个数：`sequence` 维护路径的覆盖不漏，**16 漏 → 183 漏**。
   缺口还是那个缺口（§10 已知），但它在真实语料上的规模**大一个数量级** ——
   这在此前从没量过。

### ④′ 「基线**不见了**」也曾长得像另外两件事 —— 同一条纪律的第二个面

修 ④ 的时候顺手把「`语料` 为空」也归到「判不了」。**没有量过旧行为**，
而量了之后结论和推理**不一样**（`outputs/_measure_b18_missing_baseline.py`，
两条臂一起跑、只有守卫版本在变）：

| 输入：baseline 文件不存在 | 旧（v0.1.10） | 新 |
|---|---|---|
| 臂 A 只有 `keyset`/`reach`（既存违规 0 处） | **绿**（「4 个都没有新增覆盖不漏」） | 跳过 |
| 臂 B 全量（含 `sequence\|maintenance` 既存 16 漏） | **红**（「新增覆盖不漏：16 漏（baseline 0）」） | 跳过 |

⇒ 旧行为把它拆成了**绿**和**红**两种假象，**两条都不说「基线不见了」** ——
而它既不是绿、也不是违规，是**判不了**。
⇒ 现在两种情形给**同一句**「判不了」，且 `corpus` 改成**必填** ——
防御不许因为调用方少传一个参数而静默消失（漏传当场 `TypeError`）。

⚠️ 第一版测量脚本只跑了臂 B，于是印出「旧代码报绿」—— **与读数相反**。
   **对照少跑一条臂，就会产出一条看起来像经验的错误结论。**

### ⑤ 这份语料还顺手披露了一件事

`keyset` 那条轴在这份语料上**几乎是退化的**：37 个键词、40 个等价类，
而**最大等价类 3291 项 = 全语料的 84.2%**。
⇒ 键集包含这个方向在真实文献图上**分不开**（绝大多数论文的键集完全一样）。
这是**披露，不是判据** —— 它说明「轴选得对不对」得看语料，而这件事此前从没量过。

```bash
LDV_CORPUS=openalex-citations python -m ldv.cli all    # 3907 项，466.6 s，退出码 0
```

## 它不是什么

- **不是能跑的检索服务。** 没有持久化、没有并发、没有曝光模型标定。它是一条**跑通的链**
- **不是「自动涌现」。** **什么算一个方向**必须人声明（§K9 外生）；
  内生的只有「层内哪个方向值得展开」。方向**内部的参数**才交给使用
- **没有全局目标函数**（§4.3）。每个方向有自己的代价，跨方向的**标量分明令禁止**
  —— `B12` 直接扫源码守着这一条
- **不排序、不打分。** 排序即推荐，本层不做推荐器
- **不做匹配。** 把一段处境映射到方向是检索系统上层的事（继承 `dce` 的裁定）
- **不做「增量 ≡ 全量」。** 量过了：**不成立**，而且**不成立不破坏任何一条检查**。
  它是**实现**性质，不是**正确性**标准 —— 理由见 `ldv/MEASUREMENTS.md`

## 5 分钟上手

```bash
git clone https://github.com/aic-123/ldv.git && cd ldv

python -m ldv.run_checks             # B1–B19。三态：红 / 过 / 跳过 —— **跳过不等于通过**
python -m ldv.tests.run_tests        # 236 条
python -m ldv.tests.test_injections  # 30 条：每条检查「基线绿 + 注入红」成对验一次
python -m ldv.tests.test_intake      # 外部语料验收（数据不在 ⇒ 报「跳过」，不报「通过」）

python -m ldv.cli all                # 流程 A+B+D，三个方向都跑
python -m ldv.run_checks keyset      # 只跑方向 A（reach / sequence 同理）
python -m ldv.run_checks --cap 160   # 只跑前 160 项（**会把「缩了」印出来**）
```

**零依赖**，不装任何东西就能跑。只要 Python 3（3.13 实测）。

⚠️ **Windows 上必须先设 utf-8。** 本仓库每一条输出都是中文，而 Windows 的 `python`
默认 `sys.stdout.encoding` 是 **cp1252** ⇒ `UnicodeEncodeError` → 退出码 1 ——
**和「有检查命中了」长得一模一样**：

```bash
set PYTHONIOENCODING=utf-8 & set PYTHONUTF8=1
```

（`.github/workflows/ci.yml` 里已经设了，那条注释写了同一个理由。）

### 语料在哪

**随仓库提交的 36 项**在 `ldv/corpus/nodes/`，clone 下来直接跑，不用去别处找。

**公开语料（外部，不进仓库）**：`_data/<名字>/nodes/`，用 `LDV_CORPUS=<名字>` 指过去。
按优先级找：`LDV_CORPUS`（**路径或名字**）→ `_data/<名字>/nodes`（仓库旁，再上一级）
→ `ldv/corpus/nodes`。README 不写死绝对路径，理由见下。

```bash
# 取一份 3907 项的公开语料（OpenAlex 切片，CC0；取法/丢弃明细见 ldv/tools/intake_openalex.py）
python -m ldv.tools.intake_openalex --out _data/openalex-citations

LDV_CORPUS=openalex-citations python -m ldv.cli all                 # 全量，466 s
LDV_CORPUS=openalex-citations python -m ldv.run_checks --no-probes  # 判据全跑，贵的探针不跑
python -m ldv.tests.test_intake          # 外部语料验收（数据不在 ⇒ 报「跳过」，不报「通过」）

# 在子切片上跑验收（② 要 `B8`+`B15`，全量是二十分钟级）
LDV_CORPUS=openalex-small LDV_INTAKE_MIN_NODES=200 python -m ldv.tests.test_intake
```

⚠️ **显式指定却找不到 ⇒ 报错，不回落到默认语料。** 回落会让「`LDV_CORPUS` 打错一个字」
和「指对了」**长得一模一样** —— 跑的是那 36 项，检查照样全绿、退出码 0。
不设 `LDV_CORPUS` 时才走兜底链，兜底链全落空才报「跳过」。

**找不到就报「跳过」，绝不报「通过」** —— 一个「语料不在」的仓库和一个「检查全过」的仓库
在汇总上长得不一样，但都很容易被读成「没问题」。

```
  direction.py    方向记录（不可变）+ 事件账本（只追加）
  interfaces.py   §I1–§I7 七个方法的协议 + 运行时守门人
  kernel.py       层 / 秩 / 见证 / 支撑锥 / 按需展开 / 遍历循环 / 倾向记账
  selfopt.py      §F0–§F4 自优化。外生项是**只读**的
plugins/          三个方向：keyset（键集包含）/ reach（锚点可达）/ sequence（序列前缀）
corpus/           语料装载。自己写的 front-matter 解析器，形状之外报错不猜
checks/           B1–B19 + 十个度量                          **比被检查的内核还大**
tools/            两个单变量对照（`§I4` 的 k 叉 / 带上父方向）
tests/            测试（不需要 pytest）
MEASUREMENTS.md   全部读数，以及每个读数为什么是这样
```

⚠️ **行数与条数刻意不写在这里** —— 手写的数一定会漂。要看就现跑：
`python -m ldv.run_checks` 报断言数与红数，`python -m ldv.tests.run_tests` 报测试数。

**检查层比被检查的内核大，这是有意的** —— 那不是设计偏好，是代价换来的。

## 已知的未做（不是漏了）

| 没做 | 理由 |
|---|---|
| **覆盖不漏的修法** | `sequence` 维护路径 16 漏 / 2 对。出路 (1) 的 catch-all 能修（payload = 父的前缀本身），代价是**永不细化**、叶容量变大、`B17` 可能破 —— 值不值要单独裁。健全性那半已修（根记账 / 出路 (4)）|
| **`§K2` 第二半的缺口**（`B17` 在 `reach` 上红） | **缺口是真的，且已在公开数据集上复现**（OpenAlex 子切片 6 个环 ⇒ 红 6）。修法是让 `reach` 的 `劈开` 不拆互相可达的两项 —— 但那要动插件语义，属设计裁定，不是实现缺陷。见 §7.2 / §10 |
| **检查层的超线性** | `规范重建` 是 O(n) 次重建 × 每次 O(n)，3907 项上小时级。它是**只报不判**的度量 ⇒ `--no-probes` 关掉它（**判据一条不少**，关它不可能把红变成绿）。**没有**去优化它：那会让「度量」和「判据」的代价形状分不开 |
| **覆盖不漏的真实规模** | `sequence` 维护路径在 36 项上 16 漏、在 281 项切片上 **183 漏**。缺口是同一个（§10 已知），但规模**大一个数量级**。修法同上一条 |
| `reach` 出路 (3)（子 payload 从父派生） | 治剩下的**内部**越界。代价是**两向**的：`覆盖(子) ⊇ 覆盖(父)` ⇒ 树在覆盖意义上不再变细 ⇒ `B19` 立刻红，而且本设计**不再是 Godin 意义上的格**。见 §10.2 A′ |
| 删除流程（`§M2` 情形③） | 前例（Godin 1995 §3.4）在 §10.2 C。要先定一条口径：`§I4` 的 `None` 在**删除**路径上的含义，与插入路径是否相同 |
| 方向节点**入度是否常数** | §10.2 D 的前置问题。常数 ⇒ node-copying（O(1) 访问）；无界 ⇒ 只能 fat node（O(log m)） |
| 持久化 / 并发 | 接口已验证，属纯工程 |
| 曝光模型标定 | 现在用 `1 / 展示位次`（夹下界 0.05）。标定要真实曝光数据 |
| 规范重建 | **量过了，不做。** 它要拿 §K3（**接口级**不变量）去换「结构可复现」（**实现**性质），而「不同构」**不破坏任何一条检查** |
| 压成「几张抽象视图」 | 本层是**重新编码**不是摘要 —— 那是后续抽象层的事，**不在本层兑现** |
