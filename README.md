# ldv

**分层方向视图。** 把检索系统的「方向」做成可插拔的分层结构 —— 一层比一层细，每一层只产出下层表达不出的东西。
**A pluggable layered direction view for retrieval systems.**

> **Layer = Direction** · **Deeper = Finer**
> 输出是**方向**，不是答案。押错了的代价是一次**漏**，而**用本身就是确认**。

家族位置：`Scaffold`（结构空间）→ `arena`（交互层分歧）→ `dce`（视图层分歧）→ **`ldv`（检索方向层）** → …

> 代码里那些 `§K8`、`§I4` 一样的号，指的是 [`docs/`](docs/) 里的设计文档 —— **可以逐条对上**。
> 那几份文档就是这个系统照着建的东西，一并放在仓库里，不用去别处找。

## ⚠️ 先说清楚成色

| 项 | 实际情况 |
|---|---|
| 是什么 | 检索系统的**分层方向视图**。输入是项 + 一个插件（三个方向：键集包含 / 锚点可达 / 序列前缀），输出是**一棵方向树** —— 每个方向带 `覆盖`，叶 = 该方向能表达的**分辨率下界** |
| 依赖 | **零第三方**（标准库 + 纯内存，不装任何东西） |
| 测试 | **47 条断言（红 0，跳过 1）· 179 条单元测试 · 22 条注入验伪，红 0** |
| 状态 | **接口已押定**（§I1–§I7 七个），内核冻结。**一条硬要求在维护路径上没守住**（见下） |
| 不做的 | 持久化 / 并发 / 曝光模型标定 / 全局目标函数 / 排序 / 打分 / 匹配 |
| 一句话的诚实版 | 接口押对了、内核冻结了，**但「押对」不等于「没问题」**：三个方向里只有 A 的健全性在两条路径上都成立，B / C 在**维护路径**上破了，修法待裁定（设计文档 §10.2） |

## 它只回答三句话

    这一层建不建？ 每个方向盖住什么？ 盖住的东西有没有漏？

三句话对应**三种不同性质**的东西 —— **只有第三句能红**：

| 问 | 谁答 | 性质 |
|---|---|---|
| 这一层建不建 | 内核按 §K2 | **度量**（判空次数）—— 判空越多，说明这个方向的形状越贴不上接口 |
| 每个方向盖住什么 | 插件按 §I1 命中 | **允许假阳**（§K8）—— 代价是性能，而性能**会累积** |
| 盖住的东西有没有漏 | 内核按 §I3 代价 分配归属 | **禁止假阴**（§K8）—— 破了就是**正确性**问题 |

### 不对称的那一条（§K8 是承重墙）

它只说了两句话，而两句的**处置完全不同**：

    假阳允许   → 代价是**性能**，而性能**会累积** ⇒ 必须**计量**
                 （七个度量里有三个在量它）
    假阴禁止   → 破了**正确性**             ⇒ 必须**红**（B1 守）

⇒ 「假阳率」不是一个质量指标，它是**结构在漏**的读数。一个假阳率 90% 的过滤器
不违反任何一条检查，却让整套结构白建 —— **所有方向都说「是」，等于没有方向。**

## 已经证明到哪一步

    ✅ 接口押定：三个「代价形状」完全不同的方向，一条接口都没动

       方向          假阳率   §K2判空   叶容量max/avg   方向数   它是什么
       ───────────────────────────────────────────────────────────────────────────────
       A 键集包含     50.1%      7       10 / 2.77      25     粗过滤器：只看节点自己，问得飞快
       B 锚点可达     29.0%      0        1 / 1.00      71     要遍历整张图，但切分点随手可得
       C 序列前缀      0.0%      8       10 / 3.27      16     命中把覆盖**算出来** ⇒ 说不出「是」而实际没有

       ⇒ 同一套 §K2，形状越自然，两个数都越小。**省方向 ⟺ 丢分辨率**

    ✅ 四条流程都能跑（A 运行 / B 维护 / C 构建验收 / D 自优化）
       账本（只追加）：初始 24 → B 38（结构 +14）→ A 49（展示 +10、查询时展开 +1）→ D 49（自优化不写账本）

    ✅ §K2 第二半有**外生**判据（`B17`）：叶容量 = 最大等价类
       那是该方向能表达的**分辨率下界**，任何 payload 设计都越不过去

    ⛔ **没守住**：`members(d) ⊆ 覆盖(d)` 在**维护路径**上破了（`reach` 246/328、`sequence` 36/176）
       ⚠️ `B16` 只跑「一次建完」那条路 ⇒ **一次建完全绿、维护路径全红**
       ⚠️ 而且**真的产生假阴** —— 把 `B1` 换到维护路径上跑，B / C 立刻红
       ⇒ 这与「健全性破了」是同一件事的两面。修法要先裁定（设计文档 §10.2），
         所以它现在**只报、不进退出码**

> ⚠️ 它在 `§I4` 那次改动里**没有新出现** —— 不续父方向的版本在维护路径上同样破，
> 只是破得少一点。那次改动只是**第一次让它露出来**。

## 它不是什么

- **不是能跑的检索服务。** 没有持久化、没有并发、没有曝光模型标定。它是一条**跑通的链**
- **不是「自动涌现」。** **什么算一个方向**必须人声明（§K9 外生）；
  内生的只有「层内哪个方向值得展开」。方向**内部的参数**才交给使用
- **没有全局目标函数**（§4.3）。每个方向有自己的代价，跨方向的**标量分明令禁止**
  —— `B12` 直接扫源码守着这一条
- **不排序、不打分。** 排序即推荐，本层不做推荐器
- **不做匹配。** 把一段处境映射到方向是检索系统上层的事（继承 `dce` 的裁定）
- **不做「增量 ≡ 全量」。** 量过了：**不成立**，而且**不成立不破坏任何一条检查**。
  它是**实现**性质，不是**正确性**标准 —— 理由见 `ldv/MEASUREMENTS.md`

## 5 分钟上手

```bash
git clone https://github.com/aic-123/ldv.git && cd ldv

python -m ldv.run_checks             # B1–B17。三态：红 / 过 / 跳过 —— **跳过不等于通过**
python -m ldv.tests.run_tests        # 179 条
python -m ldv.tests.test_injections  # 22 条：每条检查「基线绿 + 注入红」成对验一次

python -m ldv.cli all                # 流程 A+B+D，三个方向都跑
python -m ldv.run_checks keyset      # 只跑方向 A（reach / sequence 同理）
```

**零依赖**，不装任何东西就能跑。只要 Python 3（3.13 实测）。

⚠️ **Windows 上必须先设 utf-8。** 本仓库每一条输出都是中文，而 Windows 的 `python`
默认 `sys.stdout.encoding` 是 **cp1252** ⇒ `UnicodeEncodeError` → 退出码 1 ——
**和「有检查命中了」长得一模一样**：

```bash
set PYTHONIOENCODING=utf-8 & set PYTHONUTF8=1
```

（`.github/workflows/ci.yml` 里已经设了，那条注释写了同一个理由。）

### 语料在哪

36 项语料**在仓库里**（`ldv/corpus/nodes/`），clone 下来直接跑，不用去别处找。

要换语料：`LDV_CORPUS=<目录>`，或放到仓库根的 `corpus/nodes/`。
**找不到就报「跳过」，绝不报「通过」** —— 一个「语料不在」的仓库和一个「检查全过」的仓库
在汇总上长得不一样，但都很容易被读成「没问题」。

## 目录

```
flow.py          四条流程的可运行实现（A 运行 / B 维护 / D 自优化）
cli.py           四条流程的入口 —— 护栏进退出码，度量不进
run_checks.py    流程 C（构建验收）—— B1–B17
core/
  tri.py          三态。⚠️ 不是 bool —— bool(未展开) 抛异常
  direction.py    方向记录（不可变）+ 事件账本（只追加）
  interfaces.py   §I1–§I7 七个方法的协议 + 运行时守门人
  kernel.py       层 / 秩 / 见证 / 支撑锥 / 按需展开 / 遍历循环 / 倾向记账
  selfopt.py      §F0–§F4 自优化。外生项是**只读**的
plugins/          三个方向：keyset（键集包含）/ reach（锚点可达）/ sequence（序列前缀）
corpus/           语料装载。自己写的 front-matter 解析器，形状之外报错不猜
checks/           B1–B17 + 七个度量                          **比被检查的内核还大**
tools/            两个单变量对照（`§I4` 的 k 叉 / 带上父方向）
tests/            测试（不需要 pytest）
MEASUREMENTS.md   全部读数，以及每个读数为什么是这样
```

⚠️ **行数与条数刻意不写在这里** —— 手写的数一定会漂。要看就现跑：
`python -m ldv.run_checks` 报断言数与红数，`python -m ldv.tests.run_tests` 报测试数。

**检查层比被检查的内核大，这是有意的** —— 那不是设计偏好，是代价换来的。

## 已知的未做（不是漏了）

| 没做 | 理由 |
|---|---|
| **B / C 的健全性修法** | 三个选项都在设计文档 §10.2，**要先裁定**。而**基线就红的判据过不了注入验证** ⇒ 现在只报、不进退出码 |
| `B16` 检查器重写 | 它的 `代价 = 0` 判据对 `reach` **太强**（根的外生锚点集盖不住后来添的项）—— 要先定 B 的方向 |
| 进步量守卫 | §K2 第二半的**内核侧**版本；与外生判据 `B17` 是两回事 |
| 持久化 / 并发 | 接口已验证，属纯工程 |
| 曝光模型标定 | 现在用 `1 / 展示位次`（夹下界 0.05）。标定要真实曝光数据 |
| 规范重建 | **量过了，不做。** 它要拿 §K3（**接口级**不变量）去换「结构可复现」（**实现**性质），而「不同构」**不破坏任何一条检查** |
| 压成「几张抽象视图」 | 本层是**重新编码**不是摘要 —— 那是后续抽象层的事，**不在本层兑现** |
