# ldv

**分层方向视图** —— 把检索系统的「方向」做成可插拔的分层结构：一层比一层细，
每一层只产出下层表达不出的东西。

**A pluggable layered direction view for retrieval systems.**

> **Layer = Direction** · **Deeper = Finer**
> 输出是**方向**，不是答案。押错了的代价是一次**漏**，而**用本身就是确认**。

## 30 秒跑一遍

零依赖、零配置 —— 克隆下来直接跑（**Python 3.13+**）：

```bash
git clone https://github.com/aic-123/ldv.git && cd ldv
python -m ldv.cli a      # 流程 A：在三个方向上各跑一遍检索
```

当场建出三棵方向树，并在每棵树上跑一次检索：

```
四条流程 · 流程 C（构建验收）在 `python -m ldv.run_checks`
本轮跑：A｜方向：['keyset', 'reach', 'sequence']｜维护新项 12｜**不删**（`--remove N` 才跑 B′）

═══ 方向 keyset ═══
  初始：19 个方向（§K2 判空 6），装进 24 项，事件 34 条；待维护 12 项
── 流程 A · 运行 ──
  查询「有 source.kind=其他」→ 命中 0 项｜是=19 否=0 未展开=0｜层=6
    展示 19 个候选（位次 1..19）｜产生记录 19 条｜没给反馈 0 个（**不产记录**：没看见 ≠ 看见了不好）
  终态：19 个方向（§K2 判空 6，叶容量 最大 5 / 平均 2.4），使用记录 55 条；空方向 0（已失效 0）
  账本：初始 34 → B 34（结构 +0） → A 89（展示 +55、**查询时展开** +0） → D 89（自优化**不写账本**）
```

其余几条流程：

```bash
python -m ldv.cli all                # A + B + D，三个方向都跑
python -m ldv.cli all --remove 12    # 末尾再跑 B′ 删除 12 项
python -m ldv.run_checks             # 流程 C：构建验收
python -m ldv.tests.run_tests        # 单元 / 对照 / 守卫
```

## 它只回答三句话

    这一层建不建？ 每个方向盖住什么？ 盖住的东西有没有漏？

三句话对应**三种不同性质**的东西 —— **只有第三句能红**：

| 问 | 谁答 | 性质 |
|---|---|---|
| 这一层建不建 | 内核按 §K2 | **度量**（判空次数）—— 判空越多，说明这个方向的形状越贴不上接口 |
| 每个方向盖住什么 | 插件按 §I1 命中 | **允许假阳**（§K8）—— 代价是性能，而性能**会累积** |
| 盖住的东西有没有漏 | 内核按 §I3 代价 分配归属 | **禁止假阴**（§K8）—— 破了就是**正确性**问题 |

### 不对称的那一条（§K8 是承重墙）

它只说了两句话，而两句的**处置完全不同**：

    假阳允许   → 代价是**性能**，而性能**会累积** ⇒ 必须**计量**
                 （十个度量里有三个在量它）
    假阴禁止   → 破了**正确性**             ⇒ 必须**红**（B1 守，**两条路径各一条**）

⇒ 「假阳率」不是一个质量指标，它是**结构在漏**的读数。一个假阳率 90% 的过滤器
不违反任何一条检查，却让整套结构白建 —— **所有方向都说「是」，等于没有方向。**

## 它不是什么

- **不是能跑的检索服务。** 落盘与并发**只到「可选壳」那一层**（P6 / P8：`LockedKernel` 是**可选壳**、只在 `--locked` 时启用（默认路径**不锁**），插件自身的可变状态与 `items` / `_path` 单键写**也没覆盖**）⇒ **不声称线程安全**（★ **并发模型 / 资源管理 / 性能目标与取舍**见 [`docs/并发接口设计.md`](docs/并发接口设计.md)）；曝光模型**已显式化、量级带已用公开数据划出**，但那是**另一种界面几何**（横向槽位），**本设计的竖直列表还没有数据** ⇒ α 保守取 1.0。它是一条**跑通的链**
- **不是「自动涌现」。** **什么算一个方向**必须人声明（§K9 外生）；
  内生的只有「层内哪个方向值得展开」。方向**内部的参数**才交给使用
- **没有全局目标函数**（§4.3）。每个方向有自己的代价，跨方向的**标量分明令禁止**
  —— `B12` 直接扫源码守着这一条；而**抽象层把它升级成一条定理**（视图**唯一** ⇒ 不用挑）
- **不排序、不打分。** 排序即推荐，本层不做推荐器
  ★ **「不打分」有明文标准**（v0.1.23）：[`docs/评估标准.md`](docs/评估标准.md) §3 禁三件 ——
  **合成标量分 / 排序 / 当验收判据**；理由是一旦引入标量分，**系统即在实质上充当裁判**。
  读数只许这样用：**量化**（这个量是多少）· **掌握状态**（在哪个区间、比上次大还是小）· **定位**（哪个模块贡献的）。
  ⚠️ **比较不算打分**：单变量对照「改前 vs 改后」**只报两个数、不合成**（核验脚本 `--reverse` 就是这么做的）。
  ⇒ 哪些读数**过筛**、哪些**被剔除**（含理由），见 [`docs/评估报告.md`](docs/评估报告.md)
  ★ **那它和普通检索比好在哪？** 见 [`docs/与普通检索系统的质量对照.md`](docs/与普通检索系统的质量对照.md)
  —— **只比交付物的质量，不比效率**；实测 `python -m ldv.tools.compare_bm25`。
  ⚠️ 里面有一节（§2.4）专门写**它做不到的那件事**：**话题性 / 语义匹配它表达不出来**，
  而那**不是「没做」，是「不该它做」**。
- **不做匹配。** 把一段处境映射到方向是**检索系统上层**（**检索器层**）的事（继承 `dce` 的裁定）。
  ★ **那一层已实现**（`ldv/retriever.py` + `ldv/checks/retrieval.py`，`run_checks` 的 `(检索)` 组；
  设计稿 `docs/分层方向视图-检索器层.md`）：
  `T0`/`T1`/`T4`/`T5` 有实效（分派 / 认识是否当前 / 解释 / 展示记录），
  ★ **`T2`/`T3` 2026-10-14 起也生效了** —— `步骤 T3` 跳过「后看」的块
  （`Kernel.query(skip=...)`；依据是 `§I2` 的推论「合并说否 ⇒ 每个成员都说否」）
  ⇒ **少扫**（跑过的块从「全部」缩到「先看的」），**候选集逐项不变**（`T1` 拿全扫当基准守）。
  ⚠️ 2026-10-09 至 2026-10-14 之间它是「预备」的：那时 `T2` 算出的顺序**无处可达**

  三个探针实测「顺序反转 / 换成空元组 / 换成离散划分 ⇒ 输出**逐项相同**」。
