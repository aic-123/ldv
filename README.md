# ldv

**把语料装成一棵「分层划分树」，然后在树上做检索、推导与反事实推理。**

它做五件事：**记录**（把语料装成划分树）· **检索**（在树上定位候选）·
**推导**（从材料算谓词）· **推理**（找结构矛盾 + 回答「删了会怎样」）·
**处置**（不够格的东西降权、忽略在支上，但**不删**）。

⚠️ 第五件（**处置**）是 `§S7` 之后才写清的：它不属于前四件里的任何一件 ——
记录是「怎么装进去」，处置是「装进去之后怎么对待它」。
两者混着说，就会得出「删掉它」这种既不合 `§K4`（只分叉不覆盖）也不合 `§S7`（不物理删）的做法。

**定位：从「结构」这个方向做的认知模型** ——
记忆是分层划分，目标是内生稳态（结构不坏 + 能吸收新需求），
推理是失配驱动的结构修复（新需求 ⇒ 失配 ⇒ 改结构 ⇒ 自洽）。
不产内容、只产结构；能把**自己的产物**当材料（`我` 维度），于是反思与重构是结构里
看得见的项，不是内部日志。
认知模型有很多方向；它走的是**结构**这一路 —— 反应时 / 错误率 / 学习曲线那一类，
是另一路（表征-计算）要交的答卷。
定位是**约定**（不是定理）；它蕴含的**七条**可判承诺见 `§S1`–`§S7`。

**A system that turns a corpus into a hierarchical partition tree you can reason about.**

> **Record · Retrieve · Derive · Reason · Dispose**
> 五层都只产出**结构**，不产出答案。判错的代价是一次**漏**，而**用本身就是确认**。
>

## 30 秒跑一遍

零依赖、零配置 —— 克隆下来直接跑（**Python 3.13+**）：

```bash
git clone https://github.com/aic-123/ldv.git && cd ldv
python -m ldv.cli a      # 流程 A：在三个插件上各跑一遍检索
```

当场建出三棵划分树，并在每棵树上跑一次检索：

```
四条流程 · 流程 C（构建验收）在 `python -m ldv.run_checks`
本轮跑：A｜方向：['keyset', 'reach', 'sequence']｜维护新项 12｜**不删**（`--remove N` 才跑 B′）

═══ 方向 keyset ═══
  初始：19 个方向（§K2 判空 6），装进 24 项，事件 34 条；待维护 12 项
── 流程 A · 运行 ──
  查询「有 source.kind=其他」→ 命中 0 项｜是=19 否=0 未展开=0｜层=6
    展示 19 个候选（位次 1..19）｜产生记录 19 条｜没给反馈 0 个（**不产记录**：没看见 ≠ 看见了不好）
  终态：19 个方向（§K2 判空 6，叶容量 最大 5 / 平均 2.4），使用记录 55 条；空方向 0（已失效 0）
  账本：初始 34 → B 34（结构 +0） → A 89（展示 +55、**查询时展开** +0） → D 89（自优化**不写账本**）
```

（上面这段是**真实输出**，没删改：`方向` = 划分单元，`判空` = 无法分裂，
`叶容量` = 叶子大小，`账本` = 追加式事件日志。）

## 内核：它只回答三个问题

最小内核是一棵**分层划分树**（`ldv/core/` + `ldv/plugins/`）。
三个问题都是**结构**问题，不问内容：

    这个节点要不要继续分裂？ 它覆盖哪些项？ 覆盖有没有漏？

三者对应**三种不同性质**的东西 —— **只有第三个能红**：

| 问题 | 谁答 | 性质 |
|---|---|---|
| 要不要继续分裂 | 内核，按 `§K2` | **读数**（无法分裂的次数）—— 次数越多，说明这个谓词的形状越贴不上接口 |
| 覆盖哪些项 | 插件，按 `§I1` 命中 | **允许假阳**（`§K8`）—— 代价是性能，而性能**会累积** |
| 覆盖有没有漏 | 内核，按 `§I3` 的**代价归属** | **禁止假阴**（`§K8`）—— 破了就是**正确性**问题 |

### 不对称的那一条（`§K8` 是承重墙）

    假阳允许 ⇒ 代价是**性能**（会累积）⇒ 必须**计量**
    假阴禁止 ⇒ 破了**正确性**       ⇒ 必须**红**

⇒ 「假阳率」不是质量指标，它是**这个划分在漏**的读数 ——
**所有单元都说「是」，等于没有划分。**

## 它不是什么

**它交付结构，不交付内容。** 边界五条，每条都有判据或源码扫描守着：

- **划分单元只能人声明。** 方向函数、维度、谓词规则是**外生**的（`§K9`）——
  谓词推导只算**参数**（切分点从材料来），规则本身是人写的。所以没有「自动涌现」，
  也不需要一开始就有完美规则。
- **推理是结构的，不是语义的。** 包含、可达、递归分割、**反事实**（删了会怎样）都成立；
  「A 意味着 B」要理解内容，撞「禁止模型代填」，这一层不做。
- **不做裁判。** 没有全局目标函数、没有跨单元标量分、没有排序 ——
  `B12` 扫源码 + 协议禁词 `score / weight / priority / rating` 两头守
  （标准见 [`docs/评估标准.md`](docs/评估标准.md)）。
- **检索是另一层。** 把一段处境映射到划分单元，是**检索层**（已实现）的事；
  本层的落盘与并发只到「可选壳」那一层，**不声称线程安全**。
- **越用越顺手，不越用越懂。** 使用记录只调**内生**的展开优先级，且不跨会话累积；
  什么算一个方向**永远不学**（理由见下节「学习」）。

⚠️ 每条的理由、边界与实测（含「它和普通检索比好在哪」）见
[**它是怎么长出来的**](docs/它是怎么长出来的.md)。

## 学习：哪里不学、为什么，哪里学、学到哪

这张表是**定位的一部分**，不是免责声明。「不学」有几种完全不同的原因，
混在一起说，读者会读成「做不到」—— 所以逐处标清楚：表里每一处「不学」
都指明了替代机制或边界，这个项目**不存在「学不会」**，只存在「不在这里学」：

| 位置 | 有没有学习 | 是哪一种 | 依据 / 替代机制 |
|---|---|---|---|
| **什么算一个方向**（方向函数、维度、谓词规则） | 不学 | **设计：外生项只能人声明** | `§K9`；`B14` 扫源码守「自优化不许改外生项」；断言 `§D1` 外生准入 |
| **跨方向的评分 / 排序** | 不存在 | **没有位置** —— 不是学不了，是不放这个东西 | `B12` + 协议禁词 `score / weight / priority / rating` |
| **内生的局部代价 / 层内展开优先级** | **学** | **设计：学，但只在这里** | 流程 D（F0–F4）：使用记录 → 倾向权重 → 更新 `expand_priority` / `penalty_scale` |
| **使用记录本身** | 记录，不算学习 | **设计：记录不改结构** | 记录不写账本（「D 自优化不写账本」）；`§K6` 无信号 ≠ 负信号 |
| **解析缓存** | 不学 | **设计：纯函数缓存** | key 带 `mtime`，文件一变就失效 ⇒ 缓存 ≠ 学习 |
| **使用者入口**（`entry.py` 的 query / drill） | **学** | **设计：已接线，但只影响呈现次序** | **两段通道**：query 把「摆了哪些支」写进缓冲（`usage/_staging/`，**不算有用**，有界 50 批、暂定值）；drill 才 `promote` 成 `outcome = +1`。记录落 `<语料>/usage/*.md`、**不进 `nodes`**；下次启动读回，只排「先看哪一支」——`answer_ids` / `n_answer` / `n_branches` 逐字不变（判据 `[接入]` 八条 + 探针 `evidence/_probe_usage_wiring.py` 的 `W1`–`W10`）。★ 2026-10-25 起多一件：**负事件** `drill(verdict="wrong", actor="human")` ⇒ `outcome = -1`（判错只能外部授予，agent 只能提议），半衰期同样作用于它 |
| **否定**（项级标记 / 支级跳过） | 不学 | **设计：两条路，分工明确** | **项级**只标记（节点 front matter 的 `verdict` ⇒ 返回的 `answer_verdicts`，**不改候选集**，判断权交调用方）；**支级**才跳过（`ask(reject_below=N)`：倾向 < N 且查询 `require` 不包含该支 `must` ⇒ 不摆出来，`skipped_rejected` / `rejected_items` **差额可算**）。阈值**外生**（spec 声明），不设 ⇒ 与从前逐字相同（判据 `[否定]` 九条，含反向对照） |

两条要说清的：

1. **学的东西跨会话累积，但只到「呈现次序」为止。** 使用记录落在 `<语料>/usage/`，
   下次启动读回并折算成倾向；它只决定**先说哪一支**，`answer_ids` / `n_answer` /
   `n_branches` 逐字不变（探针 `W5` 守这条）。所以「越用越**顺手**」成立，
   「越用越**懂**」不成立。而且**只有下钻过的支才算数**：查询只把「摆了哪些支」
   写进缓冲，被摆出来只是曝光。清空：`python -m ldv.tools.usage_store clear <语料目录>`。
2. **为什么「什么算一个方向」永远不学。** 一旦让使用记录决定划分，会同时失去
   **可复现性**（同材料、不同历史 ⇒ 不同树）与**可解释性**（说不清这个方向为什么存在），
   而且是**很久以后才发现**，那时已经没法回溯。这就是 `F3` 存在的理由。

**动机（显著性三档）**：反思层把待办按**后果**分三档 ——
**必须**（结构矛盾、**根覆盖之外** ⇒ 结论可能错）/ **可延后**（切不开、待展开、**滞留** ⇒ 对但不全）/ **可忽略**（切了白切、已展开，且**不枚举**）；**档内**才按成员数定序。
★ 账本里的 `stayed`（滞留）与 `out_of_scope`（根覆盖之外）**也进清单** —— 之前只收 矛盾/展开失败/待展开，账本记着而反思层不看，那就是漏。
不是分数（有序等级），且动机只到「提问」，不加维度（`§D1`）。
完整通路「发现 → 提问 → 拍板 → 实施 → 验证」见
[`docs/谓词推导与反思层.md`](docs/谓词推导与反思层.md) §11。

### 处置与遗忘（`§S7`）

**处置有两层对象，别混**：**节点**（材料）与**使用记录**（`usage/`）。
`§S7` 的 (a) 管**两者都不物理删**，下面分开写。

| 层 | 存在哪 | 界面表现 | 遗忘方式 |
|---|---|---|---|
| **节点（材料）** | `nodes/*.md`（一项一文件） | **始终可查** —— `ask` 能返回它，`undo` 能拿它算反事实 | **不删**（`§S7 (a)`）：只追加不覆写（`§K4`）；要「不用它」，靠**支级忽略**（下面） |
| **短期显性记忆** | `usage/_staging/`（一批一文件） | **显式提示**：「这批还剩 N 支待看」 | 容量淘汰最旧（50 批，**暂定值**） |
| **长期隐性记忆（稳定区）** | `usage/*.md`（一条一文件） | **不再逐条呈现**，只体现在 `ordered_by` | **降权**（半衰期 30 天，**暂定值**），**记录永不删** |

★ **遗忘发生在计算上，不发生在存储上。** 记录是账本，只追加；
衰减因子 `0.5 ** (年龄 / 半衰期)` 只在算倾向时乘进去。

### 处置的两条分界（这是 `§S7` 的全部要点）

| | 作用对象 | 怎么判 | 说明 |
|---|---|---|---|
| **支级忽略** | **方向**（一支） | 倾向 < 阈值（外生）**且** `require` 不含该支 `must` | **不摆出来**，但项还在存储里；差额 `rejected_items` 可算 |
| **项级标记** | **项** | 只写进 `answer_verdicts` | **只标记，不改候选集** —— 判断权交调用方 |

⚠️ **忽略必须做在支上，不能做在项上**：摘掉一项 ⇒ `n_answer` 会变（那就是裁判了），
而且人明确问它时答不出。两条都是硬伤。
⚠️ **阈值外生**（`spec` / 透镜声明，系统不自己发明）—— 让系统自定阈值 ⇒
同一材料、不同历史 ⇒ 不同答案集合 ⇒ 违反 `§T1` 与可复现性。
⚠️ **明确问到就不藏**：`require ⊇ must(该支)` ⇒ 该支必摆出来。没有这一条，
「降权」会退化成「隐藏」。

⇒ 老经验影响力变小，但任何时候都能回答「它曾经学过什么」；
改半衰期就能「重新记起来」（可回退）；删记录只能 `clear`。

实测（`evidence/_probe_forgetting.py`，7 条判据）：一条 300 天前的记录，
倾向 **1.0000 → 0.0010**（10 个半衰期），记录**仍是 1 条**；
答案集合与支数**逐字不变**。

⚠️ **倾向是「累计证据」，不是「平均值」** —— 加权平均里 `w` 会被约掉，
单条老记录和单条新记录的均值一样（实测第一版就是「新 1.0000 → 旧 1.0000」）。
累计才对：重复证据累加（巩固），老证据衰减（遗忘）。

⚠️ 缺时间戳的记录**不衰减**（w = 1.0）—— 不知道时间既不能当「很老」，也不能当「很新」。

⚠️ 会话内 drill **不会**立刻改变后续查询的次序：`_tendency` 在启动时算，
巩固是**跨会话**的事（这也是「长期隐性」的含义）。

⚠️ **越具体的问题，权重机制越不起作用**（外部评审 D1 的注意）：倾向排序只在
`len(nodes) > 1` 时发生（单支查询整段跳过）⇒ 被否定的那一支如果是唯一答案，
它照样是唯一答案。这不是 bug —— 是「答案 = 项集，次序只是界面」的推论；
要真的不返回它，用 `reject_below`（支级跳过）。

⚠️ 如果哪天某一处从「设计上不学」变成「想做但做不到」，那要记成**缺陷**，
不许继续挂在「设计」名下 —— 两者的区别就是这张表存在的意义。

> 它的作用是让 clone 之后能跑起来，**不代表任何真实材料**。
>

>

> |---|---|---|

> `filled_by` 就是那条留痕：**允许填，但必须写明谁填的**。真实语料在 `_data/`（不进仓库），
> 那才是「可指回材料」的对象。
