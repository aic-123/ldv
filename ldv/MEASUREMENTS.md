## 跑

```bash
# 从**仓库根**跑 —— `python -m ldv.*` 要求 `ldv` 在 cwd 下
# Windows 上先设 utf-8，否则中文输出撞 cp1252 会 UnicodeEncodeError → 退出码 1
# （那和「有检查命中了」长得一模一样）：
#   set PYTHONIOENCODING=utf-8 & set PYTHONUTF8=1

# 四条流程
python -m ldv.cli all                    # A+B+D，三个方向都跑（顺序 B → A → D）
python -m ldv.cli a                      # 只跑流程 A（运行）
python -m ldv.cli b --holdout 30         # 只跑流程 B（维护）：只建 6 项，其余 30 项后添
python -m ldv.cli d                      # 只跑流程 D（自优化）—— **会红**，见下
python -m ldv.run_checks                 # 流程 C（构建验收）：B1–B19

# 检查
python -m ldv.run_checks keyset          # 只跑方向 A
python -m ldv.run_checks reach           # 只跑方向 B
python -m ldv.run_checks sequence        # 只跑方向 C
python -m ldv.tests.test_injections      # 30 条注入：每条检查都必须能红
python -m ldv.tests.run_tests            # 213 条单元断言
```

**退出码只看护栏**：`M3`（锥外变动）/ `F3`（外生项被改）/ **空转** / 未捕获异常。
度量（方向数 / `§K2 判空` / 叶容量 / **最大停留数** / 假阳率 / 位次 / 账本分解 /
**增量 ≡ 全量** / **可搬的判空点** / **规范重建** / **健全性** / **覆盖嵌套** /
**覆盖不漏** / **进步量** / **滞留**）走输出，不进退出码。

⚠️ **空转也进退出码**，这是刻意的：`python -m ldv.cli d` 单独跑时没有使用记录，
自优化什么都没学到 —— 那种运行**必须红**。理由见 `C7-流程跑通.md` §3.5：
`FlowD.内生量确实变了` 会**退化恒真**（0 条记录时 `penalty_scale` 从 1.0 变 0.0 也算「变了」），
旧版因此把空转印成了成功。

⚠️ 健全性的判据原来**只落在能绿的那条路径**（批建）上，维护那半由度量报出 ——
理由是**基线就红的判据过不了注入验证**（注入验证要求「基线绿 + 注入红」）。
§10.2 出路 (1) / (4) 把维护路径修绿之后，`B1` / `B16` **升级成两条路径各判一次**；
**覆盖不漏**的维护那半**还红着**（sequence 16 漏）⇒ 它继续走 baseline 守卫。
⇒ **判据的适用范围，收窄要印、放宽也要印** —— 否则「只跑一条路」与「两条路都跑」
在汇总里长得一模一样。
§K8 是「假阴禁止 / **假阳计量**」，两半都要有：假阳的代价是性能，
而性能**会累积**。一个假阳率 90% 的过滤器不违反任何一条检查，
却让整套结构白建 —— 所有方向都说「是」，等于没有方向。

> ⚠️ `§K2 判空` 是「判过几次『这一层不建』」的记账，会随**建法**轻微变化；
> **叶容量在五种建法下逐项相同**（`C7` §3.1.3）——
> **方向数只有 A / B 逐项相同**，C 会随初始批大小变（21 → 16，见下 §第 4 个度量 ③）。
> 会变的那个是记账，不变的那个才是形状 —— 这就是度量与判据的分界。

所以另取一份：**OpenAlex** 引用图切片（CC0）。取法与丢弃明细见
`tools/intake_openalex.py`；验收见 `tests/test_intake.py`。

    种子    publication_year:2020-2021, cited_by_count:>200，按被引降序取前 200
            （该筛选共命中 77,043 篇）
    切片    共被引 ≥ 2 的闭包  ⇒ **3907 项 / 24156 边 / 丢弃 196223 条外部引用**
    子切片  共被引 ≥ 5        ⇒ 281 项 / 1008 边

**两条互不相干的数法**（一条走 markdown 往返、一条直接读原始 JSON）给出同一组数
⇒ 转换器没漏写节点、没漏写边、没把 `relations` 写成别的形状。

### 结果一：`B17` 在**真实**引用图上红了（判据被证伪）

    语料              项数    边     SCC ≥2 的个数   最大 SCC    `B17`(reach)
    ──────────────────────────────────────────────────────────────────────────
    随仓库那 36 项      36     47          0            1         跳过（退化）
    OpenAlex 子切片    281   1008          6            4         **红**（6 个类被拆开）

设计文档 §7.2 的原话是「`reach` 在**合环图**上会把互相可达的两项劈成两个
覆盖完全相同的子方向 …… **真实语料是 DAG，所以这个缺口在语料上不露**」。
⇒ **后半句被证伪**：引用图不是 DAG（论文互引），281 项切片里有 6 个 ≥2 的强连通分量，
   而 `B17` 报的「被拆开的等价类」**正好 6 个**。

根因（实测，`outputs/_probe_b17.py`）：oracle 是**对的** ——
281 个 SCC 里 272 个的**正向闭包完全一致**，所以那些项**真的**不可分；
分开它们的是 `reach.split`：它按 `(汇点签名, 到汇点的距离, id)` 排序后**取中点切**，
并列的项会被中点切开。`keyset` / `sequence` 的 `split` 按**区分键**切，
并列项天然同侧 —— 所以那两条上 `B17(b)` 的论证成立，`reach` 上不成立。

⚠️ **这不是实现 bug，是判据的适用范围**：`reach` 的设计**有意**比语义更细
（`split` 的 docstring：「方向可以一路细到单项，而『可达』的语义一点没丢」），
而 §K8 允许假阳 ⇒ 更细只赔性能。`B17(b)` 要求「结构不许比语义更细」，
在 `reach` 上就是**过强**。⇒ 记在 §10 留白，不在这里改判据。

同一趟里 `B1`（两条路径）/ `B16`（两条路径）/ `B18` / `B19` **全是绿的** ——
「红 1」不等于「什么都不对」，两件事要分开报。

### 结果二：`B8` 原来是**平方**的（真缺陷，已修）

`B8`（失效局部）原来是「每检查第 k 项就 `make_kernel()` 重建、把前 k−1 项重插一遍」
⇒ 总插入次数 `n(n−1)/2`。36 项上 0.05 s，**看不出来**：

    语料               n     改前                      改后
    ───────────────────────────────────────────────────────────
    openalex-small    281   21 分钟没跑完（被杀）       0.7 s
    openalex         3907   61 分钟没跑完（被杀）       6.7 s

改成一个内核走到底、快照逐次前移（`checks/structure.py`）。**判据内容一个字没动** ——
两个实现各自吐出「每一步的 `changed` 集合」的 trace，逐字比对：

    语料/方向                     现写      增量     逐步 trace
    ────────────────────────────────────────────────────────
    b160 keyset                  0.62 s   0.01 s   相同
    b160 reach                   6.36 s   0.08 s   相同
    b160 sequence               17.38 s   0.25 s   相同
    b160 keyset · 注入            0.78 s   0.01 s   相同（都是 159 处越界）

**12/12 逐字相同**（含注入后变红那一档）。⇒ 换增量不动判据，只把 `n²/2` 降到 `n`。

### 结果三：剩下的墙，以及「判据」与「探针」要分开关

`B8` 修完之后 `run_checks` 在 281 项上还要 ~13 分钟，98% 花在**一条只报不判的度量**上：

    检查                  代价的形状                281 项实测
    ─────────────────────────────────────────────────────────
    规范重建（度量）       O(n) 次重建 × 每次 O(n)      **446 s**（reach）
    B15（判据）            3 次整建                      0.5 s
    B8（判据）             n 次插入                      0.2 s
    其余全部合计                                        < 2 s

⇒ 关键区别不是「贵不贵」，是**进不进退出码**：

    判据（进退出码）   B1–B19
    探针（只报不判）   十个度量

⇒ `--no-probes`：**判据一条不少地全跑，只把贵的探针关掉**。
   **关它是安全的** —— 度量不进退出码，关掉它**不可能把红变成绿**。
   报告里写明哪几行未跑（「没跑」与「跑了但没话说」不共用一行）。

    281 项：整趟 ~780 s  →  `--no-probes` **6.05 s**，而 `B17` 那条红照样露

#### 结果三′：全量 3907 项上 `--no-probes` **41 分 24 秒还没跑完**（主动停掉）

文档里原先写「全量是二十分钟级」—— 那是**估**的。量了之后是**下界 >41 分钟**。

先猜了两次「贵的在哪」，两次都**只对了一半**，因为**结论依赖尺度**：

    假设 1  `B8` 改完还留着一个「每步对全部方向做一次成员集快照」的 O(n) 扫描
            ⇒ 281 项：B8 keyset 0.02 s ｜ reach 0.25 s ｜ sequence 0.54 s ⇒ **不是大头**
            ⇒ 3907 项：B8(reach) **145.2 s** ⇒ 仍然不是最大的那一块
    假设 2  `cover()` 被七八块**各自独立**重算，每块 O(方向数 × n)
            ⇒ 281 项：八块合计 **0.11 s**（单次 `cover()` 40 µs）⇒ 判成「不成立」
            ⇒ 3907 项：**一块** `soundness_profile` 就是 **115.8 s** ⇒ **翻过来了**

**全量 reach 逐块实测**（`outputs/_measure_fullscale_blocks.py`）：

    coverage_of(reach) 建闭包        0.80 s
    equiv_classes(reach) [SCC]       1.04 s
    build 批建内核                 103.67 s   （7813 个方向）
    build 维护内核                  78.10 s   （2101 个方向）
    soundness_profile 批建         115.76 s
    B8(reach)                      145.19 s
    B15(reach)                     309.71 s
    ────────────────────────────────────────
    七块合计                       753.9 s ≈ 12.6 分钟

而 `run_one("reach")` 调的不止这七块：`健全性`×2 / `覆盖不漏`×2 / `进步量` /
`B16`×2 / `覆盖嵌套` 那一族**每块都是同一量级** ⇒ reach 一个方向就是二十分钟级，
再加 keyset（实测 **47.3 s**）与 sequence。

**为什么 281 项上看不出来**：`cover_reach` 的成本是 `O(n × |可达闭集|)` ——
单次调用从 40 µs 涨到 **~14.8 ms**（370 倍），而 n 只涨了 13.9 倍。
差的那 27 倍全在**闭集本身变大**上。

⚠️ **规矩**：小切片上做的对照，结论**必须带上尺度**。
   「X 不是瓶颈」不加「在 n=281 上」就是一句会误导人的话 ——
   第一版结论就是这么写歪的：它**没错**，只是**不可外推**。

⚠️ 也因此，**「把账记在 `B8`/`B15` 头上」在 281 项上对、在 3907 项上不对**：
   3907 项上更大的是**内核两次建（181.8 s）+ 那一族 cover 度量（千秒级）**。

⚠️ 另有一个 `--cap N`（只跑前 N 项），但它**连判据一起截**，会挡住结论：
   实测 `openalex-citations` 的环**全落在第 400 项之后**（前 400 项 SCC ≥2 的组 = 0），
   所以 `--cap 160` 上 `B17` 那条红**根本不会出现**。
   ⇒ 要快用 `--no-probes`，别用 `--cap`。

### 结果四：`B18` 的基线没按语料分开（也是这份料撞出来的）

`B18`（覆盖不漏的 baseline 守卫）的基线是在 36 项上冻的（`sequence` 维护路径 16 漏）。
换到 281 项的切片上，那一格是 **183 漏** ⇒ 报出「新增覆盖不漏：183 漏（baseline 16）」。
**那句话是假的** —— 没有任何东西变差，只是 baseline 换了参照物，
而「baseline 是别的语料的」与「新增违规」在输出里**长得一模一样**。
⇒ 已修：基线记**语料指纹**（项数 / 边数），对不上就报**跳过**并说清是换了语料。

⚠️ 顺带量出一个数：`sequence` 维护路径的覆盖不漏 **16 漏 → 183 漏**。
   缺口还是那个缺口（§10 已知），但真实语料上的规模**大一个数量级**。

### 结果四′：「基线**不见了**」也曾长得像另外两件事（`outputs/_measure_b18_missing_baseline.py`）

修结果四的时候顺手把「`语料` 为空」也归到「判不了」。**没有量过旧行为** ——
量了之后结论和推理**不一样**。同一份 obs、同一份「基线文件不存在」的输入，
**只有守卫的版本在变**（旧版是 `git show HEAD:...` 的逐字复制）：

    臂 A  只有 `keyset`/`reach`（既存违规 0 处）      旧 **绿**  →  新 跳过
    臂 B  全量（含 `sequence|maintenance` 既存 16 漏） 旧 **红**  →  新 跳过

### 第 4 个度量：`增量 ≡ 全量`（`checks/divergence.py`）

「增量维护后的结构」该不该等于「从零重建同一集合的结构」？
两篇独立文献把它当**正确性标准**在证（Acar 的正确性定理；Godin 与三个 batch 算法对比），
而我们**实测它不成立** ⇒ 做成**只报不判**的度量，并把它变成决策依据。

    全量   `build(全部项)`              —— 内核一开始就认识所有项
    增量   `build(前 k 项)` + 后添 N−k  —— 内核后来才认识它们

```
方向       全量方向/叶容量   k=2   k=6  k=12 k=18 k=24 k=30 k=34 k=35   最早同构的 k
─────────────────────────────────────────────────────────────────────────────────────
keyset        25 / 10      24=24 24=24 24=24 23=23 23=23  4=4  4=4  0=0   35（= N−1）
reach         71 / 1       69=69 71=71 67=67 59=59 48=48 49=49 32=32 28=28 无
sequence      16 / 10      12=17 14=18  7=10  6=8   0=0  0=0  0=0  0=0   24
```

（数字 = 「全量独有 = 增量独有」的方向个数，0 即同构。）

**三个结论，都是决策依据**：

    ① 没有一个方向能在「后添 ≥ 2 项」时同构
       ⇒ 加大初始批次**没用**（keyset 从 23 掉到 4 就卡住，到 N−1 才归零）
    ② 差异**不在分辨率** —— 三个方向的**叶容量逐项相同**（keyset 10、reach 1、sequence 10）
       ⇒ 它坏在「哪些项分到一组」，不是分辨率
    ③ ⚠️ **方向数只有 A / B 逐项相同**：`sequence` 随 k 变（**21 → 16**）。
       这是 k 叉的**结构后果**：扇出在**首次展开**时定形（§K2），
       初始批次小 ⇒ 当时看得见的符号少 ⇒ 得在更深处再分一次。
       **变的是记账，不变的是分辨率。**
       ⚠️ `sequence` 的差还**不对称**（k=2：全量独有 12 / 增量独有 17）——
       增量侧的方向**更多**，与「初始批次小 ⇒ 多分一层」同向。

⚠️ **度量也要能变。** 一个永远报同一个数的度量，和一条永远绿的检查一样没有信息量。
所以这个模块自带**比较器自检**（每次都跑）：

    同路径必须同构       `build(全部)` vs `build(全部)`        → 必须 True
    项集不同必须不同构    `build(全部)` vs `build(全部[:-1])`   → 必须 True

两条一起成立 ⇒ 比较器**不是常量**。任一条不成立 ⇒ 本次读数不可信。
`test_injections.py` 另有一条**敏感性**验证：注入「分不开写成永久标记」之后，
读数的**尺度列**必须变化（基线 25/10 → 注入 1/36）——
注意它在「同构」那一列上**看不出来**（两边都不同构），只在尺度列上露出来。
**这就是「度量必须报多个数」的理由。**

### 第 5 个度量：规范重建（`checks/rebuild.py`）

第 4 个度量量到「不成立」之后，**唯一**能让它成立的做法是把结构做成**项集的函数**。
两种做法都量了：

    规范不动点  每次插入后，从**当前项集**按**规范序**（id 升序）整树重建
    阈值重建    只在规模跨过 2 的幂时重建（Naor–Teague）—— 摊还 O(1)

```
方向       做法         同构全量的 k   k 指纹数   重建次数  重建工作量
─────────────────────────────────────────────────────────────────────
keyset     规范不动点      8 / 8         1        35       665
keyset     阈值重建        1 / 8         3         5        62
reach      规范不动点      8 / 8         1        35       665
reach      阈值重建        0 / 8         3         5        62
sequence   规范不动点      8 / 8         1        35       665
sequence   阈值重建        8 / 8         1         5        62   ★ k 叉之后买到了
```

**四个结论**：

    ① 规范不动点**确实买到了**：8/8 同构，且 **k 指纹只有 1 种**
       ⇒ 不只是「与全量一致」，而是「各 k 之间也一致」⇒ 结果不依赖初始批次
    ② 代价 **O(n) 每次插入**：35 次重建 / 工作量 665 = `2+3+…+36`
    ③ 阈值重建**只对「扇出不是恒为两个」的方向买到**：sequence **8/8、k 指纹 1 种**
       （trie 形状：首次重建时符号齐了就定形，之后添的项只落进**已有**的子方向）；
       扇出恒为两个的 keyset **1/8**、reach **0/8** —— 差异发生在**两次重建之间**，
       阈值之后添的项仍是增量的 ⇒ Naor–Teague 买到的是「摊还 O(1) 的重建」，
       **不是**「结构 = 项集的函数」
    ④ `B8` **红** —— 规范重建每次全量重算，正是 §K3 要挡的形态

⇒ **不做。** 理由不是「太贵」，是**交换的东西不对等**：它要拿 §K3（**接口级**不变量）
去换「结构可复现」（**实现**性质），而第 1 步已说明「不同构」**不破坏任何一条检查**。

★ **一条可以搬走的判据**：只有当**输出唯一**（一个值 / 一个格 / 一个规范形）时，
「增量 = 全量」才是**正确性**标准；输出是**一族**（本设计：§K1–§K9 描述一族合法树）
时它只是**实现性质**。搬这条到新领域之前先问「**这个输出是唯一的吗**」。

⚠️ **另一条与 id 无关的读数：失效范围比。** `B8` 用**方向 id** 比对，而重建会把 id
全部换掉 ⇒ **任何**重建实现都会被 `B8` 判红，结论会显得像比对的产物。所以另报一个
**用成员集合做对称差**的读数：基线 **0.00** / 规范重建 **0.06**（A、C）、**0.29**（B）。
⇒ 规范结构对插入**近似稳定**：重建在**结果**上安全，代价**全在重算**上。
（⚠️ 量的时候必须**扣掉新插的那一项**，否则读数没有区分力：不扣时基线 0.78 / 重建 0.79，
差 0.01 —— 被「x 进了路径上每个方向」这个**任何实现都有的共享项**压住了。）

`run_tests.test_rebuild` 六条断言把上面每一条都钉住，其中 ⑤ 断言的是
**`B8` 在规范重建内核上红、在路径局部内核上绿** —— 断言的是「**这条判据抓得到它**」，
不是「留一个已知红」。

### 第 6 个度量：健全性 —— **两条路径都量，而且都是判据**（`checks/coverage.py`）

`members(d) ⊆ 覆盖(d)` 是 §1 硬要求表的**第三行**（`B16` 守）。
`B16` **两条路径各判一次**（`B16 批建路径` / `B16 维护路径` 各占一行，各自注入验证）；
度量把两份读数并排印出来，是给人看的趋势。
⚠️ **判据落在哪条路径上，由那条路径的基线决定** —— 基线绿的才能当判据
（一条**基线就红**的判据过不了注入验证：注入验证要求「基线绿 + 注入红」）。
`B18` 现在就是那种形态（维护路径 16 漏），所以它只跑批建、维护那半走 baseline 守卫。

⚠️ **覆盖由外生 oracle 算，不调插件**（`_fixtures.coverage_of`）——
`B16` 原来按 `§I3 代价` 重算归属，属 `false-green` 形状 3「共享盲点」；
certifying algorithms 要求 checker **比被检查的东西简单**。

**为什么两条路径都要量** —— 这一条在两条路径上**不是同一件事**：

    一次建完     每个方向的成员集在**第一次展开时就是完整的**
                 ⇒ 子方向的 payload 从这批成员算出来，一定盖得住它们 ⇒ 天然成立
    维护路径     成员是**后来才长起来的**，而 payload 在劈开时就**冻结**了
                 ⇒ 子方向收不住「它没见过的项」⇒ 破了也没人查

```
方向        一次建完        维护路径（先建 6 维护 30）        B1（**维护路径**上的假阴）
──────────────────────────────────────────────────────────────────────────────────────
keyset      0 / 159        0 / 232                        **是**（411 个样本，0 条假阴）
reach       0 / 224        **0 / 33**  ★ 根记账修好          **是**（58 个样本，0 条假阴）
sequence    0 / 122        **0 / 86**  ★ 出路 (4) 修好       **是**（57 个样本，0 条假阴）
                                        （原来 36 / 176）
```

⇒ `sequence` **一次建完全绿、维护路径原来全红**，而且**真的产生假阴**。
两条修法落地之后 `B1` 也一起搬到了维护路径（它的 ground truth 里有**成员集**，
两条路径上的成员集不同 ⇒ 同一批查询问的是另一件事；`reach` 那格样本数
**316 → 58** 就是「出路 (1) 把 28 项挪出了结构」这条代价的读数）。

⚠️ **它不是新出现的** —— 不续父方向的版本在维护路径上同样破
（先建 2：47/235 越界），只是破得少一点。

**A 的修法已落（一行）**，单变量对照（先建 2 维护 34）：

    `common` 掺进 `req`（改前）     123 / 227  且方向数随初始批大小变（23/23/21/25/25）
    `req` 只从父续（改后）            0 / 235  且方向数恒为 25

⇒ 代价：全量假阳率 49.4% → 50.1%（**判「是」803 次里多 10 次**）。
**这不是「性能换正确」的交易，是把一笔本来兑现不了的声称收回来** ——
`common` 声称「落进来的东西都带这些键」，而劈开兑现不了它。

**B 的修法已落（§10.2 出路 (1) 根记账）**，单变量对照（先建 6 维护 30，`reach`）：

    根记账之前     128 / 328    （根的 28 个越界成员是全部越界的主要来源）
    根记账之后      **0 / 33**   （28 项落在根覆盖之外 ⇒ 不塞进结构 ⇒ 记一条账）

⇒ 关键不在「把数压小」，在于那 28 项从「静默错位」变成「**一条显式的账**」
（`stats()['根覆盖之外']`、账本 `out_of_scope` 事件、流程 B 的逐项报告）。
代价落在**范围**上：那些项在这条方向上检不出来 —— 可见、可数、有事件，**不是静默假阴**。

**C 的修法已落（§10.2 出路 (4) 项留在父方向）**，单变量对照（先建 6 维护 30，`sequence`，逐 k）：

    方向        方向数  最大叶容量  最大停留数  滞留   成员总数  越界      漏
    ─────────────────────────────────────────────────────────────────────────
    改前（照塞）  20        10         10        0      176    36/176    16
    改后（留父）   8        10         10       16       86     0/86     16

⇒ 转绿的那部分**不是被修掉的，是被挪到父方向上的**（`stats()['滞留']`）。
   两条出路都让健全性变绿，但**代价落在不同地方** ⇒ 必须分开报：

       根覆盖之外   项**不在**任何方向的覆盖里 ⇒ **范围**损失（项检索不到）
       滞留         项**在**父的覆盖里，但没有子方向表达得出来 ⇒ **划分**代价

   不是「覆盖不漏」（§1 第四行）。**别把这一条的绿灯记到那一条头上。**

   `叶容量` 看不见停在**内部**节点上的项，要用 `最大停留数`（见第 10 个度量）。

若去量一次建完，基线与注入都是绿的（0/159 vs 0/159），

### 第 7 个度量：覆盖嵌套 —— 子说的「是」，父接不接得住

    覆盖(子) ⊆ 覆盖(父)   ⟺   `命中(子,q) = 是` ⇒ `命中(父,q) ≠ 否`

§1 硬要求表里**没有**这一条 ⇒ 违反它**不破坏正确性**（父的「否」只在父的覆盖之外才下，
剪枝仍然安全）⇒ 进输出，不进退出码。但它**不是无害的**：子方向收下的东西被父否掉
⇒ 父的过滤器比子的更松 ⇒ 遍历在父那一层**白走一趟**才到子。这正是 §K8
「假阳的代价是性能，而性能会累积」的**结构形态**。

    假阳率      说「说了多少句不该说的**是**」—— **行为**侧
    覆盖嵌套    说「子说的『是』，父接不接得住」—— **结构**侧

实测（36 项语料）：`劈开` 拿不到父方向时，子方向把父的 `forb` 丢了 ⇒ A **越界 14 次**；
把父的 `forb` 续上之后 **0 次**（三个方向全部 0 次）。

出处：`ldv/checks/contract.py` 的 `cover_nesting_profile`；`ldv/tools/measure_parent.py` 表一。

### 第 8 个度量 + `B18`：覆盖不漏 —— **baseline 守卫**（`checks/coverage.py`）

`覆盖(父) ⊆ ∪覆盖(子)` 是 §1 硬要求表的**第四行**。它与健全性是**两条独立的机制**：

    第四行被破   一定有项落进「它不满足」的方向（§1 的推导）
                 ⇒ `members(d) ⊄ 覆盖(d)`（**第三行**跟着破）
    第三行被破   可以只出在根上（外生 payload 与「后来添的项」无关）
                 ⇒ 与父子关系无关（**第四行**是好的）

⇒ **照第四行去修 `reach` 会修错地方**：`reach` 的第四行 **0 漏**，
它的第三行破在「根自己的 payload 盖不住成员」上（§10.2）。

**为什么要 baseline，而不是直接进退出码。** 第四行现在在 `sequence` 的维护路径上
**本来就是红的**（16 漏 / 2 对）⇒ 一条基线就红的判据**过不了注入验证**
（注入验证要求「基线绿 + 注入红」）。处置沿用 ESLint `--prune-suppressions` 的纪律：

    新增的漏              ⇒ **红**
    账上已冻结的漏**不再发生** ⇒ 也**红**（条目失效必须报错，否则基线只会越长越脏）

```
方向|路径            漏项数   漏的对数   状态
──────────────────────────────────────────────────
keyset|batch          0        0        ✓
keyset|maintenance    0        0        ✓
reach|batch           0        0        ✓
reach|maintenance     0        0        ✓
sequence|batch        0        0        ✓
sequence|maintenance  16        2        ✗ 已冻结（D0 漏 8 项、D1 漏 8 项）
```

### 第 9 个度量 + `B19`：进步量守卫 —— **跨次数**的性质（`checks/coverage.py`）

`细化量(d) = |覆盖(d)| − max_k |覆盖(k)|` —— 一个方向比它最好的子方向细多少。
一个**方向上不进步**、却一直往下长层的实现，会**永远不终止**（或长成一条链）。
SP-GiST 的 `longValuesOK` 用 **N = 10** 当前例：连续十次展开没让覆盖变细就报错。

它是**内核自算**的（不动接口），因为 `覆盖` 内核手上本来就有。

```
方向        展开次数   无进步   最长连续段   最小细化量
────────────────────────────────────────────────────────
keyset        12        0         0           1
reach         35       10         4           0     ← 唯一报出这条读数的方向
sequence       5        0         0           1
```

⚠️ `reach` 的「无进步 10 次、最小细化量 0」**不是 bug** ——
它的子方向是「能走到锚点的项」，父的覆盖常常**恰好等于**子方向的并
（`reach` 的第四行 0 漏正是这个意思）。**这条读数第一次让这件事可见**：
`B19` 在 N=10 下没红（最长段 4 < 10），但它是**最接近阈值**的方向。

### 第 10 个度量：`滞留` + `最大停留数`（`core/kernel.py` 的 `stats()`）

§10.2 出路 (4)「**项留在父方向**」的代价。它与第 6 个度量的「根覆盖之外」
**不是同一件事**，所以**不能合并成一个数**：

    根覆盖之外   项**不在**任何方向的覆盖里（根下「否」）⇒ **范围**损失（项检索不到）
    滞留         项**在**父的覆盖里，但**没有子方向**表达得出来 ⇒ **划分**代价
                 （项仍可检索 —— 父的 `命中` 说「是」）

合并就把「**声称**盖不住」与「这一层**表达不出来**」当成一件事。

    滞留 = 「每个子方向都**证明**不收它 ⇒ 停在父方向」的项数（= 账上 `stayed` 事件数）

**`最大停留数` 是 `叶容量` 的推广**（不是另一个数）：

    停(d) = |members(d) \ ∪members(子)|          ← 停在 d 上、没再往下走的项
    最大停留数 = max_d 停(d)

    ⚠️ 必须**从成员集现算**，不能用 `Cone(x)` —— 锥是**插入时**记的，
       而某个方向**后来**才劈开时，已在它里面的项会被重新分配，锥却不会延长
       ⇒ 算出来会把「早就走到叶的项」当成「停在内部节点」。

`叶容量` 的盲区（**一个数骗人，一个数不骗**）：

```
sequence，先建 2 维护 34
    最大叶容量     **2**     ← 看起来分辨率很高
    最大停留数     **34**    ← 真相：34 项堆在**根**上（根是内部节点）
    滞留            32
    停在叶上 / 停在内部   4 / 32
```

两条**恒等式**（`run_tests.test_stay_at_parent` 查，两边互相独立地算）：

    Σ_d 停(d) == 纳入              （停在叶上 + 停在内部 == 纳入）
    Σ_{d 非叶} 停(d) == 滞留（账上）

**批建路径上两者相等**（滞留恒为 0 ⇒ 项都走到叶）：keyset 10/10、reach 1/1、sequence 10/10
⇒ 所以 `最大停留数` 是**修掉盲区后的那个数**，不是「多出来的一个数」。

⚠️ **它同时补上了 `B17` 等式的那个前提**（见下）：`叶容量 = 最大等价类`
只在滞留 == 0 时成立；滞留 > 0 时 `叶容量` 会掉到**下界以下**，而下界改由
`最大停留数` 承担。

### `B17`：叶 = **不可分等价类**（叶容量 = 分辨率下界）

`§K2` 的字面是**两句话**，内核只实现了第一句：

    展开必须产出**下层表达不出的东西**，否则不建这一层
    └────────── 第二半 ──────────┘   └─ 第一半 ─┘
                                      内核只查「劈开后一侧为空」

第二半是**语义**问题，而**内核没有语义**（§4.1：它只认七个方法）。
它手上只有 `§I3 代价`，而 `代价` **允许假阳** ⇒ 拿它当语义判据就是
`false-green` 形状 3「共享盲点」。⇒ 第二半只能**外生**判，那就是 `B17`。

**「不可分」是外生定义的**（`_fixtures.equiv_classes`，**不调插件**）——
两个项对**任何 payload** 都给同一答案：

    方向      不可分 ⟺                最大等价类   最大叶容量   叶数   等价类数
    ──────────────────────────────────────────────────────────────────────
    keyset    键集相同                  10          10        13      13
    sequence  序列相同                  10          10        11      11
    reach     **互相可达**（同一 SCC）     1           1        36      36

    reach 那条要推一下：互相可达 ⇒ 对任何锚点集 S，`x ∈ reachable(S) ⟺ y ∈ reachable(S)`
    反之（z 走不到 y）取 `S={y}` 就分开 ⇒ **不可分 ⟺ 同一强连通分量**

⚠️ **`reach` 的等价关系不是「汇点签名相同」** —— 实测签名只有 **3** 类，
   而内核把它分成了 **36** 个叶。签名相同**不**蕴涵不可分。
   拿签名当 oracle 就是拿插件的谓词复述插件。

**两半合起来是等式** `叶容量 = 最大等价类`：

    等价项对任何 payload 都给同一答案 ⇒ 必落同一个叶 ⇒ 叶容量 **≥** 最大等价类
    每个叶都是单个等价类              ⇒ 叶容量 **≤** 最大等价类
    ────────────────────────────────────────────────────────────────────
    ⇒ **等式**。任何 payload 设计都越不过去 —— 那是该方向能表达的**分辨率下界**。

⚠️ **等式有一个前提：`滞留 == 0`（每一项都走到了叶）。** §10.2 出路 (4) 之后
   这个前提**不自动成立** —— 项可以停在**内部**节点上，而 `叶容量` 看不见它们。
   实测（`sequence`，先建 2 维护 34）：

       滞留 32 ｜ 最大叶容量 **2** ｜ 最大等价类 **10** ｜ 最大停留数 **32**
       叶 D1 = {arg-0001, arg-0002}（**同一个**等价类）、叶 D2 同理
       ⇒ **叶仍然各自是单个等价类**，可是 `叶容量` 报出了 **2 < 10**

   ⇒ 掉下去的不是分辨率，是 **`叶容量` 这把尺子的量程**。一般形式是两条：

       每个叶都是单个等价类      ⇒ 叶容量 **≤** 最大等价类   （恒成立）
       等价项必落同一个**方向**   ⇒ 最大停留数 **≥** 最大等价类 （恒成立）
       两者相等（`= 最大等价类`）⟺ 滞留 == 0

   ⇒ 所以 **`B17` 只跑批建路径**（那里滞留恒为 0），维护路径上的分辨率读数
     要用 `最大停留数`（第 10 个度量）。
     ⚠️ 这条差别**不能留给读者猜**：拿 `叶容量` 去维护路径上比，会得到
     「分辨率比下界还高」这种不可能的好消息。

⇒ 顺带回答了 `C8` §7 第 2 步（`§K2` 的第三个选项值不值得做）：
  **不值得，而且原因是可证的** —— 判空点上项在该方向的语义下**就是同一个东西**，
  **没有区分信息可搬**。15 个判空点，可搬的 **0** 个。详见 `C9-等价类下界.md`。

**★ 这条检查在合环图上是红的。** 语料是 DAG（36 项 / 47 边，无环）
⇒ 等价类全是单点 ⇒ `B17` 在真实语料上**退化**（报「跳过」，**不报「过」**）。
自己造一个合环小图（`a ↔ b`、`c → a`、`d` 孤立）就露出来：

    reach 把 a、b 劈进两个子方向 D3={a} / D4={b}
    而 a ↔ b ⇒ `reachable({a}) = reachable({b})` ⇒ **两个子方向覆盖完全相同**

⇒ 一层什么都没表达的层，`§K2` 本该拦住它、没拦住（判空只查「两侧非空」）。
**这是 `§K2` 实现的缺口**，记在设计文档 §10；`B17` 是钉住它的检查
（`run_tests.test_equivalence` ⑤ 断言的就是「它现在红」）。

> ⚠️ **为什么不能只用「叶容量」这个度量守它。** 注入「能分也判分不开」之后 ——
>
>     叶容量 最大 **10 → 10**（**没变**！）   叶数 13 → 8   可搬的判空点 0 → 3
>
> 叶容量没变，是因为最大的那个等价类（10 项）本来就在**另一个**方向上，
> 局部合并只把小类并起来，够不到最大值。
> ⇒ **叶容量是「最坏情况」的数，对局部退化不敏感**；这条检查看的是**成分**。
> **度量报趋势，判据守成分。**

## 五件不显然的事

**一、`Tri` 不是 `bool`。** `bool(Tri.UNEXPANDED)` 抛异常，不返回 `False`。
「未展开」与「否」分不开，就不许印成「否」（§K6）。
同源的一条：`Report` 把**过 / 红 / 跳过**三个数分开报 ——
dce 那边实测过，一条检查静默消失时，「9 条跳过 0」和「8 条跳过 1」长得一模一样。

**二、划分是内核的责任，不是插件的责任。**
`§I1 命中` 允许假阳，所以 `命中(d, x) = 是` **不能**证明 x ∈ d；
拿它当归属谓词，「不重不漏」就永远查不出重叠。
⇒ 归属由内核按 `§I3 代价` 分配得到，插件只负责「提出两个候选方向」。

**三、检查必须成对验。** 只验「注入后红」会被「本来就红」骗过；
只验「未注入绿」会被「永远绿」骗过。所以 `test_injections.py` 每次都跑两遍。
**30 条而非 19 条**：有四条检查**各有两条判据**，所以注入也要两条 ——

    `B1`   批建路径 / 维护路径   （ground truth 里有**成员集**，两条路上不是同一件事）
    `B4`   不重 / 漏的条条有账   （第二条只在**真有滞留**的结构上验得出来）
    `B11`  完备 / 位置敏感       （只验「缺倾向会红」的话，把曝光模型退回均匀**不会有任何东西变红**）
    `B16`  批建路径 / 维护路径   （同 `B1`；且两条各要一条**不同的**注入，见下）

**另有一条注册表自检**（第 0 条）：`CASES` 的键 ∪ 副判据的编号，必须**恰好等于**
`run_checks` 声明要跑的那批。少了 ⇒ 新加一条检查、忘了配注入，套件照样报「全绿」，
**而那个「全绿」对新增的编号一个字节的信息都没有**；多了 ⇒ 注入在验一条没人跑的判据。
两个方向都报。别处没有任何东西守它。

另外**六条度量**（增量 ≡ 全量 / 分辨率不变 / 覆盖嵌套 / 健全性 / 覆盖不漏 / 进步量），
它们那条问的不是「红不红」，是「**读数会不会变**」。
⚠️ **度量那条还要选对路径**：「健全性」的注入（`req` 掺 `common`）
在一次建完那条路上**看不出来**（基线与注入都是 0/159）⇒ 度量函数**只量维护路径**。
去量一次建完的话，这条注入验证会**通过而毫无信息量**。
**而且注入要挑**：`B17` 那条试过「内核平手时乱定序」，**不红** ——
`expand()` 的平手判据 `(pa, 1) <= (pb, 2)` 与插件侧无关，两个探针方向的 `did` 还**相同**
（都是 `Dx~probe`）⇒ 怎么改插件都动不了它。有效的注入是「**插件在能分开的组上谎报分不开**」。

⚠️ **同一个病灶在两条路径上的形态不同 ⇒ 两条注入也不能共用。**
`B16` 的批建那条注入是「分配写反了」（选**代价最大**的子方向）；
把它原样搬到维护路径上，实测方向数**指数增长**（36 项跑到 100 万个方向）——
那是病态，不是缺陷。维护路径要的是另一条注入：**关掉两条出路**
（`_NoRefusal`，即 `insert` 不看 `命中`）。**挑不出对的注入，说明这条判据的真实内容还没被说清。**

**四、倾向按位次，不按个数。** `propensity = 1 / 展示位次`（夹下界 0.05）。
按「这次展示了几个」算，等于假设每个位置曝光概率相同 ——
真实检索里第一位和第十位差一个量级，那样会把偏差**原样带进**自优化。
下界是为了限住权重上界（`结果/倾向 ≤ 1/FLOOR`），否则排在第 500 位的方向
会拿到 500 倍权重，方差把自优化掀翻。

**五、过滤器只要健全，不需要嵌套。** 「越深越清晰」分**四**层，只有**两**层是硬要求：

    成员层      members(子) ⊆ members(父)      ← 硬要求（这是「分辨率」）
    过滤器层    覆盖(子) ⊆ 覆盖(父)            ← **不是**硬要求
    健全性      members(d) ⊆ 覆盖(d)           ← 硬要求（这是 §K8 那一半）
    覆盖不漏    覆盖(父) ⊆ ∪覆盖(子)            ← 硬要求（劈开不许把父的覆盖漏掉）

`命中` 说「否」的证明只依赖**方向自己**；只要它覆盖得住自己的成员，证明就有效 ⇒ 剪枝安全。
实测 A 的过滤器层有 **14 次**越界（子方向从**项**重建 payload，看不到父方向），
**无害** —— 只赔假阳。带上父方向之后它掉到 **0 次**。

⚠️ **硬要求必须量在所有该量的路径上** —— 这一条是本设计里最容易漏的一处。
`sequence` 维护路径的健全性原来破着（36 / 176），现已由 §10.2 出路 (4) 修好（0 / 86）
⇒ `B1` / `B16` 都升级成**两条路径各判一次**。
⚠️ **但「两条路径都量」不等于「两条硬要求都修好了」**：第四行（覆盖不漏）
在 `sequence` 维护路径上**仍然破着**（16 漏 / 2 对）——
出路 (1) / (4) 修的是**健全性**，实测 (4) 落地前后漏项数**一个数没动**。
⇒ 一份结构上一条绿一条红，**别把绿灯记到另一条头上**。

## 五条检查是怎么补出来的

**`B15`（结构可复现）原来会在退化结构上空转。**
「换插入顺序 ⇒ 树同构」是关于**结构**的断言；结构没建起来（根就是叶）时，
三种顺序当然「同构」—— 同构于「什么都没有」。
实测：去掉 `build()` 的预装，整棵树退化成一个方向，而 `B15` 照样报「过」。
⇒ 加了**非退化前提**（指纹少于一层分裂 ⇒ 报「未展开」，不报「过」）。

它的注入也挑了三轮才挑对 —— 看起来该变红的改法**未必真红**：

    去掉 `build()` 的预装      → 退化成一个方向   → B15 仍「过」
    `expand()` 劈之前不排序     → 迭代序一致       → B15 仍「过」
    方向攒够容量才劈（上溢分裂） → 真的顺序相关     → B15 **红** ← 用它

**`B16`（过滤器健全）补的是 `B1` 依赖查询集的那一半。**
`B1` 拿**查询集**的 ground truth 比，所以查询集一换它就可能瞎。
实测：同一个坏内核（102 个成员落在覆盖外），`B1` 在 40 条查询下判「否」，
在 **3 条**查询下判「是」。⇒ 补一条**不看查询集**的：

    B1   管「插件**说**得准不准」（行为式，靠查询集）
    B16  管「内核**分**得对不对」（结构式，不看查询集）

★ **`B16` 的判据是外生的**（`_fixtures.coverage_of`）：只按**语料 + payload**
独立重算覆盖，**不调插件、不调内核**。原来它按 `§I3 代价` 重算归属 ——
那是**复用内核逻辑**，属 `false-green` 形状 3「共享盲点」。
certifying algorithms 要求 checker **比被检查的东西简单**。
实测三方向 oracle 与插件自报**逐项一致**（keyset 25/25、reach 71/71、sequence 16/16）
⇒ 它是**独立复算**，不是「另一种说法」。

**`B18`（覆盖不漏）补的是 §1 硬要求表的第四行。**
第四行原来只是表里的一行**声称**，没有任何可红的东西。
它现在做成 **baseline 守卫**（ESLint `--prune-suppressions` 纪律）：
新增的漏会红，**账上已冻结的漏不再发生**也会红。
★ 与第三行是**两条独立机制**：`reach` 的第四行 0 漏，
而它的第三行破在「根自己的外生 payload」上（§10.2 A）。

**`B19`（进步量守卫）补的是层数策略的终止判据。**
层数不设全局上限（那是全局参数，§4.3），终止判据是**物理预算**（装得下）——
SP-GiST 的 `longValuesOK` 就是这个形态，并配一条**进步量守卫**（N=10）。
⇒ 补一条：连续 10 次展开没让覆盖变细就报错。内核自算，不动接口。

**`B17`（叶 = 不可分等价类）补的是 `§K2` 的**第二半**。**
`§K2` 有两句话，内核只实现了第一句（「劈开后一侧为空」）；
第二句（「真的产出下层表达不出的东西」）是**语义**问题，内核判不了。
⇒ 补一条**外生**的：把「不可分」定义成外生的等价关系（键集 / 序列 / **SCC**），
再要求 **叶 = 等价类**。实测 `reach` 在**合环图**上违反它 ——
把互相可达的两项劈成两个**覆盖完全相同**的子方向。真实语料是 DAG，所以语料上不露。
（详见上面的 `B17` 小节。）

**⚠️ 为什么不能用「内核平手时按桶空满定序」当它的注入**：那个改法**不红** ——
`expand()` 的平手判据是硬编码的 `(pa, 1) <= (pb, 2)`，两个探针方向的 `did` 又**相同**
（都是 `Dx~probe`）⇒ 插件侧怎么改都动不了它。换成「插件在能分开的组上谎报分不开」才红。
⇒ **看起来该红的改法未必真红**，挑不出来说明判据的真实内容还没说清。

## 改到内核的四处

跑通流程 A / B / D 时改到内核两处，修健全性又改两处。**四处都不算「押错」** ——
判据只有「必须新增方法 / 必须拆方法」两个症状，它们一个都不占：
插件一行没动、`§I1`–`§I7` 一个没动。

### 一、叶不是终态（结构性）

`expand()` 原来把「分不开」也写进 `_expanded`，于是**一个方向一旦被判成叶就永远是叶**。
后果：树只在**第一批**项上长过层，之后插进来的项全堆进已有叶里。

同一份 36 项语料，只换建法（`--holdout N` 就是在切换这个）：

| 建法 | 改前 方向数 | 改前 最大叶容量 | 只修这处 方向数 | 只修这处 最大叶容量 |
|---|---|---|---|---|
| 一次建完 36 | 39 | 10 | 39 | 10 |
| 先建 24，维护 12 | 31 | 10 | 39 | 10 |
| 先建 12，维护 24 | 15 | 16 | 45 | 10 |
| 先建 6，维护 30 | **7** | **31** | 51 | 10 |

（方向 B 锚点可达，同一组对照：一次建完 71 / 叶容量 1；先建 6 维护 30 改前 **11 / 29**，
只修这处后 **71 / 1** —— 与一次建完完全一致。）

**先建得越少，改前结构越差** —— 维护不但没帮忙，反而把结构钉死在第一批上。
`§M2` 情形④（涌现）原来**一步都走不到**，而「涌现」正是这个设计借来的核心机制。

改法（都在 `kernel.py`）：

    `_tried[did] = 试过的那批成员`
        成员集没变 ⇒ 不重试；变了 ⇒ **重试**。「分不开」只对那一次的成员集成立。

    `insert()` 落项**之后**再试一次。
        只在「进入一个方向时」试展开的话，刚落地的那一项永远轮不到被考虑。

**与 `B15` 不冲突**（改之前必须确认的事）：`B15` 要的是「同一批项、一次建完、换顺序 ⇒ 树同构」。
它成立靠 `build()` 把**当时的全集**装进根 —— 每个方向第一次被展开时成员集**已经完整**，
展开一次就定形，重试永不触发。维护路径正相反：成员集是**后来才长起来的**。
`B15` 守**批建**，维护的历史相关性是**当前实现的性质**（**「固有」二字已作废**：这是**当前实现（路径局部增量）的性质**，不是「增量」的固有代价 —— Godin 1995 的增量概念格 p.2 逐字给出「the resulting hierarchy does not depend on ... the order in which the instances are acquired」；Naor–Teague 走的是阈值重建。见 `C8` N3 / `C8` §3 发现二。）。实测：改后 `B15` 仍过。

### 二、§K2 的字面是「不建这一层」

§K2 的原话是「展开必须产出下层表达不出的东西，**否则不建这一层**」。
实现做的是「**先建出一对子方向，再把它们标成失效**」—— 那不是「不建」。
区别不是风格：它让 `方向数` 里混进 `2 × 判空次数` 个空壳，把一个**形状信号**变成了记账。

⇒ 判空时只追加**一条判定事件**（挂在**父方向**上 —— 判定的主体是它，
而且**没有子方向可以挂**），一个方向都不建。

**改的是物化，不是结构** —— 两版的**活方向数完全相同**：

| 方向 | 只修第一处：方向数（含空壳） | 其中活方向 | 修完两处：方向数 |
|---|---|---|---|
| keyset | 39（空壳 14）/ 51（空壳 26） | 25 / 25 | **25** |
| reach | 71（空壳 0） | 71 | **71** |
| sequence | 37（空壳 16）/ 41（空壳 20） | 21 / 21 | **21** |

（⚠️ 这张表是**那一轮**的读数，`sequence` 当时还是二分；`§I4` 改成 k 叉之后它是 **16**。
   A / B 不受影响 —— 它们的扇出恒为两个。）

空壳数恰好 `2 × 判空次数`（14 = 2×7、16 = 2×8、0 = 2×0），一个不漏。
去掉空壳之后 `方向数 = 活方向数`。

**代价没有消失，只是换了地方**：这一层不建 ⇒ 那些项只能留在这个叶里 ⇒ **叶容量变大**
（实测与只修第一处时**逐项相同**）。所以度量从「空权威层比例」改成成对报：
**`§K2 判空`（形状信号）+ 叶容量（代价信号）**。

可验的后果（`run_tests.test_emergence` ②，且实测能红）：**每个方向的成员集都非空**、
`方向 = 有子层 + 叶`。现有检查**都抓不到空壳** —— `B16` 查 `members ⊆ 覆盖`
（空集 ⊆ 任何集，恒真）、`B7` 查「有见证」（空壳有见证）、`B4` 只查已展开的方向。

### 两处合起来：分辨率不变，但不同构

修完两处，**最大叶容量在五种建法下逐项相同**（keyset 10、reach 1、sequence 10）——
这才是**分辨率**。**方向数只有 A / B 逐项相同**（25 / 71）；
C 会随初始批大小变（**21 → 16**）—— `§I4` 允许插件定扇出之后，扇出在**首次展开时定形**
（§K2 / §K3：已分配的项不许挪走）⇒「首次展开时组里有几个符号」取决于初始批次。
**变的是记账，不变的是分辨率。**

⚠️ 但**树不同构** —— `_shape()` 实测在「一次建完」与「分批维护」之间**不相等**。
维护的历史相关性是**当前实现的性质**（`§M2`）（**「固有」二字已作废**：这是**当前实现（路径局部增量）的性质**，不是「增量」的固有代价 —— Godin 1995 的增量概念格 p.2 逐字给出「the resulting hierarchy does not depend on ... the order in which the instances are acquired」；Naor–Teague 走的是阈值重建。见 `C8` N3 / `C8` §3 发现二。）。修复要的是「**不退化**」，不是
「维护必须重建成批建的样子」—— 这两件事必须分得开，否则会把一条设计选择当成 bug 去「修」。

### 三、根记账（§10.2 出路 (1)）—— 外生边界，不是实现 bug

`insert` 原来无条件把项塞进结构，于是**根自己**的 payload 盖不住后来添的项时，
那些项就「静默错位」（`members(根) ⊄ 覆盖(根)`）。修法只有一行，但它定了一条**口径**：

    `insert` 先问 `命中(根, {x})`
        否       ⇒ **反证**：x 落在根的覆盖之外 ⇒ 记 `out_of_scope` 事件、**不塞进结构**
        是       ⇒ 允许的假阳（§K8），照常插入
        未展开   ⇒ 「不知道」，**不许**当成「不在」，照常插入

★ **不需要新接口方法** —— `命中` 配 `ideal = {x}` 本来就是覆盖谓词。
★ 三态在这里**必须分开**：把「未展开」当「不在」就会**误删合法的项** ——
`run_tests.test_out_of_scope` 里有一个**已知答案的对照组**（根恒答「未展开」的插件）
钉住这一条。

代价落在**范围**上：落在根覆盖之外的项在这条方向上检不出来 ——
可见（`stats()['根覆盖之外']`）、可数、有事件、流程 B 逐项报告，**不是静默假阴**。

### 四、项留在父方向（§10.2 出路 (4)）—— 与第三处**共用同一个谓词**

第三处解决了 `reach`（根自己盖不住）。`sequence` 是**另一条机制**：

    父的覆盖是 `{x : p ⊑ seq(x)}`，`p` 后面那个符号来自**无穷字母表**，
    而子方向只能枚举**当前成员**用到的符号
    ⇒ 一个带**新符号**的项，任何子方向都收不住

修法与第三处**共用 `_refuses`**（就是「`命中(d, {x})` 是不是**证明**说否」），
只是作用的位置不同 —— 第三处问**根**，第四处问**每个子方向**：

    下降只进入「没有证明不收它」的子方向
        有 ⇒ 照旧按 §I3 代价最小往下走
        没有（每个子方向都证明不收）⇒ 记 `stayed` 事件、**停在父这一层**

★ 选**留在父方向**而不是**拒绝**（那是出路 (3) 的读法），理由是**代价藏不住**：

    拒绝     项从**成员集**里消失 ⇒ `B1` 的 ground truth 正是「成员 ∩ 查询」
             ⇒ 「健全性变绿」会**部分来自数据变少**
    留父     项**仍在** `members(父)` 里 ⇒ ground truth 不动、项仍可检索
             ⇒ 代价只落在**划分**上（这一层表达不出来，不是「声称盖不住」）

★ **`B4` 因此收窄**（**收窄**，不是放宽）：`∪members(子) == members(父)`
   → 「不重，且 `members(父) − ∪members(子)` **恰好是账上那些滞留项**」。
   第二条判据的注入必须跑在**真有滞留**的结构上（批建路径上滞留恒为 0 ⇒ 恒真 ⇒ 验不出东西）。
★ 外部印证：X-tree 的 supernode ——
   "created during insertion **only if there is no other possibility**"。
★ 三态同样必须分开：`是` 与 `未展开` **都放行**，只有「否」拦 ——
   `run_tests.test_stay_at_parent` ⑥ 有一个**已知答案的对照组**（子方向恒答「未展开」的插件）
   钉住这一条：那种情况下**滞留必须为 0**。

实测（先建 6 维护 30，逐 k）：越界 **36/176 → 0/86**，而**漏项数两边都是 16**
（第四行不归它管）。代价记成 **`滞留` = 16**，与第三处的 `根覆盖之外` **分开报**。
