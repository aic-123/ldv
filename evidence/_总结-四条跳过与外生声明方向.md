# 总结：四条「跳过」还剩什么没解 + 外生声明方向**推不推得出来**（2026-10-12）

**用户问的两件事**：① 四个跳过为什么还是没办法解决？② 外生声明方向也没有总结。

---

## §0 一句话

- **四条跳过 = 3 个编号**，性质**三种**：**1 条已解**（`B17`，是**语料**的性质，v0.1.19 已配对照并真跑进套件）、
  **2 条不该解**（`B20` ×2，那条轴上它**红不了** ⇒ 解了就是造一条**常驻的过**）、
  **1 条是真缺口**（`A5`，卡在**一条外生决定**上）。
- **外生声明方向：推不出来。** 四条材料分别给的是「**现状** / **能力** / **代价**」，
  **没有一条**给「**该用哪个**」；而规矩（抽象层 §10 停止条件 1）**也不许我拍**。
  ⇒ 这是**真外生**，只能你决定。
- ★ 而且**换方向 ≠ 把跳过清零**：它只解 `A5`，另外三条**一条都不动**。
- ★★ **续（v0.1.20）**：`A5` 那条真缺口**已修**（§5.9）—— 它不是「差一条外生声明」，
  而是**检查自己的缺陷**（oracle 只实现了一类账）。修完后「换到维护路径 + 方向改 `reach`」
  的阻碍**消除**；⚠️ 但**换声明本身仍未做**（那才是真外生，§10 停止条件 1）。

## §1 先对账：四条跳过到底是哪四条、各是什么性质

默认语料那趟的汇总逐字是：`跳过的是：['B20', 'B17', 'B20', 'A5']` ⇒ **4 次跳过 ⇒ 3 个不同编号**
（`B20` 在 `reach` 与 `sequence` 上各跳一次）。

| # | 跳过 | 性质 | 现在什么状态 |
|---|---|---|---|
| 1 | `B20` @ `reach` | ✗ **不该解** | 跳过 + **合成对照**（v0.1.17 起） |
| 2 | `B20` @ `sequence` | ✗ **不该解** | 同上 |
| 3 | `B17` @ `reach` | ★ **语料性质**，不是判据的毛病 | ★ **已解**（v0.1.19：有环语料上**真跑进套件** + 合成对照 + 单变量对照留档） |
| 4 | `A5` @ 视图 | ★★ **真缺口**（账恒空） | 跳过 + 合成对照 + **显式待办表**（第 ⑩ 条）+ 汇总块**点名** |

⇒ 「四个跳过还是没解决」这句话**要拆开**：**1 条已解、2 条不该解、1 条是真缺口**。
把三条不同性质的跳过说成「都没解决」，会把**已经做掉的那条**与**不该做的那两条**一起抹掉。

## §2 为什么 `B20` ×2 是「**不该解**」，不是「没解」

### 2.1 机制：它在这两条轴上**没有内容**

`B20` 问的是「反复声称能分、却连续 N 次**在标签上**什么都没分开」。
它落不落得下，由 `label_bearing` 判：**标签的取值键**（`type=<值>`）在不在这条方向的**键空间**里。

    keyset    split 按**键**切，而 `type=<值>` 就是一个键   ⇒ 这条轴**能**按标签切
    reach     split 按**可达性签名**切                      ⇒ 标签不在它的键空间里
    sequence  split 按**前缀**切                            ⇒ 同上

### 2.2 强行判会怎样（实测，`outputs/_probe_skip_forced.py`）

monkeypatch `label_bearing` 恒 `True`：

    keyset    12 展开 / 空转 5 / 最长段 3  ⇒ 过
    reach     35 展开 / 空转 10 / 最长段 2 ⇒ 过
    sequence   5 展开 / 空转 0 / 最长段 0  ⇒ 过
    汇总：断言 97 条：红 0，**跳过 4 → 2**

看着像是「解掉了两条」。**下一步把它否掉了。**

### 2.3 ★ 反向判据：把标签**随机重排**之后，它**还是过**（`outputs/_probe_b20_false_red.py`）

把 `type` 的取值**随机打乱**（与结构彻底无关 —— 正是 `test_injections` 给 `B20` 做注入时用的同一招），
**同时**强行判：

    reach     35 展开 / 空转 4 / 最长段 1  ⇒ **过**
    sequence   5 展开 / 空转 0 / 最长段 0  ⇒ **过**
    keyset    12 展开 / 空转 0 / 最长段 0  ⇒ **过**
    汇总：断言 97 条：红 0，跳过 2

**标签已经与结构彻底无关了，它照样过** ⇒ 这条轴上 `B20` **红不了**
⇒ 判它得到的那个「过」**不是读数**，是一条**永远绿的判据**。

    「一条常驻的红等于没人再看红」    ← 本仓库记过两次
    「一条常驻的过等于这条判据在骗你」 ← 同一条道理的**镜像**

⇒ **跳过是对的**：它现在做的正是「说清这条轴上没有内容」。改成「过」，
就是把「**没有内容的过**」与「**有内容的过**」混成同一个样子。

### 2.4 要真解，得换**语料**不是换判据

得造一份**标注与结构正交**的语料 —— 那正是 `test_injections.inj_b20` 干的事
（「每刀 50/50」的指派）。**生产语料上它没有内容**，这是**语料的性质**。

「已解」的意思是：**这条跳过现在有对照、有单变量对照、有真跑**，
不再是一条「不知道是判据坏了还是没内容」的读数。

## §4 为什么 `A5` 是真缺口，而且卡在**一条外生决定**上

`A5` 判的是**视图账**（滞留 + 根覆盖之外）。两条硬事实：

1. **账的两类来源只在维护路径上产生**；而视图层跑的是**批建**路径。
2. ★ 更硬的一条：**`keyset` 的账在维护路径上也是 0/0** —— 跨 6 份语料**无一例外**
   （它是**精确切分**：键要么匹配要么不匹配 ⇒ 没有滞留、没有根覆盖之外）。

跨 6 份语料 × 3 方向 × 2 路径实测（`outputs/_probe_skip_solvable.out.txt`，
格子里是「滞留 / 根覆盖之外」）：

    语料              keyset 批建   keyset 维护   reach 维护   sequence 维护
    ------------------------------------------------------------------------
    默认 36 项            0 / 0        0 / 0       0 / **28**   **16** / 0
    gh-langs              0 / 0        0 / 0       0 / **50**      0 / 0
    crossref-journals     0 / 0        0 / 0       0 / **68**      0 / 0
    pypi-deps             0 / 0        0 / 0       0 / **23**   **34** / 0
    arxiv-taxonomy        0 / 0        0 / 0       0 / **130**     6 / 0
    edge-tiny             0 / 0        0 / 0         0 / 0        0 / 0

⇒ 有账的**只有** `reach` / `sequence` 的**维护路径**（跨语料 28 / 50 / 68 / 23 / 130）。
而 **14 份 `view_spec.json` 全部声明 `方向=keyset`**（逐份查过）。

⇒ 两条一合：**`A5` 在生产上从来没判过** —— 跨 8 份语料 **0 过 / 0 红 / 8 跳过**
（`outputs/_恒定的过有多少条.md`）。
**这不是「本趟没内容」，是「这份声明让这条判据永远没内容」。**

★ **续（v0.1.20）**：上面这条**仍然成立**（生产声明没换 ⇒ `A5` 照样跳过）。
但**它当时红的那个原因是另一回事** —— 换到维护路径后会露出一个**检查自身的缺陷**
（oracle 只实现了一类账），那个**已修**（§5.9）。**两件事别混**：
「生产上没内容」是**声明**造成的，「换路径后假红」是**检查**的毛病。

## §5 外生声明方向 —— **结论：推不出来**

### 5.1 四条材料，逐条说清「它给的是什么、为什么推不出方向」

| 材料 | 它给的 | 为什么**推不出**「该用哪个方向」 |
|---|---|---|
| **14 份 `view_spec.json`** | **现状**：全部 `方向=keyset` | 这是**已做的声明**，不是**理由**。它是「**有人这么声明过**」，不是「**应该这么声明**」—— 从「现在是 `keyset`」推不出「应该是 `reach`」 |
| **`ldv/tools/gen_view_spec.py`** | `方向` 栏 = **人给**（命令行参数） | 生成器**明确不替人做决定**：docstring 逐字写「**三样能机械算出来，两样不能**」，`方向` 与 `读数` 就是那两样。它的 `P` 输出**只是候选**（信息量最低的 `P = {U}`），且**默认 dry-run** |
| **`outputs/_probe_skip_solvable.out.txt`** | **能力**：`reach`/`sequence` 维护路径上账非空 | 它说明「换过去**有用**」，**不说**「**该**换过去」。**有用 ≠ 该做** |
| **`outputs/_findings_real_data.md` 问题 3** | **代价**：手工补 `reach` 的外生声明**不可行** | 方向数是**严格 `2n−1`**：3907 项 ⇒ **7813** 个方向 ⇒ 声明就 **285 KB**。（`keyset` 79 方向 / 2401 B、`sequence` 118 方向 / 3613 B 还好，但 `sequence` 在 281 项上给 **183 漏**） |

**四条材料一条都没给「该用哪个」。** 它们给的是**现状、工具边界、能力、代价** ——
决策需要的那个**理由**（「这批 id 属于哪条方向」）**不在材料里**。

### 5.2 规矩上也不许我推

`docs/分层方向视图-抽象层.md` §10 停止条件 1：**`P` / `E` 必须外生** ——
「**猜一个就是替人做 `§K9` 的决定**」。同一条写在 `gen_view_spec.py` 的 docstring 与设计稿 §3。

⇒ ★ **要分开说的两件事**：
**不是「我推不出来」，是「推出来也不许我拍」**。前者是能力问题，后者是**规矩**。
（如果只答前半句，下次还会有人问「那你再想想」。）

### 5.3 ★ 还有一条更硬的：换方向**不解决另外三条跳过**

即便把 `方向` 改成 `reach`：

    B20   在那条轴上**仍然红不了**（§2.3）—— 换方向与「标签在不在键空间里」是两件事
    B17   在**无环**语料上**仍然跳过**（§3）—— 换方向与「语料有没有环」是两件事
    A5    **不一定会判**（见 §5.8 —— 换声明**alone 不够**）

⇒ 「换方向」**不是**一个「把 4 条跳过清零」的动作，是**改这一层的语义**。

### 5.4 三条路（要你拍板的那一处）

| 路 | 做什么 | 代价 / 后果 |
|---|---|---|
| **(a) 改 `方向`** | `view_spec.json` 的 `方向` 改成 `reach` 或 `sequence` | 视图层**含义变了**（不再按键集切）；`reach` 在 3907 项上声明 **285 KB**；`sequence` 在 281 项上 **183 漏**。⚠️ **不是「唯一能真判 `A5` 的路」** —— 改声明**alone 不够**，见 **§5.8** |
| **(b) 留 `keyset`，把跳过理由写准** | 让跳过理由**说清是哪两头**造成恒空 | **不消除**跳过，只是说得更准。★ **实测：这一条已经做完了** —— v0.1.18 的 `a5_empty_reason()` 在生产上印的就是完整因果（见下），不是「做了一半」 |
| **(c) 维持现状** | 跳过 + 合成对照 + 显式待办表 + 点名 | **`A5` 至今没在生产上判过** —— 必须**如实记着**（已在 README「已知的未做」与 ⑩ 的 `NEVER_JUDGED` 表里） |

**先说一句实话：(b) 已经落地了，所以它不再是选项。**
我把 `_rc_v0.1.19.txt` 里 `[跳] A5` 那一行逐字读了一遍 —— 现行理由**已经把两头因果都印出来**：

    ⚠️ 而这不是「本趟没查到东西」——账的两类来源（滞留（§10.2 出路 (4)）/
    根覆盖之外（出路 (1)））**只在维护路径上产生**（批建的根声明为「覆盖一切」⇒
    根覆盖之外由构造为 0；实测 3 个方向 × 6 份语料批建都是 0/0），而视图层跑的是
    **批建**路径（`view_report` → `batch_kernel`）；本仓库 14 份 `view_spec.json`
    声明的方向又都是**精确切分**（`keyset`）⇒ 账**恒空**（连维护路径上也是 0/0，实测）。
    ⇒ 这条「跳过」在当前配置下是**永久的**（换语料也一样），不是本趟的。

两头都在：**① 视图层跑批建**（对三个方向都是 0/0，与声明无关）**② 声明是 keyset**
（把唯一有内容的维护路径也关掉）。所以 (b) **不需要再动生产代码**。

⇒ **真正要你拍的只剩 (a) 与 (c)**：要么改声明（**唯一能真判的路**，但语义变了），
要么如实记着「`A5` 在生产上从未判过」。**(b) 不是选项，是已完成项。**

### 5.5 ★ (a) 到底改了什么 —— 实测（默认语料 36 项 / 47 边）

三条轴各算一遍「最粗稳定细化」（`outputs/_probe_direction_meaning.out.txt`，全程只读）：

| 方向 | `\|U\|` 方向数 | `\|Q\|` 视图数 | 收缩比 | 最大块 | 具体化 | 声明收着 |
|---|---|---|---|---|---|---|
| **`keyset`（现状）** | 25 | **8** | 0.320 | 13 | 203 | 159 |
| **`reach`** | **71** | **8** | 0.113 | **36** | 256 | 224 |
| **`sequence`** | **16** | **5** | 0.312 | 11 | **122** | **122** |

**① 换的是「方向」这个词指什么** —— 同一句话「把 N 个方向粗分成 K 组」，
`方向` 的含义整个换掉：

| 方向 | 一个「方向」是 | 视图分的组 = |
|---|---|---|
| `keyset` | 一条**键要求**（要哪些键 / 不要哪些键） | 按**键的包含**分组 |
| `reach` | 一个**锚点集** | 按**图上的位置（可达性）**分组 |
| `sequence` | 一个**前缀语言** | 按**顺序敏感的前缀**分组（`('概念','案例')` ≠ `('案例','概念')`） |

⇒ 视图层交出的那份「对结构的认识」，从「**按键的包含**分」变成「**按图上的位置**分」，
再变成「**按顺序敏感的前缀**分」。**同一个位置，三种完全不同的精度/代价组合。**

**② 换的是 `E`（「稳定」对谁说的）** —— 三棵不同的方向树（`|E|` = 24 / 70 / 15 条树边）。
「两块能不能并」的判据跟着换。

**③ `读数` 生成器拒绝照抄（**规矩**），但实测**其实搬得动**。**
把 `keyset` 的五条读数（计数/最大/平均/中位数/覆盖计数）**原样**搬到另两条轴上跑 `§A4`：

    三条轴 A4 = 是（全过）—— outputs/_probe_readings_portable.out.txt

★ 按纪律**当场证它会红**：把「中位数」谎报成 `distributive` ⇒ **三条轴全被抓**（A4 = 否）。
⇒ 这个「全过」有意义。**「读数必须重声明」是生成器的规矩**（「那是另一条方向的声称，
搬过来就是替人改声明」），**不是实测会红** —— 两者不许混。

**④ 不变的是**：算法（最粗稳定细化）、定理（唯一 ⇒ 不用挑）、边界（视图层只交出一份认识，
不改结论）。⇒ **不是换方法，是换对象。**

**⑤ 声明的体积**（默认语料 36 项，机械那几栏的 JSON）：

    keyset    25 方向 / 24 边    1 618 B
    reach     71 方向 / 70 边    4 467 B
    sequence  16 方向 / 15 边    1 065 B

⚠️ 死路表 §1.2 记的「`reach` 要 **285 KB**」是**全量语料（3907 项）**上的代价，
**不是**默认语料上的 —— 两个数说的不是一件事，别混。

### 5.6 ★ 一个必须说清的区分：改 `方向` ≠ 改 `E` 的**语义**

死路表 §1.1 记着一条：「**换 `E` 的语义**（对称闭包 / 共同出邻）」= **换语义，否**
（`E` 是**有向**的「父→子」；`§A1`–`§A7` **全是「对 `E`」说的** ⇒ 换一个**不由 `E` 定义**的关系，
七条一条都不适用）。

**改 `方向` 不碰这一条。** 三条轴的 `E` **含义完全相同** —— 都是
「**有向的父→子**」树边（`gen_view_spec.build_spec` 逐字：`([d.parent, d.did] for d in dirs if d.parent)`）。
变的是**哪一棵树**（`U` = 25 / 71 / 16 个方向），**不是 `E` 是什么意思**。

    ⇒ 改 `方向`：**换对象**（换一棵树），`E` 的语义不动，`§A1`–`§A7` 全部照旧适用。
    ⇒ §1.1 那条：**换语义**（把 `E` 换成另一种关系）⇒ 七条**一条都不适用**。

**两件事，别混** —— 混了会把一条**被否的路**套到一条**没被否的路**上。

### 5.7 ⚠️ 一个要纠正的读法：「只是细节的语义变了，方向树的解释性不降低」

**不能这么读。** 三条轴**不是同一棵树的三张读法** —— `|U|` 从 **25** 变成 **71**（或 **16**）。
同一棵树换个解释，`|U|` **不会变**。⇒ **换的是整棵结构层**，所以「解释性」这件事
**要重新评估，不能默认它没降**。实测（`_rc_v0.1.19.txt` 的 `B13` 行 + `C0-方向选定.md` §4）：

| 方向 | 扇出 max | `§K2` 判空 | 叶容量（最大 / 平均） | 结构层规模 |
|---|---|---|---|---|
| `keyset` | 2 | — | — | 25 方向 |
| `reach` | **2** | **0** 次 | **1** | **71** 方向（**大 2.8×**，且插件是**偏函数**、每次要跑图遍历） |
| `sequence` | **7** | **8** 次 | **10 / 3.27** | 16 方向 |

⇒ **不能默认「不降低」**：`sequence` 上**有实测的降低** —— §I4 硬编码「→ 两个方向」，
有序方向只能把 k 个符号**二分** ⇒ **形状不自然 ⇒ 多花层数**（第 2 轮实测切出 **43% 空权威层**，
`reach` 是 **0%**；读数后来换成判空/叶容量，**结论不变**）。`reach` 上则**没测到降低**，
但它**树更大、更贵**。**三条轴各有各的代价，没有一条是「白换」。**

★ 对的那一半：**视图层的算法 / 定理 / 边界确实不变**。但换的也**不止是「解释」** ——
视图层吃进去的**对象**换了（25 / 71 / 16 个方向），交出的那份「认识」也就跟着换了。
