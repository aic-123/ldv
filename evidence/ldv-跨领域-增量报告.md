# 跨领域增量报告 · 已注入材料对后续检索的影响

**问题（逐字）**：

> 「甲，然后做完系统内的校验以后再去做一遍跨领域的测试，像这次五个领域的一样，
> 但是要**保留已注入的材料对后续检索的影响**」

**材料**：`_data/ext-*` 里**自动发现**的 10 份 SNAP 数据集（按节点数升序）：

    邮件/组织 · 邮件/企业 · 金融/信任 ×2 · 技术/P2P · 社交/协作 · 学术/合作 · 学术/合著 · 学术/引用 ×2
    1005 → 36692 节点（规模轴跨 36 倍）

**留档**：`outputs/_task_ext_incremental.out.txt`（本报告每一个数字都从它逐字抄来）。

**跑法（可复现）**：

    python outputs/_task_ext_incremental.py

⚠️ 探针**逐份续跑**（sidecar 存「读数 + 语料指纹」，指纹相符就沿用）——
   单份最大语料（`ext-enron`，36692 项）跑满约 **28 分钟**，一次跑完 10 份会超过单次调用时限；
   每份的读数都是**真跑**出来的，续跑只省重复计算。
   **材料一变（改判据 / 换数据）⇒ 指纹变 ⇒ 该条作废重算。**

## 一、一句话结论

**「已注入材料的影响」落在判断层，不在候选集；代价落在判断流水线，不在建树。**

| 层 | 读数 | 说明 |
|---|---|---|
| **候选集** | **0/10** 有差异 | 结构性免疫（中心定理的推论） |
| **判断层** | **7/10** 有差异（单变量 9 份里 **6** 份） | 效应量：**30/72** 块的画像变了 |
| **声明可行性** | **1/10** | `ext-email` 抽走 A 后原声明**点空** |
| **建树** | ②÷③ = **0.95–1.04×** | 增量与从头跑**同一串 `insert`** ⇒ 本应 ≈1 |
| **判断流水线** | ②÷④ = **2.92–5.23×**（单变量 9 份） | 这才是「保留 A 的材料」真正的价钱 |
| **少扫** | **6/10** | 取决于块的合并 `forb` 是否含查询要求键 |
| **正确性** | ②候选 = 真值 **10/10** | 增量建树**不影响检索正确性** |

## 二、设计：为什么必须有第 ④ 臂

| 臂 | 是什么 |
|---|---|
| ① | 其他系统 —— BM25 词袋（索引文本**不含栏位值**） |
| ② | 本系统·**增量** —— A 插前 30% 建树，B **在同一个内核上**续插剩下 70%（**A 长出的树保留**） |
| ③ | 本系统·**从头** —— 同一批项一次全插 |
| ④ | **丢掉 A** —— 只插 B 的项 |

⚠️ **「② ≡ ③」是恒真的**：`ids_a + ids_b == ids` 且顺序不变 ⇒ ②③ 跑的是**同一串 `insert`**
⇒ 「增量后的树 ≡ 从头建的树」**由构造保证**，**不是实测发现**。
把它当读数报出来 = 一条**恒真的断言**（`false-green` 的典型形态）。

⇒ 真正有内容的问题是：**「留着 A」与「丢掉 A」结果一样吗？**
一样 ⇒ 「已注入材料的影响」**无从谈起**；不一样 ⇒ 影响**看得见**。

### 2.1 计时必须拆成两段

`建树`（只 `insert`）与 `判断`（spec / 覆盖 / 建视图 / 检索）是**两把尺子**。
拿 ② 的**整条流水线** ÷ ③ 的**只建树**，量到的是「流水线有多重」，不是「分两次插有多贵」。

⇒ 本报告的耗时一律分段报：`②建树 / ③建树 / ④建树` 与 `②判断 / ④判断`。

**机制**：说否 ⟺ `forb(块) ∋ 查询要求键`；`forb(块)` = 块内**所有方向** `forbid` 的**交**。

⇒ 同一子树的方向**共享**禁止键 ⇒ 说否块**可以是多方向**的
（`ext-email` 里最大 **5 方向**，`ext-wikivote` 里有一个 **6 方向**块）。

★ ⇒ 少扫的多寡取决于「块的合并 `forb` 是否含查询要求键」——
与**语料 × 查询**的组合有关，**不是必然**（10 份里 **4 份**一个块都没说否：
`bitcoin` / `gnutella` / `coauth` / `enron`）。

## 四、为什么候选集是 0

候选集来自内核持有的 `items`，**不由结构定** —— 这是中心定理的推论：

> `Q = csr(P)` **唯一** ⇒ 候选集 ≡ 不用视图时的候选集。

⇒ **「已注入材料对候选集的影响」在结构上就不可能存在**（10 份实测全 0）。
要让「已注入材料」**看得出来**，只能看**判断层**（块画像 / 建议 / 读法）——
而 `§14.6` 自 2026-10-14 起认的**两条收益**，正是**判断质量**与**少扫**。

## 五、`ext-email`：声明被抽空

十份里只有 `ext-email` 的 `方向A`（233）**严格小于** `方向B`（367）。
把 A 的材料抽走后，`spec_b` 点名的方向里有些**根本不存在** ⇒
`build_views(kD, spec_b, …)` **抛 `KeyError`**。

★ **这一份上「影响」是硬的**：不是「读数变了」，是**原声明用不了**。
⇒ 与《综合报告》第四节一致：**材料一变，声明就必须重写**。

## 六、边界（这份报告**没有**说什么）

- **没有**说增量建树更贵 —— **建树两臂同价**（0.95–1.04×，10/10 份）。
  贵的是**判断流水线**（2.92–5.23×），而那是「材料多 30%」的代价，不是「分两次插」的代价。
- **没有**报精确耗时 —— 本机读数对并发负载敏感（本趟 ±5%、上一趟 ±30%），**只读量级**。
- **没有**说「已注入材料的影响总是有」 —— `ext-coauth` 与 `ext-astroph` 上三个判断字段**全同**；
  `ext-enron` 上建议与画像全同、只有读法不同。
- **没有**把「判断层变了」读成「判断层变**好**了」 —— 本报告只测**变没变 / 变多大**，
  「好」要拿真值比（那是《综合报告》里「外生验证」那一节的活）。
- **没有**说「方向集由键空间定」 —— `ext-bitcoin` / `ext-wikivote` / `ext-hepth-cite` 是反例。
- **没有**覆盖全部 12 份语料 —— 本轮 **10 份**（`_data/ext-*` 里已有 MANIFEST 的）。
  `ext-brightkite`（社交/地理，58228 项）与 `ext-slashdot`（社交/技术，82168 项）**尚未生成**
  ⇒ **不进本轮**。这是**范围边界**，不是「跑过了没效果」。
- **没有**做全量 —— 用户口径「**先不跑全量，实验级就够了**」。
