# 认知原型

> **定位（约定，不是定理）**：本项目是一个**认知原型** —— 它不产出内容，只产出
> 认识的**结构**；它能把**自己的产物**当材料（`我` 维度），于是反思与重构不是
> 内部日志，而是结构里**看得见的项**。
>
> ⚠️ 「认知原型」是 **Ⅲ（约定）**：它不可被证明，只能被**立**。本文不声称
> 「证明了它是认知原型」—— 本文只做三件事：① 把定位**蕴含的可判承诺**写成断言
> （§S1–§S5，正文在 `docs/形式化断言集.md`）；② 给出 `我` 维度的机制与边界；
> ③ 为**已设定的方向函数**写出可量化的发展标准，并记录「设定 → 设立 → 使用」的范式。

---

## 1 定位：它是什么、不是什么

**是什么**（三句话）：

1. 它把材料变成**分层划分树**：每一层比上一层细，只产出上一层表达不出的东西。
2. 它的答案**是位置**（「这一带」+ 覆盖），不是命题；它**从不生成内容**。
3. 它能**包含自己**：系统自己的产物（断言、文档、决策、记录）可以标成 `我=是`
   进结构 —— 于是「反思」与「重构」是可查询的项，不是藏在日志里的过程。

**不是什么**（边界，防止把定位读成吹牛）：

| 不是 | 为什么 |
|---|---|
| 不是 AGI | 它没有**模拟人的认知过程**：没有反应时、没有错误率、没有学习曲线的预测 —— 那些是「当人的模型」要交的答卷 |
| **不是「表征-计算」那一支的认知模型** | 不做蕴含、不做语义判定、推不出新命题。⚠️ 这句要读准：**它拒绝的是「模拟人的认知过程」，不是「有认知结构」** |
| 不是知识库 | 它不存答案；空值合法、填充留痕；「已验证」只能外部授予 |
| 不是搜索引擎 | 它返回「这一带」，不返回排序列表（禁排序 / 禁打分 / 禁合成分） |
| 不是推理机（**语义**推理） | 它不做蕴含；`reach` 只做可达性，不是逻辑推理。**但它做「结构诊断-修复」** —— 见下面那条 |
| 不是「模型代填」的任何东西 | 内容必须可指回材料；计数从结构算（§S1） |

### ★ 它是哪一类：结构主义那一支的认知模型（2026-10-25 写清）

上面那张表里有两句容易被读成「它什么模型都不是」。**不是那个意思。**
按「结构主义 / 发生认识论」（皮亚杰的**同化–顺应**）那一支的标准，它是认知模型，
而且三件都有实测：

| 那一支的要求 | 这里对应什么 |
|---|---|
| **世界模型** = 对材料世界的结构化表征 | 分层划分树；能答**结构反事实**（`undo`：删这一项结构会怎样） |
| **目标** = 维持自身组织（内生稳态） | 「结构不坏 + 能吸收新需求」。`next` 的三档就是「哪里不平」的清单 |
| **推理** = 失配 → 改结构 → 自洽 | 新需求（未知键）⇒ `out_of_structure` + `can_agent_fill` ⇒ `derive` 造维度 ⇒ 需求满足。**四步实测跑通**，判据 `S39a–e`（含反向对照）、断言 **§S6** |

**三条边界**（别过度乐观）：① 失配的判定是**结构判定**（键在不在词汇表、成员在不在
覆盖里），**不是语义判定** —— 判不了「这两句话互相矛盾」；② 修复手段是**有限集合**
（造轴 / 劈支 / 删项 / 记账），推不出新命题；③ 它说「哪一支分不开」，**不说「为什么」**。

⇒ 准确的名字是 **「结构诊断-修复」**，不是逻辑推理。**它是真的在推理，只是推的不是命题，是结构。**

### ⚠️ 一处必须说清的：内置演示语料

随仓库的 36 项（`ldv/corpus/nodes/`）**36/36 都是 `filled_by: 模型(...)`**。
它是**演示语料**，让 clone 之后能跑起来，**不代表任何真实材料**。

「不产内容」说的是**系统运行时** —— 它的输出（答案 / 请求 / 报告）可指回材料。
**演示语料是预先填好的材料**，与「系统运行时产不产内容」是两件事。
但这两件事极容易被混为一谈，所以在这里**明说**，而不是等读者 `grep` 出来再质疑。

`filled_by` 就是那条留痕：**允许填，但必须写明谁填的**。
真实语料在 `_data/`（不进仓库），那才是「可指回材料」的对象。

## 2 定位凭什么算数：五条可判承诺

定位不可证，但它**蕴含**五件可判的事。任一条红，这个定位就名不副实：

| # | 承诺 | 断言 | 怎么判 |
|---|---|---|---|
| ① | **不产内容**：所有输出可指回材料（front matter / 边 / 计数） | §S1 | 找一个「无出处」的字符串 |
| ② | **答案是位置**：方向 + 成员集 + 覆盖；没有命题、没有标量 | §S2 | 查返回形状与禁词 |
| ③ | **反思显性**：每条方向请求带证据（信号 / 链 / 阈值 / 涉及的项 / 已试过） | §S3 | 字段齐 + 项集可复算 |
| ④ | **重构显性**：每次维度 / 谓词变更留账（生效 / 未生效 / 改名）且可回退 | §S4 | 账可查 + 回退实测 |
| ⑤ | **自我标签一致**：`我` 维度**外生**（人写，不是系统推的）、可指认、可回退 | §S5 | 查来源（`make_self_corpus`）+ 删掉后回退 |

⚠️ **其中三条只判到「半」**（断言集 §7 自己标着）：S1 只有契约可读（**「无出处字符串」
的自动化判据 2026-10-22 才补上**，见 `run_tests.test_no_unsourced_strings`）、
S2 只有形状可判、S5 的「来源可判」靠人看。S3 / S4 是「是」。

⚠️ **顺序不许反**：先问「这条承诺真的成立吗」，再问「系统守不守它」。
反过来会得到一条「系统绿所以定位对」的幻觉。

## 3 `我` 维度：让结构装下自己

### 3.1 是什么

`我` 是一个**外生**维度：`我=是` 标系统自己的产物，`我=否` 标外部材料。

- **锚在人**：谁算「我的产物」由仓库里**已提交的文件**决定 —— 那是人的动作，
  不是使用记录（`§K9` 的同族理由：外生项不许被 usage 驱动）。
- **机械抽取**：工具只从已有文字里抽字段（标题行、表格列），**不生成内容**（§S1）。
- **可回退**：自我语料是**生成物**；删掉目录即回到原状（与 §D7 同一手法）。

### 3.2 机制

    python -m ldv.tools.make_self_corpus --out <目录>
    LDV_CORPUS=<目录> python entry.py

抽取规则（全部机械）：

    docs/形式化断言集.md  → 每条断言一个节点（编号 / 级 / 含定理 / 来源）
    docs/*.md + README.md → 每个文档一个节点（标题 / 种类 / 来源）
    所有节点              → 我: 是（外生声明：这些是系统的产物）

### 3.3 能回答什么（自指的例子）

    「哪些断言含定理部分？」   ⇒ 种类=断言 ∧ 含定理=是 ⇒ 10 项
    「约定类的有哪些？」       ⇒ 种类=断言 ∧ 级=Ⅲ ⇒ 5 项
    「系统的文档有几份？」     ⇒ 种类=文档 ⇒ N 项

⚠️ 它答的是**位置**（哪一带），不是「哪条断言更重要」—— 后者是打分，红线。

### 3.4 边界（如实记）

1. **`级` 是抄的**：从断言集的总表抄，不是系统判的 —— 系统不评自己的断言。
2. **自我语料里 `我=是` 是恒定键**：全部 52 项都是「我的产物」⇒ 零区分力 ⇒
   入口 facet 会把它剔掉（`n_constant_keys`）。它真正的用处是在**混合语料**里
   分「我的产物 / 外部材料」—— 目前**没有**混合语料，如实记。
3. **反思 / 重构记录还没有进自我语料**：`directions.json` 的请求在外部语料上
   未触发；「0 条」要如实报，不能印成「没有问题」（§S3 的 ㊅ 守这条）。
4. **自我语料没有 `view_spec.json`** ⇒ 抽象层判据（§A）跑不了 —— 它是
   **能查的自我认识**，不是完整五层树（与一次性树同一边界）。

## 4 方向函数与它的发展标准

### 4.1 什么叫「方向函数」

**方向函数 = 决定「什么才算一个方向」的那条规则。** 已设定的五个：

| 方向函数 | 它说「什么算一个方向」 | 落在哪 |
|---|---|---|
| `keyset` | 键集相同即同一方向 | 插件 `keyset` |
| `reach` | 互相可达即同一方向 | 插件 `reach` |
| `sequence` | 同前缀即同一方向 | 插件 `sequence` |
| 谓词推导 | `量 > 切分点` 的**二分**即一个方向 | `predicates.derive` |
| 派生维度 | 一个新字段 / 新度量切出来的一层（经 `keyset` 生效） | `derived/*.json` |

### 4.2 **准入线**：一次建树是否合格（读数 + 准入四关 + 外生阈值；不是分数）

每条读数必须先过**准入四关**（`docs/评估标准.md`）：R1 有刻度（≥2 个值）·
R2 说的是系统不是环境 · R3 归因到机制 · R4 不与别的读数互为函数。

| # | 读数 | 怎么算 | 阈值（外生） | 为什么是刻度 |
|---|---|---|---|---|
| **L1** | 可复现 | 同材料两次建树，指纹相同 | 相同（硬） | 没有它，别的读数不可比 |
| **L2** | 假阴 | 命中说「否」而覆盖里其实有 | **0**（硬） | §K8 唯一禁止的那一侧 |
| **L3** | 覆盖不漏 | `members(d) ⊆ cover(d)` | 硬 | §A1 |
| **L4** | 分辨度 | **L4a** 最大叶 · **L4b** 分布形状（p90/p50、max/p50，无量纲）· **L4c** 分支熵（bit） | L4a **≤ 叶容量 50**（硬）；L4b / L4c **只报** | 「展开到底还能不能分」+「切得匀不匀」 |
| **L5** | 有效展开 | 最长「连续没变细」链 | **< N = 10** | 「切了白切」的刻度（B19） |
| — | 方向数 / 层数 / 常数键占比 | 直接数 | **只报，不设阈值** | 多不等于好 |

### 4.3 准入阶梯 L1–L5：逐级推进，**不是总分**（成长曲线见 §4.6）

    L1 能建树且复现 → L2 无假阴 → L3 覆盖不漏 → L4 分辨度达标（L4a 硬线） → L5 每次展开都有效

- 每个方向函数**各报各的**；`跳过` = 前提不成立（如 `E = ∅`），**不是过**。
- **禁止**：把 L1–L5 压成一个成熟度分数；跨方向函数排序；把阶梯当验收排序。
  （比较 ≠ 打分；一旦合成分数，系统即在实质上充当裁判。）

### 4.4 现状（读数，实测；只报量级）

| 方向函数 | 语料 | 方向数 / 层数 / 最大叶 | 备注 |
|---|---|---|---|
| `keyset` | ext-wiki-vote（带 influence） | 61 / 8 / 1888 | 加维度前 **37 / 8 / 3191**（§D7 探针实测） |
| `keyset` | openalex-citations | 79 / 16 / 3291 | |
| `keyset` | cora-labeled | 13 / 7 / 818 | |

⚠️ 读数只报量级（本机噪声 ±30%）；**不据此排序**。

### 4.5 使用方式（**不许**变成裁判）

- **判据**（进退出码）：L1–L3、L4 的硬阈值、L5。
- **读数**（只报告）：方向数 / 层数 / 常数键占比。
- **证据**（证明判据会红）：注入 / 反向对照 / 留档脚本。
- **发展读数 G1–G6**：只进「读数」角色 —— 报曲线 / 报差 / 报分布，**不进退出码、不排序**。
  唯一例外：**G5-1（已实现的 A3 动作数 = 0）是判据** —— 它守的是红线，不是趋势。

### 4.6 发展读数（G1–G6）：随**维护**的进展，不是随**使用**的成熟

⚠️ 先把「使用」拆开，否则这句话会骗自己：

| 「使用」指什么 | 改不改结构 | 为什么 |
|---|---|---|
| **查询** | **不改结构** | `§K9`（外生项不许 usage 驱动）+ 维度必须人批准。⚠️ **内生量**（倾向 → 呈现次序）**会**按使用记录调整，且**跨会话累积**（记录落在 `<语料>/usage/`，下次启动读回）；但它只改「先说哪一支」，`answer_ids` / `n_answer` / `n_branches` **逐字不变**（探针 `W7`）。**两段通道**：查询只进缓冲（**不算有用**，`W3`），下钻才 `promote`（`W4`）—— 被摆出来只是**曝光**，不是**有用**。缓冲**有界**（`STAGE_CAP = 50`，**暂定值、未经标定**：多少次查询之内还该记得住，是人的判断）；**正式记录永不淘汰**（`clear` 是唯一删除路径）。逐处标记见 README「学习」一节 |
| **录入 / 维护** | 改 | 材料变了 ⇒ 树要跟上（`§A7`） |
| **人拍板**（加维度 / 加谓词） | 改 | 唯一能改「定义」的动作（`§D1`） |

⇒ **「随查询越来越成熟」只在「呈现次序」这一层成立**（先看哪一支更顺手），
  在「什么算一个方向」上**永远不成立**。两者别混成一句话 ——
  前者是「越用越顺手」，后者才是「越用越懂」，而后者按设计不存在。
  ⚠️ 而且「顺手」的**分母**只有下钻过的支 —— 查询本身只进缓冲、不产倾向。
能测的「发展」只有三件，各自可判、**不合成、不排序**：

**G1 维护保真**（测「跟得上」）：材料增量后 `Q′ ⊑ Q*`（传播 ⊑ 重算，`§A7`）、
覆盖不漏（`§A1`）、假阴仍为 0（`§K8`）。⚠️ 它测的是**不退化**，不是「更好」。

**G2 规模稳定性**（测「方向函数在规模上扛不扛得住」）：同一方向函数、一族
**规模不同**的材料各建一次树，报 `最大叶 vs |U|` 的曲线。**不设阈值**
（阈值依材料而变），只报曲线。实测（`evidence/_probe_scale_family.py` 脚本 ·
`evidence/_probe_scale_family.out.txt` 本次输出；六份，1 005 – 30 000 项）：

| 语料 | \|U\| | 方向数 | 层数 | 最大叶 | 叶/项 |
|---|---|---|---|---|---|
| ext-email | 1 005 | 367 | 40 | 47 | 0.047 |
| ext-bitcoin | 3 783 | 33 | 6 | 1 998 | 0.528 |
| ext-wiki-vote | 7 115 | 61 | 8 | 1 888 | 0.265 |
| ext-coauth | 9 875 | 9 | 4 | 5 569 | 0.564 |
| ext-astroph | 18 771 | 9 | 4 | 5 784 | 0.308 |
| ext-web-stanford-30k | 30 000 | 31 | 7 | 12 311 | 0.410 |

读法：**|U| ×30 而最大叶 ×262，方向数 367 → 31（不随规模增长）** ——
规模主要被**叶子**吸收，不是被**分辨率**吸收。⇒ 这条曲线说明：单靠既有的
方向函数，「更大」不会自动「更细」；要更细只能加维度（G3），而那是人的动作。
⚠️ 跨语料**不是单变量对照**（材料形状不同）⇒ 只读量级与趋势，不读因果；
58k / 82k 两份**超出时间预算**（单份 > 10 分钟），上端**如实缺**。

**G3 维度增益**（测「人拍板带来的分辨率」）：加一个维度前后最大叶的差
（wiki-vote 实测 **3 191 → 1 888**，方向 37 → 61）。这是唯一叫「发展」的机制，
且驱动是**人**，不是使用 —— 与 `§D1` 的外生准入同一条线。

**G4 分辨度**（测「分得细不细、匀不匀、随规模往哪走」）：三件子读数，
两两不互为函数（R4 自查：秩相关 |rho| < 1，见探针 `G4-*` 判据）。
⚠️ G4 **不重复报** L4a 的最大叶 —— L4a 问「这一棵合不合格」，G4 问「这条曲线往哪走」。

- **G4a 分布形状**：叶容量的 `p90/p50` 与 `max/p50`（无量纲 ⇒ 与规模无关）
- **G4b 规模指数 alpha**：`log(最大叶)` 对 `log|U|` 的最小二乘斜率。
  **alpha > 1 = 分辨率随规模退化**（叶子涨得比项数快）
- **G4c 分支熵**：每个内部节点的子支成员数分布熵（bit），按节点成员数加权。
  它问的是「切开时**匀不匀**」——与「切得多深」（最大叶）不是同一个刻度：
  把一个 1000 项的节点切成 500+500，熵 1.00 而叶很大；切成 10 个 100，熵 3.32 而叶很小。

实测（`evidence/_probe_growth.py --only g4` 脚本 ·
`evidence/_probe_growth_g4.json` 本次留档；六份规模族，1 005 – 30 000 项）：

| 语料 | \|U\| | 方向 | 层 | 叶数 | p50 | p90 | max | p90/p50 | max/p50 | 熵(bit) |
|---|---|---|---|---|---|---|---|---|---|---|
| ext-email | 1005 | 367 | 40 | 184 | 2 | 13 | 47 | 6.50 | 23.50 | 0.55 |
| ext-bitcoin | 3783 | 33 | 6 | 17 | 23 | 518 | 1998 | 22.52 | 86.87 | 0.59 |
| ext-wiki-vote | 7115 | 61 | 8 | 31 | 52 | 607 | 1888 | 11.67 | 36.31 | 0.81 |
| ext-coauth | 9875 | 9 | 4 | 5 | 1477 | 5569 | 5569 | 3.77 | 3.77 | 0.90 |
| ext-astroph | 18771 | 9 | 4 | 5 | 4599 | 5784 | 5784 | 1.26 | 1.26 | 0.91 |
| ext-web-stanford-30k | 30000 | 31 | 7 | 16 | 362 | 7238 | 12311 | 19.99 | 34.01 | 0.88 |

读法：**alpha = 1.54** ⇒ 叶子涨得比项数快，**分辨率在随规模退化**，不是持平
（|U| x30 而最大叶 x262）。
另一件更值得看的事：**分支熵只有 0.55 – 0.91** —— 2 支完全均匀才 1.00。
所以最大叶大**不是「没切」，是「切得不匀」**：每次切开总有一支吃掉大部分。
但**反过来不成立**：ext-astroph 的熵 0.91（很匀）却只有 5 个叶、最大叶 5 784 ——
它是「少切了几刀、每刀都切得匀」。⇒ **熵必须与 L4a 一起看**，单独看会读出「很匀」的错觉。
（R4 自查也印证：熵与 max/p50 的秩相关是 **-0.66** —— 负相关，不是同一个刻度。）

⇒ 要让树变细，**加维度（G3）比调切分点更有效**；而加维度是人的动作（`§D1`）。

⚠️ 跨语料**不是单变量对照**（材料形状不同）⇒ alpha 只读量级与趋势，不读因果；
58k / 82k 两份超出时间预算，上端**如实缺**（与 G2 同一批边界）。

**G5 自主度**（测「哪些动作系统自己做、哪些必须人拍板」）：**不报比例、不合成分数**，
报**动作 × LOA 等级**的分布。刻度借 Sheridan & Verplank (1978) 的 LOA 量表
（后被 Parasuraman / Sheridan / Wickens 2000 收成「人在环内 / 环上 / 环外」三分），
**只取有序等级，不取任何加权公式** —— 加权就是打分，打分就是裁判（E-1）。

| 级 | 含义 | 本项目**已实现**的动作 |
|---|---|---|
| **A0** 全人工 | 人做，系统不参与 | 2 个：新增派生维度（人写 sidecar）· 改方向函数定义（人改代码） |
| **A1** 提议后批准 | 系统提议 + 人逐条批准 | 1 个：批准维度（系统只执行人写的「已批准」） |
| **A2** 规则内自动 | 自动 + 人可回退 | 6 个：装载语料 · 建树 · 推导候选谓词 · 预算内挑谓词 · 回答查询 · 查询入缓冲并按倾向排序（**下钻才 promote**） |
| **A3** 改规则本身 | 系统自己定「什么算一个方向」 | **0 个 —— 禁止** |

★ **A3 = 0 是判据不是读数**（`G5-1`）。另有 **2 条禁止项声明**
（系统自选新维度定义 / 系统自改准入线阈值）登记在案，但**不进分母** ——
把「声明禁止」和「已实现的动作」混在一张表里数，判据就会去数声明
（探针第一版实测红 2 条，就是踩了这个）。

四条实测核查：代码里**没有**写 `_data/*/derived/` 的路径（`G5-2`）·
每个 sidecar 的 `_meta.named_by` 非空（`G5-3`）· 批准动作从 `corpus_dir` 读（`G5-4`）·
预算与规则也从语料读、不是系统学出来的（`G5-5`）。

第五条路是**回退**：`python -m ldv.tools.usage_store clear <语料目录>` 清空记录 ⇒
次序立刻回默认（探针 `W7`）。A2 那一格的「人可回退」不是形容词，就是这条命令。

⇒ 读法：**自主度的上限由红线定死，不由代码能力定死。**「更自主」在这里只能表现为
A0 → A1 → A2 的迁移（例：把「人写 sidecar」改成「系统提议 + 人逐条批准」），
**不能**表现为 A3。

**G6 请求命中度**（测「结构对真实问题覆盖到哪」）：请求集**外生** —— 人写、版本化、
冻结在 `evidence/requests_g6.json`（32 条：wiki-vote 16 + openalex 16，含 2 条刻意
拼错的键）。**系统不参与出题**：自己出题自己答，命中率可以被刷。

四分类直接用 `query` 的既有返回字段，不新造接口：
`direct`（不需要松弛就答上）· `relaxed`（丢掉一个键才答上）· `none`（连松弛都救不了）·
`rejected`（键不在词汇里 —— **分母不含它**，那是「问题写错了」，不是「结构答不上」）。

实测（`evidence/_probe_growth.py --only g6` 脚本 ·
`evidence/_probe_growth_g6.json` 本次留档；请求集本身在
`evidence/requests_g6.json`）：

| 语料 | 请求 | direct | relaxed | none | rejected |
|---|---|---|---|---|---|
| ext-wiki-vote | 16 | 13 | 2 | 0 | 1 |
| openalex-citations | 16 | 10 | 5 | 0 | 1 |
| **合计** | **32** | **23** | **7** | **0** | **2** |

直接命中 **23/30 = 0.767** · 需松弛 **7/30 = 0.233** · 答不上 **0/30 = 0.000**。

⚠️ **`none = 0` 是这条读数的真结果，不是「没问题」**：它说明在真实词汇上结构没有
盲区，缺口全部表现为「要松弛」（问题本身过约束），而不是「答不上」。
⇒ 这条读数的信息量主要在 **direct : relaxed 的比**，不在「有没有 0」。

⚠️ 它测的是「结构 vs 请求集」的匹配，**不是随查询成熟**（查询不改结构，本节开头已拆）。
请求集一换读数就会变 ⇒ 必须冻结版本，否则前后不可比。

**两层记忆与遗忘**（2026-10-22）：短期**显性**记忆 = 缓冲区（`usage/_staging/`，
容量 50 批，超了淘汰最旧，入口显式报「还剩 N 支待看」）；长期**隐性**记忆 = 稳定区
（`usage/*.md`，**稳定就是正式**，不再逐条呈现，只体现在 `ordered_by`）。

★ **遗忘发生在计算上，不发生在存储上**：记录是账本、只追加；
衰减因子 `0.5 ** (年龄 / 半衰期)` 只在算倾向时乘进去 ⇒ 老经验影响力变小，
但任何时候都能回答「它曾经学过什么」，改半衰期就能「重新记起来」。
实测（`evidence/_probe_forgetting.py`）：300 天前的记录倾向 **1.0000 → 0.0010**，
记录仍是 1 条，答案集合与支数逐字不变。

⚠️ 倾向是**累计证据**不是平均值（平均里 `w` 会被约掉 ⇒ 单条老记录看不出衰减）；
⚠️ 缺时间戳不衰减（w = 1.0），不猜；⚠️ 会话内 drill 不立刻改次序（巩固是跨会话的事）。

**分工**：L1–L5 是**准入线**（一次建树合不合格）；G1–G6 是**发展读数**
（跟不跟得上 / 规模上扛不扛得住 / 加维度有没有增益 / 分得细不细匀不匀 /
谁在做决定 / 对真实问题覆盖到哪）。两层都**不产分数**；唯一进判据的是 G5-1。

## 5 范式记录：设定 → 设立 → 使用

三步，每步的**输入 / 输出 / 反例**都记下来 —— 这是「显性化」的落点。

### 5.1 设定方向函数（外生）

- **输入**：人写规则（`Rule(名, 量, 分档)`；插件契约 §I1–§I2）
- **输出**：`predicates.json` 的 `参数`（切分点从材料算，同一份材料唯一）
- **反例**：让系统自适应 `N` ⇒ 结构依赖历史（`§K9` 同族）；自动给组合起名 ⇒
  定义基础词汇（外生项）被系统代劳

### 5.2 设立标准（读数 + 四关 + 阈值）

- **输入**：一条读数（有刻度、说的是系统、归因到机制、不与别的读数互为函数）
- **输出**：`(读数, 阈值, 角色)` 三元组；角色 ∈ {判据, 读数, 证据}；阈值**外生**
- **反例**：把「区分度」当阈值 ⇒ 系统在当裁判（它只许排序）；
  把「环境量」（端口占用、机器负载）当读数 ⇒ R2 红

### 5.3 使用标准（判据 / 读数 / 证据三角）

- **输入**：标准 + 一份语料
- **输出**：判据（退出码）· 读数（报告）· 证据（证明判据会红）
- **反例**：用「标准全绿」当质量证明 ⇒ 绿只说明**没违约**，不说明**好**；
  把读数排序 ⇒ 系统当裁判

### 5.4 记录本身在哪（可指认，不靠记忆）

`docs/认知原型.md`（本文）· 断言集 `§S1–§S5` · `predicates.json` 的七段 ·
`directions.json` 的三段 · release 正文 · `git log`。

## 6 一句话

> 它不是一个「知道很多」的系统，是一个**知道自己有什么**的原型：
> 结构可指认、反思有证据、重构留账、标准不产分数。
> 标准分两层：**准入线**（一次建树合不合格）与**发展读数**（随维护跟不跟得上、
> 规模上扛不扛得住、加维度有没有增益）—— 都不需要相信它，拿纸或拿命令就能核。
