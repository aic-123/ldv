## 1 契约 `ldv-http/1`

**为什么先做它**：后面三件全都建在「响应长什么样」上。原来 `serve.py` 的响应是
「CLI 输出的等价物」—— 那是一个**观测结果**，不是**契约**：谁也不知道改哪个字符算破坏。

| 头 | 出现时机 | 含义 |
|---|---|---|
| `X-Ldv-Protocol: ldv-http/1` | **每个**响应 | 契约版本。**只增不改**：字段可加，已有含义不许变 |
| `X-Request-Id` | 每个响应 | 本请求的 id；客户端给了合法值就**沿用**（跨服务串一条链） |
| `X-Ldv-Error` | 4xx / 5xx | 机器可读的失败种类，见下表 |
| `Retry-After` | 401 / 429 | 什么时候可以再试（秒） |

`X-Ldv-Error` 的取值是**契约**（正文是中文说明，会随行文改；这个头不改）：

| 状态码 | `X-Ldv-Error` | 什么意思 | 调用方该做什么 |
|---|---|---|---|
| 400 | `bad-request` | 参数写错了 | **别重试**，改参数 |
| 401 | `unauthorized` | 没带 token / token 认不出 | 补 token |
| 403 | `forbidden` | token 有效，但这个租户不是它的 | 换 token |
| 404 | `not-found` | 租户/任务不存在（**或在管理员眼里不存在**） | 查名字 |
| 409 | `conflict` | 建租户重名 | 改名 |
| 429 | `rate-limited` | 配额用完 | **等一下再来** |
| 429 | `queue-full` | 队列满（与配额是两件事） | 等一下再来 |
| 5xx | `internal` / `unavailable` | 服务端问题 | 报警 |

**失败顺序也是契约**（`Handler` 类文档里有同一张表）：

    401 你是谁 → 403 不是你的 → 400 参数错 → 404 没这个租户 → 429 配额没了

三个「为什么这样排」：

- **400 在 429 之前** ⇒ 写错的请求**不烧配额**（否则调试会把配额耗光）；
- **404 在 429 之前** ⇒ 摸不存在的租户不烧配额；
- **403 在 404 之前** ⇒ 「存在但不是你的」与「根本不存在」**对无权的调用方长得一样**
  ⇒ 不泄露租户是否存在。

判据：⑳ 58（同请求两次逐字相同）、59（不认识的参数 ⇒ 400，不静默忽略）、63（四种失败两两不同）。

## 2 认证与配额（`serve_auth.py`）

**原来的状态**：`GET /<tenant>/run` **谁都能跑**。一个能被摸到的服务，这是第一位的洞。

### 盘上是什么

```json
{"tokens": [
  {"name": "alice", "sha256": "<64 位十六进制>", "tenant": "demo", "quota_per_min": 60},
  {"name": "ops",   "sha256": "<…>",            "tenant": "*"}
]}
```

`tenant: "*"` = 管理员（全部租户 + 建/删租户）。

造一个（明文只出现这一次）：

```bash
python serve.py --mint-token alice --tenant demo
```

### 三个不显眼但都是「不这样就会静默错」的选择

1. **盘上只存摘要**。`tokens.json` 是 `sha256(token)`，不是 token。备份、误提交、贴进 issue
   都不会泄露可用凭据。比较用 `hmac.compare_digest`——`==` 在第一个不同字节就返回，
   把「前几位对不对」变成可测的时间差。
   ⚠️ 这是**摘要**不是**加盐哈希**：文件泄露 + 弱 token ⇒ 可离线爆破。
   所以 `mint()` 用 `secrets.token_urlsafe(32)`（约 256 bit），不是人想得出的词。
2. **缺 `quota_per_min` ⇒ 60，不是「不限」**。默认值取**紧**的那一侧：
   写配置的人漏一个字段，结果不能是「从此不限量」。要不限，显式写 `0`。
3. **配额是固定窗口**（60 秒），代价写在明处：窗口边界前后各打一次，最坏 1 秒内用掉 2× 配额。
   选它是因为**可测**（不用注入时钟就能验边界）。要换成滑动窗口，判据得一起改。

### 生命周期：过期与轮换（2026-10-29 补）

业界对 API key 有一条我们原来**没有**的要求：**有轮换与过期，且支持双 key 重叠**。
现在补上了，做法刻意保守：

| 事 | 怎么做 | 为什么不这样就会出事 |
|---|---|---|
| 过期 | `tokens.json` 每条可写 `"expires_at": "2027-01-31"`（只写日期 ⇒ 按那天 23:59:59 算） | 永不过期的 token 是一条**永久凭据** |
| 缺省 | **不写 = 不过期**，但启动时把「N 个 token 没设过期」印在脸上 | 缺省设 90 天会让**已在用**的 `tokens.json` 某天全体失效 —— 一次格式升级不该打死既有部署 |
| 写坏 | `--start` 直接报错（`ValueError`） | 写错的时间与「没写」在运行时**一模一样**，而前者让人以为已经设了保护 |
| 轮换 | `--rotate <名字> --tokens <文件>`：造**同名新条目**，旧的留着到期 | 换 key 时删旧的 ⇒ 客户端还没换完就 401，那是停机 |
| 401 的分支 | 「没带」/「认不出」/「**已过期**」三种正文分开写 | 都回 401 是对的（客户端不该为原因写三个分支），但正文说「过期」人才知道去换，而不是去查拼写 |

```bash
python serve.py --mint-token alice --tenant demo --expires-days 30   # 带期限
python serve.py --rotate alice --tokens tokens.json                  # 换新的，旧的不动
```

⚠️ 双 key 重叠能成立，靠的是 `authenticate_detail` **遍历完所有条目**再判
（命中就 `break` 会让「同名两条」里只看得到第一条 —— 而轮换期间正是两条并存的时刻）。

### 入口不给你「裸奔」的机会

`main()` 里**没有默认放行**：要么 `--tokens tokens.json`，要么**显式** `--allow-anonymous`，
否则**拒绝启动**并打印怎么造 token。默认值取紧的那一侧 ——「忘了配认证」不能等于「对外裸奔」。

> ⚠️ 类属性 `Handler.store` 的默认值是「匿名全通」，这一条**只对进程内嵌**（判据、探针）成立。
> 说清楚比藏着好：如果有人自己 `ThreadingHTTPServer(("0.0.0.0", port), serve.Handler)`，
> 他就绕过了 `main()` 的那道门。**要对外，就起 `main()`**。

判据：⑳ 60（无/错 token ⇒ 401 + `WWW-Authenticate`）、61（不是你的 ⇒ 403）、
62（429 + `Retry-After`，且**不消耗任务表**）。

## 3 租户生命周期（`serve_tenants.py`）

约束②说「一租户一目录，备份=拷目录」，但**建/删原来没有入口** —— 手工 `mkdir` + 从别处
拷一份 `view_spec.json`。手工步骤真正的代价不是麻烦，是**每次做的形状都可能不一样**。

| 操作 | 端点 | 行为 |
|---|---|---|
| 建 | `POST /tenants/<名>` | 建 `nodes/`（空）+ `view_spec.json`（**空声明**）；重名 ⇒ **409，不覆盖** |
| 列 | `GET /` 或 `GET /tenants` | 只列**你有权看**的 |
| 删 | `DELETE /tenants/<名>` | 整目录挪进 `<根>/.trash/<名>.<时间戳>` —— **不是 `rm`** |

**建出来的库是空的，而且空库能跑**：`GET /<新租户>/run` 立刻是 200，正文「装进 0 项」。

> 这一条顺手**修掉一个口径不一致**：内核 2026-10-25 就定了「空语料是合法的」
> （`corpus/loader.py::load_nodes` 明写「新库就是 0 项」），但壳里 `_load_tenant`
> 还要求 `nodes/` 下至少一个 `.md` ⇒ 建完的租户立刻 404。**壳与内核在「空库」上
> 说法不同**，而服务层的「建租户」正好把这个矛盾摆到台面上。
> 现在两边同口径；不往新库里塞占位文件 —— 那是「为了让它看起来能用而编一条数据」。

**删是可逆的**：回收站放在租户根**里面**（`.trash/`，点开头 ⇒ 不出现在租户列表里），
这样「备份 = 拷目录」不变 —— 拷走根目录时，被删的东西也跟着走。

**名字先过白名单**：`^[A-Za-z0-9_-][A-Za-z0-9._-]{0,63}$`，且不许是保留字
（`tasks` / `tenants` / `healthz` / `readyz` / `metrics`）。检查发生在**任何路径拼接之前** ——
`POST /tenants/../../etc` 在拼接之后才判就已经晚了（`Path` 已经把它规约掉了）。
保留字那条同样不是洁癖：一个叫 `healthz` 的租户会让端点**互相遮蔽**，而遮蔽方向取决于路由顺序。

判据：⑳ 64（建 + 空库可跑）、65（重名 409 且原节点一个没少）、66（删 ⇒ 回收站 ⇒ 挪回来又能跑）。

## 4 调度器（`serve_sched.py`）

**它补的是最后一段**：时钟让 `k` 能由时间推，但**没人按节奏调** `agenda.tick()`。
没有它，「主动性」仍然要求「有人记得来敲一下」。

**一条红线**：`tick()` **自己不幂等** —— 每调一次就往账本记一行 `seen`，而账本是 `k` 的
**唯一**基线 ⇒ **重复 tick 会催熟 k**（门槛降得比时间过得快）。

所以幂等由调度器守，用**槽位**做键：

    slot = epoch // interval     同一槽只 tick 一次，换槽才允许下一次

且槽位**落盘**（`<根>/.sched.json`，临时文件 + `os.replace` 原子替换）。
只放内存的话，一个重启循环（systemd `Restart=always` + 起不来）会在同一槽里反复 tick ——
那正是幂等最该挡住的情形，也恰好是内存版挡不住的。

默认 `interval = 1800 s`，与 `agenda.IDLE_PERIOD_MIN` **同刻度**：一槽一档，
于是「闲置多久 ⇒ k 涨多少」与服务自己的节奏对得上。

判据：⑳ 70（同槽两次只 tick 一次；跨槽才再走）、71（列得出但不完整 ⇒ 跳过，不猜它想要什么）、
73（**换一个新实例** = 模拟重启，同一槽仍然 already）、72（**反向对照**：槽位每次都变 ⇒ 同槽 tick 两次）。

### 不承诺

- **不做补偿**：进程停着那段时间不补票。停 3 小时再起来，下个槽才走一格 ——
  `k` 按**账本时间**算，不是按 tick 次数。
- **不做租约**（P3）：两个实例同时跑会各 tick 一次。单实例是 P1 的前提，写在这里而不是「大家注意一下」。

## 5 观测（`serve.py`）

| 端点 | 答什么 | 鉴权 | 失败时 |
|---|---|---|---|
| `GET /healthz` | **这个端口有人听吗**（不碰磁盘、不看配置） | 无 | —（进程在就 200） |
| `GET /readyz` | **能干活吗**：租户根可读 / 有可服务租户 / 认证策略 / 调度器 | 无 | **503**，逐项说哪项不行 |
| `GET /metrics` | 进程内计数，**Prometheus 文本**（标准出口，看板直接吃） | 管理员 | 403；未装库 ⇒ 明确回退 JSON |
| `GET /metrics.json` | 同一份计数的**结构化**版本（判据与端到端读它） | 管理员 | 403 |

`/readyz` 的四项**各自独立报**，因为「服务坏了」与「还没建好」必须分得开 ——
否则排障从看日志变成猜。没起调度器（进程内嵌 / `--no-tick`）**不算不 ready**：那是配置，不是故障。

每个请求一行 JSON 到 stderr（`--quiet` 可关）：`ts / req / m / path / code / error / ms`。
出事先看 `req`，再看 `code` / `error`。

⚠️ `/metrics` 是**计数器不是时序库**：它只回答「这个进程自起来以来发生过几次」，
不回答「过去一小时慢不慢」。

**为什么两个出口**：Prometheus 文本是**给看板**的（标准格式、可以直接 scrape）；
JSON 是**给判据**的（字段更细、能断 `计数["提问"]`）。两者读的是**同一份字典**——
不另存一套 `Counter` 对象，因为「两套计数一定会漂」，而漂了之后你分不清哪份是对的。
实现见 `serve.prometheus_text()`（依赖 `requirements-shell.txt` 里那一个库）。

判据：⑳ 67（客户端给的 `X-Request-Id` 被沿用）、68（healthz/readyz 分开且都为 200）、
74（metrics 只给管理员）、69（**反向对照**：租户根空 ⇒ readyz **503**）。

## 6 一个 agent 真的能走完的那三件（`/ask` `/drill` `/agenda`）

**P1 做完了才发现少了半边**：壳只会在租户上「跑一遍流水线」并把追踪文本吐出来 ——
那是**诊断**，不是**答案**。真正回答问题的 `entry.App`（需求 → 这一带的节点 / 分叉处的几支）
在**另一个进程**里，而且它自己写着「只绑 `127.0.0.1`，无鉴权，不是对外服务」。

⇒ 一个 agent 走不通全程：**有鉴权的那半不会答题，会答题的那半没有鉴权**。
三件接到同一个端口、同一套 token 上：

| 端点 | 干什么 | 语义 |
|---|---|---|
| `GET /<租户>/ask?require=&forbid=&plugin=&refresh=` | 需求 → 这一带的节点 / 分叉处的几支 | 只读；答案由 `answer_ids` 定义 |
| `POST /<租户>/drill?did=&verdict=` | 下钻 = 「这一支有用」的**唯一真实信号** | 写使用记录；只改次序不改集合 |
| `GET /<租户>/agenda?k=&tick=` | **现在轮到谁**（主动性在 agent 侧的出口） | `tick=1` 会记一行 `seen` |

### 四条不显眼但都是「不这样就会静默错」的决定

1. **一个租户一个 `App`，而且要缓存**。`App` 里有两处跨请求状态：`_last_shown`
   （刚才摆了哪些支）与 `_tendency`（这一支的历史倾向）。每个请求新建 App ⇒
   `drill` 拿到的 `_last_shown` 是空的 ⇒ 使用记录**永远记不下来**，而它返回的文案
   「这一支不在刚展示的候选里，不记」听起来**像**是正常业务判断 ——
   「功能没接上」与「业务上不该记」长得一样，这是最该防的形状。
   ⚠️ 失效规则：**只看目录 mtime**（加/删/改名会重建）。原地改一个文件的内容**不会**
   重建，那要 `?refresh=1`。这是取舍：逐文件 stat 在 28 万项语料上是每请求 O(n)。
   所以「什么时候能看到新内容」有明确答案：**加/删会看到，原地改要 refresh**。

2. **`verdict=wrong` 服务层不转发。**判错（这一支被推翻）只能由人授予 ——
   内核的 `actor` 参数就是为这件事设的。接口一旦对 agent 开放，agent 就会把
   自己读不懂的标成错的。⇒ 服务端固定 `actor="agent"`，并在边缘直接 403。

3. **两种「不是成功也不是失败」的答案都给 200**：
   `out_of_structure`（这个问题**超出本结构的词汇**）与 `empty_corpus`（**库还是空的**）。
   它们都是**关于状态的事实**，不是「你参数写错了」。混成 400 会让调用方去改一个
   本来没错的参数。
   ⚠️ `empty_corpus` 是端到端跑出来的：空库的 `all_keys` 是空集，原来那条「拼错的键」
      判据会把**任何**问题都判成「你打错了」，第一次接触新库的人看到的就是这句假话。

4. **答案的判据是 `answer_ids`，不是整串正文**。`/ask` 的返回里有 `ms`（本趟耗时），
   两个并发客户端拿到的正文**必然不同**（实测：4 路并发，正文 2 种，唯一差异是
   `"ms": 0.03` vs `"ms": 0.02`；`answer_ids` 去重后只有 1 种）。
   ⇒ 拿整串做 golden 会得到「时有时无」的假红。这一条写进契约：**`ms` 是观测字段**。

### 坏语料：不许拖死连接，也不许让 readyz 说谎

端到端实测抓到的两个真缺陷（都已修）：

| 现象 | 原因 | 现在 |
|---|---|---|
| `/run` 遇到重复 id 的节点 ⇒ **连接被断**（客户端拿到 `RemoteDisconnected`，日志里只有 traceback） | `_execute` 只捕 `OSError`，而 `CorpusError` 从 handler 穿了出去 | **500 + 说清是哪一处**（「租户 X 的语料读不进来 —— CorpusError: 重复的 id: p1」） |
| 坏语料时 `/ask` 全 500，而 `/readyz` **照样 200** | readyz 只查「目录在不在」 | readyz 多一项 **`没有已知装载失败`**，失败后 **503** 并指名租户；修好后**自己回到 200** |

⚠️ 这一项的语义是「**已知**装载失败」（本进程亲眼见过的），**不做主动扫描** ——
每请求把全部租户装载一遍，在 28 万项语料上是每个 readyz 几秒，那会让探针本身变成故障源。
这句差别写在 `/readyz` 的返回里，不藏在注释里。

## 6.5 端到端：`e2e_agent.py`（真进程 + 真 HTTP，27 步）

进程内判据验证的是「函数行为对」，**不是**「一条真流程走得完」。所以另有一个脚本：

    python e2e_agent.py            # 起真进程（python serve.py --tokens …），只走 HTTP
    python e2e_agent.py --keep     # 留着临时目录排障

它走的是 agent 的真实顺序，**27 步**（6–8 秒）：

    造 token（走 CLI，并核对「打印的摘要 == 真 token 的 sha256」）→ 起进程（没租户时 readyz 必须 503）
    → 建库 → 空库先问一句 → 喂 8 个节点 → 问 → 问结构外的键 → 问全库（分叉）
    → 下钻（记下来了；只改次序不改集合；agent 不能判错）→ 议程
    → 等 5 秒**一个请求都不发**，看调度器自己 tick（账本 0 → 2 行）
    → 异步任务提交/轮询 → 坏语料（500 + readyz 503 + 修好自愈）→ 配额 → 401/403/404
    → **重启**（账本一行没丢、token 仍有效、答案不变）→ 删/恢复 → 观测

三件**只有它测得到**的事（进程内判据结构上测不了）：

1. `main()` 的启动路径（认证拒绝、调度器线程、参数解析）；
2. 一个坏节点会不会**拖死整个服务**（进程内那个版本来就是断连，看不到）；
3. **重启**之后账本 / 租户 / token 还在不在。

定位：它是**证据**（8 秒、spawn 进程、要等调度器），**不是判据** —— 所以不塞进 `run_tests`。
`run_tests` 里对应的是 `test_service_agent_http`（13 条，进程内、1 秒级），守同一批行为。

## 7 判据 ↔ 出口条件

P1 的出口条件（`服务层评估.md` §4）逐条对上：

| 出口条件 | 判据 |
|---|---|
| 401 / 403 / 404 / 429 **长得不一样** | ⑳ 60 · 61 · 62 · 63 |
| 建 / 删租户各一条，删**走回收站** | ⑳ 64 · 65 · 66 |
| 调度器单实例 **tick 幂等** | ⑳ 70 · 72 · 73（+ 71 跳过不完整租户） |
| `/healthz` 与 `/readyz` 分开，缺语料**如实不 ready** | ⑳ 68 · 69 |
| （契约：`ldv-http/1` 冻结） | ⑳ 58 · 59 |
| token 生命周期（过期 / 写坏 / 双 key 重叠） | ⑳ 85 · 86 · 87 |
| 指标双出口（文本标准 / JSON 给判据） | ⑳ 74b |
| agent 面（ask / drill / agenda）+ 坏语料不拖死连接 | ⑳ 75–84（`test_service_agent_http`，13 条） |

判据函数：`ldv/tests/run_tests.py::test_service_p1`（30 条）与
`test_service_agent_http`（13 条）。全程在**临时根**里、租户**现建**、
节点由判据自己写 —— 不依赖 `_data/` 下任何语料，因此**不会因外部语料不在而跳过**。

## 8 没做的、以及为什么

| 没做 | 为什么现在不做 | 什么时候做 |
|---|---|---|
| **多实例租约** | 没有真实并发需求就先引进「任务表外置 + 租约 + 重复 tick」三个坑 | P3，且要先有并发读数 |
| **任务表落盘** | `TaskTable` 在内存：进程被杀 ⇒ 排队任务丢（已完成的也不会补） | 与租约一起做（跨进程版 = 落盘） |
| **按租户的独立配额** | 现在配额按 **token** 算。多个 token 指向同一租户时，租户级上限不可控 | 有「一租户多调用方」的真实场景时 |
| **`--tokens` 热加载** | 改 token 要重启。重启会丢任务表（见上条） | 与落盘一起 |
| **TLS / 反代** | 壳只监听 `127.0.0.1`。对外要么反代加 TLS，要么别对公网开 | 部署时定 |
| **`App` 缓存的原地改内容** | 失效只看目录 mtime：加/删会重建，**原地改要 `?refresh=1`** | 有「热更新同一批节点」的需求时（要付每次请求 O(n) stat） |
| **`/metrics` 跨重启** | 计数器在进程内，重启归零（端到端第 ⑰ 步就撞到这一点） | 与外采/落盘一起做 |
| **`/readyz` 主动扫描语料** | 只报**已知**装载失败（理由见 §6） | 有缓存/索引层时（扫描成本才降得下来） |

上面的每一条都**重新查过成熟方案**（`APScheduler` / `pyrate-limiter` / `prometheus-client` / `FastAPI` / `huey` / `watchdog`），逐条给了「换 / 不换 + 触发条件」：见
[`壳层选型.md`](壳层选型.md)。结论是**只有两处真该补**（token 生命周期、指标标准出口），
其余五处不换的理由都写在那一份里。

⛔ 停止条件不变：壳的需求开始倒逼内核改接口 ⇒ 约束①破了 ⇒ 停下重划边界。

## 9 怎么起

```bash
# ① 造 token（明文只出现一次）
python serve.py --mint-token alice --tenant demo
# ② 把打印的 JSON 条目写进 tokens.json
# ③ 起（默认就带调度器：每 1800 s 走一格；认证必需）
python serve.py --tokens tokens.json --port 8765
# ④ 建租户 → 喂节点 → 跑
curl -X POST -H "Authorization: Bearer $TOK" http://127.0.0.1:8765/tenants/demo
curl -H "Authorization: Bearer $TOK" "http://127.0.0.1:8765/demo/ask?require=type=论文"
curl -X POST -H "Authorization: Bearer $TOK" "http://127.0.0.1:8765/demo/drill?did=D2"
curl -H "Authorization: Bearer $TOK" "http://127.0.0.1:8765/demo/agenda?k=0"
curl -H "Authorization: Bearer $TOK" "http://127.0.0.1:8765/demo/run?plugin=keyset"
curl http://127.0.0.1:8765/readyz
```

本地自用（只该在 `127.0.0.1`）：

```bash
python serve.py --allow-anonymous
```

调试完记得 `python serve.py --mint-token` 造的那行——**明文没有第二次机会**，
丢了就再 mint 一个（旧的摘要从 `tokens.json` 删掉即可，它不会自己过期）。
