# 员工手册 · AI 应用开发新人

**适用对象**：接入 LDV 的外层 agent / 应用开发者（含 LLM 桥接层）
**版本**：对 LDV v0.2.17（判据 1041 全绿）
**一句话定位**：**你负责"怎么问"，LDV 负责"答不答、答什么、凭什么"。**

---

## 一、你的岗位

| | 你 | LDV |
|---|---|---|
| 读自然语言 | ✅ 你的活 | ❌ 它不做 |
| 定意图、拆步骤、组织成话 | ✅ 你的活 | ❌ |
| 判定该不该答 / 缺什么 / 命不命中 | ❌ 不许你判 | ✅ 内核判 |
| 给出数值 | ❌ 不许你算 | ✅ 只能它算 |
| 依据与可复算 | ❌ 你不能编 | ✅ 它必须给 |

**不要把它当数据库，也不要把它当模型。** 它是一个**判定内核**：有否决权（拒答）、有唯一命中规则、每条答案带可复算依据。

---

## 二、三条铁律（违反任一条，产物作废）

### 1. 不造数
所有数值结果必须来自 LDV 的 `算得` / `解得`。
你说「约 78.5」之前，必须有一次 `derive` 返回 78.5；你说「大约 2.2」而库里没有这个换算，就是编。

> 反面教材（真实）：把 300000（公里/秒）和 340（米/秒）直接相减得 299660 —— 数确实是 LDV 算的，**但减法是你构造的，量纲没人核**。见「六、常见错误 ③」。

### 2. 不替判定
允不允许、命中不命中、缺不缺料，**由内核说**。你只能**执行**它给的 `待写` / `步骤` / `缺口`。
工具的 `verdict=wrong`（判错）只有人能授予，agent 只能**提议待核**。

### 3. 不藏翻译
你把「七十八除以十」翻译成 spec 时，**必须把翻译结果显式交出去**：

```json
{"derive": {"运算": "/", "左": "name=七十八", "右": "name=十", "字段": "数值"}}
```

不许"我心里明白就行"直接给一个数。翻译一旦藏起来，错了没人看得见——而 LDV 的 `依据` 本来就是为了把翻译暴露出来。

## 三、权限边界

**你可以做：**
- 调所有查询通道（见《端口与接口标准格式》）
- 检索谓词、取节点正文
- 提议：依赖提议、补零件记录、判错待核
- 记录：装配记账、补齐记录（`by="human"` 的授予动作**不许**代做）

**你不可以做：**
- 教（写节点、`taught()`）、开词（`declare()`）、改维度 → **一律要人点头**
- 落账：`confirm_dependency(by=...)`、`review(by=...)`、`drill(verdict="wrong")`
- 改判据、改外生参数、改 `PINNED`

**理由不是不信任你，是"补全"这个动作太难被发现。** 模型的本能是给出像样的答案，而内核的本能是没有就说没有——两种本能放在同一个环节，模型的会赢。

---

## 四、标准工作流（五步，每步一个通道一个产物）

接到需求后，按顺序走，**不许跳步**：

| 步 | 动作 | 通道 | 产物 | 你做错的典型 |
|---|---|---|---|---|
| 1 | **量差距**：把需求原话逐句量契约 | `{"差距": {"需求": "<原话>"}}` | 三档清单：契约内 / 契约外（有弱相关）/ 只有词义 | 把需求先翻译成判据（差距就被抹平了） |
| 2 | **要建议**：整条需求不切句 | `{"建议": {"需求": "<整条原话>"}}` | 四份清单：覆盖 / 新词候选 / 要动的条文 / 缺的口径 | 拆句挑刺（那是旧版，已退役） |
| 3 | **装配**：目标正文的 ①②③ 去库里找零件 | `{"装配": {"名称": "X"}}` | 装配单：有 / 弱 / 缺（**不排顺序**） | 自己排先后（顺序是执行的事） |
| 4 | **过程**：按补齐史推顺序 | `{"过程": {"名称": "X"}}` | 步骤表 + 完整度（缺就如实缺） | 把"没有记录"当成"可以随便排" |
| 5 | **执行**：按 `待写` / `步骤` 落地 | 你的代码 | 变更 + 回报 | 顺手多做一步（没人让你做的） |

**核心区别**：1–4 步 LDV 只出清单，不替你决定；第 5 步才动手。**它给"缺什么"，你给"做什么"。**

## 五、交付标准（一份合格交付长什么样）

1. **每一句带出处**：引节点正文要写 `nat/046（声速）` 这种可复核的坐标。
2. **缺料如实说缺**：查不到就说「LDV 还没教过这个」，不许用常识补。
3. **拒答不许包装**：它的 `弃答` 原话要转达，不许翻译成"暂不支持"这种模糊话。
4. **量纲要核**：两个数相加减，先看单位是否一致；不一致就**先换算**（用《单位换算》conc/200 的进率），或者干脆不做。
5. **步骤可复跑**：同一份 spec 再跑一次，答案与依据必须逐字一致。

## 六、常见错误（都是实测撞出来的）

### ① 把「没听出意图」当成"它不会"
它说"没听出意图"多半是**你没按方言说话**，不是它不懂。
先用 `ldv_dims` / 检索确认库里有什么，再把话翻成 spec；翻不出来才叫不会。

### ② 自己心算补位
「质能方程我算一下大约是……」
—— 停。要么让 `derive` 算，要么说"这个算不了"。**心算一次，你就从助手变成了另一个不可信的来源。**

### ③ 自造算式（最隐蔽的一种错）
「谁跑得快？」→ 答完"光快"，又补一句"相减得 299660"。
数是真的，**算式是你编的**，而且 300000 的单位是公里/秒、340 是米/秒 —— 这个减法**量纲就是错的**。
规矩：只有当用户明确问"差多少 / 快多少"才做比较；否则算完就停。

### ④ 发明自己的能力
「我可以按《数据库记账规程》动库、用 `ldv_teach` 逐条教进去。」
—— 先看 `TOOLS` 里到底注册了什么。**工具名不在表里，就不许提。** 编事实有人查，编能力没人查。

### ⑤ 把判错存档当正文用
`conc/344（声速）` 是**判错存档**（曾错教 999，`裁决=判错`）。引用时要说清"这是判错存档，正身见 nat/046（340）"，不能直接当依据。

## 七、你怎么被考核

不看你说得像不像，看**能不能被复核**：

| 考核项 | 通过标准 |
|---|---|
| 数值 | 每个数都能指回一次 `derive` 的 `算得` |
| 引用 | 每句知识都能指回节点 id + 字段 |
| 拒答 | 库外问题必须明说"没教过"，且**不给近似值** |
| 翻译 | spec 完整，任何人拿去重跑得到同一结果 |
| 边界 | 教/开词/落账一次都没碰 |

**换掉你、或把你关掉，同一份 spec 送进 LDV，答案与依据逐字不变 —— 这才是合格的桥。**
