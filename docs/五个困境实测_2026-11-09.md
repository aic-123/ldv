## 困境一｜空结果被翻译成肯定句

**案例**：订单系统返回空，Agent 编了一个格式完美的退款单号，一周 17 次。

**它的做法**：空不是"没有这个字段"，空是有结构的。

真实回执（`find loans {borrowerId:"U999"}`）：

```json
{"ok": true,
 "解读": {"结论": "空结果", "任务标签": "无此记录", "条数": 0,
          "空结果不算故障": "ok=1 但没有文档 = 账面就是这样，不是连不上"},
 "结果": []}
```

三层都摆出来了：**结论**（空结果）、**任务标签**（无此记录）、**它不是故障**（防误判为连不上）。
另外空的时候它会顺手取一条样本，报出**该集合真实的字段名**，用来区分"真没有"与"谓词写错"。

**0 命中 ≠ 没教过**，是同一类问题的另一半：

```
{"require": ["name=量子纠缠"]}
→ ok=false, out_of_structure=true
→ "这个问题**超出本结构的词汇** —— 它不代表材料里没有，只代表这里没有这个维度"
→ suggest: ["name=量词", "name=重量", "name=能量"]
```

**判定：强覆盖。** 它自己不会编（它不生成语言），而且它给的每个"空"都带一个可分辨的标签。

**缺口**：编造发生在上层 agent。LDV 能做的只有——**弃答原话必须被转述**，不许包装。这条已写进《外接应用开发规范》conc/462，但它是纪律，不是闸门；上层不听，它也拦不住。

## 困境二｜间歇失败与鬼打墙

**案例**：单次失败率 4%，12 次调用整体约 40%；参数陷阱（日期格式、枚举、必填被省略）；失败后反复用同一参数重试直到预算耗尽。

**它的做法**（都是现成机制）：

- **不重试**：《端口调用规程》conc/393 ——「一次不通就如实回报（什么错、多久超时），不轰炸端口；要不要重试由人定」。
- **失败码**：mongo 回执解析成 `未授权(13/18) / 命令错 / 连接不上`，写 Mongo 失败还带 `错号 + errmsg`。
- **挂账**（今天刚补）：写失败落 `mongo_ledger.jsonl`，一条一行——
  ```json
  {"op":"insert","库":"ldv_test","集合":"chain_probe","步骤":2,
   "已尝试":[{"单号":"L1003","状态":"已还清"}],
   "允许值":{"状态":["待还","已还","逾期"]},"错号":121,"errmsg":"Document failed validation"}
  ```
  这就是"第 2 步失败，已尝试参数 X，允许值 Y"的原型：**X 和 Y 都在账上**，不需要下一个人重新踩。
- **预算闸**：查语料自带预算与花费账——
  ```
  总查询 89｜总花费 118
  按结论：精确命中 30｜多命中收不窄 9｜查不到（预算内）10｜预算用完没找到 6｜裸检索 34
  ```
  "鬼打墙"在这里会表现为「预算用完，没找到」的计数上涨——**它数得出来**。

**判定：部分覆盖。**
**缺口**：① 4%×12 的组合失败率是调用方的重试策略问题，LDV 只保证"单次不重试、失败留痕"，不给重试方案；② 日期格式/必填缺失这类**通用 schema 校验**它不做——它只校验自己认的实体字段（如 update 只许改状态类字段）。

## 困境三｜Evals 高分、生产体验差

**案例**：评测 95 分；retrieval 92%、reranker 最好、prompt 改二十版；抽 20 条反馈，真正的检索/生成质量问题只有 3 条，其余是权限、跨系统聚合、同步延迟 14 小时。

**它的做法**：**今天的这次对话本身就是这个困境的样本。**

- 评测面：保证矩阵 53 条承诺、判据 1100 条全绿——**分数满分**。
- 生产面：我给它的三个真实任务，装配把 A（空结果审计）和 C（断层归因）都判成"可交付"，**两次都是人发现的**（假阳性来源：二字片段凑分数）。
- 反应：它自己的「局限」里写着"提到过这个词 ≠ 就是这块砖，分低的当缺"——它**知道**自己会说谎，只是没说全。
- 修完（v0.2.18：三字门槛 + 停用字 + 规范句主句）后 A/C 才降级为"交人判"。

它还有两条**归因用的规程**（今天教的）：<br>
《评测维度对照》conc/478——权限（评测用万能账号 vs 真实 403）、数据新鲜度（刚刷新 vs 昨天那份）、跨系统聚合（单系统 vs 拼两个库）、延迟（只记对错不记秒数）；<br>
《断层归因》conc/479——归因落工程层，**不许给"模型需要微调"这类结论**。

**判定：部分覆盖。**
**缺口**：它没有生产观测回路（不看真实反馈、不做抽取统计）。它能出归因清单，但"抽 20 条里 3 条是模型、17 条是工程"这个结论得**人喂给它的案例**才能算。

## 困境四｜延迟与质量二选一

**案例**：开 thinking 首字 3–5 秒，90% 用户以为卡死；关 thinking TTFT 800ms，质量暴跌。

**它的做法**：它没有 thinking，但它有**按问题类型分流**——四句不同的话，四条不同的路（实测）：

| 说一句 | 路由 |
|---|---|
| 声速乘三等于几？ | **算术（*）** —— 确定性计算，毫秒级 |
| 谢谢你 | **社交问法** —— 查场面规程，零推理 |
| 挑是什么意思？ | **查字典** —— 直接查条目 |
| 用月亮造个句子。 | **造句** —— 模板 + 词卡 |

有确定性工具的（算、查、引）**天然走快路径**；需要多步的才走 `差距 / 建议 / 装配 / 过程` 这些清单通道。

**判定：部分覆盖。**
**缺口**：它没有"快/慢分级"的显式声明，也没有"处理中"的反馈（那是产品层）；它只提供了"分流"这件事本身的机制。

## 困境五｜长任务失忆，上下文越多越糟

**案例**：跑几十步后，失败诊断、未完成子目标、三小时前的约束被冲走；78% 多步任务失败率 >40%；塞 50 轮导致 token×3、延迟 2s→15s。

**它的做法**：**不靠窗口，靠账 + 按需检索 + 主动遗忘**。

| 机制 | 现状（本机实测） |
|---|---|
| 对话账本 `dialog.jsonl` | **507 轮**，每轮记 说了/听到/指向/凭什么/答了 |
| 答题账本 `answers.jsonl` | **255 条**（derive/solve/moral 逐条留底，含上次作答对账） |
| 决策账 `decision_ledger.jsonl` | **104 条**（每条判据一次"在候选里挑了谁"） |
| 装配账 `assemble_ledger.jsonl` | **6 条**（过程由补齐史推出来，不排顺序） |
| 使用侧车 `usage/*.md` | **6932 份**（权重按半衰期衰减） |
| 半衰期 | `HALF_LIFE_DAYS` 可被语料 `usage/config.json` 覆盖；**置 0 = 关闭衰减，行为与加衰减前逐字相同**（判据 `[遗忘] ④` 的反向对照） |

它的立场是「**上下文在账里，不在猜里**」：要哪段就按需检索，而不是把 50 轮全塞进去。

**判定：部分覆盖。**
**缺口**：账是"历史"，不是"**工作记忆**"。它没有当前任务的状态机（未完成子目标、待确认约束）——`差距/建议/装配/过程` 出的都是**清单**，谁在做第几步、下一步等谁，它不记。它也不自己决定"什么该留、什么该淡"——`context_keys` 由调用方传，不传它就不看。

## 一句话总评

五个困境里，LDV 的位置很一致：**它管"判定与留痕"，不管"语言与调度"。**

- 困境一它接得住（空有结构、拒绝有标签）；
- 困境二它接住一半（不重试、有码、有账；重试策略与 schema 校验归调用方）；
- 困境三它今天是**病人也是医生**——自己出过假阳性，也存着归因规程；
- 困境四、五它只提供了**机制**（分流、账本、衰减），产品形态与工作记忆那两层得在外面做。

**它最像样的地方不是答得对，是"答不了的时候留下一条能查的痕迹"**——五个困境里有三个（静默失败、鬼打墙、失忆）本质上都是"痕迹丢了"，而它刚好只会做痕迹。
