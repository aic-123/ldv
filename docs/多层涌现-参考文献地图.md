## 一、四个缺口 × 对应文献（全部已核）

### 缺口 1 · 层 = 方向，越深越清晰 → **HNSW**

Malkov & Yashunin, *Efficient and robust approximate nearest neighbor search using
Hierarchical Navigable Small World graphs*, arXiv:1603.09320（IEEE TKDE）

> Hierarchical NSW incrementally builds a multi-layer structure consisting from hierarchical
> set of proximity graphs (layers) for **nested subsets** of the stored elements. The maximum
> layer in which an element is present is selected randomly with an **exponentially decaying
> probability distribution**. This allows producing graphs … while additionally having the
> **links separated by their characteristic distance scales**. Starting search from the
> **upper layer** together with utilizing the scale separation … allows a **logarithmic
> complexity scaling**.

> can be seen as an **extension of the probabilistic skip list structure [27]** with proximity
> graphs instead of the linked lists.

**判定：这就是「最近的一层只保留方向信息、越深越清晰」的现成实现，而且是 O(log n) 的。**
一处关键差别：HNSW 的层高是**随机分配**的，不是按使用分配的 —— 这正是缺口 2 要改的地方。

### 缺口 2 · 规则按使用自我优化 → **工作负载驱动的物化视图选择**

Anderson / Panduman / Sasaki / Onizuka, *Workload acceleration by optimizing materialized
view selection using local search*, CIKM '25, arXiv:2606.03772

> Materializing the results of **frequent sub-queries in workloads** … However, when updates are
> made to the underlying tables, the corresponding materialized views must be maintained, which
> can be time-consuming. Therefore, there is a **trade-off between the benefit of using
> materialized views and the overhead of view maintenance**.

> we incorporate **incremental view maintenance cost directly into the optimization objective**
> of an integer linear program and apply **local search** … We treat two sub-queries as
> **neighbors if one contains the other**.

> ILP is known to be **NP-hard**

**判定：这是「规则按使用自我优化」的现成形式化，目标函数就是你要的那个权衡。**

**★ 关键对应**：MV 的「维护开销」 = 你这边的「下层插入导致上层视图失效」的代价。
**两者是同一个量。** 不需要新造。

### 缺口 3 · 索引本身可以是学出来的方向函数 → **学习型索引**

Kraska 等, *The Case for Learned Index Structures*, SIGMOD 2018

> all of those indexes remain general purpose data structures; they assume nothing about the
> **data distribution** and do not take advantage of more common patterns prevalent in real
> world data … **knowing the exact data distribution enables highly optimizing almost any index
> structure**.

> **a B-Tree can be considered as a model which takes a key as an input and predicts the position
> of a data record in a sorted set**

> the assumption that we can **observe the distribution of queries**, e.g., from historical logs,
> holds in many applications, especially within databases

> we assume that future queries come from the **same distribution as historical queries**. When
> this assumption does not hold, one could use … **importance weighting to directly address
> covariate shift**

**判定：「方向 = 学出来的模型」有直接先例。最后那句把缺口 4 焊了进来。**

### 缺口 4 · 反馈不能直接用 → **无偏排序学习 / 反馈环退化**

Joachims / Swaminathan / Schnabel, *Unbiased Learning-to-Rank with Biased Feedback*,
arXiv:1608.04468

> Implicit feedback … its **inherent biases are a key obstacle** to its effective use.

> the na¨ıve approach of treating a click/no-click as a positive/negative relevance judgment is
> **severely biased** … This presentation bias leads to an **incomplete and skewed sample**

> we present a **counterfactual inference framework** … we derive a **Propensity-Weighted
> Ranking SVM**

Jiang / Chiappa / Lattimore / György / Kohli, *Degenerate Feedback Loops in Recommender
Systems*, arXiv:1902.10730（AAAI 2019）

> a **self-reinforcing pattern of narrowing exposure**

> we identify **sets of sufficient conditions that make them degenerate over time**

> **systems with some level of random exploration can be degenerative**

**判定：这条最要紧，见 §三。**

## 二、三处交汇 —— 这才是本轮最有价值的部分

### 交汇 1 · 两个领域独立给出同一个修法

| 领域 | 正文 |
|---|---|
| 数据库 / 索引（Kraska） | 「future queries … same distribution … when this assumption does not hold ⇒ **importance weighting**」 |
| 信息检索 / 排序（Joachims） | 只看到自己展示过的反馈 ⇒ **propensity weighting** |

**同一个修法，两个领域独立收敛到它。**
⇒ 倾向权重**不是可选项，是必要构件**。

### 交汇 2 · 「更清晰的方向」= **包含关系**

| 领域 | 正文 |
|---|---|
| HNSW | 层是 **nested subsets** |
| MV selection | 「neighbors if **one contains the other**」 |

**两个领域用同一个关系描述「更细的方向」。**
⇒ 「视图的视图」的形式化就是**包含**：更细的方向包含于更粗的方向。

### 交汇 3 · 维护成本是共同的核心量

| 出处 | 同一个量 |
|---|---|
| MV selection | 目标函数里显式含**增量维护成本** |
| counting / DRed（上一轮已核） | 增量维护的**算法本身** |
| 本设计 | 下层插入 ⇒ 上层见证失效的**代价** |

**三处指的是同一个量。** ⇒ 只需要**把它测出来**，不需要发明它。

## 三、★ 探索不是解药

本来打算写「必须有探索，否则塌缩」。degenloop 直接否掉了：

> systems with **some level of random exploration can be degenerative**

⇒ 「加一点随机」**不构成修复**。该照它的**充分条件**来（论文给的是用户兴趣动态系统的退化条件），
工程侧的对应修法是交汇 1 里那个**倾向权重**。

**这条直接改掉一条设计决策：不要用「随机探索」当防塌缩机制。**

## 四、对上一轮结论的更正

| 上一轮 | 更正 |
|---|---|
| 「#3 无匹配/相似度是**死穴**，视图生成视图默认会死」 | **在检索框架下解禁** —— HNSW 的邻居就是按距离选的，学习型索引就是学分布。**因为方向不是断言**，相似度可用 |
| 「必须有确认者（人），否则不能涌现」 | **使用本身即确认** —— 死路的代价是一次 miss，不是一条假断言 |
| 「涌现必须是定理」 | 换成 **「判断必须可测、可撤、带倾向权重」** |

**纪律换了，但没有丢** —— 从「不许判断」换成「判断必须可测可撤」，是同一个位置上的约束。

## 六、对设计的三条硬要求（文献直接推出）

1. **层的形状**：嵌套子集 + 尺度分离（HNSW）。层数不要拍脑袋 ——
   用指数衰减分布，或按使用频率分配。
2. **层的目标函数**：收益（用得多）− 维护开销（下层插入导致失效）。
   用 MV selection 那一套，不要自己发明。
   **注意它是 NP-hard ⇒ 必然走近似 + 局部搜索，不可能有精确解。**
3. **反馈必须带倾向权重**，否则自我优化会朝「只展示自己已经相信的方向」塌缩。
   两个领域独立给出同一修法 ⇒ 这条没有余地。

## 七、结论

上一轮的结论是「多层派生 + 见证**没有对口前作**」。**在检索框架下这句话不成立。**

有三个成熟领域直接覆盖：

    分层导航（HNSW）        → 给「层 = 方向」的形状
    工作负载驱动的视图选择   → 给「按使用优化」的目标函数
    无偏反馈（unbiased LTR） → 给「反馈怎么用」的纪律

**要的东西不是没人做过，是分散在三个领域里，没人拼在一起。**
而拼法很自然 —— 每个缺口都有现成件，且它们的交汇处（倾向权重、包含关系、维护成本）
互相咬合，不是硬凑。
