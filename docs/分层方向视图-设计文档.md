## §0 这份文档的边界

**是**：接口定义、内核不变量、可执行检查、验收方式。
**不是**：实现。本轮不写代码、不选具体方向函数、不选具体权衡。

文档里每条约束都写了「**为什么它存在**」——
理由是约束的一部分（去掉理由，下一个人就会把它当成可以商量的偏好）。
但**规范条款（§1–§9）里没有**任何「上一版怎么写、后来怎么改」的内容。

⚠️ **例外是刻意的**：**§10 之后的收尾章**（留白表 / 里程碑 / 裁定与落地 / 引用 / 收尾），
与 `ldv/C*.md` 的里程碑报告。
那些地方的内容**就是**「哪一条已落地、哪一条还没、为什么」，属于状态与审计 ——
把过程删掉，它们就没有内容了。**§1–§9 的规范条款里不许有；状态章里必须有。**

## §1 一句话

**把「检索的方向」做成可插拔的层结构：内核只保证形状，不替你选方向。**

层 = 方向；越深越清晰。方向由使用者声明，方向内部的权衡由使用反馈优化。

**「越深越清晰」分四层，只有两层是硬要求**（实测三个方向后定稿；第四行 2026-10-07 降级）：

| 层 | 要求 | 谁在守 · 守到哪一步 |
|---|---|---|
| **成员层** | `members(子) ⊆ members(父)` | **硬要求** —— 这才是「分辨率」。由**内核的构造**保证，`B4` 复查划分（**不重，且漏的恰好是账上那些**） |
| **过滤器层** | `覆盖(子) ⊆ 覆盖(父)` | **不是**硬要求 —— 只有**度量** `cover_nesting_profile`；实测越界 0 次（无害，只赔假阳） |
| **健全性** | `members(d) ⊆ 覆盖(d)` | **硬要求** —— 这才是 §K8 那一半。判据 `B16` **两条路径各判一次**（批建 / 维护）+ 度量（同一个读数） |
| **覆盖不漏** | `覆盖(父) ⊆ ∪覆盖(子)` | ⬜ **不是硬要求**（2026-10-07 降级）—— 它与「`滞留 == 0`」**是同一个条件**（实测 16 == 16，双向差 0），而后者已被出路 (4) 用「代价在**划分**」换掉了。判据是 `B18` **baseline 守卫**（冻结既有、对新增红）+ 两条路径的度量。**见 §10.2 B 末的裁定** |

⚠️ **四行现在处于四种不同的守备状态 —— 这是有意的，不必强行拉齐。**
（rustc 的 `rust-2024-compatibility` 过渡 lint 组同样允许组内严重度不一致：
`warn-by-default` / `deny-by-default` / `allowed-by-default` 混装。）
要的是**每一行的状态都被写明**：

    第一行  内核构造守（结构上成立，`B4` 复查**收窄的**划分）
    第二行  明说**不是**硬要求，只有度量
    第三行  判据**两条路径各一次**（两条路径的基线都绿 ⇒ 两条各自注入验证）
    第四行  与第二行**同类**：明说**不是**硬要求，判据是 baseline 守卫 + 度量
            —— 维护路径上**仍然破着**（sequence 16 漏 / 2 对）。
               ⚠️ 它**不是**「健全性的修法管不到的另一条机制」——
               实测**漏项与滞留项是同一批**（16 == 16）；两条路的差别只在**处置**。
               ⇒ 裁定：**不加兜底**，第四行降级。见 §10.2 B 末。

⚠️ **「判据只跑一条路」这件事必须写在输出里** —— 否则它长得跟「两条路都过」
**一模一样**。这正是本设计反复要防的那个形状在**检查设计**上的形态。
（`B18` 现在仍是这种形态：它是 baseline 守卫，维护路径上的既存违规**被冻结**而不是被修掉。
所以它的读数必须把「冻结了几条」与「新增了几条」分开印。）

理由：方向 payload 只是一个**过滤器**（成员集合的过近似）。过滤器只要**健全**
（覆盖得住自己的成员），`命中` 说「否」的证明就是有效的 ⇒ 剪枝安全。
层层嵌套不是必须的，**健全才是必须的**。详见 `ldv/C5b-第三方向复核.md` §2.2 / §3.3。

**第四行不是风格偏好，原本是前两行的必要条件**（`C10` §4）——
⚠️ 但这条推导 **2026-10-07 被出路 (4) 切断了**（(4) 正是「不让项落进它不满足的方向」），
剩下能守的只有**精度**；所以第四行降级，与第二行同类。详见 §10.2 B 末：

    一个项**什么时候**落进 d，不由 d 决定 —— 由**下降**决定
    （`§I3 代价` 取最小；取不到 0 也照落，落点就是那个代价最小的子方向）
    ⇒ 只要 `覆盖(父) ⊄ ∪覆盖(子)`，就**一定**有项落进「它不满足」的方向
    ⇒ `members(d) ⊄ 覆盖(d)` ⇒ `命中` 的「否」就**证不住** ⇒ 假阴（§K8 禁）

⇒ 它同时给出一条**对插件的约束**：子方向的 payload 只能从**父方向的 payload** 派生，
**不许**掺「当前成员」算出来的东西（A 的 `common`、C 的 `p*`）。那些都是
**对未来的声称**，而劈开兑现不了 —— 实测（`C10` §4.2）：一次建完 0 个越界，
维护路径 123 / 313 / 68 个越界，并各自产生真假阴。

⚠️ **硬要求表现在的实测状态**（别混；2026-10-07 更新）：

**第四行（⬜ 已降级）**在 **C（`sequence`）** 上不成立：维护路径 **16 漏 / 2 对**
（D0 与 D1 各漏 8 项）。⚠️ 这 16 个漏项与「**滞留**」的那 16 个**是同一批项**
（`outputs/_probe_leak_vs_stay.py`，双向差 0）⇒ 它**不是**「健全性的修法管不到的
另一条机制」，而是出路 (4) 的**同一件事的另一种说法**。见 §10.2 B 末的裁定。

**B（`reach`）的覆盖一次都没漏**（0 / 35 对）—— 它的越界来自「根的外生 payload
盖不住后来添的项」，那才**真是另一条**机制（**范围**，不是划分；见 §10.2）。
**照第四行去修 `reach` 会修错地方。**

**第三行（健全性）**在 **B 与 C** 上都不成立：`reach` 维护路径 **128 / 328**、
`sequence` **36 / 176**。⚠️ `reach` 这个数**换过尺子**：旧判据按 `§I3 代价 = 0` 判，
量出 246 / 328 —— 多出来的 118 是**尺子自己造的**（`代价 = 0` 只对锚点成立，
而覆盖是「能走到锚点的所有项」）。见 §7.4。

## §2 定位

### 2.1 它是什么类别的东西

**检索系统**，不是派生系统。这个区分决定了后面全部纪律：

| | 派生系统 | **本设计（检索系统）** |
|---|---|---|
| 层的产物 | 新**断言** | 新**方向**（路由提示） |
| 错了会怎样 | 假断言**永久留存** | 死路 —— 没人走，代价是一次 miss |
| 谁确认 | 必须有人 | **使用本身即确认** |
| 允许相似度 | ❌ 禁 | ✅ 允许（方向不是关于世界的声称） |

**⇒ 不需要人在环里。** 这是选择检索框架的主要原因。

### 2.2 与既有两条线的关系

- **继承 dce 的纪律**：三态检查、度量走 `report()` 不进退出码、跳过不等于通过、
  「已核 / 未核」分开标。
- **借 arena 的一条**：「**0 和『没有』分不开，就不许印成 0**」——
  在本设计里变成 §K6（「未展开」不许折叠成「否」）。

### 2.3 不做真值判断

系统**不判断任何东西的真假**，只判断**方向导得好不好**。
而「导得好不好」是**测出来的**，不是**断言的**。

## §3 名词

| 词 | 定义 |
|---|---|
| **节点** | 被检索的对象。身份 = 字面 id，不做语义对齐 |
| **方向** | 一个层上的一个可路由单元。不是一个集合，是一个**带谓词的入口** |
| **层** | 方向的分级。秩 = 1 + max(父方向秩) |
| **细化 ⊑** | 细方向 ⊑ 粗方向。由 §I2 的「合并」定义，**不是**由相似度定义 |
| **见证** | 强制出某个方向的最小下层配置（一组下层方向） |
| **支撑锥** | `Cone(x)` = **插入 x 时走过的那条路径**。等价于「见证含 x 的方向」：`x` 只被放进一个叶，它的祖先链就是全部见证含 x 的方向 |
| **展开** | 按需计算一个方向的下一层。**不是**预先物化 |
| **使用记录** | 一次交互构成的使用信号 + 其**倾向权重** |

## §4 内核 / 插件分界

借 **GiST**（Hellerstein/Naughton/Pfeffer, VLDB 1995）的模式：
把「什么算近、什么算包含」暴露成用户实现的方法，树本身留在内核。

> by **exposing the key methods and the tree's split method to the user,
> arbitrary search trees may be constructed**

### 4.1 内核（固定，通用）

层的存在与秩 · 细化关系的形式 · 见证与支撑锥 · 按需展开 ·
失效只分叉不覆盖 · 倾向权重的记账位 · 遍历循环 · 三态语义 ·
以及 §K8 那条契约（假阴禁止 / 假阳计量）

**「内核固定 / 插件按方向换」有执行方式上的前例。** SP-GiST 最初把
`Cluster`（节点 → 磁盘页的映射）**放在插件接口里**，实现里把它**移进了内核**，
理由写得直接（官方文档 65.3.3）：

> 「The SP-GiST core is responsible for efficient **disk mapping** and searching
> the tree structure. It also takes care of **concurrency and logging** considerations.」

⇒ 判据是「**是不是每个方向都一样的事**」：磁盘映射 / 并发 / 日志，对每个 opclass
都一模一样 ⇒ 归内核；「什么算一个方向」随方向变 ⇒ 归插件。
本 §4.1 的内核清单就是按这条判据切的。

### 4.2 插件（按方向换）

什么算一个方向 · 两个方向怎么合 · 一个东西该进哪个方向 ·
方向太满怎么劈 · 方向怎么存 · 什么算一次「使用」

### 4.3 关键决定：**没有全局目标函数**

权衡**不**是一个全局参数，它下放给 §I3（代价）和 §I4（劈开）两个局部方法。

理由：一旦定下全局量，就变成「按哪个方向都会不满意」。
内核只定义**权衡被调用的位置**，不定义权衡本身。

## §5 接口（§I1–§I7）

GiST 是**六方法**。本设计是**七个** —— 多出的 §I6 是因为 GiST 没有反馈环，本设计有。

### §I1 `命中(方向, 查询) → 是 | 否 | 未展开` ← GiST `Consistent`

判断该方向下是否存在可能命中的项。

- **必须**：不许**假阴**（说「否」而实际有命中）
- **允许**：假阳（说「是」而实际没有）—— 代价是性能，不是正确性
- **三态**：「未展开」是**独立的第三值**，不许折叠为「否」

原文对这条契约的表述：

> an **accurate test for satisfiability is not required** here: Consistent **may return true
> incorrectly without affecting the correctness of the tree algorithms**. The penalty for such
> errors is in **performance**

**这是整个模块化方案安全的原因**：方向函数在结构上只是一个**过滤器**，
过滤器的错只损失性能。**所以插件可以是不准的。**

### §I2 `合并(一组方向) → 更粗的方向` ← GiST `Union`

- **必须**：结果**覆盖**所有输入（不许丢）—— 这是**行为上的覆盖**：
  细方向说「是」的查询，粗方向**不许说「否」**
- **「更粗」的形式化就是它**，但**不要**读成 `合并({细}) = 粗`

**⚠️ 一个「看起来像」但错的定义**（实测三个方向后排除，见 `C5b` §2.2）：

    错写法：`细 ⊑ 粗`  ⟺  `合并({细}) = 粗`          ← **错**
    为什么错：**合并(单元素) 是恒等** —— 合并一个方向只能得到它自己。
              于是那个等式对任何严格细化都要求 `细 = 粗`，自相矛盾。
    实测：A 39/39、B 71/71、C 37/37 个方向都满足 `合并(单元素) = 自身`，
          所以这条**三个方向一致地不成立** —— 与方向无关，是文本问题。

**正确读法**：`⊑` 是**覆盖关系**（`覆盖(细) ⊆ 覆盖(粗)`），
而「更粗」的**可操作判据**是 §I2 那条「必须覆盖」——它才是能查的那一半。

### §I3 `代价(方向, 待放入项) → 可比较的数` ← GiST `Penalty`

- **必须**：在同一层内两两可比
- **这里承载局部权衡**。收益与开销的折算方式由插件决定，内核不参与

### §I4 `劈开(父方向, 一组项) → None | 一组方向（≥2 个）` ← GiST `PickSplit`

- **入参是「父方向 + 一组项」**：
  - 「一组项」而不是「一组方向」—— 因为展开是**按需**的（§3），
    首次展开时子方向**还不存在**，内核手上只有项
  - **父方向**递进来，是为了让子方向成为父的**可证细化**（§1 表第四行；
    ⚠️ 该行 2026-10-07 已降级 —— 递父方向仍然有用，只是不再挂「硬要求」的名），
    而不是让插件从项里**重新猜**父的意图。不要求用，但不给就猜不准（见下）
- **返回 `None` = 插件声明「这一层分不开」**；否则必须给 **≥2** 个候选方向
  - ⚠️ **不要求恰好两个**：有序方向（trie 形状）自然就是 k 叉
  - ⚠️ **少给（< 2）是违约**（`PluginContractError`）—— 内核不替插件猜，
    也不静默当成分不开
- **必须**：结果构成**划分**（不重不漏）——
  ⚠️ **「不漏」在 §10.2 出路 (4) 之后是收窄的**：
  `∪members(子) ⊆ members(父)`，且 `members(父) − ∪members(子)` **恰好是账上那些滞留项**
  （`stayed` 事件）。「不重不漏」变成「**不重，且漏的恰好是账上那些**」——
  那是**收窄判据**，不是放宽（`B4` 查的就是这条）
- **但划分由内核保证，不由插件保证**：
  `§I1 命中` 允许假阳，所以 `命中(d, x) = 是` **不能**证明 `x ∈ d` ——
  拿它当归属谓词，**重叠永远看不出来**。
  ⇒ 归属由内核按 §I3 分配得到，插件只负责**提出候选方向**。
  **否则这条「必须」是空转的：立得住，但查不动**（`B4` 查的就是内核的分配）
- ⬜ **原为「必须」，2026-10-07 降级为「有代价的期望」**：`覆盖(父) ⊆ ∪覆盖(子)`
  （§1 表第四行）—— 见本节末与 §10.2 B 末。
  ⚠️ 它与「`滞留 == 0`」是**同一个条件**（实测 16 == 16，双向差 0）：
  做不到时的代价是**划分**（项停在父上、检索得到，只是这一层没细分），不是**范围**

**为什么「分不开」必须是插件说出来的**（而不是让内核从内容里猜）：

如果编码成「返回两个**相同**的 payload」、由内核从「分配后一侧为空」**反推**
「插件分不开」，那么两种东西长得一样：

    插件**判**分不开        接口的正常用法 —— 插件的判断
    插件给的候选**切不动**   候选退化 —— 插件与内核之间的摩擦

⇒ 现在分开记（账本 `unsplittable` 的 `by` 字段 = `"plugin"` / `"kernel"`），
`stats()` 分两个数报。**分开记才有信息量**：一个永远返回空组的插件，
与一个诚实声明「分不开」的插件，在「从内容反推」的读法下产出**完全相同**的账本 ——
那就是「空转与通过长得一模一样」在接口层的形态。
实测（36 项语料，一次建完）：三个方向 `判空·切不动` **一律 0** ——
即插件确实在用自己的判断说话，内核没有替它兜底。

前例：SP-GiST 的 `PickSplit` **直接返回一个布尔**
（「indicating whether further partitioning should take place or not」）。
出处：`ldv/C8-成熟方案对照.md` N5；逐字引文见 `分层方向视图-成熟方案与跨领域文献.md` §2.2。

**⚠️ 「两个」是 B-tree 的遗产 —— 实测必须放开成 k 叉**：

| | 最自然的切分 | 强制二分 | k 叉 |
|---|---|---|---|
| B 锚点可达 | 二分就够 | 71 方向 / 7 层 | 71 / 7（**不动**） |
| A 键集包含 | 二分就够 | 25 / 7 | 25 / 7（**不动**） |
| **C 序列前缀** | **trie：按「下一个符号」分出 k 个** | **21 / 7**，判空 8 | **16 / 5**，判空 8 |

⇒ C 省下 **5 个方向、2 层**，而**叶容量（10）与假阳率（0.0%）一个数没动**。
A / B 是**反向判据**：它们的 payload 语义里没有比「一个键有 / 没有」
「按图上位置取中点」更细的 k 分解 ⇒ k 叉**不该动它们**，实测也确实没动。

**⚠️ 带上父方向的实测效果**（`C10` §3）：

    覆盖嵌套 `覆盖(子) ⊆ 覆盖(父)`     越界 14 次 → 0 次
    假阳率（A）                        56.7% → 49.4%（判「是」的绝对条数 926 → 793）
                                       ⚠️ 再修 `req`（§7.4）之后是 **50.1% / 803 次** —— 那是**另一个变量**
    ★ 顺带挖出的缺陷                   见 §10.2

⇒ 「能让 A 的过滤器真正嵌套、假阳率大概率下降」这条预测**成立**。
⚠️ 成熟系统里**没找到需要父方向的前例**（ART / SP-GiST 的 opclass 都看得到前缀），
所以这一步的依据是**本设计的实测**，不是前例。

**⚠️ 带上父方向也定下了一条对插件的硬约束**（`C10` §4.3）：

    子方向的 payload **只能从父方向的 payload 派生**
    **不许**掺「当前成员」算出来的东西

三个方向各踩过一次，形态不同但是同一句话：

| 方向 | 用了什么「当前成员」算出来的东西 | 形态 |
|---|---|---|
| A | `common`（当前成员的键集之交） | 子方向的 `req` 比父还高 |
| B | 「只按成员分」（payload = 成员自己） | 子方向盖不住**父的 payload** |
| C | `p*` = 当前成员的最长公共前缀（压缩 trie） | 子方向跳过了「父前缀到 `p*`」之间那段 |

理由见 §1 第四行（⚠️ 那条「它是健全性的必要条件」的推导 2026-10-07 被出路 (4) 切断，
见 §10.2 B 末）。但这条**插件约束本身仍然成立**：实测三个方向各踩一次，
每一次都同时造出**覆盖越界**（第二行）与**假阴**。实测的修法（A，一行）：
`req` 只从父续，`common` 仍用来**挑判别键**但不进 payload。

### §I5 `编码 / 解码(方向)` ← GiST `Compress` / `Decompress`

- **必须**：解码结果**覆盖**编码前（可以更粗，不可以更细）

### §I6 `信号(方向, 交互) → 使用记录 | 无` ← **本设计新增**

判定一次交互是否构成「使用」。

- **必须**：允许返回「**无**」—— 「没有观测到使用」**≠**「使用了但为负」
- 返回的记录**不含**倾向权重 —— 倾向由内核填（内核知道展示了什么）

### §I7 `记录(方向) → 可序列化` ← 内核要求的最小载体

不是新语义，是**接口的形状要求**：方向必须可序列化，否则无法留痕、无法分叉。

### §I 之外的一条：**插件允许自带缓存**（不是违约）

七个方法只规定了**输入与输出**，没有规定**算几遍**。所以插件**可以**在实例里
留一份记忆 —— 这不是钻空子，是接口的必然结果：`§I1` 的签名**没有世界参数**
（见 `plugins/reach.py` 开头），插件必须自带世界；**既然自带世界，它就也可以自带记忆**。

但缓存是**假绿**最容易进来的地方 —— 过期值**不报错**，判据照旧说「是」，
只是它比的是**上一版的答案**。所以「允许」要配两条**必须**：

| 必须 | 内容 | 落地 |
|---|---|---|
| **① 前提被检查** | 「值算没算都一样」+ **数据持久**（世界在构造之后只读） | `test_reach_cache_premise`：AST 扫写入点 + 行为侧比图指纹 + **已知答案的对照组** |
| **② 透明性被检查** | 缓存开 / 关 ⇒ **逐项相同** | `test_reach_cache_transparency`：三臂对照（参考实现 / 无缓存 / 有缓存）+ 注入 |

依据（逐字，Acar / Blelloch / Harper 2002, POPL, §2）：

> **The key requirement, therefore, is not that there are no side-effects, but
> rather that all data is persistent**

—— 即**闭包的环境不可被改**。这正是「图在构造之后只读」那条前提。

⚠️ **缓存的键与值的粒度是同一件事的两面。** 只换键不换值，缓存仍然无用：
键是 `payload` 时，值若是标量，就会被同一 payload 的后一项覆盖。
落地实例与实测读数见 `plugins/reach.py` 与 `MEASUREMENTS` 结果八。

## §6 内核不变量（§K1–§K9）

| # | 不变量 | 挡什么 | 出处 |
|---|---|---|---|
| **K1** | **严格派生**：层 n+1 的见证 ⊆ 层 ≤n | 循环 | HNSW 的嵌套子集 |
| **K2** | **非平凡**：展开必须产出下层表达不出的东西，否则**不建这一层** | **无信息的层** | arena 四条准入条件的机械化 |

> ⚠️ **§K2 的一个时间维度：判「分不开」只能对那一次的成员集成立。**
>
> 「展开必须产出下层表达不出的东西」是关于**一组项**的判断。
> 但维护会往一个方向里加项（§M2），**同一组项**在加完之后可能就分得开了。
> 若把「分不开」写成**永久标记**，一个方向一旦被判成叶就永远是叶 ——
> 树只在第一批项上长过层，`§M2` 情形④（涌现）**一步都走不到**。
>
> ⇒ 「分不开」必须带**它是对哪一组项判的**：成员集没变就不重试，
> 变了就重试。这**不是**把 §K2 放松，是把它读到它本来就该有的精度。
> 出处：`ldv/C7-流程跑通.md` §3.1。

> ★ **§K2 的字面是「不建这一层」—— 实现就真的不建。**
>
> 「不建」的字面含义是：被判「分不开」的那一层**不存在**。
> ⇒ 判空时**只追加一条判定事件**（挂在**父方向**上：判定的主体是它，
> 而且**没有子方向可以挂**），一个方向都不建。
>
> ⚠️ **代价不会消失，只会换地方**：这一层不建 ⇒ 那些项只能留在这个叶里
> ⇒ **叶容量变大、分辨率下降**（查询要多扫几项）。
> 所以 §7.1 的度量必须**成对报**：
> **`§K2 判空`（形状信号）+ 叶容量（代价信号）**，它们是同一件事的两种记账。
>
> 可验的后果（`run_tests.test_emergence` ② 里查了）：**每个方向的成员集都非空**，
> 且 `方向 = 有子层 + 叶`。若判空改为「建出来再作废」，这两条**都会红**。
>
> ★ **「不建这一层」有直接前例，而且它在成熟框架里是一个参数。**
> SP-GiST（Aref & Ilyas 2001）把「展开到多深」做成参数 `PathShrink`，三档：
>
>     Never Shrink    展开到最大分辨率（可能长出长而稀疏的结构）
>     Leaf Shrink     **「no index node will have one leaf node」** ← **逐字就是本 §K2**
>     Tree Shrink     **「eliminate all single child internal nodes」**（Patricia 式合并）
>
> 而「**空分区要不要保留**」是另一个参数 `NodeShrink`，原文并明确提醒：
> **它「has no effect on the path length of the tree」** ——
> 即它**只动表示（forest / 变长节点），不动结构**。
> 这与 B-4 的「**数变了但结构不该变**」是**同一个区分**，只是他们把它写成了参数文档里的一句提醒。
>
> ⇒ 所以本 §K2 是**三档里的中间那档**，而且「代价落到叶容量」不是唯一的解：
> `Tree Shrink` 把区分信息**并进父节点**（ART 的 `Path Compression`，代价是「partial key 不能就这么丢掉」，
> 所以它要**存下来**）。要不要走这一档是 §10 的留白。
>
> 出处：`ldv/C7-流程跑通.md` §3.1、§6 ①；`ldv/C8-成熟方案对照.md` N1；
> 逐字引文与页见 `分层方向视图-成熟方案与跨领域文献.md` §2.1。

> ⚠️ **上面那段说的「三档」只覆盖了 §K2 的**第一半**。**
>
> §K2 的字面是「展开必须产出**下层表达不出的东西**，否则不建这一层」。
> `PathShrink` 那三档管的是「**分区要不要保留**」—— 也就是**第一半**（两侧非空）。
> **第二半**（「真的表达出下层表达不出的东西」）**内核判不了**：那是语义问题，
> 而内核没有语义（§4.1）。⇒ 由**外生**检查 `B17` 守，见 §7.2。
> **实测那个缺口是真的**：`reach` 在**合环图**上会把互相可达的两项劈成两个
> **覆盖完全相同**的子方向 —— 一层什么都没表达的层，内核的判空没拦住。

| **K3** | **有见证 ⇒ 局部失效**：插入 x 的失效范围 ⊆ `Cone(x)` | 改一点全量重算 | counting 算法的非递归域 |
| **K4** | **只分叉不覆盖**：方向失效只追加状态，不改历史 | 「失效」与「从未存在」分不开 | arena §C10 + 「0 和没有」 |
| **K5** | **良基秩 + 树性**：`rank = 1 + rank(父)`（**单父**），无环 | 无限嵌套 | 良基序 |
| **K6** | **三态**：「未展开」独立于「否」 | 把「没搜」印成「没有」 | arena「0 和没有分不开就不许印成 0」 |
| **K7** | **倾向权重**：进入自我优化的记录必须带倾向权重 | 只优化自己展示过的方向 | 见 §8 |
| **K8** | **假阴禁止 / 假阳计量** | 插件不准导致漏结果 | GiST 的 `Consistent` 契约 |
| **K9** | **内生 / 外生分界**：外生项不许被 usage 驱动 | 无限递归 | 见 §8.2 |

> ★ **§K5 的「树性」是 `§10.2 D`（持久化）的前提，原来没被写进去、也没被检查。**
>
> 原来的措辞是 `rank = 1 + max(rank(父))` —— 那个 `max` 是**为 DAG 写的**
> （一个方向多个父）。而持久化的路线**押在入度上**：
>
>     树（每方向一个父）  ⇒ node-copying ⇒ 访问旧版本 **O(1)**
>     DAG（一个方向多父） ⇒ 只能 fat node ⇒ 访问旧版本 **O(log m)**
>
> 而 `B13` 原来只查「无环 / 无自环 / 见证更粗」⇒ **对 DAG 照样放行**。
> 实测（`outputs/_probe_b13_gap.py`）：把一个子方向再挂到第二个父下面
> （语义入度 1 → 2），`B13` 仍报「是」。⇒ **前提成立与否，判据上长得一模一样。**
>
> ⇒ 本版把「树性」**写进 §K5 并并进 `B13`**（四条：无自环 / 见证更粗 / 父链终止 /
> **恰好一个父**），并把**多父（DAG）**标成一个**具名留白**：谁要启用它，
> **先接受 `§10.2 D` 从 node-copying 掉到 fat node**（见 §10.2 D）。
>
> ⚠️ **「入度」在实现里有两条边，必须说清查的是哪条**：
> `_children` 是**父 → 子**（语义边），`Direction.parent` / `witness` 是**子 → 父**（反指针）。
> 按语义边算，每个子方向恰好 1 个前驱（常数）；按反指针算，「前驱」= **扇出**，
> 而 §I4 是 k 叉 ⇒ **不常数**（实测 36 项语料上 `sequence` 扇出到 **7**）。
> Driscoll 的 `p` 是**指针前驱** ⇒ 持久化层**必须**把 `_children` 当权威边、
> 把 `parent`/`witness` 当**派生索引**；`B13` 查的就是「两条边互为转置」。

> ★ **§K8 的不对称性不是约定，是「见证的可检查性」的直接后果。**
>
> 契约的两半不对称：假阳**允许**（代价是性能），假阴**禁止**（破坏正确性）。
> 理由不在工程习惯里，在**可检查性**：
>
>     一个「是」  可以由下游复核（拿真项再判一次）⇒ 允许错
>     一个「否」  是「此处**不存在**」的断言 ⇒ 要证明它，得把这里**全部**看完
>                 ⇒ **没有小见证** ⇒ 无法检查 ⇒ 只能禁止，不能允许
>
> McConnell 等 2011 把这件事写成**代价**（§5.8 + Lemma 5，p.32）：
> 「Following the suggestion would have the undesirable consequence that
> **only problems in NP∩coNP could have certifying algorithms.**」
> 即：要求两侧见证都短，问题就被压到 NP∩coNP —— 所以「否」侧的小见证是**额外要求**，不是白来的。
>
> ⇒ 这条是**契约的理由**，不是可商量的偏好。谁想「放宽假阴」，先回答：
> **「否」的小见证是什么？** 答不上来就不能放宽。
>
> 出处：`ldv/C8-成熟方案对照.md` N6；逐字引文见
> `分层方向视图-成熟方案与跨领域文献.md` §2.5。

### §6.1 秩、见证、细化的**方向约定**（三条不变量都依赖它）

§1 说「越深越清晰」，§K1 说「层 n+1 的见证 ⊆ 层 ≤n」，§I2 说「`细 ⊑ 粗` ⟺ `合并({细}) = 粗`」。
**三条同时成立只有一种读法**，必须先把它写明，否则很容易读成
「见证 = 子方向」—— 那个读法和 §K1 直接冲突。

    秩 = 树深，秩越大越细        ← §1
    父 = 合并(子们)              ← §I2（合并把一组细方向收成一个粗方向）
    子.witness = (父,)           ← §K1（子在第 n+1 层，父在第 n 层 ⇒ 见证指向更粗的层）
    根 rank = 1，**外生**        ← §8.2（最外层意图必须人声明，所以根不需要见证）

⇒ 由 `子.witness = (父,)` 与 `父.rank < 子.rank` 两条，**循环在结构上不可能**
（`B13` 查的就是这个）。

## §7 可执行检查（§B1–§B19）

按 arena 的 B 系列风格：**每条禁令配一条会红的检查**，
且检查**扫描可观测的东西**（ground truth / 产物结构 / 源码文本），
不是扫描「是否声明过遵守」。

⚠️ **基线就红的判据过不了注入验证**（注入验证要求「基线绿 + 注入红」）。
所以凡是当前破着的硬要求，**判据只能落在基线绿的那条路径上**，另一条路径由**度量**报出；
或者用 **baseline 守卫**（冻结既有违规、对新增红）。这不是权宜，是**判定基线**的纪律。

⚠️ **反过来，判据的适用范围也必须写在输出里 —— 收窄要印，放宽也要印。**
判据落在哪条路径上，由「**那条路径的基线是否绿**」决定：

    `B1` / `B16`   两条路径的基线都绿 ⇒ **各占一行**（`批建路径` / `维护路径`），
                   两条各自注入验证
    `B18`          维护路径的基线**红着**（`sequence` 16 漏 / 2 对）⇒ 判据只在批建，
                   维护那半走 **baseline 守卫**（冻结既有、对新增红）

「只跑一条路」与「两条路都跑」在汇总里长得一模一样 —— 这个形状两个方向都要防。

| # | 检查 | 红了说明 |
|---|---|---|
| **B1** | 假阴：ground truth 上，`命中` 说「否」而实际有命中 | 违反 §K8 |
| **B2** | 合并覆盖：`合并(P)` 覆盖 P 的全部元素 | 违反 §I2 |
| **B3** | 代价可比：同一层内 `代价` 的返回两两可比 | 违反 §I3 |
| **B4** | 劈开成划分：**不重，且漏的恰好是账上那些**（§10.2 出路 (4) 之后是**收窄**版） | 违反 §I4 |
| **B5** | 解码覆盖：`解码(编码(d)) ⊒ d` | 违反 §I5 |

**B12 与 B14 是源码文本检查** —— 因为它们要防的是「实现的时候悄悄加了一个东西」，
而不是「运行时结果不对」。这与 arena 的 B 系列同形。

**每条检查三态**：`是`（过）/ `否`（红）/ `未展开`（跳过）。
**跳过要显式报出，与「通过」分开计数。**

⚠️ **`B16` / `B18` / `B19` 三条与它们的度量共用一个外生覆盖定义**
（`ldv/checks/_fixtures.py::coverage_of`，与 `B17` 的 `equiv_classes` 并列）。
拆在两处就会出现「同一条性质两种算法」—— 而那正是**与被检查对象共用盲点**的形状。

### §7.0 `B15` / `B16` 各自钉住了什么

**`B15` 要带一个非退化前提。** 「同构」是关于**结构**的断言；
结构没建起来（根就是叶）时，三种插入顺序当然「同构」—— 同构于「什么都没有」。
⇒ 指纹少于一层分裂时，`B15` 报**「未展开」**，不许报「过」。
（**空转与通过长得一模一样**，这是本设计的第 4 次踩到它。）

**`B16` 补的是 `B1` 依赖查询集的那一半。** `B1` 拿**查询集**的 ground truth 比，
所以查询集一换它就可能瞎。实测：同一个坏内核（102 个成员落在覆盖外），
`B1` 在 40 条查询下判「否」，在 **3 条**查询下判「是」。⇒ 必须补一条**不看查询集**的：

    B1   管「插件**说**得准不准」（行为式，靠查询集）
    B16  管「内核**分**得对不对」（结构式，靠**覆盖**）

### §7.0.1 `B16` 为什么必须按外生覆盖判（**结论**）

按 `§I3 代价` 重算归属**不是**一条合格的判据 —— 那**就是把被检查对象的运算重放一遍**。
两条外部判据把它排除得很干净：

**（一）McConnell 等 2011 §5.5 的「两个被排除的极端」。** 原文排掉的第一种就是
「拿程序的运算记录当见证」：

> We could take w as the record of the computation of P on x … **However, it does not
> satisfy the simplicity requirement, since a proof of the witness property is tantamount
> to proving the correctness of P.**

**（二）对 `reach` 在原理上就过强。** `代价 = 0` 只对**锚点本身**成立，
而 `覆盖 = reachable(payload)` 是「能走到锚点的**所有**项」。GiST 1995 明说
`Consistent` **允许不精确**（"an accurate test for satisfiability is not required here"）
⇒ 拿一个**精确性**代理去判一个**只要求不许假阴**的量，是**判据选错了**，不是插件写错了。

⇒ **`B16` 按外生覆盖判**（`_fixtures.coverage_of`，不调插件、不调内核），
与 `B17` 的做法一致。**不新增接口方法 ⇒ 不用重验 §I1–§I7。**
三个方向各一个覆盖定义（keyset 键集包含 / sequence 前缀包含 / reach 可达），
它们与插件自己的覆盖谓词**逐方向实测一致**（25/25、71/71、16/16）——
oracle 不是「另一种说法」，是同一件事的**独立重算**。

### §7.0.2 判据落在哪条路径上 —— **由那条路径的基线决定**

    第三行 批建基线**绿**（0/159、0/224、0/122）⇒ 判据落在批建
           维护基线**也绿**（0/232、0/33、0/86）⇒ **两条路径各判一次**
           （`B1` 与 `B16` 都是这样；两条各自注入验证）
    第四行 ⬜ **2026-10-07 已降级**（不再走「升级成判据」这条路）
           批建基线**绿**（0 漏）⇒ 判据落在批建
           维护基线**红着**（sequence 16 漏 / 2 对）⇒ **baseline 守卫**（冻结 + 对新增红）

**这条规则的两个方向都要印出来：**

    「只跑一条路」不许长得跟「两条路都跑」一样 ⇒ `B1` / `B16` 的标题带
    `（批建路径）` / `（维护路径）`，两条各占一行
    「基线绿所以升级成判据」不许跳过一步 ⇒ 一条**基线就红**的判据过不了注入验证，
    直接搬上去只会让套件常红、红成噪声（`B18` 就是这种形态，所以它留在 baseline 守卫）

⚠️ **「基线绿」是升级的**充分条件**，不是「这条硬要求修好了」的同义词。**
   `sequence` 维护路径上：第三行（健全性）绿、**第四行（覆盖不漏）红** ——
   一份结构上一条绿一条红，**别把绿灯记到另一条头上**。
   ⚠️ 但这**不是**「两条独立机制」：实测**漏的 16 项就是滞留的 16 项**（双向差 0）——
   健全性绿是因为那 16 项被**挪到父方向**记了账，不是因为它们消失了。见下 B 末。

### §7.1 §K8 的另一半是**度量**，不是判据

`B1` / `B16` 管「假阴禁止」；「**假阳计量**」不进 B 系列，因为假阳**允许**（代价是性能）。
但它必须被**量出来**：

    假阳率 = 假阳次数 / 判「是」总次数

理由：假阳的代价是性能，而性能**会累积**。一个假阳率 90% 的过滤器
不违反任何一条检查，却让整套结构白建 —— **所有方向都说「是」，等于没有方向**。

⇒ 进 `report()`，**不进退出码**（继承 dce：度量走输出，退出码只承载「有没有违规」）。

**同类的另外九个度量**（同样不进退出码）：

    §K2 判空        被判「这一层不建」的**方向数** —— 形状与接口贴合度的信号
                    A 7 / B 0 / C 8（同一套 §K2，形状越自然越少）

    叶容量          最大 / 平均 —— 判空把项**留在叶里**，这是它的代价
                    A 10 / 2.77、B 1 / 1.00、C 10 / 3.27
                    ★ 同项再报一个 **最大停留数** —— `叶容量` 的**推广**，见下

    增量 ≡ 全量     「先建 k 项再维护」的结构 vs「一次建完」的结构**同不同构**
                    —— 「知道未来」到底改不改变结构。见下

    规范重建        把它做成项集的函数之后，同构买不买得到、代价多大
                    —— 规范不动点 8/8 同构（k 指纹 1 种）但 O(n) 每次插入。见 §7.3

    健全性          `members(d) ⊆ 覆盖(d)` —— §1 硬要求表**第三行**，**两条路径都量**
                    —— 现在**两条路径全绿**（出路 (1)/(4) 落地之后）。见 §7.4

    覆盖嵌套        子方向说「是」的查询，父方向不许说「否」 —— 假阳的**结构**侧
                    —— A 从 14 次越界掉到 0 次（带上父方向之后）。见 §7.5

    覆盖不漏        `覆盖(父) ⊆ ∪覆盖(子)` —— §1 表**第四行**，⬜ **2026-10-07 已降级**
                    —— 它与「`滞留 == 0`」是**同一个条件**（实测 16 == 16，双向差 0）；
                       看似「独立」只因 `reach` 那半**不漏**（0 / 35 对）而破在**根**上 ——
                       那是**范围**问题，不是划分问题。见 §7.6 与 §10.2 B 末

    细化量          **度量** `细化量(d) = |覆盖(d)| − max_k |覆盖(k)|` —— 报「切得多**不匀**」（趋势）
    变细守卫         **判据** `B19`：`|覆盖(d)| − min_k |覆盖(k)| ≤ 0` ⟺ **没变细**，连续 N=10 ⇒ 红
                    —— ⚠️ 两个聚合**不是一个东西**（2026-10-07 改，见 §7.7）；
                       层数不设全局上限时，`B19` 是终止判据的守卫

    ★ 滞留          项**在父的覆盖里、但没有子方向表达得出来** ⇒ 停在父这一层（§10.2 出路 (4)）
                    —— 与「根覆盖之外」是**两条不同的代价**：那条是**范围**，这条是**划分**

**★ `滞留` 与 `最大停留数` 为什么要单独立项**（两个数各治一个盲点）：

    滞留          出路 (1) 与出路 (4) 都会让健全性变绿，但**代价落在不同地方**：
                  出路 (1) 项**不在任何方向的覆盖里**（范围损失，项检索不到）
                  出路 (4) 项**仍在父的覆盖里**（划分代价，项检索得到，只是这一层没细分）
                  ⇒ 合并成一个数就把「声称盖不住」与「这一层表达不出来」当成一件事

    最大停留数    `叶容量` 的定义默认**每一项都走到了叶**。出路 (4) 之后这个前提不成立
                  ⇒ 项可以停在**内部**节点上，`叶容量` 就看不见它：
                      实测（`sequence`，先建 2 维护 34）：叶容量 **2**、最大停留数 **34**
                      同一份结构，一个数说「分辨率很高」，一个数说「34 项堆在根上」
                  ⇒ `最大停留数` 是 `叶容量` 的**推广**：项都走到叶时两者**相等**
                     （批建路径上三个方向实测相同）⇒ 它不是「另一个数」，是**修掉盲区后的那个数**

**「`叶容量` 的洞」这条是本轮实测挖出来的，不是推理** —— 它的形态是
「**一个数骗人，一个数不骗**」：修健全性的改动让 `叶容量` 从 10 掉到 2（看起来更好了），
而真实扫描量从 10 涨到 34。**只看 `叶容量` 会把这次改动读成进步。**

**★ 第四个度量：`增量 ≡ 全量`**（`ldv/checks/divergence.py`）

    全量   `build(全部项)`              —— 内核一开始就认识所有项
    增量   `build(前 k 项)` + 后添 N−k  —— 内核后来才认识它们

两篇独立文献把它当**正确性标准**在证（Acar 的正确性定理；Godin 与三个 batch 算法对比），
而我们**实测它不成立**。⇒ 不能进退出码（会让套件常红、红成噪声），
但**更不能不上报**（不上报等于假装它成立）。

实测读数（36 项语料，扫 k ∈ {2,6,12,18,24,30,34,35}）：

    方向       全量方向/叶容量   k=2   k=6  k=12 k=18 k=24 k=30 k=34 k=35   最早同构的 k
    ─────────────────────────────────────────────────────────────────────────────────────
    keyset        25 / 10      24=24 24=24 24=24 23=23 23=23  4=4  4=4  0=0   **35**（= N−1）
    reach         71 / 1       69=69 71=71 67=67 59=59 48=48 49=49 32=32 28=28 **无**
    sequence      16 / 10      12=17 14=18  7=10  6=8   0=0  0=0  0=0  0=0   **24**

（数字 = 「全量独有 = 增量独有」的方向个数，0 即同构。）

三个结论，**都是决策依据**：

    ① 没有一个方向能在「后添 ≥ 2 项」时与全量同构
       （keyset 要 k = N−1，reach 到 N−1 都不同构，sequence 要 k = 24）
       ⇒ 想让它成立，**加大初始批次没用**，得做**规范重建**（§10 第 3 步）
    ② 差异**不在分辨率**：三个方向的**叶容量逐项相同**（keyset 10、reach 1、sequence 10）
       ⇒ 它破坏的是「哪些项分到一组」，不是分辨率
    ③ ⚠️ **方向数只有 A / B 逐项相同**：`sequence` 随 k 变（**21 → 16**）。
       这是 k 叉的**结构后果**，不是记账差异 ——
       扇出在**首次展开**时定形（§K2），初始批次小 ⇒ 当时看得见的符号少
       ⇒ 得在更深处再分一次 ⇒ 方向数更多。**变的是记账，不变的是分辨率。**
       ⚠️ `sequence` 的差还**不对称**（k=2：全量独有 12 / 增量独有 17）——
       增量侧的方向**更多**，与「初始批次小 ⇒ 多分一层」同向。

⚠️ **度量也要能变。** 一个永远报同一个数的度量，和一条永远绿的检查一样没有信息量。
所以这个模块自带**比较器自检**（每次都跑）：

    同路径必须同构       `build(全部)` vs `build(全部)`       → 必须 True
    项集不同必须不同构    `build(全部)` vs `build(全部[:-1])`  → 必须 True

两条一起成立 ⇒ 比较器**不是常量**。任一条不成立 ⇒ 本次读数不可信。
`test_injections.py` 另有一条**敏感性**验证：注入「分不开写成永久标记」之后，
读数的**尺度列**必须变化（基线 25/10 → 注入 1/36）。

出处：`ldv/checks/divergence.py`；`ldv/C8-成熟方案对照.md` N4、§7 第 1 步。

> ★ **为什么这两个数要成对报。**
>
> §K2 的字面是「否则**不建这一层**」⇒ 被判「分不开」的那一层**不存在**，
> 所以没有任何「空的方向」可数。但**代价没有消失，只是换了地方**：
> 这一层不建 ⇒ 那些项只能留在这个叶里 ⇒ 叶容量变大 ⇒ **分辨率下降**。
>
> ⇒ 两个数一起报，**它们是同一件事的两种记账**：
>
>     §K2 判空    形状与接口贴合度（判了几次「不建」）
>     叶容量      那些项最后堆到哪儿去了（**代价**）
>
> ⚠️ `§K2 判空` 数的是**方向**，不是**判定事件数**：成员集每变一次就重判一次
> （§K2 的时间维度），所以账本里的判定事件**可能多于**这个数。
>
> ⚠️ `§K2 判空` 会随**建法**轻微变化（它本来就是「判过几次」的记账），
> 但**方向数与叶容量不随建法变化**（实测五种建法逐项相同，见 `C7` §3.1）。
> 这正是「度量」与「判据」的分界：会变的那个是**记账**，不变的那个才是**形状**。
>
> 出处：`ldv/C7-流程跑通.md` §3.1、§4、§6 ①。

### §7.2 §K2 的第二半：内核**判不了**，只能外生判

`§K2` 的字面是两句话：

    展开必须产出**下层表达不出的东西**，否则不建这一层
    └────────── 第二半 ──────────┘   └─ 第一半 ─┘

内核实现的是**第一半**：`劈开后一侧为空 ⇒ 不建`。它判不了第二半 ——
因为「两个子方向是否真的表达了新东西」是**语义**问题，而**内核没有语义**
（§4.1：内核不认识任何方向，只认七个方法）。内核手上只有 `§I3 代价`，
而 `代价` **允许**假阳 ⇒ 拿它当语义判据就是 `false-green` 形状 3「共享盲点」。

⇒ 第二半只能由一条**外生**检查守：**`B17`**。

**它怎么判**：把「不可分」定义成**外生**的等价关系（**不调插件**），
再要求 **叶 = 等价类**：

    方向      不可分等价关系            最大等价类   最大叶容量   叶数   等价类数
    ──────────────────────────────────────────────────────────────────────
    keyset    键集相同                  10          10        13      13
    sequence  序列相同                  10          10        11      11
    reach     **互相可达**（同一 SCC）     1           1        36      36

    keyset    方向谓词只看 `keys(x)`  ⇒ 键集相同 ⇒ 对任何 payload 同答案
    sequence  方向谓词只看 `seq(x)`   ⇒ 序列相同 ⇒ 同上
    reach     方向谓词是 `x ∈ reachable(S)`
              ⇒ 互相可达 ⇒ 对任何锚点集同进同出；反之取 `S={y}` 就分开

⚠️ **`reach` 的等价关系不是「汇点签名相同」** —— 实测签名只有 **3** 类，
   而内核把它分成了 **36** 个叶。签名相同**不**蕴涵不可分；
   拿签名当 oracle 就是拿插件的谓词复述插件（形状 3 的另一种写法）。

**两半合起来才是等式** `叶容量 = 最大等价类`：

    等价项对任何 payload 都给同一答案 ⇒ 必落同一个叶 ⇒ 叶容量 **≥** 最大等价类
    每个叶都是单个等价类              ⇒ 叶容量 **≤** 最大等价类
    ────────────────────────────────────────────────────────────────────
    ⇒ 等式。任何 payload 设计都越不过去 —— 那是该方向能表达的**分辨率下界**。

⚠️ **等式有一个前提：`滞留 == 0`（每一项都走到了叶）。** §10.2 出路 (4) 之后
   这个前提**不自动成立** —— 项可以停在**内部**节点上，而 `叶容量` 看不见它们。
   实测（`sequence`，先建 2 维护 34）：

       滞留 32 ｜ 最大叶容量 **2** ｜ 最大等价类 **10** ｜ 最大停留数 **32**
       叶 D1 = {arg-0001, arg-0002}（**同一个**等价类）、叶 D2 同理
       ⇒ **叶仍然各自是单个等价类**，可是 `叶容量` 报出了 **2 < 10**

   ⇒ 掉下去的不是分辨率，是 **`叶容量` 这把尺子的量程**。
     一般形式要写成两条：

        每个叶都是单个等价类        ⇒ 叶容量 **≤** 最大等价类   （恒成立）
        等价项必落同一个**方向**     ⇒ 最大停留数 **≥** 最大等价类 （恒成立）
        两者相等（`= 最大等价类`）  ⟺ 滞留 == 0

   ⇒ 所以 `B17` **只跑批建路径**（那里滞留恒为 0），而维护路径上的分辨率读数
     要用 `最大停留数`。**一个数在一条路上是下界、在另一条路上不是 ——
     这种差别必须写在数自己的定义里，不能留给读者猜。**
   （`run_tests.test_stay_at_parent` ⑧ 把这条钉住了，含批建路径的对照。）

**★ 这条检查在合环图上是红的。** 随仓库那 36 项语料是 DAG（36 项 / 47 边，无环）
⇒ 等价类全是单点 ⇒ `B17` 在它上面**退化**（报「跳过」，**不报「过」**）。
自己造一个合环小图（`a ↔ b`、`c → a`、`d` 孤立）就露出来了：

    reach 把 a、b 劈进两个子方向 D3={a} / D4={b}
    而 a ↔ b ⇒ `reachable({a}) = reachable({b})` ⇒ **两个子方向覆盖完全相同**

⇒ 那一层**表达不出下层表达不出的东西** —— 正是 `§K2` 第二半要拦的。
内核没拦住，因为它的判空只查「两侧非空」。**这是 `§K2` 实现的一个缺口**，
记在 §10；`B17` 是钉住它的那条检查（`run_tests.test_equivalence` ⑤）。

**★★ 而且它在公开数据集上真的露出来了 —— 「真实语料是 DAG」这半句是错的。**

拿 OpenAlex 的引用图切片（3907 项 / 24156 边，`tools/intake_openalex.py`）跑
`run_checks`，`B17` 在 `reach` 上报**红**，被拆开的等价类**正好 6 个**：

    语料             项数   边      SCC ≥2 的个数   最大 SCC   `B17`(reach)
    ─────────────────────────────────────────────────────────────────────────
    随仓库那 36 项     36     47          0            1        跳过（退化）
    OpenAlex 子切片   281   1008          6            4        **红**（6 个类被拆开）

⚠️ 上表最后那一列是**判据侧**的读数（2026-10-07 之前）。当天裁定之后 `reach` 的
`B17` 报「过」，而**被拆开的类数照报**（全量 3907 上 **28** 个）—— 见下面那节。

**引用图不是 DAG** —— 论文互引（同一会议/期刊的对引、勘误对、综述与原文）会造出环。
⇒ 「真实语料没有环」是一个**没验过的前提**，它一碰到真数据就翻了。

⇒ 这件事的价值不在「多了一条红」，在**它把缺口的适用条件从「人工造的小图」
   换成了「真实数据」**：合环小图可以被人说成是构造出来的边角情形，
   而 OpenAlex 是 CC0 的公开语料，谁都能重跑。
   ⇒ 它同时是 `test_intake.py` ② 那条判据**被证伪**的原因（见该文件开头）。

⇒ 另外两个数一起报出来，免得「红 1」被读成「什么都不对」：
   同一趟里 `B1`（假阴，两条路径）、`B16`（健全性，两条路径）、
   `B18`（覆盖不漏）、`B19`（变细守卫）**全部是绿的**。

#### ★★ 2026-10-07 裁定：(b) 那一半在 `reach` 上**从判据降为度量**

上面那条「红」是**判据的适用范围**问题，不是实现缺口 —— 这一点 281 项上就看出来了。
裁定的依据是**`reach.split` 的实现**：

    `reach.split` 按 `(汇合签名, 到汇合点的距离, id)` 排序后**取中点切**。
    第三个分量 `id` 是**认输的 tie-break** —— 前两个分量完全并列时，它保证切得开。
    ⇒ 前两个分量并列的两项（互相可达，或到汇合点等距）**必然被劈到两侧**，
      而它们的覆盖**完全相同**。

⇒ 所以这不是「内核忘了查第二半」，是**这个方向的 `split` 有意比语义更细**。
而 `§K8` **允许假阳**（代价记在性能上）⇒ 「结构不许比语义更细」这条判据在 `reach` 上
**过强**。`B17` 拆成两半，**两半分开处置**：

    (a) 叶 = 不可分等价类      **仍是判据**（三个方向都跑）
    (b) 叶之间覆盖不重复        `keyset` / `sequence` 上**仍是判据**；
                               `reach` 上**降为度量**，只报不判

实测（全量 3907，同一趟）：`reach` 的 `B17` 现在报

    [过] 叶 = 不可分等价类 …… 3907 个叶 = 3277 个等价类；最大叶容量 1 = 最大等价类 497
         ｜（b）**本方向不判**：**28 个等价类被拆到多个叶**（`reach` 的 `split` 有意
         比语义更细，`§K8` 允许假阳）—— **只报不判**

⚠️ **「判据不再红」不等于「现象消失」。** 那 28 个类**仍在**，只是从**判据列**
移到了**度量列**。这不是措辞问题 —— 若只是把红删掉，下一轮没人会知道这件事还在发生。
⇒ `run_tests` 为此**新加了一条断言**（`run_tests.py` ⑤，断言数 403 → 404）：
`B17`(a) 报「是」的**同时**，`absorption_profile(...)["被拆开的等价类"] > 0` 必须成立。

⚠️ **反面纪律同样重要**：**不许**把一条**常驻的红**记成「已知红」留在判据列。
**一条常驻的红等于没人再看红** —— 它训练所有人忽略那一列，于是下一次**真的**红
也一起被忽略。过强的判据要么**收窄适用范围**（本条），要么**降级**。

⚠️ **复核点**：`reach.split` 的 tie-break 一旦不再用 `id`（比如改成按覆盖签名分），
这条裁定就要重开 —— 判据当时的前提是「`split` 有意更细」，那个前提写在
`equivalence.py` 的 `b17_leaf_is_equivalence_class` 的 docstring 里。

出处：`ldv/checks/equivalence.py`、`ldv/checks/_fixtures.py` 的 `equiv_classes`、
实测报告 `ldv/C9-等价类下界.md`、外部语料验收 `ldv/tests/test_intake.py`。

### §7.3 第五个度量：规范重建（`ldv/checks/rebuild.py`）

第 4 个度量（`增量 ≡ 全量`）量到「不成立」之后，**唯一**能让它成立的做法是
把结构做成**项集的函数** —— 即**规范重建**。它同样**只报不判**（判据是 `B8`）。

两种做法都量了（36 项语料，扫 k ∈ {2,6,12,18,24,30,34,35}）：

    方向       做法         同构全量的 k   k 指纹数   重建次数  重建工作量
    ─────────────────────────────────────────────────────────────────────
    keyset     规范不动点      8 / 8         1        35       665
    keyset     阈值重建        1 / 8         3         5        62
    reach      规范不动点      8 / 8         1        35       665
    reach      阈值重建        0 / 8         3         5        62
    sequence   规范不动点      8 / 8         1        35       665
    sequence   阈值重建        8 / 8         1         5        62   ★ k 叉之后**买到了**

    规范不动点  每次插入后，从**当前项集**按**规范序**（id 升序）整树重建
    阈值重建    只在规模跨过 2 的幂时重建（Naor–Teague）—— 摊还 O(1)

**四个结论**：

    ① 规范不动点**确实买到了**：8/8 同构，且 **k 指纹只有 1 种**
       ⇒ 结果**不再依赖初始批次大小**。这是「买到」的实义 ——
          「8/8 同构」只说「与全量一致」，「指纹 1 种」才说「各 k 之间也一致」
    ② 代价是 **O(n) 每次插入**：35 次重建 / 工作量 665 = `2+3+…+36`
    ③ 阈值重建**只对「扇出不是恒为两个」的方向买到**：
       **sequence 8/8、k 指纹 1 种**（trie 形状：首次重建时符号齐了就定形，
       之后添的项只落进**已有**的子方向）；而**扇出恒为两个**的
       keyset 1/8、reach **0/8** —— 差异发生在**两次重建之间**，
       阈值之后添的项仍是增量的
       ⇒ Naor–Teague 买到的是「摊还 O(1) 的重建」，**不是**「结构 = 项集的函数」
    ④ `B8` **红** —— 规范重建每次全量重算，正是 §K3 要挡的形态
       （`run_tests.test_rebuild` ⑤ 断言的就是「这条判据抓得到它」）

**⇒ 决定：不做。** 理由不是「太贵」，是**交换的东西不对等**：

    它要拿  §K3（**接口级**不变量：改一点不许全量重算）
    去换    「结构可复现」（**实现**性质）

而第 1 步已说明：「不同构」**不破坏任何一条检查** —— 它是一条**读数**，不是违规。
拿一条硬不变量去换一条读数的好看，不划算。（为什么二者**不相容**：见 §10.1。）

⚠️ **另一条与 id 无关的读数：失效范围比。** `B8` 用**方向 id** 比对，
   而重建会把 id 全部换掉 ⇒ **任何**重建实现都会被 `B8` 判红，
   结论会显得像比对的产物。所以另报一个**用成员集合做对称差**的读数：

    失效范围比 = |{成员集}_before △ {成员集}_after| / 方向数

    基线（路径局部增量） **0.00**｜规范重建 0.06（A、C）/ 0.29（B）

   ⇒ 规范结构对插入**近似稳定**：重建在**结果**上是安全的，代价**全在重算**上。
     这**不改变结论** —— §K3 挡的是**工作量**，不是**结果差异**。

> ⚠️ **量的细节**：`before`/`after` 的成员集必须**扣掉新插的那一项**。
> 不扣的话量到的是「x 加进了路径上的每个方向」—— 那对**任何**实现都一样，
> 读数就没有区分力（不扣：基线 0.78 / 重建 0.79，差 0.01，读不出差别）。

出处：`ldv/checks/rebuild.py`；`ldv/C8-成熟方案对照.md` §7 第 3 步、N3。

### §7.4 第六个度量：健全性 —— **必须在两条路径上都量**

`members(d) ⊆ 覆盖(d)` 是 §1 硬要求表的**第三行**（`B16` 守）。

**它两条路径都是判据**（`B16 批建路径` / `B16 维护路径` 各占一行，各自注入验证）。
⚠️ **判据的适用范围必须印在输出里** —— 「只跑一条路」与「两条路都跑」在汇总里
长得一模一样。这条规则对**收窄**同样适用：`B18` 就只跑一条（见 §7.0.2）。

⚠️ **覆盖由外生 oracle 算，不调插件**（§7.0.1）。下表是三级单变量对照里
**不修**的那一列（`reach` 与 `sequence` 那两行就是缺陷本身）；修后见下面的逐条对照：

    方向        一次建完     维护路径（先建 6 维护 30）    B1（**维护路径**上的假阴）
    ──────────────────────────────────────────────────────────────────────────────────
    keyset      0 / 159     0 / 232                      **是**（411 个样本，0 条假阴）
    reach       0 / 224     **128 / 328**（最差 = 根 D0）  **否**（30/367 条假阴）
    sequence    0 / 122     **36 / 176**（最差 D4）       **否**（17/141 条假阴）

    ⚠️ `reach` 维护路径那一格：旧尺子（`代价 = 0`）量出 **246 / 328**。
       差的 118 是**旧尺子自己造的** —— `代价 = 0` 只对锚点成立，
       而覆盖是「能走到锚点的所有项」。**换尺子不是修好了 118 个缺陷。**

**为什么不能只看 `B16` 的读数** —— 这一条在两条路径上**不是同一件事**：

    一次建完     每个方向的成员集在**第一次展开时就是完整的**
                 ⇒ 子方向的 payload 从这批成员算出来，一定盖得住它们 ⇒ 天然成立
    维护路径     成员是**后来才长起来的**，而 payload 在劈开时就**冻结**了
                 ⇒ 子方向收不住「它没见过的项」⇒ 破了也没人查

⇒ **一次建完全绿、维护路径全红**，而且**真的产生假阴**（`B1` 在维护路径上判「否」）。
这是「空转与通过长得一模一样」在**流程**上的形态：
检查存在、是绿的，但它从没跑在出问题的那条路上。

⚠️ **`B1` 也一起搬到了两条路径**（与 `B16` 同一步）。理由不是「顺手」：
   `B1` 的 ground truth 里**有成员集**（`members(d) ∩ ideal(q)`），而成员集在两条路径上不同
   —— 同一批查询问的其实是**另一个**成员集。实测样本数就不一样：

       keyset   批建 401 / 维护 411
       reach    批建 316 / **维护 58**   ← 出路 (1) 把 28 项挪出了结构，样本随之减少
       sequence 批建 101 / 维护  57

   `reach` 那一格是关键：**样本数自己就是一条读数** —— 它把「出路 (1) 的代价」
   从「一个静默的状态」变成了「维护路径上能查的东西变少了」。

**A 的修法只有一行**，单变量对照（先建 2 维护 34）：

    `common` 掺进 `req`（不修）       123 / 227  且方向数随初始批大小变（23/23/21/25/25）
    `req` 只从父续（修后）              0 / 235  且方向数恒为 25

⇒ 一行修好：维护路径 `B1` / `B16` 转绿、方向数恢复「不随初始批大小变」。
代价：全量假阳率 49.4% → 50.1%（**判「是」803 次里多 10 次**）。
**这不是「性能换正确」的交易，是把一笔本来兑现不了的声称收回来** ——
`common` 声称「落进来的东西都带这些键」，而劈开兑现不了它。

**B 的出路 (1) 是「根记账」**（§10.2）。单变量对照（先建 6 维护 30，`reach`）：

    根记账之前     128 / 328    （根的 28 个越界成员是全部越界的主要来源）
    根记账之后      **0 / 33**   （28 项落在根覆盖之外 ⇒ 不塞进结构 ⇒ 账上）

⇒ 关键不在「把数压小」，在于**那 28 项从「静默错位」变成了「一条显式的账」**
（`stats()['根覆盖之外']`、账本 `out_of_scope` 事件、流程 B 的逐项报告）。
代价落在**范围**上：那些项在这条方向上检不出来 —— 可见、可数、有事件，**不是静默假阴**。

**C 的出路 (4) 是「项留在父方向」**（§10.2）。单变量对照（先建 6 维护 30，`sequence`，逐 k）：

    照塞（子方向都证明不收，也照塞）   36 / 176 越界   滞留 **0**     方向 20
    留父（项**留在父方向**）          **0 / 86** 越界  滞留 **16**    方向 8

    ⚠️ 漏项数**两边都是 16，一个数没动** —— 出路 (4) 修的是健全性，
       不是「覆盖不漏」（§1 表第四行，⬜ 2026-10-07 已降级）。
       ⚠️ 而这 16 个漏项与那 16 个滞留项**是同一批项**（双向差 0）⇒ 两者**不是两条独立机制**，
       是**同一批项**的两种**处置**。别把这一条的绿灯记到那一条头上，更别当两条机制去修。

⇒ 转绿的那部分**不是被修掉的，是被挪到父方向上的**（`stats()['滞留']`）。
所以代价分两处报，别合并：**范围损失**（根覆盖之外）与**划分代价**（滞留）。
⚠️ 同一份结构上 `叶容量` 会从 10 掉到 2（看起来更好了），而真实扫描量涨到 34 ——
   `叶容量` 看不见停在**内部**节点上的项，要用 `最大停留数`（§7.1）。

出处：`ldv/checks/coverage.py` 的 `soundness_profile` / `render_soundness`；
读数与三级单变量对照见 `ldv/tools/measure_parent.py` 表二；`ldv/C10-签名改动复核.md` §4。

### §7.5 第七个度量：覆盖嵌套 —— 子说的「是」，父接不接得住

    覆盖(子) ⊆ 覆盖(父)   ⟺   `命中(子,q) = 是` ⇒ `命中(父,q) ≠ 否`

§1 硬要求表里**没有**这一条（硬的是成员层与健全性）⇒ 违反它**不破坏正确性**：
父的「否」只在父的覆盖之外才下，剪枝仍然安全 ⇒ 进输出，不进退出码。

但它**不是无害的**：子方向收下的东西被父否掉 ⇒ **父的过滤器比子的更松** ⇒
遍历在父那一层**白走一趟**才到子。这正是 §K8「假阳的代价是性能，而性能会累积」
的**结构形态**。

与假阳率的分工：

    假阳率      说「说了多少句不该说的**是**」—— **行为**侧
    覆盖嵌套    说「子说的『是』，父接不接得住」—— **结构**侧

实测（36 项语料）：`劈开` 拿不到父方向时，子方向把父的 `forb` 丢了 ⇒ A **越界 14 次**；
把父的 `forb` 续上之后 **0 次**（三个方向全部 0 次）。

出处：`ldv/checks/contract.py` 的 `cover_nesting_profile`；`ldv/tools/measure_parent.py` 表一。

### §7.6 第八个度量 + `B18`：覆盖不漏 —— **baseline 守卫**

`覆盖(父) ⊆ ∪覆盖(子)` 是 §1 表的**第四行** —— ⬜ **2026-10-07 已降级**（见 §10.2 B 末）。
⚠️ 它**不是**「与健全性并列的另一条独立机制」—— 为什么不是，见下面第二条实测。

    健全性破了      `members(d) ⊄ 覆盖(d)` —— 某个成员不在自己方向的覆盖里
    覆盖不漏破了    `覆盖(父) ⊄ ∪覆盖(子)` —— 父说「是」的项，**每个子都说「否」**

**实测（外生覆盖，36 项语料）**：

    方向        一次建完          维护路径（先建 6 维护 30）
    ────────────────────────────────────────────────────────
    keyset      0 漏 / 12 对       0 漏 / 12 对
    reach       0 漏 / 35 对       0 漏 / 35 对
    sequence    0 漏 /  5 对       **16 漏 / 2 对**（D0 漏 8、D1 漏 8）

⇒ **`reach` 的覆盖一次都没漏，而它的健全性破了 128 / 328** —— 乍看像「两条机制」的证据。
⚠️ **但它不是「同一问题的另一条机制」，是「另一个轴上的问题」**：`reach` 那半破的是
**范围**（根的外生 payload 盖不住后来添的项），不是**划分**。
**照第四行去修 `reach` 会修错地方**：它要修的是「根的外生 payload」（§10.2）。

⚠️ **而 `sequence` 那半的 16 个漏项，与它的 16 个「滞留项」是同一批项**
（`outputs/_probe_leak_vs_stay.py`：D0 8/8、D1 8/8，双向差 0）⇒ 在 `sequence` 上
**`覆盖不漏` 与「`滞留 == 0`」是同一个条件**。理由也显然：滞留的触发条件是
「每个子方向都**证明**不收它」= `命中(k,{x}) = 否`，而「否」按定义就是
「`x` **不在** `k` 的覆盖里」。
⇒ 「**两条独立机制**」这个说法要**改口径**：它们是**同一批项**的两种说法，
差别只在**处置**（出路 (4) 把项留在父上；兜底把它接进一个子方向）。

两个数都要报，别只报一个：

    `漏项数`     一共漏了几项 —— **代价**信号
    `漏的对数`   有几对父子漏了 —— **定位**信号（哪一层先破）

**判据 `B18` 是 baseline 守卫**，两头都守：

    观测 > baseline           → **红**（新增违规）
    baseline > 0 且观测 == 0  → **红**（条目不再发生 ⇒ 去收紧 baseline）
    其余                       → 绿；观测 < baseline 时另报「可以收紧」

**★ 第 0 条：baseline 必须按语料分开，判不了就报「未展开」。**

    指纹相符（`项数` / `边数` 都对得上）  → 按上面三条判
    指纹不符、或基线里没记指纹          → **未展开**（跳过），并说清是**换了语料**

理由只有一条：baseline 是**语料相关**的读数。「换了一份语料」、
「基线文件不见了」、「新增违规」三者若不分开报，在输出里**长得一模一样** ——
而前两者既不是绿也不是违规，是**判不了**。

⇒ 配套两条硬纪律：

    语料指纹是**必填参数**：漏传 ⇒ 调用点当场 `TypeError`。
      （防御不许因为调用方少传一个参数而**静默消失**。）
    基线文件不存在 ⇔ 基线里没记指纹 ⇔ 指纹不符 —— 三种情形给**同一句**「判不了」。
      （不许拆成「绿」和「红」两种假象。）

⚠️ **跳过 ≠ 通过**：它明确地说「这条守卫在本语料上判不了」，而不是「本语料不漏」。

为什么不是「一条写死的判据」：批建路径基线**绿**（三个方向都 0 漏）⇒ 那半可以直接判；
维护路径基线**红**（`sequence` 16 漏 / 2 对）⇒ 只能冻结。
**纯度量永远不红**，于是「声称是硬的、实际没人管」这个毛病原样保留；
baseline **保留了「能红」**。

> Enabling a new lint rule as "error" can be challenging when the codebase has many
> violations … **Existing violations must be resolved before enabling the rule** …
> ESLint provides a way to **suppress existing violations** … **While the rule will be
> enforced for new code, the existing violations will not be reported.**
> — ESLint 官方文档 *Bulk Suppressions*

> If you run ESLint again you will notice that it **exits with a non-zero exit code and an
> error is reported about unused suppressions**.
> — 同上（`--prune-suppressions` 那条纪律）

⚠️ **baseline 与 §B9 的纪律方向相反，不能混**：`§B9` 管的是**方向的失效历史**
（只增不改）；baseline 管的是**判据的豁免清单**（只减不增）。

**升级里程碑**：⚠️ **这一条现在不挂那个里程碑了**（2026-10-07 裁定，见 §10.2 B 末）——
第四行**降级为「有代价的度量 + baseline 守卫」**，不再往「真判据」升级
（升级它的价格是废掉已落地的出路 (4) / `滞留` / `最大停留数` / `B4` 收窄）。
**健全性**那一半仍然挂在**「B / C 的维护路径修法落地」（§10.2）**上 ——
到达之后，它从「度量」升级成**真判据**。

出处：`ldv/checks/coverage.py` 的 `cover_leak_profile` / `b18_cover_leak_baseline`；
基线文件 `ldv/checks/cover_leak_baseline.json`（用

### §7.7 第九个度量 + `B19`：变细守卫 —— **跨次数**的性质

**两条读数，两个不同的聚合**（2026-10-07 分开，理由见下）：

    度量 · 细化量(d) = |覆盖(d)| − **max**_k |覆盖(k)|     报「切得多**不匀**」（趋势）
    判据 · `B19`     |覆盖(d)| − **min**_k |覆盖(k)| ≤ 0  守「有没有真**变细**」（成分）

**「进步」为什么是覆盖的细化度，而不是叶容量**：叶容量是**后果**、会滞后；
覆盖的细化度才是**插件声称的东西** —— 守卫要抓的正是「**声称**却分不出东西」。

> When longValuesOK is true, it is expected that successive levels of the SP-GiST tree
> will absorb more and more information into the prefixes and node labels of the inner
> tuples, **making the required leaf datum smaller and smaller** … To prevent bugs in
> operator classes from causing infinite insertion loops, **the SP-GiST core will raise
> an error if the leaf datum does not become any smaller within ten cycles of choose
> method calls.**
> — PostgreSQL 18 文档 §65.3.4.2（`longValuesOK`）

⇒ 「进步」= **datum 变小** = payload 细化度（**不是**叶容量）；**N = 10**。
而且**内核自己算** —— 原文算的是 leaf datum 的大小，一个内核看得见的量，
**插件不需要新报任何东西** ⇒ **不动接口、不用重验**。

**`B19` 红了说明**：存在一条根→叶路径，其上**连续 10 次**展开**没有任何一个子的覆盖严格小于父**。

⚠️ **与 `§K2 判空` 是两条不同的检查，不能合并**：

    §K2 判空   判「**这次**分不开」—— **单次**性质
    B19        判「**反复声称**却分不出东西」—— **跨次数**性质

#### ★ 2026-10-07 改动：谓词从 `max子` 换成 `min子` —— 原来把**两件事**算成了一个记号

原来只有一条：

    `细化量(d) = |覆盖(d)| − **max**_k |覆盖(k)|`
    `无进步(d) ⟺ 细化量(d) ≤ 0`

它把**两件不同的事**算成了同一个记号。全量实测（`outputs/_probe_b19_depth.py`，
逐字输出在 `outputs/_b19_depth_fullscale.txt`）：

    没变细      **没有任何一个子**的覆盖严格小于父  ⇒ 这次展开**一个项都没分开**
    不均衡切    至少一个子严格更小，只是**最大的那个**子没变小 ⇒ 它**分开了东西**

    语料      项数    已展开   细化量≤0   其中「没变细」   最长没变细段   B19
    ────────────────────────────────────────────────────────────────────────
    36         36       35       10          **0**            0          绿
    281       281      280       80            5             2          绿
    3907     3907     3906     1515          599            **9**       绿

⇒ `max` 聚合让「切得**不匀**」被读成「**没切**」。全量上把 `B19` 顶红的那条
**10 跳链逐跳打出来，一跳「没变细」都没有** —— 其中 `D15` 一步切掉了 **1035 项**：

    D3   不均衡切  父 1044 ｜ max子 1044 ｜ min子 1040
    D15  不均衡切  父 1044 ｜ max子 1044 ｜ min子    9     ← 这一步切掉 1035 项
    D7369 不均衡切 父    2 ｜ max子    2 ｜ min子    1

⇒ 所以**判据的谓词改成 `min子`**（「没有任何一个子严格更小」），
而 `细化量`（`max子`）**留作度量** —— 报「切得多不匀」的趋势。
**「度量报趋势，判据守成分」在这里是两个不同的公式，不是一个公式的两种读法。**

⚠️ **「无进步」这个词就此作废** —— 它先后指过两件事（`细化量 ≤ 0` 与「没变细」），
留着必然被读错。现在一律说「**没变细**」（判据）或「**切得不匀**」（度量）。

⚠️ **词与名一起改了**：度量族名 `进步量` → `细化量`，检查名 `进步量守卫` → `变细守卫`。
「进步量」这个词**同时**当过度量名和判据名，正是这次要拆开的混淆源。
现在：**度量 `细化量`（`max子`，报趋势）** ／ **判据 `变细守卫`（`min子`，守成分）**。

⚠️ **改谓词不是把红藏起来**：「没变细」**真的存在**（3907 上 599 次，最长连续 9 跳），
判据仍在工作。改的只是「**哪些算**没变细」。

#### ★ 另一条更要紧的：原来那句「真语料上不会红」，**理由本身是尺度相关的**

原话是「**真语料上 `B19` 不会红**：树只有 7 层，够不到 N=10」。
它给的**理由**是「树深 < N」—— 那么尺度一大、树一深，它**必然**翻。实测三档：

    语料      项数    最大深度（层数）   最长连续段（旧谓词）   最长没变细段（新谓词）
    ──────────────────────────────────────────────────────────────────────────
    36         36       6（7）                  4                      0
    281       281       9（**10**）             6                      2
    3907     3907      12（**13**）         **10** ⇒ 旧谓词**红**     9 ⇒ 新谓词绿

⇒ 那句声称在 **281 项上就已经是错的**（层数 10，不是 7），只是 `最长连续段 6 < 10`
还够不到阈值 ⇒ **它绿着，但绿的理由不是「没有空转」，是「树不够深」**。
这是「空转与通过长得一模一样」的**反面**：**没空转与空转长得一样**。

⚠️ **`N = 10` 仍是拍出来的值**（照 SP-GiST 前例，不是本语料标出来的），
而改完谓词后全量上最长「没变细」段 = **9** —— **离阈值只差 1**。
这条**绝对阈值**在 3907 这个尺度上已经贴着边。**这一条留作已知的脆弱点**，见 §10。

#### 注入验证：**夹具必须跟着谓词换**（换聚合 ⇒ 换夹具）

    基线（原插件，在 16 项**环**上平衡二分）    最长没变细连续段 = log2(16) = **4**  < 10 ⇒ 绿
    注入（每次只切掉一个锚点）                  最长没变细连续段 = 16 − 1   = **15** ≥ 10 ⇒ 红

⚠️ **夹具从「链」换成了「环」，理由是构造性的**（`ldv/tests/test_injections.py::_cycle`）：

    链   反向锥逐级**严格嵌套** ⇒ 任何真子集的覆盖都严格更小
         ⇒ 「没变细」**按构造不可能出现** ⇒ 判据在这个夹具上**永远绿**
    环   每一项的反向锥都 = **整个环**（强连通）
         ⇒ 任意非空锚点集都撑满同一个覆盖 ⇒ 「没变细」可以**连续成立**

⚠️ 而且**两条最自然的注入都走不通**，写在这里免得下一个人重走：

    路一  「**一个**子退回父 payload」（原注入）⇒ 另一侧仍**严格更小** ⇒ 不算没变细
    路二  「**每个**子都退回父 payload」⇒ 两侧代价都是 0 ⇒ 内核把成员全判给靠前那个
          ⇒ 另一侧为空 ⇒ `§K2` 判「分不开」⇒ **这一层根本不建** ⇒ 判据「未展开」

⇒ 路二的根因值得记住：`reach` 的 `代价 == 0 ⟺ 项 ∈ payload`（**不是** ∈ 覆盖）。
  所以「两侧覆盖都 ⊇ 父」时，成员在两侧**都**是 0 分 ⇒ 必然平手。
  能红的形状只能是「**两侧代价可区分，但覆盖都不变小**」。

**实测（36 项语料，批建）**：

    keyset      12 次展开，没变细 0 次（最长 0）｜切得不匀 0 次（最长 0），最小细化量 1
    reach       35 次展开，没变细 0 次（最长 0）｜切得不匀 10 次（最长 4），最小细化量 **0**
    sequence     5 次展开，没变细 0 次（最长 0）｜切得不匀 0 次（最长 0），最小细化量 1

⇒ `reach` 那一行的**度量**是**真读数**：`reach` 的 `覆盖 = reachable(payload)` 对 payload 单调，
而它的 payload 是「本组各项」⇒ 某些展开里**最大的那个子方向的覆盖就等于父的覆盖**
（另一组的项能到达同一批锚点）。那一层买到的是**分辨率**，不是**过滤力**。
这个数以前**没有地方报**。
⚠️ 注意「切得不匀 10 次」**不等于**「10 次没分开」—— 那 10 次**每一步都切掉了东西**
（`min子` 严格更小），所以**判据不判它**。

出处：`ldv/checks/coverage.py` 的 `progress_profile` / `b19_progress_guard`。
探针：`outputs/_probe_b19_depth.py`（三档语料）、`outputs/_probe_b19_injection.py`（注入候选）。

## §8 反馈模型

### 8.1 倾向权重是必要构件

自我优化的输入是**使用反馈**，而使用反馈**天然有偏**：你只观测得到
**你展示过**的方向的使用情况。

两个领域独立收敛到同一个修法：

| 领域 | 正文 |
|---|---|
| 数据库 / 索引 | 「future queries … same distribution … when this assumption does not hold … **importance weighting** to directly address covariate shift」 |
| 信息检索 / 排序 | 「treating a click/no-click as a positive/negative relevance judgment is **severely biased**」⇒ **Propensity-Weighted** |

**⇒ 倾向权重不是可选项。**

**分工**：内核填倾向（内核决定展示了什么，因此知道展示概率）；
插件只负责 §I6 —— 判定「这次交互算不算信号」。

### 8.1.1 曝光模型：按**位次**，不按**个数**

    展示在第 k 位  ⇒  propensity = 1 / k        （夹一个下界，见下）

**不能按「这次展示了几个」算** —— 那等于假设**每个位置的曝光概率相同**。
真实检索里第一位和第十位的曝光概率差一个量级；按个数算，
倾向加权会把偏差**原样带进**自优化，而自优化的目的恰恰是修掉它。

**下界的理由**：`1/位次` 随位次线性衰减，权重 = 结果 / 倾向 因此随位次线性增长。
夹一个下界 `PROPENSITY_FLOOR` 是为了**限住权重上界**（≤ `1/FLOOR`）——
不夹的话，排在第 500 位的方向会拿到 500 倍权重，方差大到把自优化掀翻。

**为什么这条要写进文档**：把曝光模型退回「按个数」，**不会有任何东西变红** ——
除非它被写成可执行判据。所以 `B11` 除了查「100% 带倾向」，
还查**「第 1 位与第 N 位的倾向必须不同」**。没有后半条，
这条约束就是一句注释。

### 8.2 递归停在哪里：内生 / 外生

    方向函数是插件 ⇒ 选哪个插件能否也按 usage 优化？
    ⇒ 那「优化它」需要目标 ⇒ 那个目标又按 usage 优化？⇒ 无限递归

**停的地方就是模块化的边界。**

| 信号 | 内生 / 外生 | 处置 |
|---|---|---|
| 层内哪个方向值得展开 | 内生 | 可自我优化 |
| 层内局部权衡 | 内生 | 放进 §I3 |
| **什么算一个方向** | **外生** | **必须人声明** |
| **最外层意图** | **外生** | **必须人声明** |

外生项一旦允许自我优化，会同时失去**可复现性**（同数据不同历史 ⇒ 不同结构）
与**可解释性**（说不出为什么长这样）。

### 8.3 探索不是解药

**不要**用「加随机探索」当防塌缩机制：

> systems with **some level of random exploration can be degenerative**

防塌缩靠 §8.1 的倾向权重，不靠随机。

## §9 怎么知道接口押对了

内核接口是一个**赌注**：押错了就需要第二个内核。

工业界的证据是——**PostgreSQL 里同时存在 GiST / SP-GiST / GIN 三种可扩展索引**。
但**共存本身不是证据**：它证明的不是「一套接口装不下很多方向」，而是
**GiST 的方法集装不下「不平衡的空间划分树」这一类** ——
SP-GiST 论文原话是「the class of unbalanced spatial indexes, e.g., the quadtree,
the trie, and the k-D tree, is not supported by GiST」（p.217）。
⇒ 真正承重的是**「装不下的那一类」有多大**，不是「有几套接口」。
本设计要证的正是：**三个差异极大的方向，装得下**。

**验收方式（也是第一版该做的事）**：

> 用**差异足够大**的方向去试**同一个内核**。
>
> - 每个都**只需要写插件** ⇒ 接口押对了
> - 有一个**逼着改内核** ⇒ 押错了，现在就知道

**所以第一版不该做的**是「支持很多方向」——
那是结果，不是手段。手段是**差异足够大的方向**。

**实测做了三轮**（A 键集包含 / B 锚点可达 / C 序列前缀）：

| 轮次 | 方向 | 压到接口了吗 | 记录 |
|---|---|---|---|
| 1–2 | A + B | 1 处签名级（§I4 入参）+ 2 处文档 | `C5-判定报告.md` |
| 3 | **C 顺序敏感** | **0 处**（2 处文档） | `C5b-第三方向复核.md` |

**为什么第三个必须与前两个不像**：两个方向押对，可能只是**两个方向恰好相像**。
A 与 B 的 payload 都是**无序集合** —— 把元素顺序打乱，方向一点不变。
C 是**有序**的（`('概念','案例')` ≠ `('案例','概念')`），所以它压的是前两个压不到的位置。
结果：**还是只需要写插件**。

### §9.0 跑通 A/B/D 改到了内核，但**不算第四轮**（必须分清）

跑通流程 A/B/D 时改了一次 `kernel.py`（**叶不是终态**，`C7` §3.1）。
那**不是**「押错」——判据只有 §9.1 那两个症状，它两个都不占：

    没有新增方法      §I1–§I7 一个都没多
    没有拆分方法      `劈开` 仍是一个方法、仍返回两个值

它改的是**内核自己的实现**（`expand` 把「分不开」当成了永久标记），
**插件一行没动、接口一个没动**。所以：

    §9 的三轮判定（0 处结构改动 ⇒ 内核冻结）**不变**
    §10 里两条 `§I4` 留白**仍按原顺序**（先做可能推翻接口的，最后做纯工程的）

**同一轮里第二次改内核**（§K2 按**字面**「不建这一层」实现，§K2 的 ★ 块）
也一样不算 —— 它把「建了再作废」改成「真的不建」，**没有新增也没有拆分任何方法**。
它影响的是 §7.1 的**度量定义**（空权威层 → `§K2 判空` + 叶容量），不是接口。

**这条区分本身就是本项目的中心纪律**：`押错了` 与 `实现有 bug` 必须分得开 ——
前者要重做内核，后者修一行就够。把两者混起来，会为了一个实现缺陷去重验整个接口。

### §9.1 判定「押错」的**症状**（只有这两个）

    必须新增第 N+1 个方法        ← 七个位置不够表达
    必须把某个方法拆成两个        ← 一个位置塞了两件事

**签名 / 入参写错不算押错** —— 漏掉的是参数写法，位置还在。
把这两类**分开记**：只要「结构改动」为 0，就可以冻结内核。

理由：押错的本质是**七个位置漏掉了一件事**。症状只有上面两个。
签名写错只是同一个位置换了种写法 —— 它该改的是文档，不是内核。

> ⚠️ **这两个症状在真实系统里确实会响，但响的是「框架」层，不是「插件」层。**
>
> SP-GiST 自己的方法集从论文的 **3 个**（`Consistent` / `PickSplit` / `Cluster`）
> 长到实现的 **5 + 2 个**（`inner_consistent` / `leaf_consistent` 拆开、`config` 新增、
> `Cluster` 移进内核）。差集**恰好命中上面两个症状**：
> `Consistent` 被**拆成两个**（一个位置塞了两件事），`config` 是**新增的第 N+1 个方法**。
>
> ⇒ 但这**不推翻**本设计的三轮判定。区别在**症状出现在哪一层**：
>
>     框架层（GiST → SP-GiST）   整个结构类别变了（有序树 → 空间划分树）⇒ 症状该响
>     插件层（我们的 A / B / C） 同一个结构类别内换方向      ⇒ 症状不该响
>
> 三轮实测的症状数都是 **0**，判定**不变**。这条注记的作用是**把边界写明**：
> 将来真出现「必须新增第 8 个方法」，先问一句是**插件层**还是**框架层** ——
> 是框架层，那说明要换的是内核，不是补一个方法。
>

       ⚠️ 实测的**形状失效范围**只有 0.06–0.29（基线 0.00）—— 那**不改变结论**：

    4  ✅ **已做** —— `§I4` 的签名改动（返回一组方向 / 「分不开」显式返回 / 带上父方向）

       ⇒ **三处改动没有一处需要新增方法、拆方法、或换返回值的类型** ——

### §10.1 第 3 步顺带定下的一条判据：**什么时候「增量 ≡ 全量」才是正确性标准**

两篇独立文献把它当**正确性标准**在证，而本设计里它**只是一条读数**（第 1 步）。差别不在工程习惯：

| 输出 | 「增量 ≡ 全量」是什么 | 例子 |
|---|---|---|
| **唯一**（一个值 / 一个格 / 一个规范形） | **正确性**要求 —— 两条路必须到同一个地方 | Acar：增量求值的**值**；Godin：Galois 格对给定 context 是**唯一**的 |
| **不唯一**（一族都合法的结构） | 只是**实现性质** —— 「哪一棵树」不是正确性的一部分 | 本设计：§K1–§K9 描述的是一族合法树，不是唯一那棵 |

⇒ **判据**：搬一条「增量 ≡ 全量」到新领域之前，先问 **「这个输出是唯一的吗？」**
唯一 ⇒ 可以当**检查**（进退出码）；不唯一 ⇒ 只能当**读数**，
否则你会为了一个**不必要的**规范形，去付全量重算的代价（本步实测：O(n) 每次插入）。

**为什么 §K3 与「结构 = 项集的函数」不相容**（论证，不靠比对）：

    结构 = f(项集)   ⇒ 项集变一个元素，f 的取值就变
    f 的取值变       ⇒ **整棵树**都是 f 的函数 ⇒ 全部方向都要重新确定
    ⇒ 失效范围 = 全部 ≠ Cone(x) ⇒ **§K3 违反**

⚠️ **第 4 条动签名（要重验），其余都是加检查或加分支（不用重验）。**

**`§I4` 是七个位置里最像 B-tree 遗产的一个**：它「能装下」三个差异极大的方向，
但**装得下 ≠ 装得好** —— 每次都要多花点东西。本版把「恰好两个」这条 B-tree 遗产
去掉了（改成 k 叉），C 的层数开销随之消失（7 → 5，§I4）；
而 A 花掉的那部分**不是 `§I4` 的形状问题** —— 是 `劈开` 用了「当前成员」（§1 第四行）。

### §10.2 ★ 健全性（第三行）在 B / C 的维护路径上不成立；覆盖不漏（第四行）随之**降级** —— 裁定与落地

**根因是「下降」**：一个项**什么时候**落进 d，不由 d 决定 —— 由**下降**决定
（§I3 代价取最小；取不到 0 也照落）。但由此有**两条**不同的破法，**不能合并成一句**：

    一、**覆盖不漏被破**（`覆盖(父) ⊄ ∪覆盖(子)`）

#### A · `reach` —— 出路 (1) **根记账**（已落地）

`insert` 之前先问 `§I1 命中(根, {x})`：**只有「否」才是否证**。

    否          这是**证明** ⇒ 项按定义不在这次声明的范围内 ⇒ 记一条事件、**不塞进结构**
    是          允许是假阳（§K8）⇒ 不作数，照常插入
    未展开      「不知道」不许被当成「不在」⇒ 照常插入

方向与 §K8 完全一致：**否**是证明，**是**是允许的假阳。

这条规则**不新增接口方法** —— `命中` 已经**就是**那个谓词：
`ideal = {x}` 的单元素查询问的就是「这个方向里有没有 x」。
⇒ **不用重验 §I1–§I7。**

**为什么挂在根上**：一条跨邻域的不变量（Bε-tree）——

> Messages addressed to a key k are guaranteed to be applied to k's leaf or in some
> buﬀer along the **root-to-leaf path** towards key k. **This invariant ensures that
> point and range queries in a B ε-tree have a similar I/O cost to a B-tree.**
> — Bender 等, *An Introduction to Bε-trees and Write-Optimization*, USENIX ;login: 2015

查询是从根沿 `劈开` 往下走的 ⇒ **根在每一条查询路径上** ⇒
那是唯一能保证「记了账就一定会被看见」的位置。

实测（先建 6 维护 30，`reach`）：

    根记账之前     128 / 328
    根记账之后      **0 / 33**        28 项落在根覆盖之外

⇒ 代价落在**范围**上，不在正确性上：那些项在这条方向上检不出来，
但它们**在账上**（`stats()['根覆盖之外']`、账本 `out_of_scope` 事件、流程 B 的逐项报告）。
**「认识」与「纳入」因此必须分开报**（`认识 = 纳入 + 根覆盖之外`）——
合并成一个数就是把「知道」与「收下了」当成一件事。

**为什么不能学 GiST 直接加宽根**：GiST 的 `AdjustKeys` 在每次插入后沿父链上溯，
把父的键**重算成子们的并**：

> **PR2:** Otherwise, **modify the entry E which points to N so that E.p is the Union of
> all entries on N.** Then AdjustKeys(R, Parent(N)).
> — Hellerstein / Naughton / Pfeffer, *Generalized Search Trees*, VLDB 1995

那在 GiST 里是**正常做法**，在本设计里等于**替人改声明** ⇒ 撞 §K4（方向不可变），
并连带 §8.2（外生项一旦允许自我优化，会同时失去可复现性与可解释性）。
⇒ **「根记账」不是不得已的补丁，是「根是外生的」这一条决定的必然形态。**

**「放不进主结构的项」有三条形态，(1) 的选择其实是三选**：

| 形态 | 项在哪 | 查询要多扫吗 | 事后能补吗 |
|---|---|---|---|
| GIN pending list | **旁挂**清单（物化） | 要 | 能（vacuum 时并回主结构） |
| Bε-tree buffer | **节点内部**（物化，随节点落盘） | 要 | 能（消息最终投递到叶） |
| **本设计（已落地）** | **只在账里**（不物化） | **不要** | **不能** |

> If consistent response time is more important than update speed, use of pending entries
> can be **disabled** by turning off the fastupdate storage parameter for a GIN index.
> — PostgreSQL 18 文档 §65.4.4.1

⇒ 不选物化的理由写成「**要快**」（查询不用多扫一份），不是「不该记」。
**两者不可兼得**：不物化 ⇒ 失去「事后还能补进去」的能力。

#### A′ · `reach` 出路 (3)：子 payload 从父派生（**已裁定：不采纳**，2026-10-07）

⚠️ **它声称要治的靶子不存在。** 出路 (1) 根记账落地之后实测
（`outputs/_probe_reach_internal.py`，36 项语料，**分方向**数越界）：

    一次建完            71 方向 / 224 成员 / 越界 **0**   （根 0 ｜ **内部 0**）
    维护 30（先建 6）    15 方向 /  33 成员 / 越界 **0**   （根 0 ｜ **内部 0**）  根覆盖之外 28

而且这不是「被修掉了」，是**按定义不可能有**：

    一个项成为方向 d 的成员  ⟺  `代价(x, payload(d)) == 0`  ⟺  `x ∈ payload(d)`
    而 `payload(d) ⊆ reachable(payload(d)) = 覆盖(d)`
    ⇒ `members(d) ⊆ 覆盖(d)` **恒成立**

根是唯一例外 —— 它的 payload 是**外生声明**的锚点集，项从根进入时**不过那道判定**。
⇒ 原来的越界**全部**由根引起，内部那批只是**根越界的下游效应**（那些项先在根上越界，
再往下走，落进它们不满足的内部方向）；出路 (1) 在根上拦住 ⇒ 下游那批**根本没进结构**。

⇒ **(3) 现在只剩「把 28 个根覆盖之外的项收进来」这一条范围收益**，
而那条已由出路 (1) 换成**一条显式的账**（`stats()['根覆盖之外']` / `out_of_scope` 事件）。

**代价（若采纳）必须说清，因为它是两向的**：

    `payload(子) ⊇ payload(父)` ⇒ `覆盖(子) ⊇ 覆盖(父)`（覆盖对 payload 单调）
    ⇒ 树在**覆盖**意义上不再变细
    ⇒ §7.7 的 `min子` 谓词**每次都成立** ⇒ `B19` 连续 N 次 ⇒ **红**

⚠️ 这里两个读数**恰好一致**（度量 `细化量` 也恒为 0）—— 因为「**每个**子都 ⊇ 父」
比「**最大的那个**子 ⊇ 父」更强。§7.7 那次改谓词要处理的**不是**这种情形，
而是「**有些**子在变细、最大的那个没变」。

⚠️ **外部对照也要说清**：Godin 等 1995 把「子比父细」做成**序的定义**，
而它的新 intent 是**收窄**：

> These new pairs are always in the form **(Y ∪ {x\*}, Y' ∩ f\*({x\*}))** for some pair
> (Y, Y') ∈ G.
> — Godin / Missaoui / Alaoui 1995

⇒ Godin 只印证「**派生**」这个机制，**不**印证「加宽」这个做法。
走了 (3)，本设计**就不再是 Godin 意义上的格** —— 会变成
「**成员变细、覆盖变粗**」的两向结构。**这是 (3) 的真实代价。**

---

**盘上的三条派生机制，答案一致：收窄，不并**（正文与出处见 §2.4(h)）

| 机制 | 装不下时怎么做 | 已有节点的键 |
|---|---|---|
| Godin 1995（新节点） | 新建 `(Y ∪ {x\*}, Y' ∩ f\*({x\*}))` | **不动**（Table 2 第 1 类 `X'` 一栏写 `No change`） |
| ART 2013（前缀不符） | 新建节点，前缀取**公共前缀** | 有效键**不变**，只重新分配存储 |
| 空间分解（k-d / quadtree / SP-GiST） | 加深一层 | 子区域 ⊆ 父区域（**这是分解的定义**） |

⇒ **「子 payload 加宽到父 payload」在盘上的文献里没有前例。**
唯一一次「并 intent」（Godin Algorithm 1 第 8 行）产出的节点 extent 是 **`Ø`** ——
那是**格底**，不是装数据的节点。
而所有「加宽」的前例（GiST `AdjustKeys` / BRIN / X-tree supernode）都是**自下而上**加宽**父**，
且都不改「子比父细」这个方向 —— **与 (3) 方向相反。**

**加宽撞的不是 §K8，是 §7.7**

    假阳      §K8 **允许**（代价记在性能上）⇒ 加宽在**契约**这一层站得住
    没变细    §7.7 的 `min子` 谓词每次成立 ⇒ `B19` 连续 N 次 ⇒ **红**

⇒ 所以 (3) 的代价**不在正确性**，在**「这个结构还叫不叫分层」**。

**（下面这半只在「采纳 (3)」的前提下才需要 —— 现已不需要，留作记录）**

**要落地，先得定一件事：`payload` 分两半**

    `payload(d) = 这一层自己声明的锚点  ∪  从父继承来的锚点`

    `members ⊆ 覆盖`  由**继承**那半保证 —— 沿路径归纳：`覆盖(子) ⊇ 覆盖(父)`，
                      而链的顶端由出路 (1) 的**根记账**守住（不在根覆盖里的项不进结构）
    `B19` 的「变细」   只算**自有**那半 —— 否则加宽会把「变细」也一起抹掉

外部对照：Godin 的「Modified node」只改 extent、**不改 intent**；ART 只重新分配存储、
**不改有效键**。⇒ 「**哪些是这一层自己说的**」与「**哪些是继承来的**」在两边**本来就是分开的**，
不是本设计新造的区分。

⚠️ **但这是裁定，不是实现细节**：分两半会让 `payload` 从「一个集合」变成「一个有序对」，
`§I4` 的签名、`encode` / `decode` 都要复核。

⇒ **2026-10-07 裁定：不采纳。** 理由是靶子不存在（见本节开头那张读数），
而代价（`B19` 红 / `payload` 变有序对 / 文献无前例）一样不少。
**28 项留在账上** —— 与下 B 末的处置同形：把一条静默的错换成一条显式的账。

⚠️ **复核点**：本读数在 36 项语料上是**穷尽**的（先建 6 维护 30 = 全部 36 项）。

那意味着本裁定的前提破了，要重新裁定。

#### B · `sequence` —— 出路 (4) **项留在父方向**（**已落地**）

    父的覆盖是 `{x : p ⊑ seq(x)}`，`p` 后面那个符号来自**无穷字母表**，
    而子方向只能枚举**当前成员**用到的符号
    ⇒ 一个带**新符号**的项，任何子方向都收不住

**出路是四条，不是三条**：

| 出路 | 内容 | 代价 |
|---|---|---|
| (1) | 加一个 **catch-all 子方向**（payload = 父的前缀本身） | 覆盖不漏成立，但它永不细化、叶容量变大、`B17` 可能破 |
| (2) | 子方向枚举**整个世界**在该位置的字母表，空桶也建 | 要同时放宽 §K2 与「不存在空壳方向」 |
| (3) | `insert` 遇到收不住的项就**拒绝 / 记事件**（同 A 的机制） | 同 A：代价在**范围**（项从**成员集**里消失） |
| **(4)** | **不新增子方向、也不拒绝 —— 让项留在父这一层** | 不动 §K2、不动 §I4；代价在**划分**（项仍在父的覆盖里，父的 `命中` 说「是」） |

**(4) 的触发条件**由空间索引那边独立印证（X-tree）：

> The X-tree therefore **avoids overlap whenever it is possible without allowing the tree
> to degenerate; otherwise, the X-tree uses extended variable size directory nodes,
> so-called supernodes.**
> — Berchtold / Keim / Kriegel, *The X-tree*, VLDB 1996

> **Supernodes are created during insertion only if there is no other possibility to
> avoid overlap.**
> — 同上

⇒ (4) **不是默认档，是最后手段** —— 与 §K2 的字面同形（**先试建，建不出来才不建**）。

**落地的形态**（`ldv/core/kernel.py::insert`）：下降**只进入「没有证明不收它」的子方向**。

    ok = [k for k in kids if not 证明不收(k, x)]
    if not ok:   ⇒ 记一条 `stayed` 事件（挂在**父**上），**停在这一层**
    else:        ⇒ 照旧按 §I3 代价最小往下走

「证明不收」= `命中(k, {x}) = 否`。**`是` 与 `未展开` 都放行** ——
与 §K8 的不对称同一条纪律：假阳允许（代价是性能），假阴禁止。
⇒ 不用新增接口方法，**不用重验 §I1–§I7**（`命中` 已经就是那个谓词）。

**为什么选 (4) 而不是 (3)（这是本节唯一一处与原裁定的偏离，理由必须写下来）**：

    (3) 拒绝     项从**成员集**里消失 ⇒ `B1` 的 ground truth 正是「成员 ∩ 查询」
                 ⇒ 「健全性变绿」会**部分来自数据变少** —— 那是把代价藏进读数里
    (4) 留父     项**仍在** `members(父)` 里 ⇒ ground truth 不动、项仍可检索
                 ⇒ 代价只落在**划分**上（这一层表达不出来，不是「声称盖不住」）

⇒ 同一份结构上实测：`members ⊆ 覆盖` 都转绿，但 (4) 把代价**记成了另一条账**（`滞留`）。

**单变量对照**（先建 6 维护 30，逐 k）：

    方向        方向数  最大叶容量  最大停留数  滞留   成员总数  越界      漏
    ─────────────────────────────────────────────────────────────────────────
    改前（照塞）  20        10         10        0      176    36/176    16
    改后（留父）   8        10         10       16       86     0/86     16

    ⚠️ **漏项数两边都是 16，一个数没动。** 出路 (4) 修的是**健全性**，
       不是「覆盖不漏」（§1 表第四行，⬜ 2026-10-07 已降级）—— 出路 (1) 的 catch-all 才管那一条。
       ⚠️ 但这 16 个漏项与那 16 个滞留项**是同一批项**（实测双向差 0）⇒
       **「两条机制」的说法要改口径**：是**同一批项**的两种**处置**。
       别把这一条的绿灯记到那一条头上。

⚠️ **`B4` 因此收窄了**（**已落地**，`checks/contract.py::b4_split_is_partition`）。
`B4` 原来查 `∪members(子) == members(父)`；(4) 之下改成**「漏的恰好是账上那些」**：

    ∪members(子) ⊆ members(父)
    members(父) − ∪members(子) = 滞留集（必须与账上的 `stayed` 事件逐项相符）

那是**收窄判据**，不是放宽 —— 「不重不漏」变成「**不重，且漏的恰好是账上那些**」。
⇒ 它现在是**两条**判据，各自独立注入验证：

    第一条  不重：∪members(子) 里没有重叠、没有多余的项
    第二条  漏的条条有账：`漏集 == stayed_of(父)`
            ← 注入：把账上的 `stayed` 事件**全删掉**，第二条必须红

⚠️ **第二条判据在批建路径上验不出来**（那里滞留恒为 0 ⇒ 两边都是空集 ⇒ 恒真）。
   注入必须跑在**真有滞留**的结构上（`sequence`，先建 2 维护 34，实测滞留 32）——
   否则「判据成立」只是「没有东西可判」的另一种说法。

**顺带挖出来的一个数的盲区**：`叶容量` 默认**每一项都走到了叶**，(4) 之后不成立。

    实测（`sequence`，先建 2 维护 34）：
        叶容量      **2**     ← 看起来分辨率很高
        最大停留数  **34**    ← 真相：34 项堆在**根**上（根是内部节点）

⇒ 补 `最大停留数`（`停(d) = |members(d) \ ∪members(子)|`，**从成员集现算**，
不用 `Cone(x)` —— 锥是插入时记的，方向后来才劈开时不会延长）。
它是 `叶容量` 的**推广**：项都走到叶时两者相等（批建路径上三个方向实测相同）。
⇒ 两条**恒等式**（`run_tests.test_stay_at_parent` 查）：
   `停在叶上 + 停在内部 == 纳入`、`停在内部 == 滞留（账上）`。

⚠️ **它不只是「另一个数」，它把 §7.2 的等式前提也补上了**：`叶容量 = 最大等价类`
   只在 `滞留 == 0` 时成立；滞留 > 0 时 `叶容量` 会掉到**下界以下**（实测 2 < 10），
   而下界改由 `最大停留数` 承担（32 ≥ 10）。**叶仍然各自是单个等价类** ——
   掉下去的是尺子的量程，不是分辨率。**`B17` 因此只跑批建路径**（见 §7.2）。

⚠️ **一条「不适用」但排除它比采纳它更值钱的候选**：R\*-tree 的 forced reinsert
（第一次溢出**不分裂**，先把远处的项重插一遍）。

| | R\*-tree 要治的病 | 本节要治的病 |
|---|---|---|
| 病根 | **重叠**，根因是**分裂轴选得不好** | **无穷字母表** |
| 为什么重插有效 | **别的节点接得住**那些项 | **没有任何子方向接得住** |
| 结论 | 采纳 | **排除** —— 无对象可挪 |

⇒ 这个排除**加固了本节的判断**：问题**不是「分裂分得不好」，是「分不了」**。
凡是「换一种分法 / 挪个地方」的办法都够不着它。

##### ★ 第四行（覆盖不漏）与出路 (4) 是**同一个条件的两种说法** —— 裁定：**降级，不加兜底**

**一、实测：漏的项 == 滞留的项**

`sequence` 先建 6 维护 30（`outputs/_probe_leak_vs_stay.py`）：

    方向    漏项   滞留项   漏−滞   滞−漏
    D0        8       8        0       0
    D1        8       8        0       0
    ─────────────────────────────────────
    合计     16      16        0       0

⇒ **每一个漏项都被滞留下了，一个不多一个不少。**
理由也是显然的：滞留的触发条件是「每个子方向都**证明**不收它」= `命中(k,{x}) = 否`，
而「否」按定义就是「`x` **不在** `k` 的覆盖里」⇒ 滞留项天然是漏项。

⇒ **`覆盖(父) ⊆ ∪覆盖(子)` 与「`滞留 == 0`」是同一个条件。**
⇒ 文档里反复说的「**两条独立机制**」要**改口径**：它们是**同一批项**的两种说法，
   差别只在**处置**（(4) 把它留在父上；兜底把它接进一个子方向）。

**二、实测：兜底子方向会接住**全部**滞留项**

出路 (1) 的兜底 payload = **父的前缀本身** ⇒ `覆盖(兜底) = 覆盖(父)`。
直接拿插件问一遍（不是推断）：

    方向    滞留   兜底的 `命中({x})`：是 / 否 / 未展开
    D0        8      是 8   否 0   未展开 0
    D1        8      是 8   否 0   未展开 0
    ─────────────────────────────────────────
    合计     16      是 16  否 0

⇒ 加兜底 ⇒ **滞留归零** ⇒ `滞留` / `最大停留数` / `B4` 收窄 / 出路 (4) 的整套记账
**全部变成空转**；反过来，`B17` 的前提（`滞留 == 0`）**恢复**，它就能跑维护路径了。

⚠️ **但代价一点没少**：兜底的覆盖 = 父的覆盖 ⇒ 进它**一点精度都不涨**
（§7.7 的度量 `细化量` = 0；`min子` 谓词也成立 —— 这里两侧读数**一致**）。
两条路的**假阳代价完全相同**，差的只是**记账形状**。
（`B19` 不会因此红：兜底是**叶**，它下面没有「连续 N 次展开」可数 —— 连续段到它就断了。）

**三、成熟系统里「覆盖不漏」不是要求，是构造的后果**

    R-tree   **AT3**  「Adjust EN.I so that it **tightly encloses all entry rectangles in N**.」
                     （删除路径同形：`CondenseTree` **CT4**）
             ⇒ 父的覆盖矩形 = 子们的并，**按构造成立**
    GiST     **PR2**  「E.p is the **Union** of all entries on N.」
             ⇒ 同上

⇒ 这些系统**不需要**「覆盖不漏」这条要求，因为它们把父的键做成**派生聚合**。
本设计**不能**这么做 —— payload 由**插件声明**、方向**不可变**（§K4，§10.2 A 已论证
「学 GiST 加宽根 = 替人改声明」）。
⇒ **漏是 §K4 的价格**，不是实现没做到。

    SP-GiST 的 `choose` 有「按需加子节点」(`spgAddNode`) 与「放宽前缀」(`spgSplitTuple`)
    两条现成机制，但**两条都不给覆盖不漏**：字母表无穷 ⇒ 加多少个子都不够，
    除非加的那一个**就是父自己**（即兜底）。

**四、裁决：不加兜底；第四行从「硬要求」降为「有代价的度量 + baseline 守卫」**

理由是一条**链**：

    第四行的原始理由是「它是**健全性**的必要条件」（§1 表下那段推导）
    而那条推导在**出路 (4) 落地之后已经被切断** —— (4) 正是「不让项落进它不满足的方向」
    ⇒ 剩下的只有**精度**
    而 §1 已经把精度（第二行 过滤器层）**明说成「不是硬要求，只有度量」**
    ⇒ 第四行与第二行**同类**

⇒ 为一条**已经声明「不是硬要求」**的性质，付一个**没有前例**的新概念
（「兜底方向不再展开」—— 否则它会被再劈一次，造出与兄弟同 payload 的子方向），
并**废掉已落地的** (4) / `滞留` / `最大停留数` / `B4` 收窄 —— **不值**。

    ✅ 保留：`B18` baseline 守卫（冻结既有 16 漏、对**新增**红、条目失效红）
    ✅ 保留：两条路径的漏项读数（**度量**）
    ⬜ 降级：第四行**不再是 §1 的硬要求**，与第二行并列为「有代价的、被度量的性质」
    ❌ 不做：兜底子方向（出路 (1)）

⚠️ **第四行仍然是「最想修的那一条」** —— 它是本设计**唯一**一处「硬要求表里有一行做不到」
的位置，而**做到它的价格是废掉另一套已落地的机制**。这个取舍必须写在 §1 的表里，
不能只在 §10.2 里。

**五、顺带挖出的一处静默缺口：`hit_items` 只在叶上收成员**

修这条时发现（`outputs/_probe_leak_vs_stay.py`）：

    滞留项 16 个 ⇒ 进 `hit_items` 的 **0 个**

`query` 原来是「说「是」⇒ 有子方向就往下走（**不收自己的成员**）；没有子方向才收」。
滞留项停在**内部**方向 ⇒ **父的 `命中` 说「是」，而 `hit_items` 里没有它**。
而 `QueryResult.render()` 照样印「**命中 0 项**」—— 名字像答案、实际不全。

⇒ 这是「空转与通过长得一模一样」的又一形态：**少掉的部分不会让任何东西变红。**
⇒ **已修**（`core/kernel.py::query`：改成**每个说「是」的方向都收**），
   并加 `run_tests.test_query_hit_items`（五条断言，含**反向判据**与**三态不许被带偏**）。
   **注入验证**：改回只在叶上收 ⇒ **289 条里只有那条完整性断言红**（24/86 项没进）。
⇒ 同时删掉一段**空操作**：`if hits: status = …` ——
   `hits` 非空 ⇒ 有方向说「是」⇒ 上面两个分支给出的正是同一个值
   （`fold(是, 未展开) == 未展开`）。留着它会让读者以为「有没有命中项」参与了三态判定。

**「收不住的项」不进 `Tri`**（不是第四态）：成熟答案的做法是**标记挂在元组上、答案仍是三态**。

> … if the picksplit function ends up placing all the leaf tuples in the same node, the
> core SP-GiST code will **override that decision** … Such a tuple is **marked
> allTheSame** to signify that this has happened. **The choose and inner_consistent
> functions must take suitable care with such inner tuples.**
> — PostgreSQL 18 文档 §65.3.4.2

⇒ **不动 §K6、不用重验**。

#### C · 删除流程（`§M2` 情形③）（**已落地**）

前例逐字见 `分层方向视图-成熟方案与跨领域文献.md` §2.4(i)；落地前要定的事见同文件 §4.7。

##### 先分清：四条前例治的是**四种病**，不是四选一

| 病 | 前例 | 本设计 |
|---|---|---|
| 账本要留痕 | Bε-tree tombstone | **要**（`§K4` / `B9` 直接要求） |
| 向上递归 + 重新连接 | Godin 1995 §3.4 | **要**（遍历骨架） |
| 父的覆盖要收缩 | Guttman 84 `CondenseTree` CT4 | ⬜ **不采纳** —— 前提在本设计里不成立，见下 |
| 单子节点冗余 | ART `Path Compression` ｜ SP-GiST `Tree Shrink` | **本流程不产生**（见下） |
| 与兄弟合并 | B-tree | **排除** |

> **Tree Shrink:** The internal nodes are merged together to **eliminate all single child
> internal nodes**. This strategy is adapted from structures like the **Patricia trie** …
> — Aref & Ilyas, *SP-GiST*, JIIS 17:2/3 2001

##### 「不删」管的是**结构**，不只是账本

`§M2 情形③` 的原文是「**标记**「曾由 `W` 强制，现已不成立」—— **不删**」。
它的理由句给了判据：「「这个方向不再被强制」和「这个方向从来没存在过」必须分得开」
—— 而**分得开**靠的是**方向还在**（`_dirs` 里查得到 + 账本里有记录）。

⇒ **「不删」同时管住结构**：方向不从树里摘掉，`_children` 也不动。

⇒ 三条处置的裁决：

    把项重插回树    **不发生** —— CT6 的前提是 CT3 压掉了节点；不压 ⇒ 没有孤儿
    与兄弟合并      **排除** —— Guttman 逐字：`there is no adjacency in the B-tree sense`
    压掉单子方向    **不发生** —— 单子只在**删掉节点之后**才出现（ART 逐字「**now** has
                    only one child」）；不删 ⇒ 不产生单子

⇒ 而且这三条**互相关联**：压单子与「不删」**不可能同时成立** ——
   挑「不删」，菜单就只剩 CT4 那一条。

##### 流程：两件事（原写的第三件**不采纳**）

    ① 把 `x` 从 `items` 与 `members(D)`（`D ∈ Cone(x)`）里去掉
    ② 对 `D ∈ Cone(x)` 的每个方向追加一条**失效事件**（账本只增不改 —— `B9`）

**不删方向、不动 `_children`、不压单子、不与兄弟合并、不把项重插。**

次序依据：Godin §3.4 说「从**最低的**含该项的方向起、**向上递归**」，
且「`much easier than adding an instance`」；Bε-tree 说删除**复用插入那条路**
（「deletes are encoded as messages, deletions are algorithmically very similar to insertions」）。

##### ③「向上收缩父的 payload」——**不采纳**，理由是它的前提在本设计里不成立

原文把 ③ 写成**硬要求**（Guttman CT4 的对应），理由是：

> 删掉 `x` 后 `members` 变小，**若 `payload` 跟着收窄**，`∪覆盖(子)` 就变小
> ⇒ 父的 `payload` 不跟着收窄就红。

**那句话里有一个条件句。** 它的前提是 `payload` 是**从 `members` 派生的聚合**
（R-tree `AT3` / GiST `PR2` 逐字：`E.p is the **Union** of all entries on N`）。
本设计**不满足**这个前提：

    `payload` 由**插件声明**，`Direction` **不可变**（`§K4` 的结构保证）
    删一个成员**不改变**任何 `payload`
    ⇒ `覆盖(父)` 与 `∪覆盖(子)` **两边都不动**
    ⇒ `B18` / `B16` 在删除路径上**按构造不变**

实测（`ldv/MEASUREMENTS.md` 结果十一，随仓库 36 项语料、删最后 1/3）：
三个方向上 `B16` / `B18` 的**逐方向读数**一个都没动。

⇒ 采纳 ③ 得先推翻 `§K4` 的不可变 —— 而「改父的键」这条路在 `§10.2 A`
   已经因为同一个理由被排除过（根是**外生**的 ⇒ 改它等于替人改声明）。
   ⇒ **不采纳**，并在 `Kernel.remove()` 的 docstring 里写明为什么。

⚠️ **不采纳 ≠ 不检查**。前提「payload 不随 `members` 收缩」**必须被守**：
一旦将来有人改了 `remove()` 让它动覆盖（例如真去实现 ③），
`D2` / `D3` 就该开火。所以下面六条里 `D2` / `D3` **照配**，
只是它们在这一版上按构造恒绿 —— 它们是**守卫**，不是会开火的判据。

##### ⚠️ 失效的方向**继续答查询**

    若「失效」被实现成「不参与检索」⇒ 成员还在语料里、查询可能命中 ⇒ **假阴**
    ⇒ §K8 的唯一禁令被破

⇒ **标记只影响账本，不影响 `命中`。**

##### 工作量的界：`Cone(x)`

Godin §3.4 逐字：「The number of pairs to examine is **limited to pairs (X, X')
where X' ⊆ f({x})**」—— 这就是我们的 `Cone(x)`，
与 `B8`（插入路径的「变动 ⊆ `Cone(x)`」）是**同一个界**，只是路径不同。

##### `§I4` 的 `None` 在删除路径上**不适用**（原来那条口径问题消失）

    删除路径**不调 `劈开`**：
      标记   不碰结构
      收缩   ⬜ **不采纳**（见上）—— 所以这条路也不经过它
      重插   不采纳（CT6 的前提是 CT3 压掉了节点；不压 ⇒ 没有孤儿）
    ⇒ 不是「同义」，是「**不适用**」。要写进文档，否则下一个人会以为漏了。

#### D · 持久化 / 并发（**已落地**：P6 = `core/persist.py`，P8 = `core/locking.py`）

这一节的**前置问题**是「方向节点的入度是不是常数」。答案是**两条边的**：

| 按哪条边算 | 是什么 | 入度 | 实测（36 项语料，三个方向） |
|---|---|---|---|
| **`_children[父] = (子, …)`** | 语义边：**父 → 子** | **1，常数** | 非根方向**恰好一个父**，根 0 个 |
| `Direction.parent` / `witness` | 存储边：**子 → 父**（反指针） | **= 扇出，不常数** | 扇出 max **7**（`sequence`；§I4 是 k 叉） |

> Let d be the number of pointer fields in an ephemeral node and let **p be the maximum
> number of predecessors of an ephemeral node in any one version**. We assume that
> **p is a constant**.
> — Driscoll / Sarnak / Sleator / Tarjan, *Making Data Structures Persistent*, JCSS 1989

⚠️ **「入度」这句话本身不完整 —— 它取决于把哪条边物化成指针。**
本设计**同时物化了同一个关系的两条边**（`_children` 与 `parent`/`witness`），
所以「入度是 1」和「入度是扇出」**同时成立**，只是各自说了一条边。

**为什么这决定成败**（node-copying 的原话）：

> We must also store pointers to the new copy in **all predecessors** of the copied
> node in the newest version. If there is no space in a predecessor for such a pointer,
> the predecessor, too, must be copied.
> — Driscoll 等 1989

copy 一个方向，要改**它所有前驱**的指针：

    按**父 → 子**算 ⇒ copy 子 ⇒ 只改 **1** 个父     ⇒ 摊还 **O(1)**   ✓（正是 `p` 常数那一条）
    按**子 → 父**算 ⇒ copy 父 ⇒ 要改**扇出**个子     ⇒ **O(扇出)**，扇出不常数 ⇒ node-copying **断掉**

> (iv) Find a more efficient way than the fat node method to make linked structures of
> **unbounded in-degree** persistent. **The node-copying and node-splitting methods
> completely break down in this case**; the fat node method needs only O(1) space per
> update step but increases access times by a **logarithmic factor**.
> — Driscoll 等 1989 §6（未解决问题之四）

⇒ **裁决**：本设计**声明为树**（每方向 ≤1 父）；持久化层**只认 `_children` 为权威边**，
`parent` / `witness` 是**可从 `_children` 重算的派生索引**（两条边互为转置）。

三条理由：

1. **实测就是树**（上表）：三个方向 × 批建/维护/涌现，非根方向的语义入度**处处为 1**。
2. **不需要多父**。`§M2` 情形④（涌现）**已经落地为「叶长出新层」**（`split`），
   不是「多个细方向合并成一个粗方向」。`ORIGIN_EMERGENT` 这个来源**从未被构造过**。
3. **代价不对称**。树 ⇒ node-copying（**O(1) 访问旧版本**）；
   保留 DAG 的可能性 ⇒ 只能 fat node（**O(log m) 访问**）。
   「留着以后可能用」的代价是**永远付 O(log m)**，而这笔代价**现在没有买家**。

⚠️ **多父（DAG）是「具名留白」，不是删掉**：`Direction.witness` 是**元组**、
`ORIGIN_EMERGENT` 已声明、§I2 的 `合并({细})` 收的是**一组**。
谁要启用**合并涌现**，**先要接受**：§10.2 D 从 node-copying 掉到 fat node，
且 §K5 的 `max(rank(父))` 要**回改**（现在是单父）。

##### 这条前提原来**没有任何检查守着**

`§K5` 的原文是 `rank = 1 + max(rank(父))` —— 那个 `max` 是**为 DAG 写的**；
`B13` 原来只查「无环 / 无自环 / 见证更粗」⇒ **对 DAG 照样放行**。
实测（`outputs/_probe_b13_gap.py`）：把一个子方向再挂到**第二个父**下面
（语义入度 1 → 2），`B13` 仍报「是」。

⇒ 这是「空转与通过长得一模一样」的又一形态：**前提成立与否，判据上长得一模一样。**
一个「入度恰好是 1」的结构与一个「入度变成 2」的结构，在 `B13` 的结论上**没有区别**。

⇒ **修法：把「树性」写进 §K5，并并进 `B13`**（不另开一条 —— 两者守的是**同一个东西的形状**，
分开写会出现一个「无环但有多父」的中间态，而那个中间态**没有设计含义**）：

    P1  无自环                            `d ∉ d.witness`
    P2  见证更粗且存在                     `rank(见证) < rank(d)`
    P3  父链终止（无环）                   逐级上溯必须落到根
    P4  **树性**                          非根方向**恰好一个父**；根没有父；
                                        `parent` 与 `_children` **互为转置**；
                                        `witness == (parent,)`（§6.1）
    P5  扇出**报**在 detail 里             node-copying 的成本侧读数，**不进退出码**

⚠️ **编号用 `P` 不用 `D`**：`§10.2 C` 的删除判据已经占了 `D1–D6`。

**注入验证**（新增 `B13·树性`，走 `EXTRA_CASES`）：注入改在**最贴近判据的那条边**上 ——
`_children` 是唯一写「父 → 子」的地方，所以把一个已有的子方向**再挂到第二个父**下面，
就造出了一个 DAG。基线绿、注入红（`31/31`）。

⚠️ **注入不能只改 `parent` 字段**：那只让两条边**打架**（`D4` 的另一半），
而入度本身没变 —— 测不到树性。

##### 并发那一半

争用点由**锥**决定（§K3：失效范围 ⊆ `Cone(x)`）。实测：**36/36 条锥都以根开头**，
且**每条长度都 > 1** ⇒

    **根是全局必经点** ⇒ 它是并发写的**唯一公共争用点**（共享前缀越短，争用越少）

而树性在这里给的是**锁的作用域**：改一个方向只需接触**它那一个父**
⇒ 锁沿着**路径**局部化，**不会级联到无界个前驱**。
若按「子 → 父」那条边加锁，改一个父就要锁住**扇出个**子，而扇出不常数
⇒ 锁的集合**无界**，并发写会级联 —— 这与 node-copying 断掉是**同一个原因**。

**两条外部印证**（都在 B-树那一支，且都是**已核**）：

> 「Deadlock freedom is guaranteed by the **well-ordering of the locking scheme**, as shown below.」
> — Lehman & Yao 1981, p.660（§6.1 死锁自由）

> 「The solution given above for insertion uses **at most a constant number of locks** (three)
> for any process at any time.」
> — Lehman & Yao 1981, p.668（§8 LOCKING EFFICIENCY）

⇒ 本设计的锁**良序**来自「下降 = 秩递增」（与 `remove` 一次拿锥的顺序**同一个**），
**有界**来自「作用域 = 锥」而不是「扇出」。

⚠️ **Lehman–Yao 里「锁整个树」是特例，不是常态**（同一篇 p.668）：

> 「In situations where excessive deletions cause the storage utilization of tree nodes to be
> unacceptably low, a batch reorganization or an underflow operation which **locks the entire
> tree** can be performed.」

⇒ 全局锁在成熟系统里**有它的位置**（批整理/欠满重整），但**不是**常规写路径。
本设计**没有**批整理这条流程（`§10.2 C` 已裁定不压单子、不合并），所以**连那个特例都没有**。

**PostgreSQL 的做法**（`src/backend/access/nbtree/README`，2026-10-07 的 `master`）
把「锁的作用域 + 顺序」写得很直白：

> 「In most cases we release our lock and pin on a page **before** attempting to acquire pin
> and lock on the page we are moving to. In a few places it is necessary to lock the next page
> before releasing the current one. This is **safe when moving right or up, but not when moving
> left or down** (else we'd create the possibility of deadlocks).」

> 「…This is **the only point where Lehman and Yao have to simultaneously hold three locks**
> (a lock on the child, the original parent, and the original parent's right sibling).」

⇒ 「先放父再拿子」还是「先拿子再放父」，**不是风格，是可不可能死锁** ——
两者分别对应「往哪走」这一个变量。本设计只有一个方向（根 → 叶），
所以顺序只有一种：**秩递增**。

##### 现状的形态与代价（Overmars 的第二条办法）

| 形态 | 空间 | 访问版本 i | 本设计现状 |
|---|---|---|---|
| 显式存每版 | Θ(n)/次更新 | O(1) | 否 |
| **只存账 + 重放** | **O(m)** | **Θ(i)** | **是** |
| 每隔 k 版存一份（混合） | O(m) + 快照 | O(i/k + k) | 否 —— 可选的升级 |
| fat node | O(1)/步 | O(log m) | 否 |
| node-copying | O(1)/步（摊还） | **O(1)** | 否 |

> An alternative method is to **store no versions but instead to store the entire sequence
> of update operations, rebuilding the current version from scratch each time an access is
> performed.** … **accessing version i takes Θ(i) time** …
> — Driscoll 等 1989

⇒ **只要「能回看旧版本、不要求快」⇒ 现状就够**，但**必须把代价写进文档**：
访问版本 i 是 **Θ(i)**。不写，读者会把「能回看」读成「回看很快」——
那是「空转与通过长得一模一样」的另一种形态：**能力在，代价没写**。

**落地清单**：

    P1–P4  §K5 / `B13` 的树性                   ✅ **已落地**（本版；注入 `B13·树性`）
    P5     扇出读数                              ✅ **已落地**（`stats()['最大扇出']` + `B13` detail）
    P6     **持久化层只认 `_children` 为权威边**  ✅ **已落地**（`core/persist.py`）
    P7     访问版本 i 的代价写进文档（Θ(i)）      ✅ 本节（上表）
    P8     并发：锁沿路径局部化，根是公共争用点    ✅ **已落地**（`core/locking.py`）

⚠️ **P6 是 P1–P5 的**兑现**，不是可选项**：`B13` 只保证**内存里**两条边不打架；
一旦落盘时把 `parent` 和 `_children` **各存一份**，两者就可能**漂移**，
而漂移之后的症状正是「node-copying 悄悄按错了那条边」——
检查还在、还绿，代价已经换了。

##### 落地（P6）：**两条边只存一条** —— `core/persist.py`

存档里**只有一个方向的边**：`_children`。`parent` / `witness` **读回时现算**
（`derive_parents`），`witness` 连算都不用单独算 —— `§6.1` 定死了
`子.witness == (父,)` ⇒ 它是 `parent` 的函数。

**外部印证**（PostgreSQL `src/backend/access/nbtree/README`，2026-10-07 的 `master`）：
它的磁盘格式里**只有 downlink（父 → 子）**，**没有**子 → 父指针；要找父页：

> 「The parent page must be found using the same type of search as used to find the parent
> during an insertion split.」

⇒ 那是**同一个裁决**：**子 → 父那条边根本不落盘**，需要就重算。
而且它证明这条边**可以事后补**：

> 「Our approach is to create any missing downlinks **on-the-fly**, when searching the tree
> for a new insertion.」

⚠️ **但它补的是权威边**（downlink 就是权威边，只是可能因崩溃而缺），
本设计**不补**任何东西 —— 权威边缺了就是存档坏了，当场报错（见下）。

**四条判据 + 两个「错一处」的对照**（`run_tests.test_persistence`，三个方向各一遍）：

    P6-1  **往返逐字相同**       `from_dict(to_dict(k))` 与原件在结构指纹上逐项相等
    P6-2  **存档里没有派生边**    `方向` 的每一行不含 `parent` / `witness`
    P6-3  **派生边可重算**        与内存里的 `parent` / `witness` 逐项相符
    P6-4  **存档幂等**            同一份结构 ⇒ 同一份字节
    P6-5  ★ **权威边不是树 ⇒ 当场报错**（同一个子两个父、悬空方向、格式号不符）

    对照① `_to_dict_storing_derived`   落盘时**也存一份**派生边（`§10.2 D` 说的「各存一份」）
    对照② `_from_dict_trusting_derived` 读回时**信任**存档里的派生边，不重算

**注入实验**（★ 这一格是本轮最值钱的地方）：

    取一份**带派生边、且派生边已漂移**的存档（漂移**不动**权威边 —— 那正是
    「两份曾经一致、后来只改了一份」的形态），两个 loader 各读一遍：

        漂移量        权威 loader（只认 `_children`）   双份 loader（信任存档）
        ────────────────────────────────────────────────────────────────────
        未漂移        == 原件 ✓                        == 原件 ✓   ← ⚠️ **同输出**
        一处漂移      == 原件 ✓                        ≠ 原件 ✗   ← ★ 对照在这里分开
        全量漂移      == 原件 ✓                        ≠ 原件 ✗

⚠️ **「未漂移时两个 loader 同输出」这一行必须留着。** 它说的是：
**光测「读回来对不对」是测不出「只存了一份」的** ——
两个实现在**干净**的存档上产出完全相同的结果。
⇒ 判据 P6-1 单独**不足以**支撑这个裁决；**注入必须造出漂移**。
（少这一行，就会出现一个「看起来在测 P6、其实只是在复述 loader 实现」的判据。）

**★ P6 的兑现点：读回来的内核也要过 `B13`。** 落盘/读回是**第二个入口**，
而 `B13`（含 P4 树性）只跑在**内存**那一侧。实测：

    只认权威边 ⇒ 读回后 `B13` 报「是」
    信任派生边 ⇒ 读回后 `B13` 报「否」（`D13.parent=D0，但它不在那个父的子列表里（两条边打架）`）

⇒ 「检查还在、还绿」这次**没绿** —— 因为检查被真的接到了第二个入口上。

**三处「不落盘」，形态不同、理由同源**：

    `parent` / `witness`            可从 `_children` 重算        ⇒ 不存（本节主语）
    `_shown` / `_last_frontier`     **会话态**，不是结构态        ⇒ 不存
    `reach` 插件的距离/可达缓存      **派生状态**，可从图重算      ⇒ 不存

第 3 处是**同一条纪律在插件那一层**的实例：读回之后缓存是**冷的**，
但 `代价` 读数**逐项相同**（实测，`test_persistence` ⑩）。
⚠️ 第 2 处有个可验的后果：一个刚读回来的内核**这一轮什么都没展示过** ——
把上一轮的展示次序灌进去等于**替它伪造曝光位次**，而倾向权重正是从位次算的（§8.1）。

##### 落地（P8）：**锁的作用域 = 锥** —— `core/locking.py`

锁的粒度 = **方向**，作用域 = **锥**（`PathLocks.scope` 就是一行 `frozenset(cone)`）。
它这么短，是因为**结构**已经替它做了事：树性保证「改一个方向只需接触它那一个父」。

    P8-1  **作用域 = 锥**          `insert` / `remove` 拿的锁**恰好**是它走过的路径
    P8-2  **根是唯一公共争用点**    所有锥的**公共**交 == `{根}`
    P8-3  **与扇出无关**           路径锁 max **7** < 扇出锁 max **13**（三个方向）
    P8-4  ★ **互斥**（barrier）    真锁绿 / **空锁红**（已知答案）
    P8-5  ★ **反向判据**           `LockedKernel` 与 `Kernel` 跑出来**逐字相同**

⚠️ 而**更强**的一条是改 `Kernel` 本身之前/之后的单变量对照：
同一趟 `cli all --remove 12` 的输出 **102 行，`diff` 0 处差异**（`MEASUREMENTS` 结果十二 §五）
—— 把三个函数体重排成「每步进出一次钩子」**没有动任何一个读数**。

    对照① `GlobalLocks`  全局一把锁    ⇒ P8-1 / P8-2 红
    对照② `FanoutLocks`  锁 `d` 连带锁它所有的子 ⇒ P8-1 / P8-2 / P8-3 红

⚠️ **P8-1 与 P8-2 在本批语料上由同一个事实推出**（锥都从根开头、且没有别的方向在所有锥上）
⇒ 两个对照会**同时**带红两条。这是**真耦合**，照实打印，不挑一条来报 ——
一个「只报自己那条」的对照是**被挑选过的**证据。（同 `§10.2 C` 的 `D6 → D2`。）

**⚠️ 本轮挖出来的一条边界：「作用域 = 锥」不蕴含「线程安全」。**

    作用域    哪些**方向**要锁 —— 由锥决定，**P8 的判据守的就是这个**
    线程安全  所有**共享可变状态**都进了某个临界区 —— **更大的**一件事

⇒ 结构锁之外还有两处**粒度 O(1)** 的短临界区，它们**不是结构锁**、**也不随扇出变**：

    `Kernel._new`      方向编号的分配（`_counter += 1` + `_dirs[did] = d`）
    `Ledger.append`    账本只追加（`_seq += 1` + 两次 `list.append`）

    ⚠️ 它们**没有**被「锥」覆盖 —— **两个互不相交的锥也会在这里相遇**。
       所以「根是**唯一**公共争用点」这句话**只在结构锁这一层成立**；
       把它读成「整个内核只有根一个相遇点」就**说错了**。

⚠️ **仍未覆盖的**（不声称）：插件自身的可变状态（`reach` 的缓存是**同一个实例**共享的）、
`Kernel.items` / `_path` 的单键写（CPython 下单次 dict 写是原子的，但**不是**契约）。

**★ 一处真的绊脚石：手递手（crabbing）不能顺手做。**

`insert` 的成员那一笔写在**下降结束之后**（`for did in path`），不是随行写 ——
而这不是随手写的顺序，它**决定了分裂语义**：

    随行写   走到 d 时先 `members(d) += x`，再 `expand(d)`
             ⇒ **祖先**会看见这个新项 ⇒ 祖先**可能因为这次插入而分裂**
    末尾写   走到 d 时 `members(d)` 里**还没有** x
             ⇒ 祖先的分裂**不受这次插入影响**

两者**不是**同一个算法：随行写会让「先建 6 维护 30」的结构与批建**不同**，
而 `test_emergence` ③ 钉住的正是「尺度与分辨率**不随建法变化**」。

⇒ 后果直接落在并发上：**手递手到那时已经放掉了祖先的锁**，而末尾那一笔要写**整条锥**。
本实现因此**持有整条锥**（`ExitStack` 逐层进、末尾一起出）。
这与「根是唯一公共争用点」一致（锁的**集合**仍是锥），
但「同时持有几把锁」是**另一个读数** —— Lehman–Yao 的 **3** 是手递手之后的数，
**不是**本实现的数。两个数不能混着引。

**★ 另一处：并发**测不出**并发。** 实测（`outputs/_probe_locks.py` ⑤）：

    8 线程 × 120 项插入，同一份语料：
        真锁（锥上拿锁）   方向 27｜编号唯一 ✓｜异常 0｜账本 seq 连续 ✓
        全局锁              方向 27｜编号唯一 ✓｜异常 0｜账本 seq 连续 ✓
        **空锁**            方向 27｜编号唯一 ✓｜异常 0｜账本 seq 连续 ✓   ← ⚠️ **也全绿**

⇒ 压力测试下「空锁与真锁长得一模一样」—— 临界区太短、GIL 帮了忙。
**所以互斥不靠压力测试判**，靠一个**确定性的**探针：用 `threading.Barrier(2)`
逼两个线程**同时**想进同一个方向的临界区 ——
真锁下两个都超时（谁都没进去），空锁下两个都进去（barrier 放行）。
这一条**必然**红，不靠概率。

#### 为什么这一节值得单列

它是本设计**第一次**遇到「一次建完与维护路径不是同一件事」
—— 而两条路径的差别**不是精度，是流程**。`B16` 存在、是绿的、写在 §7 的表里，
却从没跑在出问题的那条路上。这正是「**空转与通过长得一模一样**」在
**检查设计**上的形态，而不是在检查结果上。修法要动的不是某一行代码，是
**「一条硬要求该在哪几条路径上量」**。

## §12 一句话收

**内核通用 + 接口通用 —— 方向由人声明，方向内部的参数交给使用。**
接口是七个方法，插件允许不准（假阴除外）。
**三个**差异极大的方向（键集包含 / 锚点可达 / 顺序前缀）都只用这七个位置跑通，
且 `§I4` 的签名改动（k 叉 / 显式「分不开」/ 带上父方向）**没有推翻任何一条接口条款**
⇒ **接口押对，内核冻结**。

⚠️ 但「接口押对」不等于「已经没问题」。本版挖出来的是**检查的覆盖缺口**，
而且**缺口有两种形状**：

    **尺子错了**   `B16` 按 `§I3 代价` 重算归属 —— 那是把被检查对象的运算重放一遍，
                   而且对 `reach` **在原理上过强**（`代价 = 0` 只对锚点成立）
                   ⇒ 判据必须换成**外生覆盖**（§7.0.1），不新增接口、不用重验
    **路没走全**   健全性与覆盖不漏在**维护路径**上不成立，
                   而判据只跑**一次建完**那条路 —— 检查存在、是绿的，
                   却从没跑在出问题的那条路上（§7.0.2）

⇒ 健全性那一条**已经补上**：出路 (1) / (4) 把维护路径修绿 ⇒ `B1` / `B16`
  升级成**两条路径各判一次**。覆盖不漏那一条**还差一半**（`sequence` 维护 16 漏）
  ⇒ 它继续走 `B18` baseline 守卫。
⇒ 现在四行硬要求**各处于一种守备状态，而且每一行的状态都写在 §1 的表里**：
内核构造守（收窄的划分）/ 明说不是硬要求 / 判据两条路径各一次 / **baseline 守卫**。
**「判据只跑一条路」不再藏在实现里。**

⇒ 下一步是 §10.2 剩下的那件**已落地**：
持久化的**落盘与并发**（`core/persist.py` / `core/locking.py`，见 §10.2 D 的 P6 / P8）。
（⚠️ 删除流程（§10.2 C）**2026-10-07 已落地**；`reach` 的 (3) **不在其中** ——
2026-10-07 已裁定**不采纳**，见 §10.2 A′。）
⇒ **§10.2 整节（A / A′ / B / C / D）至此全部落地或裁定完毕。**
剩下的两件都**不是**「还没做」，是**已经写明的边界**：
并发**只做作用域、不做线程安全**（两处 O(1) 短临界区不被锥覆盖）；
访问旧版本仍是 **Θ(i)**（没做快照/混合）。
**不是「支持更多方向」，是把已定的硬要求量在所有该量的路径上。**
