# 内部时钟（`core/clock.py` + `--agenda-tick`）

**2026-10-29** ｜ 配套：`core/agenda.py`（议程层）· `docs/谓词推导与反思层.md` §13.2x

---

## §1 为什么现在要有

议程层回答「现在轮到谁」，但它**自己没有时间**。`now` 一直靠调用方传，默认值散在几处，
于是有一件结构性的事一直没解决：

> **「我闲了」只能由宿主数着报。** 宿主不说话，`k` 就不动 ——
> 一个三天没人来问的库，门槛还停在 `k=0`，待办一条都不会自己浮上来。
> 「主动性」于是依赖**外部有没有人搭理它**。

这不是「实现没写完」，是**缺一个单点**：谁说了算「现在几点」。

## §2 它做了什么（三件，仅此三件）

| 能力 | 落点 |
|---|---|
| **唯一的「现在」** | `clock.now()`：默认系统本地时间（naive，与既有 `agenda.jsonl` 的写法**逐字兼容**） |
| **可钉住 / 可快进** | `clock.set_source(fn)` / `clock.frozen(t)`（`with` 块，退出恢复原状） |
| **统一的年龄口径** | `clock.age_days(t, at=None)` —— 议程层不再各算各的 |

接上之后，`k` 可以**由时间推**：

    k = clamp( (now − 最近一次「看到待办」) // IDLE_PERIOD_MIN , 0, IDLE_CAP )

- `IDLE_PERIOD_MIN = 30`（**暂定值**，同 `usage` 缓冲那 50 批的性质，不是标定出来的）
- `IDLE_CAP = 6`（`τ(k)=0.5−0.3k`，k=6 已是 −1.3，再涨只会「全都要」——那不是主动，是噪声）

入口：`python -m ldv.cli --agenda-tick [--idle-minutes N]`（`N` 是**演示用的快进**，
借 `--agenda` 的 `--days` 那个先例；诊断账本写在临时目录，不碰语料旁的 `agenda.jsonl`）。

## §3 三条边界（越一条就不是它了）

1. **不改档位、不改答案集合。** 变的只有 `k` 从哪来。判据 `★ [时钟] 56` 是反向对照：
   同 `k` 下，「时钟推」与「人手给」的 `到点 / 未到 / 阈值` **逐字相同**。
2. **不假装闲过。** 账本里一条 `seen` 都没有 ⇒ `k=0`（判断 `★ [时钟] 51`）。
   否则第一次运行就会把全部待办一次性倒出来 —— 那是噪声，不是主动。
3. **不做「定时执行」。** 时钟只给「现在」，不给「该不该做」。
   加一个「到点就自动改结构」的循环，等于把「只提议」改成「自己动手」——
   那要单独裁定，本层不做（也**没有**守护进程：没人调用就不走）。

## §4 与宿主那条路的关系

`next(idle=k)`、MCP 的 `next(idle=)`、`--agenda K` **一条都没改**：
不传 `idle` ⇒ `k=0` ⇒ 与从前逐字相同。时钟是**新增的第二条来源**，不是替换。

两条来源的差别只有一处，也是这一层唯一的新意：

| 来源 | 谁决定「闲了」 | 适用 |
|---|---|---|
| 宿主（原有） | 宿主数着报 | 会话内、有人在用 |
| 时钟（新增） | 距上次「看到待办」多久 | 跨会话、没人搭理的库 |

## §6 已知的空白

- **`IDLE_PERIOD_MIN` / `IDLE_CAP` 没有标定过。** 30 分钟是拍的；要真有读数，
  得在长场景里量「多久没人来问」的分布 —— 那时再调，现在只标「暂定」。
- **没有事件时间戳。** `reflect.Event` 仍不带 `ts`；「反复出现」的计数靠
  `agenda.jsonl` 的 `seen` 行，不靠事件流。要让事件本身带时间，是另一件事（会动 `Event` 的形状）。
- **没有守护进程 / 调度器。** 这一层只提供「走一格」的能力，谁按什么频率来调，
  是宿主（或未来的服务层）的事。
