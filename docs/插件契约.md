# 插件契约（§I1–§I7）—— 六个问题

> 规范原文在 [`分层方向视图-设计文档.md`](分层方向视图-设计文档.md) §5 与 `ldv/core/interfaces.py`；
> 形式化断言在 [`形式化断言集.md`](形式化断言集.md) §2（**§I1 / §I2 是 §T1 与 §A1 的共同前提**）。
> **本文不复述规范**，只回答「一个插件作者或审查者真正会问的那六个问题」，
> 每条注明**依据在哪、有没有判据守**。守不住的条目录实说「守不住」。

## 0 先说什么叫「回答了这个问题」

一个接口问题只有三种状态，混在一起就会变成「靠读代码才能回答」：

| 状态 | 含义 |
|---|---|
| **结构上成立** | 接口上就不可能那样（不是「约定了不」，是「办不到」） |
| **纪律 + 判据** | 写在这份文档里，且有判据盯着，违约会红 |
| **纪律，无判据** | 写在这份文档里，但**没有东西守** —— 明说，不装作有 |

下面每条都标了它是哪一种。

## 1 七个方法一张表

| 号 | 方法 | GiST 对应 | 生产调用方 | 抛异常时 |
|---|---|---|---|---|
| §I1 | `hit(方向, 查询)` | `Consistent` | `kernel.query` / 检索流程 | **折成「未展开」** + 记一笔（不是「否」—— 那侧危险） |
| §I2 | `merge(一组方向)` | `Union` | CLI 建根（`plug.merge([])`）、抽象层折视图 | 直接传播（无封装器） |
| §I3 | `penalty(方向, 项)` | `Penalty` | 插入时的归属分配 | 异常 / 非数 / NaN / inf ⇒ `PluginContractError` |
| §I4 | `split(父方向, 一组项)` | `PickSplit` | 展开 | 异常 ⇒ `PluginContractError`；候选 < 2 个 ⇒ `PluginContractError` |
| §I5 | `encode(方向)` / `decode(blob)` | `Compress` / `Decompress` | `core/snapshot.py`（快照进出，base64） | 直接传播（无封装器） |
| §I6 | `signal(方向, 交互)` | —— **本设计新增** | `kernel.record_usage` | 直接传播（无封装器） |
| §I7 | `record(方向)` | —— | **无生产调用方**（见 §7） | —— |

§I4 的三种返回是**契约的核心**，单独说：`None` = 插件**声明**这一层分不开
（正常返回，进账本，`by="plugin"`）；一组候选（≥2 个）= 提出切分；
给 1 个或 0 个 = **违约**，内核不替它猜、也不静默当成「分不开」。
（为什么：把「写错了」和「说分不开」分开，账本才有信息量 —— `interfaces.py` 的 docstring 有完整论证。）

## 2 六个问题

### Q1 可以修改传给它的对象吗？

**`Direction`：结构上改不了。** 它是 `@dataclass(frozen=True)`，赋值即 `FrozenInstanceError`
（`ldv/core/direction.py`）。这不是纪律，是类型。

**项：按引用传递，内核不复制 ⇒ 纪律，无判据。** `split` / `penalty` 收到的是
`kernel.items` 里的**原对象**。纪律要求插件把它们当不可变值读；
三个内置插件的项是 `frozenset`（客观上改不动），但第三方插件传 `dict` 就能改，
而**没有任何判据守这一条**。

> 备选方案是内核递一份浅拷贝 —— 没做：每此插入都要为全部项付一次复制代价，
> 而内置插件不需要。真要允许不可信插件时，这一条必须升级成判据或进程隔离。

### Q2 可以保存跨调用缓存吗？

**可以，有两个条件，且都有判据。** `reach` 插件就是活例（`ldv/plugins/reach.py`）：

1. **缓存键必须覆盖该方法的全部输入。** 只按 `item` 做键时复用 ≈ 1×（30.5M 个键），
   按 `payload` 做键后复用 ≈ 3907× —— 键与值的粒度是同一件事的两面。
   ⇒ 判据 `test_reach_cache_premise`：**前提（图不可变）必须被检查，不许靠读代码断言**。
2. **缓存不许改变数值语义。** ⇒ 判据 `test_reach_cache_transparency`：三臂对照
   （开缓存 / 关缓存 / 独立重算）钉住「逐项相同」。

⚠️ 缓存的另一面是 Q3：带缓存的插件**不是**可重入的。

### Q3 可以被多个线程同时调用吗？

**不许假定可重入。** 并发契约在 `LockedKernel`（锁的作用域 = 锥，
[`并发接口设计.md`](并发接口设计.md) §3），并且：

- **默认路径不锁** —— 并发是可选入口（`cli --locked`），不是默认行为；
- **服务壳不声称线程安全** —— README「它不是什么」第一条就是这个；
- 读写锁不采纳的理由也写在同处：`query` 会写，不存在只读路径。

⇒ 带缓存的插件（`reach`）只在**同一把锁的保护下**安全。这一条是**纪律**：
锁在壳层，插件自己看不见锁，也**没有判据**能判「插件被并发调用了」
（并发三面里的 B 面走落盘，不走插件）。

### Q4 可以持有 Kernel 或内部节点的引用吗？

**结构上拿不到内核。** 全部生产调用面只递这些东西：

    hit(方向, 查询) · penalty(方向, 项) · split(父方向, 一组项)
    signal(方向, 交互) · merge(一组方向) · encode(一个方向) · decode(一串字节)

**没有任何一处把内核递进插件。** `merge` 收的是一组方向、`encode` 收一个方向，
都是值。⇒ 不是「约定了不给」，是接口上不存在这个东西。
（真要拿，插件只能自己去 import 内核模块 —— 那是它在破坏自己的可测试性，接口不阻止，
也不承诺阻止；见 §0 的边界。）

### Q5 插件抛异常之后，内核还有效吗？

**有效，而且政策是分方法的**（`ldv/core/interfaces.py` 的三个 `call_*` 封装器）：

| 方法 | 政策 | 为什么不同 |
|---|---|---|
| §I1 `hit` | 折成 `Tri.UNEXPANDED`，并记一笔 | 遍历**不能中断**；折成「否」等于假阴，是危险的那一侧（§K8） |
| §I3 `penalty` | 升格 `PluginContractError` | 不可比的数会让归属分配变成随意 —— **不许静默** |
| §I4 `split` | 升格 `PluginContractError` | 建树路径吞异常 ⇒ 树长成另一个样子而没人知道 |

`PluginContractError` 的 docstring 就是它的语义：**修插件，不修内核。**
「插件使坏时内核的行为」由注入验证覆盖（`test_injections`，71 条）。

### Q6 接口兼容性由谁保证？

**形状：`validate_plugin` 在建内核时查**（八个方法 + `name`，缺即报错，
`ldv/core/kernel.py` 的 `__init__` 第一件事就是它）。

**行为：没有版本号 —— 这是已知缺口，不是疏忽。** 协议与三个内置插件同仓库演进，
改一条 §I 的语义要同步改三份插件 + 对应判据，目前靠这个约束保证一致。
对外发布兼容政策（版本号放哪、`FORMAT` 式的大门要不要）**还没有到需要它的那一天**；
到那天要先决定「兼容」是对谁兼容 —— 同一进程内的替换实现，还是第三方写的插件。

## 7 一个写这份文档时发现的真问题：§I7 没有消费者

全仓 grep：**没有任何一处调用 `.record(`** —— 不含判据、不含证据脚本、不含测试。
`validate_plugin` 要求它在（否则建不了内核），但**没有人生成它的产物**；
留痕实际由**账本**（ledger）与**使用记录**两套机制承担。

两条路，选一条，**不建议留着不标记**：

1. 给它一个真实消费者（比如把「方向摘要」并进留痕格式）；或
2. 从协议里删掉 `record`，`validate_plugin` 同步改成七项。

一个**没有消费者的协议方法**是「抽象在等待一个不存在的要求」——
这正是设计审查要抓的形状（每一层要有不可替代的职责）。
本条已登记为待办，不假装它有用。

## 8 一页速查

    Direction        改不了（frozen）
    项               不许改 —— 纪律，无判据（Q1）
    缓存             可以 —— 键覆盖全部输入 + 不改语义，两条判据（Q2）
    多线程           不许假定可重入；锁在壳层，默认不锁（Q3）
    内核引用         接口上不存在（Q4）
    抛异常           §I1 折成未展开；§I3/§I4 升格违约（Q5）
    兼容性           形状有校验，行为无版本号 —— 已知缺口（Q6）
    §I7 record       零调用方 —— 待办：接上或删掉（§7）
