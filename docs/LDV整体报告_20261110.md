## §1 它是什么：一句话、一个类别、七条承诺

### 1.1 一句话

**把一份语料装成一棵分层划分树，在树上做五件事：记录（建树）、检索（定位）、推导（算谓词）、推理（找矛盾 + 反事实）、处置（降权不删）。五层只产出结构，不产出答案。**

它不拿向量找相似段落。推理是结构的——包含 / 可达 / 递归分割 / 反事实——不是语义的。

⚠️ 两个容易混的层次，先分清（后面的章节按这个分法走）：

```
方向树   回答"去哪儿找"     结构平面：划分、检索、链、反事实
路由     回答"这件事怎么做"  交互平面：推演、组合、端口、结算、验收
```

**路由不是方向树的替代，是长在它上面的第二层**：路由要用树来查规程（`name=` 找节点）、
用账本来留痕、用端口来做事。没有树，路由只是一堆 if；没有路由，树只能回答"哪一带"。

### 1.2 它属于哪个类别（这个区分决定了后面全部纪律）

| | 派生系统 | **LDV（检索系统）** |
|---|---|---|
| 层的产物 | 新**断言** | 新**方向**（路由提示） |
| 错了会怎样 | 假断言**永久留存** | 死路——没人走，代价是一次 miss |
| 谁确认 | 必须有人 | **使用本身即确认** |
| 允许相似度 | ❌ 禁 | ✅ 允许（方向不是关于世界的声称） |

⇒ **不需要人在环里**。这是它选"检索框架"而不是"派生框架"的根本理由：
方向函数可以**不准**（假阳只赔性能），只要**不假阴**（说"否"而实际有 ⇒ 破坏正确性）。

### 1.3 七条可判承诺（定位不可证，但这七件可判）

任一条红，这个定位就名不副实。

| # | 承诺 | 断言 | 怎么判 |
|---|---|---|---|
| ① | **不产内容**：所有输出可指回材料 | §S1 | 找一个"无出处"的字符串（`test_no_unsourced_strings`） |
| ② | **答案是位置**：方向 + 成员集 + 覆盖；无命题、无标量 | §S2 | 查返回形状与禁词 |
| ③ | **反思显性**：每条方向请求带证据 | §S3 | 字段齐 + 项集可复算 |
| ④ | **重构显性**：维度/谓词变更留账且可回退 | §S4 | 账可查 + 回退实测 |
| ⑤ | **自我标签一致**：`我` 维度外生、可指认、可回退 | §S5 | 查来源 + 删掉后回退 |
| ⑥ | **失配修复收敛**：改结构能让失配消失且不弄坏结构 | §S6 | 失配 → 反向对照 → derive → 满足 → 自洽 |
| ⑦ | **记忆处置是降权不是删除** | §S7 | 数文件数 + 两次查询差额可算 + 明确问到不跳 |

⚠️ 其中四条只判到"半"（S1 只有契约可读、S2 只有形状可判、S5 的来源靠人看、S7 的阈值是外生约定）。
S3/S4/S6 是"是"。**顺序不许反**：先问"这条承诺真的成立吗"，再问"系统守不守它"。

### 1.4 明确不做（是取舍，不是欠缺）

| 不做 | 为什么 |
|---|---|
| 语义推理 | 不做蕴含、不做语义判定、推不出新命题；它做的是**结构诊断-修复** |
| 知识库 | 不存答案；空值合法、填充留痕；"已验证"只能外部授予 |
| 搜索引擎 | 返回"这一带"，不返回排序列表（禁排序/禁打分/禁合成分） |
| 模型代填 | 内容必须可指回材料；计数从结构算（§S1） |

再往上就是语义推理（"A 意味着 B"）——那要理解内容，撞"禁止模型代填"。
**这已经是这个架构能到的结构推理的天花板。**

### 1.5 与三条既有路线的位置

| 维度 | 关系数据库 | RAG | 知识图谱 | **LDV** |
|---|---|---|---|---|
| 组织单位 | 行/表 | 文本块 + 向量 | 三元组 + 本体 | **分层划分树** |
| 检索 | 精确匹配 | **相似度** | 图遍历 | **划分收窄**（不相似、只覆盖） |
| 完备性 | 可证 | 无保证 | 查询可证、图谱完整性无保证 | **无假阴是判据** + 完备性声明 |
| 学习 | 无 | 索引重建 | 无 | 有，**只到呈现次序** |
| 解释 | 查询计划 | 无 | 路径可读 | 链路投影 + 折叠 + 注意力事实 |
| 内容 | 存取 | **生成** | 存取 | **只产结构** |
| schema 演化 | 迁移 | 重嵌入 | 本体工程 | **声明式**（缺谓词当场 declare） |

一条硬边界：LDV 的检索不做"像不像"，只做"在不在划分里"。
所以它**不会**给你语义近邻（那是 RAG 的活），也**不会**因表达不同漏掉划分内的项（那是 RAG 的痛点）。
**互补位置，不是竞争位置。**

### 2.2 一次 `query` 的完整路径（12 步，按 `entry.py:703` 起的实际顺序）

| # | 步骤 | 失败时的行为 |
|---|---|---|
| 1 | 入口分派：`查字典`/`对话`/`联想` 走独立通道 | 各自弃答，不混检索 |
| 2 | 组合问法判定：27 个键互斥（推演/组合/端口/…） | 混发 ⇒ 明确拒收 |
| 3 | 空库检测（0 项） | **单独说"还没有材料"，不是"键写错了"** |
| 4 | 未知键三分类：拼错 / 缺谓词 / 缺维度 | 拼错 ⇒ 建议改名；缺谓词 ⇒ 当场给提案；缺维度 ⇒ 指向方向请求 |
| 5 | `auto_declare`（可选）：可声明的当场声明后重问 | 声明不生效则照原样报 |
| 6 | `ensure(plugin)`：取/建内核，`root=` 不碰环境变量 | 建树失败 ⇒ 抛，不静默 |
| 7 | `reject_below`（外生阈值）落到本次查询 | `None` ⇒ 不跳（与旧版逐字相同） |
| 8 | `_resolve`：逐层向下，三态，记 `stayed`/`out_of_scope` 账 | 命中 0 ⇒ 给 `relax`（逐键试） |
| 9 | 倾向排序：`ordered_by = usage` | **只改次序**；`answer_ids`/`n_answer`/`n_branches` 逐字不变 |
| 10 | `k.show(...)`：显式曝光一步（不是遍历副作用） | 位次假则曝光假 |
| 11 | `usage_store.stage(...)`：进**缓冲区**，**不算有用** | 下钻才 `promote` |
| 12 | 返回：`nodes`/`n_branches`/`n_answer`/`stopped`/`attention`/（可选）`impact` | 截断由调用方给 `max_branches`，账仍平 |

这条路径上有三个"看起来一样、其实不同"的分叉，是设计最用力防的形状：

```
键不在词汇表  ⇒ out_of_structure=True   （这里没有这个维度，该请人）
键在、组合为空 ⇒ 这一格是空的            （结构里有维度，只是没命中）
库是空的      ⇒ empty_corpus=True        （连结构都还没有，别去改参数）
```

三者混成一句"没查到"，人就会去改一个本来没错的东西。

### 2.4 三条贯穿全系统的纪律

| 纪律 | 形态 | 为什么 |
|---|---|---|
| **三态** | 是 / 否 / **未展开**；`bool(Tri.UNEXPANDED)` **抛异常**而不是 False | "没搜"与"没有"分不开，就不许印成 0 |
| **可移除（I5）** | 每条路由一个 `_xxx_rule()`；没教过 ⇒ 走旧路，逐字相同 | 删掉它，行为退回上一版——不是"应该没事" |
| **不作分** | 无全局目标函数；无跨方向标量；报告字段白名单；协议禁词 | 一旦合成分数，系统即在实质上充当裁判 |

第三条不是口号：`impact` 曾写过"占全树 = 子树方向数 / total"，
**当场被 `B12`（无全局标量分，扫源码）抓住**——分母是跨方向全局总数，归一化就是打分的第一步。
现在只报绝对数，比例由调用方自己算。

## §3 方向树：内核是怎么把"检索"变成"划分"的

### 3.1 名词（设计文档 §3，一个不能混）

| 词 | 定义 | 最容易搞错的地方 |
|---|---|---|
| **节点** | 被检索的对象，身份 = 字面 id | 不做语义对齐 |
| **方向** | 一个层上的可路由单元 | **不是集合，是带谓词的入口** |
| **层** | 方向的分级；秩 = 1 + max(父方向秩) | 秩越大越**细** |
| **细化 ⊑** | 细方向 ⊑ 粗方向 | 由"合并"定义，**不是相似度** |
| **见证** | 强制出某方向的最小下层配置 | **向上指**（子.witness=(父,)），不是向下 |
| **支撑锥** | `Cone(x)` = 插入 x 时走过的那条路径 | 等价于"见证含 x 的方向" |
| **展开** | 按需计算一个方向的下一层 | **不是预先物化** |
| **使用记录** | 一次交互的信号 + 倾向权重 | 权重由内核填，插件不许填 |

一条必须记牢的约定：**`合并({细}) = 粗` 是错的读法**——
合并单元素是恒等，于是那个等式对任何严格细化都要求"细=粗"，自相矛盾。
实测 A 39/39、B 71/71、C 37/37 个方向都满足"合并(单元素)=自身" ⇒ 三个方向一致地不成立。
**正确读法**：`⊑` 是覆盖关系（`覆盖(细) ⊆ 覆盖(粗)`），可操作判据是"粗必须覆盖细"。

### 3.2 为什么"划分"能替代"相似"

```
方向 payload 只是一个过滤器（成员集合的过近似）
过滤器只要健全（覆盖得住自己的成员）⇒ "否"的证明就有效 ⇒ 剪枝安全
层层嵌套不是必须的，健全才是必须的
```

由此得到两条不对称的契约（§K8）：

```
假阳  允许 —— 代价是性能（多扫几项），不影响正确性
假阴  禁止 —— "此处不存在"的断言，要证明它得把这里全部看完
              ⇒ 没有小见证 ⇒ 无法检查 ⇒ 只能禁止
```

这不是工程习惯，是**可检查性**的直接后果。
谁想"放宽假阴"，先回答："否"的小见证是什么？答不上来就不能放宽。

### 3.3 七个接口（§I1–I7）

GiST 是六方法；本设计是七个——多出的 §I6 是因为 GiST 没有反馈环，LDV 有。

| 接口 | 签名 | 必须 | 对应 GiST |
|---|---|---|---|
| **§I1 命中** | `命中(方向, 查询) → 是 \| 否 \| 未展开` | 不许假阴；允许假阳；三态独立 | `Consistent` |
| **§I2 合并** | `合并(一组方向) → 更粗的方向` | 结果覆盖所有输入（细说"是"的，粗不许说"否"） | `Union` |
| **§I3 代价** | `代价(方向, 待放入项) → 可比较的数` | 同层两两可比；**局部权衡在这里** | `Penalty` |
| **§I4 劈开** | `劈开(父方向, 一组项) → None \| ≥2 个方向` | 结果构成划分；`None` = 我判"分不开"；<2 个是违约 | `PickSplit` |
| **§I5 编码/解码** | `编码(方向)` | 解码结果覆盖编码前（可更粗，不可更细） | `Compress` |
| **§I6 信号** | `信号(方向, 交互) → 使用记录 \| 无` | 允许返回"无"（没观测到 ≠ 负）；**不含权重** | **新增** |
| **§I7 记录** | `记录(方向) → 可序列化` | 方向必须可序列化，否则无法留痕/分叉 | — |

三个细节值得单独记：

1. **§I4 的入参是"父方向 + 一组项"**。给父方向，是为了让子方向成为父的**可证细化**，而不是让插件从项里重新猜父的意图。实测带上父方向：覆盖嵌套越界 **14 → 0**，A 的假阳率 56.7% → 49.4%。
2. **"分不开"必须由插件说出来**，不许内核从"分配后一侧为空"反推——否则"插件判分不开"与"插件给的候选切不动"长得一模一样。账本 `unsplittable` 的 `by` 字段分 `plugin`/`kernel`，`stats()` 分两个数报。
3. **k 叉不是二分的让步，是实测要求**：C（序列前缀）强制二分 21 方向/7 层、判空 8；改 k 叉 **16/5**、判空 8，而**叶容量与假阳率一个数没动**。A/B 是反向判据：k 叉不该动它们，实测也确实没动。

### 3.4 内核 / 插件分界，与"没有全局目标函数"

判据只有一条：**是不是每个方向都一样的事**。

| 归内核（每个方向一样） | 归插件（随方向变） |
|---|---|
| 层的存在与秩、细化关系的形式 | 什么算一个方向 |
| 见证与支撑锥、按需展开 | 两个方向怎么合 |
| 失效只分叉不覆盖、记账位 | 一个东西该进哪个方向 |
| 遍历循环、三态语义、§K8 契约 | 太满怎么劈、怎么存、什么算一次使用 |

**关键决定：没有全局目标函数。** 权衡下放给 §I3（代价）与 §I4（劈开）两个局部方法。
理由：一旦定下全局量，就变成"按哪个方向都会不满意"。
内核只定义**权衡被调用的位置**，不定义权衡本身。

### 3.5 九条不变量（§K1–K9）

| # | 不变量 | 挡什么 | 怎么守 |
|---|---|---|---|
| **K1** | 严格派生：层 n+1 的见证 ⊆ 层 ≤n | 循环 | 见证向上指 + 秩等式 |
| **K2** | 非平凡：展开必须产出下层表达不出的东西，否则**不建这一层** | 无信息的层 | 判空只记 `unsplittable`，一个方向都不建 |
| **K3** | 有见证 ⇒ 局部失效：插入 x 的失效范围 ⊆ `Cone(x)` | 改一点全量重算 | 支撑锥 |
| **K4** | 只分叉不覆盖：失效只追加状态，不改历史 | "失效"与"从未存在"分不开 | 账本只追加 |
| **K5** | 良基秩 + 树性：`rank = 1 + rank(父)`，**单父**，无环 | 无限嵌套 | `B13` 四条 |
| **K6** | 三态：未展开独立于否 | 把"没搜"印成"没有" | `Tri` 不可转 bool |
| **K7** | 倾向权重：进自我优化的记录必须带权重 | 只优化自己展示过的方向 | 内核填权重 |
| **K8** | 假阴禁止 / 假阳计量 | 插件不准导致漏结果 | `Consistent` 契约 |
| **K9** | 内生/外生分界：外生项不许被 usage 驱动 | 无限递归 | `B14` 扫源码 |

两处值得展开：

- **§K2 的字面是"不建这一层"，实现就真的不建。** 判空时只追加一条判定事件（挂在父方向上），一个方向都不建。代价不会消失，只会换地方：这一层不建 ⇒ 那些项留在叶里 ⇒ **叶容量变大、分辨率下降**。所以度量必须**成对报**：`§K2 判空`（形状信号）+ 叶容量（代价信号）。
- **§K5 的"树性"是持久化的前提。** 树（每方向一个父）⇒ node-copying ⇒ 访问旧版本 O(1)；DAG（多父）⇒ 只能 fat node ⇒ O(log m)。`B13` 原来对 DAG 照样放行；现在把"恰好一个父"并进 `B13`，DAG 标成**具名留白**：谁要启用它，先接受持久化掉一档。

### 3.6 "越深越清晰"四行的真实守备状态

这是全系统最容易被读成"四行都成立"的一张表。实际是四种状态，**有意不拉齐**：

| 行 | 要求 | 状态 | 实测 |
|---|---|---|---|
| 成员层 | `members(子) ⊆ members(父)` | **硬要求**，内核构造守 + `B4` 复查 | 三个方向均成立 |
| 过滤器层 | `覆盖(子) ⊆ 覆盖(父)` | **不是**硬要求，只有度量 | 修父方向后越界 0 次 |
| 健全性 | `members(d) ⊆ 覆盖(d)` | **硬要求**，`B16` 两条路径各判一次（现行绿） | 设计文档记过维护路径越界读数：`reach` 128/328、`sequence` 36/176（**历史观测**，不是现行判据状态） |
| 覆盖不漏 | `覆盖(父) ⊆ ∪覆盖(子)` | ⬜ **2026-10-07 降级**，baseline 守卫 + 度量 | `sequence` 维护路径 16 漏/2 对（同上，历史观测） |

⚠️ 第三、四行的数字要连着读：它们是**当时维护路径上的观测**，用来解释"为什么这一行降级/为什么判据按路径分开"，
**不是**"现在还有 128 条红"。现行状态以 §0.4 为准（`run_checks` 97/0、`run_tests` 1228/0）。
把历史读数当现行红、或把现行绿当"那件事解决了"，是同一类误读。

第四行不是"忘了修"，是**裁定**：它与"滞留 == 0"是同一个条件（实测 16 == 16，双向差 0），
出路的代价落在**划分**（项停在父上、检索得到，只是这一层没细分），不是**范围**。
把它判成"必须"等于把已接受的代价重新判成错。

⚠️ **"判据只跑一条路"必须写在输出里**——否则它长得跟"两条路都过"一模一样。
这正是本设计反复要防的形状，在**检查设计**上的形态。

### 3.7 三个插件（当前的方向函数）

| 插件 | 根 payload | 子 payload | 一句话 | 天然形状 |
|---|---|---|---|---|
| `keyset` | `keyset.merge([])` | `(req, forb)` 各续一键 | 按**键**二分：一半要求有，一半要求没有 | 二分（语义分辨率就是二分） |
| `reach` | `frozenset(init_items)` | `frozenset(锚点)` | 按**可达锚点**选边 | 二分（中点） |
| `sequence` | `frozenset({()})` | 带前缀的序列 | 按**序列前缀**切 | **k 叉**（trie） |

两条硬约束：

1. **子方向 payload 只能从父 payload 派生，不许掺"当前成员"算出来的东西。** 三个方向各踩一次（A 的 `common`、B 的"只按成员分"、C 的 `p*`），每次同时造出覆盖越界与假阴。
2. **插件允许自带缓存，但要配两条必须**：① 前提被检查（"值算没算都一样" + 数据持久）；② 透明性被检查（缓存开/关逐项相同）。缓存是假绿最容易进来的地方——过期值不报错，判据照旧说"是"。

### 3.8 事件账本：七类事件，只追加

```
born            方向被建出来
witness_updated 见证被缩小（事实变了，不是判断）
invalidated     不再被强制——标记，不删（detail 必带 members_after）
unsplittable    §K2 判"这一层不建"（判定，不是失效）
out_of_scope    项按证明落在根覆盖之外 ⇒ 不塞进结构
stayed          项留在父方向：每个子方向都证明不收它
usage           一次交互的使用记录（含倾向权重）
```

三条设计后果：

- **`Direction` 不可变**：payload 建出来就不再改，要改就是新事件 ⇒ §K4"只分叉不覆盖"是**结构上成立**，不靠自觉。
- **"曾由 W 强制、现已不成立"与"从未存在过"在账本上长得不一样**——一旦覆盖，这两件事就再也分不开了。
- **`unsplittable` 挂在父方向上**，因为没有子方向可以挂。它让"判过分不开"与"从没判过"分得开。

### 3.9 三态的代价

`Tri` 不是 `bool`：`bool(Tri.UNEXPANDED)` **抛异常**，而不是悄悄变 False。
同一个毛病在别处的形态是把"跳过"计入"通过"——所以 `checks/_framework.py` 的 `Report` 连**计数**都分开：
`红 / 过 / 跳过` 三列，跳过**永远不算通过**。这一点在本报告里也照办（§0.4、§11）。

### 3.10 方向树的规模读数（它现在有多细）

| 语料 | 项数 | 方向数 | 层数 | 最大叶 | 平均叶 |
|---|---:|---:|---:|---:|---:|
| 内置 36 项（keyset） | 36 | 31 | — | 10 | 2.77 |
| 3 万节点网页图 | 30 000 | 31 | — | **12 302** | **1 874** |

★ **方向数几乎不变，叶粗了三个数量级**。这不是"树坏了"，是**方向函数对这类材料分辨率不足**的读数：
材料里有差异，但键抓不到。这正是 `direction_requests` 该报的场景——也是"基本层级优先选键"那条待验证项的由来。

## §4 五层操作：记录 / 检索 / 推导 / 推理 / 处置

### 4.1 记录（建树）

| 环节 | 实现 | 关键读数 |
|---|---|---|
| 装载 | `corpus/loader.py`，自写 front matter 解析器（零依赖） | 只认四种形状，形状之外**一律报错，不猜** |
| 索引 | `corpus/index.py` + `~/.cache/ldv/<语料>.index.json` | 36 692 项：直读 20.94 s → 索引 2.26 s（**9.3×**）；冷盘 228 s → 2.3 s（≈99×） |
| 分片 | `nodes/<id 后两位>/` ⇒ 100 桶 | 28 万文件枚举 300 s 超时 → 分片后 **0.6 s** |
| 建树 | `kernel.insert` / `build_keyset` | 7 115 项 6.7 s；3 万 216.6 s；10 万 3 239 s（**超线性**，见 §9.9） |
| 快照 | `snapshot.py`（默认关）/ `session.py`（快照+日志） | 恢复 0.26 s；每节点成本从 0.3 s 压成 O(1) |

索引的三条纪律：**不存 body**（主流程不用）、**不进语料目录**（写到 `~/.cache/ldv/`，随时可删）、
**失效可复现**（stat 全量比 (mtime_ns, size)；不匹配只重读那几个文件）。

### 4.2 检索（划分收窄）

- **答案 = 位置**：返回 1 支或 N 支，N 支合起来正好是答案（`Σ各支 == n_answer`）。
- **账平**：`n_answer` / `n_branches` / `branches_shown` 三个字段让截断也验得了。
  接口**不截断**——只有界面才截（否则"Σ各支≠答案"在客户端看起来像切分漏了，实测踩过：31 支截成 12，3 610≠7 115）。
- **拼错拒收**：`type=出度1-4`（多打一个数字）⇒ 与"材料里真没有"长得一模一样 ⇒ 必须当场拒。
- **松弛**：0 结果时逐键试，给"去掉哪个键就有几项"——确定性，不是搜索。
- **无假阴是判据**：覆盖漏了是正确性问题，必须红（§K8）。

### 4.3 推导（谓词从材料算，规则由人写）

```
规则（外生，人写）   「按 out_degree 切分：零值单列 + 非零三分」
参数（内生，算）     切分点 [0, P33=2, P67=5]
谓词（确定）         `出度>0` / `出度>2` / `出度>5`
```

- **必须是二分**，不是档位标签。档位互斥，预算按区分度挑可能同时选中两个互斥档 ⇒ 合取为空。
- **预算 N = 3 外生定死**，不交给系统调（否则 N 依赖历史 ⇒ 外生项自我优化 ⇒ 同材料不同历史不同结构）。
- **区分度只用于排序**，不当阈值。

### 4.4 推理（结构矛盾 + 反事实）

**结构矛盾三类**（只在结构层，不做语义矛盾）：

```
边打架        方向声明 parent=p，但不在 p 的子列表里
子覆盖越出父  子方向成员并集 ⊄ 父方向成员
孤立方向      没有父、也不是根
```

⚠️ 清单为空时**也要报查了什么**（覆盖读数）——否则"没查"与"查了没发现"长得一样。

**反事实**（`core/impact.py`）：

| 函数 | 回答 |
|---|---|
| `removal_impact(kernel, ids)` | 删这些项 ⇒ 哪些方向会空 / 会缩 / 哪些项根本不在结构里 |
| `blast_radius(kernel, did)` | 一个方向的整个子树：方向数 / 覆盖项数 |
| `compare_prediction(kernel, ids)` | 预测 vs 实测（会改内核，调用方给副本） |

实测 **12/12 组预测与实测一致**（4 语料 × 3 规模）。9 863 项/9 方向，删 10 项的影响分析 **0.004 s**。
这是"推理"而不是"统计"的判据：预测与实测对得上，才叫推理。

### 4.5 处置（降权、不删、忽略在支不在项）

```
遗忘发生在计算上，不发生在存储上
  记录：只追加，永不删
  倾向：0.5 ** (年龄 / 30 天) 只在算的时候乘进去
  结果：老经验影响力变小，但任何时候都能答"它曾经学过什么"
```

实测：300 天前的记录倾向 **1.0000 → 0.0010**，记录仍是 1 条，答案集合与支数逐字不变。

| 处置 | 作用对象 | 结果 |
|---|---|---|
| **支级忽略** | 方向（一支） | 不摆出来，项仍在存储里；差额可算 |
| **项级标记** | 项 | 只写 `answer_verdicts`，不改候选集 |

两条必须：**忽略做在支上**（摘项会让 `n_answer` 变，那就是裁判了）；**明确问到就不藏**（`require ⊇ must` ⇒ 必摆）。
阈值外生——自定阈值会让同材料、不同历史给出不同答案集合，违反 §T1。

### 4.6 五层的天花板

| 层 | 能力 | 判据 |
|---|---|---|
| 判断 | 项属不属于方向（健全） | `B1` 假阴 0 |
| 传递 | 可达闭包 · 递归分割 | `B13` / §K2 |
| **反事实** | 删了会怎样 · 影响面多大 | ㊾–⑤② |
| ✗ 语义 | "A 意味着 B" | 撞"禁止模型代填"，不做 |

### 4.7 自优化与声明：两个只碰内生量的入口

**自优化（`core/selfopt.py`，F0–F4）**——文件很短，因为它只准动内生量：

```
F0 收集使用记录
F1 内核填倾向权重（缺权重的不许进 F2）
F2 更新内生量
F3 断言外生项未被改动
F4 断言无跨方向的全局评分
```

为什么方向函数不能也按 usage 优化：那"优化它"需要目标，而目标又按 usage 优化 ⇒ 无限递归。
这就是 §K9 的实践形态。

**值谓词声明（`core/declare.py`）**——把"字段上的比较"变成一等谓词：

```
金额>=3000 / 状态=待修 / 耗时<5
```

六个比较算子；**只追加不覆盖**；0 命中拒收；只对 `_data/` 下的用户语料开放。
两条容易踩的：① 写进文件 ≠ 进得了 `all_keys`——响应里的 `生效` 才是关键；
② 清空声明树 ⇒ 逐字回原样（§D7 可回退）。

### 4.8 评估路由：自查三条

`{"评估": …}` 不是检索，是自查：① 判错支 ② 三方对账 ③ 场面单清点；
产出"平 / 悬 / 要人拍板"三态。它是 v0.1.87"路由代替机制"的第一个例子——
需要的时候才表现出评估，不是常驻一个评估器。

## §5 可解释性三件：chain / folded / attention

LDV 解释"为什么给我这几条"不靠自然语言，靠三个只读读数。

### 5.1 `chain`：把一支还原成一条路

```
根 → … → 该支
每一步标：相干（问题要的键在这一步被分开）/ 过路（只是经过）
```

★ **只读**：跑前跑后树的签名（方向数/边数/成员总数）逐字相同。

### 5.2 `folded`：换成与人同单位的讲述

同字段的连续二元切分合并成"字段步"。读数：**LDV 2 步 vs 人 1.86 步**（同一单位，不是"想得更深"）。
另外报**检索深度 / 到叶深度**，并让**兄弟分支可见**（被排除的近邻带成员数）。

这条修的是一个具体缺陷：v0.1.55 之前"链长 5–10"被读成"想得比人深"，
m2 的字段级诊断发现——**相干字段数恒为 2**，差在讲述单位（二元步 vs 字段决策）。折叠是呈现层修正，不是结构层。

### 5.3 `attention`：为什么它排前面

| 字段 | 含义 |
|---|---|
| `basis` | `default` / `usage`（取值域与 `ordered_by` 相同，不新造枚举） |
| `half_life_days` | 半衰期（语料可改，默认 30） |
| `rows[].n_records` | 这条支被记过几次 |
| `rows[].last_used_days` | 最近一次多少天前；`null` = 缺时间戳 ⇒ **不衰减**，不猜 |
| `rows[].span_days` | 首末两次的跨度 |

**零分数、零排名、只读、可移除**。字段名避开协议禁词（score/weight/priority/rating）。
它不参与任何计算，只是把已有排序的理由说出来——若有人让排序去读它，I5 就破了。

### 5.4 三件共同的一条

三者都不改**答案集**：`answer_ids` / `n_answer` / `n_branches` 逐字不变（`W7` 探针 + `[接入] ③` 判据）。
"解释"与"作答"是两条通道——这是它能既解释又不当裁判的原因。

## §6 反思层：报告 → 议程 → 自问 → 请求 → 闭环

反思层不是一个模块，是**五件按时间尺度排开的事**：

```
结构哪里不平         reflect.py      三档清单（必须/可延后/可忽略）   纯函数，不看时间
现在轮到谁           agenda.py       ACT-R 激活 + τ(k) + 冷却        看时间，不看后果
我想做什么           selfask.py      三类自问句                       组合前两者 + 处境
这里该不该加维度     request.py      B19 信号 → 人拍板 → 注入          开环→闭环
哪些变更需要留账     versioning/账本  追加、可回退                    跨进程
```

### 6.1 边界：只碰内生量

```
§5 的表：  什么算一个方向        → 外生，必须人声明     ← 没碰
           层内哪个方向值得展开   → 内生，可自我优化     ← 只碰这个
```

反思层**不改方向函数、不改判据、不改任何外生项**；也**不引入标量分**。

### 6.2 报告：白名单五字段 + 三档

| 字段 | 含义 |
|---|---|
| `方向数` / `待展开数` | 结构规模 |
| `展开序` | 建议先展开的方向 id（**外生规则**：成员数降序、did 升序） |
| `逐方向` | 成员数 / 子方向数 / 是否待展开 |
| `排序规则` | 写死的那条规则名（可审计） |

**没有**"分数 / 健康度 / 优先级分"——有意为之。判据 `㉕ 无标量分` 扫字段白名单。

三档 `significance()` 只**看后果、不看大小**：

| 档 | 含义 | 例 |
|---|---|---|
| **必须** | 不处理 ⇒ **结论可能错** | 边打架 / 子覆盖越出父 / 孤立方向；**整类缺失**（该类型一条都没进） |
| **可延后** | 不处理 ⇒ **结论对但不全** | 切不开 / 待展开 / 展开失败 / 滞留；**部分缺失** |
| **可忽略** | 不处理 ⇒ **没有变化** | 切了白切（m≤1）/ 已展开 |

⚠️ 一个 3 项的方向如果结构矛盾，仍然"必须"；一个 5 000 项的叶如果只是"切不开"，仍然"可延后"。
**"可延后"不等于不重要**，它只是"不处理不会让结论错"。

### 6.3 顺序消费：`--reflect` 只调顺序

前提是一条实测：同一份语料按正序/反序跑完全部查询 ⇒ 方向数 19/19，
结构签名（did/parent/子数/成员数）**逐字相同**。判据 `㉔ 结构不变` 钉这条。

⚠️ 如实记录：`--reflect` 与默认路径**终态完全相同**（25 方向/判空 7/记录 72 条）——
预展开的那些方向，查询本来也会展开。**在当前查询集下，"展开顺序"不是瓶颈。**
报告的价值在可观测（知道哪些方向待展开），不在改变结果。

### 6.4 方向请求：系统只提问、不回答

数据形状 `<语料>/directions.json`，三段：`请求`（系统写）/ `已批准`、`已拒绝`（**人写，程序重写不覆盖**）。

| 字段 | 为什么必须有 |
|---|---|
| `涉及的项` + `项数` | 证据：到底是哪几个项切不开 |
| `已经试过` | 含谓词推导结果——防"你不是已经有谓词推导了吗" |
| `当前状态` | 一句话说清卡在哪（不是"没变细"，是"这些键切不开这 N 项"） |
| `请求` | 请求的是**新维度**，不是方向定义 |
| `判据编号` + `阈值` | 可指回 `B19` 原始读数；N=10 是外生的，人能申诉 |

信号：`B19` 连续 N 次展开没变细。⚠️ **"连续"是树链，不是调用次数**（沿根→叶、连续多少个已展开方向没变细，不含叶）。

⚠️ 实测：现有语料**一律不触发**（36 项上树只有 9–19 个方向，链长够不到 10；全量 3 907 项最长 9，差 1）。
不触发时也要说"本趟查了多少"。

### 6.5 闭环：人拍板之后，系统真的做

`request.apply_approved(nodes, corpus_dir)` 把 `已批准` 里声明的维度**注入成键**：

```
人写： {"维度": "scope", "取值": null}
系统： ① 查材料里有没有这个字段（点路径也认）
       ② 有 ⇒ 每节点加键 scope=<值>
       ③ 没有 ⇒ 记"未生效：材料里没有这个字段" —— 不假装成功
```

实测：默认 36 项，不开 `--apply-approved` **19 个方向**；开 **47 个方向**。
⇒ 不是"账记对了"，是**结构真的变了**（判据 `㊜`）。

四条红线：系统不自己加维度、不猜、不提优先级；没写 `维度` 的批准条目不算；
"未生效"必须报；**默认关**（键集变大 ⇒ 所有既有读数都会变）。

### 6.6 矛盾报告走同一条通道

一开始把矛盾报告判成"系统 bug 指示器 ⇒ 不该闭环"。用户纠正是对的：

> 矛盾报告对应的修订方式是**增加新谓词或者请求新方向**。

⇒ 三类矛盾都指向"当前谓词与方向切不开这批项"，修订动作**不是**系统自己补子列表/裁成员
（那会把 bug 掩盖成绿），而是产出一条与 B19 同构的请求。仍然**不自动改结构**。

### 6.7 议程层：现在轮到谁

```
激活  B_i = ln(Σ_j age_j^-0.5)          （ACT-R base-level）
阈值  τ(k) = τ0 · k^-0.5                （k = 空闲轮次，由宿主报）
冷却  被驳回的待办进 cooldown_until，不是永久跳过
兜底  老化：久未处理的会浮上来
```

两个量、两个方向，别混：**激活**说"这条被反复碰到"，**阈值**说"我闲了多久"。
只有 tick 被调用才走，**没有守护进程**。

### 6.8 自问层：把待办合成"我想做什么"

| 类型 | 从哪来 | 句子形状 | 请求什么 |
|---|---|---|---|
| **矛盾问** | `contradictions()` 必须档 | "A 说 X，B 说 ¬X——用哪个？" | 人裁决 |
| **待展开问** | `graded()` 可延后档 + 激活排序 | "这一支撑不起更细划分，要不要新维度？此处是我试过的…" | 人声明维度 |
| **无词问** | 处境触碰：最近事件 × `all_keys` | "这段里有 N 个东西我没有词描述：…（逐字）" | 人决定要不要 `declare` |

每句强制四段：`陈述` / `证据`（没有就不许生成）/ `已试过` / `请求`。
**生成不出有证据的句子 ⇒ 返回空清单**——空是设计的诚实（同"曝光不算热"）。

**出箱**：把自问句写进 `<语料根>/outbox.jsonl`（只追加），只在"使用态"语料上发生；
发射点是既有操作（drill/taught）的收尾，**不自起进程**。
`trigger.json` 启用时主动 POST 出箱摘要到人配的端口；失败如实写 `trigger.log`，不重试轰炸。

### 6.9 五件的分工（一句话记住）

| 层 | 回答 | 时间尺度 | 输出 |
|---|---|---|---|
| 反思 | 结构哪里不平 | 无时间 | 三档清单 |
| 议程 | 现在轮到谁 | 有衰减 | 到点/未到 |
| 自问 | 我想做什么 | 有处境 | 三问句 |
| 请求 | 该不该加维度 | 跨会话 | directions.json |
| 闭环 | 批了有没有用 | 跨版本 | 方向数变化 |

## §7 缓冲区：四套，一套规则

### 7.1 为什么要有缓冲

"推导出来就用"有三个失效模式：

```
① 没经过检查     空谓词、id 撞车会静默进结构
② 看不出进来过什么 拒收的、待处理的，事后无从追溯
③ 把"被摆出来"当"有用"  曝光与使用混成一件事
```

⇒ 缓冲区统一成三步：**候选 → （判据自动筛选）→ 采用 / 拒收（带理由）**。
系统里现在有**四套**，形状相同、对象不同。

### 7.2 谓词缓冲：`predicates.json` 四段

| 段 | 含义 | 进划分？ |
|---|---|---|
| `候选` | 所有推导出来的谓词（不筛） | ✗ |
| `采用` | 过判据 + 排进预算的 | ✅ **只有这一段** |
| `超预算` | 过判据、但排在预算外的 | ✗ |
| `拒收` | 判据不过的 + **理由** | ✗ |

两条提交判据（自动、可复现）：

```
① 真二分：0 < 满足数 < 总数     （==0 空谓词；==总数 一个都切不开）
② 预算：过①的按区分度降序取前 N（区分度只排序，不当阈值）
```

**实测拒收率**（6 份真实语料）：

| 语料 | 候选 | 采用 | 超预算 | 拒收 | 拒收率 |
|---|---:|---:|---:|---:|---:|
| `pypi-deps` | 6 | 3 | 3 | 0 | 0% |
| `ext-coauth` | 6 | 3 | 1 | **2** | 33% |
| `gh-langs` | 4 | 2 | 0 | **2** | **50%** |
| `arxiv-taxonomy` | 5 | 3 | 1 | 1 | 20% |

被拒的都是同一类：`出度档>0` 在"没有孤立点"的语料上满足数 = 总数（切不开）；
`出度档>1` 在稀疏图上满足数 = 0。**不缓冲的话，这些谓词会切出一堆空方向，
而 §K2 只会报"有 6 个方向是空的"——报的是症状，不是病。**

### 7.3 记忆缓冲：`<语料>/_staging/`

```
nodes/                  ← 正式（参与结构）
_staging/
├── nodes/              ← 待提交（不参与结构）
└── rejected/           ← 拒收 + <文件名>.理由.txt
```

四条提交判据（确定性）：

```
① front matter 能解析
② 有 id（没有就用文件名——与 loader 约定一致）
③ id 不与已有节点重复
④ 文件名不与已有节点重复
```

`load_nodes()` **只读 `nodes/`**，不碰 `_staging/` ⇒ 缓冲区里的东西**不影响任何结构与读数**。
这是"暂存 ≠ 已提交"在结构上成立的原因。

容量与淘汰：`CAPACITY = 100`（外生）；超限**报出来**，不静默淘汰；淘汰**按进缓冲区时间 FIFO**（`stage` 用 `copy` 不用 `copy2`，让 mtime = 进缓冲区时刻）；`rejected/` 与已提交的 `nodes/` **不淘汰**。
⚠️ 淘汰**不按访问次数**——那依赖历史，会破可复现。

实测（pypi-deps 端到端，跑完还原）：暂存 2（1 正常/1 id 撞）⇒ 缓冲期结构仍 60 ⇒ 提交 1 进 `nodes/`、1 进 `rejected/` 并写理由 ⇒ 结构 60→61⇒还原 60。
边界：空缓冲区不报错；10 个全撞 id ⇒ 0 提交/10 拒收/10 个理由文件；100 个批量 ⇒ 60→160。

### 7.4 使用缓冲：`usage/_staging/`（两段通道）

这是全系统最容易被误解的一套，因为它的"缓冲"是**语义上的**：

```
query   ⇒ stage（进缓冲区，只记"被摆出来过"）
drill   ⇒ promote（提升成正式记录，+1）
wrong   ⇒ promote(outcome=-1)，只接受 actor=human
遗忘    ⇒ 半衰期只作用在计算上，记录仍在
清空    ⇒ clear() 是唯一删除路径
```

| 参数 | 值 | 状态 |
|---|---|---|
| `STAGE_CAP` | 50 批 | **暂定值、未经标定**——"多少次查询之内还该记得住"是人的判断 |
| `HALF_LIFE_DAYS` | 30 | 语料可改（`usage/config.json`，外生落盘） |
| 曝光 | 不计分 | `W3` 探针：100 次曝光 0 条 |
| 正式记录 | 永不淘汰 | 只追加 |

★ **两段通道的意义**：被摆出来只是**曝光**，不是**有用**。
如果不分段，"系统自己排前面的支"会因为被看到而更靠前——自反馈环，且无法审计。

### 7.5 交流缓冲：一次性树

两个 LDV 对讲后，把每段交流当成**一次缓冲区域的新建树**，用完就抛弃：

```
_data/_msg/<会话>/
├── nodes/        ← 消息落的节点（正文 = 消息原文 JSON，逐字未改）
└── rejected/     ← 撞 id 的 + 理由（同缓冲区形状：不覆写、不静默）
```

抛弃 = **显式删目录**；`status` 只报不淘汰（同 `_staging` 的规则）。
这里有一个实测坑：判据曾把根"静默读进结构"——后来改成判据前后 save/restore 并**验恢复**。

### 7.6 四套的共同规则

| 规则 | 谓词 | 记忆 | 使用 | 交流 |
|---|---|---|---|---|
| 不参与结构 | ✅（只有"采用"进） | ✅（load 只读 nodes） | ✅（load 不递归 staging） | ✅（用完即弃） |
| 拒收带理由 | ✅ | ✅ | —（无拒收） | ✅ |
| 不静默淘汰 | ✅（超限报） | ✅（超限报） | ✅（超限报还剩 N 支） | ✅（status 只报） |
| 可显式清除 | 重写文件 | `commit` / 删除 | `clear()` | 删目录 |
| 确定性 | ✅ 同材料同结果 | ✅ 四判据 | ⚠️ 依赖事件时间（记录本身确定） | ✅ |

### 7.7 缓冲与索引的协同（实测）

```
首次建索引        重读 80（全读）/ 命中 0
二次装载          重读 0 / 命中 80
再提交 1 个节点   只重读 1 个（其余 80 仍命中）
```

⇒ 缓冲区提交（新增文件）会让索引**精确地**只重读新增的那一个。
两个机制不打架，也不互相掩盖。

### 7.8 缓冲的边界（缺口，不藏）

- `STAGE_CAP = 50` **未标定**；`CAPACITY = 100` 是外生拍的，没有压力测试支撑。
- 淘汰只按时间，不按"是否快被用到"——这是为了可复现付的代价。
- 使用缓冲只覆盖"支"，**条目级代谢没有做**（支的粒度上时态不表达，did 会变；要先定"一条记录的年龄"在支内怎么算）。
- 交流缓冲的"一次性树"没有自动清理策略——**故意不设计**，按用户原话"遵守缓冲区域的规则，不去特意设计"。

## §8 路由生态：把"能力"改写成"可教的路"

### 8.1 为什么是路由，不是机制

早期每加一种能力，就在代码里加一个 `if` 分支——能跑，但三件事都做不到：

```
教不了    规矩散在代码里，改一次要改代码、跑全量
说不清    出了错只能读代码，不能指着一条文档说"它该这样"
拆不掉    删一个分支可能牵连别处，没有"退回上一版"的保证
```

v0.1.58 起开始出现"教出来的路由"（装配/过程/差距/建议）；v0.1.87 把哲学定成
**"只教路由并组合"**；v0.2.27 把**教法定死七段**。三步合起来是同一个做法：
**规矩写进语料，算子留在代码**。

```
语料节点（形态: 路由）   触发 / 动作 / 停手线 / 次数 / 留痕 / 依据 / 可移除
代码                    怎么换写法、怎么发一次、怎么排序——只做机械动作
授权                    `_xxx_rule()` 按 `name=` 找节点；找不到 ⇒ 走旧路
```

⇒ 每条路由都满足 I5：**删掉那个节点，行为逐字退回上一版**。
这不是"设计得干净"，是**可移除性可以被判据验**（反向判据逐字对拍）。

### 8.2 七段骨架（少一段不算教完）

| 段 | 写什么 | 反例 |
|---|---|---|
| `**触发**` | 什么情形走它。判据要**看得见**：status、`reason`、字段名 | "感觉不对的时候" |
| `**动作**` | 具体做什么，取最小动作 | "妥善处理" |
| `**停手线**` | 什么时候**不许**做；猜错的后果写在这儿 | 只写"要小心" |
| `**次数**` | 做几次、边界在哪 | 不写次数 ⇒ 会无限试 |
| `**留痕**` | 交出什么让人能复算 | "记一下" |
| `**依据**` | 点名哪本规程、哪个节点 | "按惯例" |
| `**可移除**` | 删掉这个节点，行为退回什么样 | 写不出 ⇒ 它偷偷改了别处 |

判据 `D-Route2` 扫真语料：**凡是标了 `形态: 路由` 的节点，七段少一段就红**。
当前 15 条路由节点，15 条七段齐全（1228 条判据里的一条）。

### 8.5 一条路由的解剖：`conc/559 挂了先查再定`

这是最完整的一条，可以当七段样板读（正文 60 行，这里只摘骨架）：

```
触发     写操作发出去了、回执没到手（5xx/超时/连接被拒）
         —— 两件确定：报文发了、回执没回；成没成，不知道
动作     ① 列清手里有的（接口/参数/回了什么/有没有单号；没单号就是没单号）
         ② 查对方那边（不是查自己），查法由外面给
         ③ 拿核项认领（字段=值，每一项都对上才算这一单）
         ④ 定性三件：在 ⇒ 已收下，凭据是它的编号；不在 ⇒ 由人说要不要再发；
                      认不准 ⇒ 成没成说不准
         ⑤ 查不通另算：查不了 ≠ 不在
         ⑥ 每条结论摊出判据（查法给了/查通了/返回空不空、核项全不全对）
停手线   不重发；不把查不到当没办成；不把查到像的当就是这一单；
         不拿查询改数据；不抹掉写失败记录；只查一次
次数     一次（查的读请求本身挂了可按 534 重发，最多 2 次）
留痕     查过 = {三态, 查的接口, 查的参数, 查到条数, 判据, 能做什么, 不许, （认不准时）看过的}
         写失败那一份不覆盖
依据     《写操作不重发》558、《对方故障有界重试》534
可移除   删掉 559 ⇒ 写挂了只报缺，不去查（与 v0.2.36 逐字相同）
```

代码侧（`_api_verify`）落到两个值：

| 状态 | 判据 | 能做什么 |
|---|---|---|
| **在** | 三条全"是"，核项全对 | 拿数据当回执往下走，**不再发** |
| **不在** | 三条全"是"，返回 0 条 | 可以再发，**发不发由人说** |
| **认不准** | 核项对不上（附 `看过的`：对上的/差在） | 整块交人 |
| **查不了** | 查的请求自己挂了 / 查法根本不成立 | 前者等恢复；后者**先改查法** |
| **没查** | 任务书没给"查" | 只报缺，不猜 |

⚠️ "查不了"分两种原因是 v0.2.39 才修的：**查发出去了但挂了**（等对方恢复）与
**查根本没发出去**（接口名不在目录/没配地址 ⇒ 先改查法）——原来一句"等它恢复"在后者上是错的。

### 8.7 推演：X 到 Y 是一条边，不是"有关"

| 项 | 规矩 |
|---|---|
| 边 | 四项齐全：前提 / 规则 / 结论 / 依据；**缺一件跳过，不补默认值** |
| 方向 | X→Y 成立不等于 Y→X 成立 |
| 链 | 若干条首尾相接的边，**最多 5 跳**；超了报"路太长，分段问" |
| 依据 | 没有文献的一跳不许跨；链里一跳缺依据，末端标**未确立** |
| 报缺 | 三态分开：缺一个观测值（人给了就能用）/ 缺一个中间结论（来路你已有）/ 缺一条路（补值也接不上） |

**实测抓到的两处真断裂，都是链写坏了不是代码坏了**：

```
① 第一跳结论「偏好 w0>−1、wa<0，证据增强」 vs 第二跳前提「w0>−1、wa<0」
   —— 名字就是钥匙，多几个字就接不上
② 结论写成动作（「去拟合 w」）⇒ 下一跳没东西可接
```

两条都补进停手线：**接不上先看名字与词性，别急着补边**（补边等于把断裂藏起来）。

### 8.8 三个"诚实"补丁：值 / 真假 / 来源

这三条是 v0.2.33–v0.2.38 的主线，解决的是同一件事的三个面：**它凭什么说这句话是语料里的。**

| 版本 | 节点 | 补的是 | 关键设计 |
|---|---|---|---|
| v0.2.33 | 551 值入形态 | **值**从哪来 | 句子我出、值你给；只换值不改措辞；前提结论一起换；不生成新边 |
| v0.2.34 | 552 不知道 | **真假**说不说 | 值/路/判三种不知道；遮 551 又给填 ⇒ 不静默；填值成功 ⇒ 逐值"真假我不知道" |
| v0.2.38 | 560 起点来源 | **起点**谁给的 | 一条起点一行：`调用方` / `组合上一步（第N段 X）` / `形对不对得上` / `真不真`（恒"我不知道"） |

v0.2.38 修的是一个具体漏洞（T3b）：伪造「退款 RF-0001 已入账」——**与语料某条边的前提逐字相同**——
它照接、1 跳到"可以结案"，返回里没有一处说起点是外面给的。
根子在 `诚实` 那句"全部由语料原文逐跳得来"：只看边，把起点也算成了语料原文。

```
边    我教的接法
起点  别人递的观测
两件事坏起来的后果不同 ⇒ 必须分开标
```

实测：遮掉 560 ⇒ 字段消失、`诚实` 退回旧句、其余字段逐字相同（I5）。
**边界**：只标"谁给的、形对不对"，仍**不验真假**，也**不判断该不该采信**。

### 8.9 组合与长线：走完 ≠ 做成

```
{"组合": {"要": "任务书那一句", "步": [{"推演": …}, {"推演": …}, …]}}
限制：最多 5 段；一段一条路由；段段重新过 query；某段弃答才停
回填：«上一步» 把上一段结论**整段**带进下一段的入参
结束：三态（没到 / 用完了 / 判不了）；给了「验收」才逐条核回单
```

**实测（长线任务，4 则任务书）**：

| | ok | 走几段 | 停在哪 | 逐段 |
|---|---|---|---|---|
| A | True | 5 | — | 推演·推演·推演·差距·建议 |
| B | False | 2 | 2 | 端口·推演 |
| C | False | 2 | 2 | 推演·推演 |
| D（对照） | True | 2 | — | 推演·差距 |

五条结论：

1. **A 走满 5/5，但第 5 段是"通"不是"成"**：差距/建议没有"需求是不是一段人话"这条判据，
   JSON 进来、噪声出去，全程 `ok=True`。**组合让它走完，不代表任务做成。**
2. **B 真开票成功，下一步拿不动回执**：回执里有 `invoice.id=INV-0001`，但组合只有 `«上一步»`（整段）这一种搬法。
3. **C 越界第 2 段就被顶回去**：没有顺着第一段往下滑——这是它最该守的地方，守住了。
4. **D 同一份单子，人挑一句就可用**：说明瓶颈在"从单据里取一句"，不在推演。
5. 五段长线的金额回归：22 行、56 937.37 / 1 161.33 / 568.21 / 55 207.83 **逐分相同**，验收 3 条全过。

### 8.10 端口族：一次写操作的完整生命周期

```
① 查目录（553）      接口名 → 方法/路径/参数
② 发（_api_call）    GET 可重试（最多 2 次）；写只发一次（558）
③ 读回执（532）      顶层没有凭据就往里看一层
④ 4xx（533）         只改写法，改一次发一次；日序定不了不猜
⑤ 5xx（534）         原样重发，最多 2 次；写操作不重发
⑥ 写挂了（559）      查一次，定性在/不在/认不准
⑦ 结算（554/555）    分页取数、Decimal half-up、四项金额核对
⑧ 验收（557）        逐条核回单，三条全过才算"到了"
```

**实测读数（8891/8893 自测服务，4% 随机 503）**：

| 场景 | 读数 |
|---|---|
| GET 挂 0/1/2 次 | 1 / 2 / 3 次请求 |
| GET 挂 3 次 | 3 次请求后弃答 + 报缺（不无限重试） |
| 遮掉 534 | **1 次请求**（反向对照：规则真的在起作用） |
| POST 挂 2 次 | **1 次请求**（写操作不重发） |
| "已受理但回 503" | 旧版受理 **2 次**（重复开票）→ 新版 **1 次** |
| 挂了先查：不给查 | 停在第 5 段，结束=**没到**（其实对方收下了） |
| 挂了先查：给查 | 结束=**到了**，凭据 `ST-20260001`，受理仍 **1 次** |
| 挂了先查：没落账 | **不在**，交人决定要不要再发 |
| 4xx 明确拒收 | **不去查**（账一定没记，查是白花一次请求） |

⚠️ 一个曾经犯过的错要记在这里：v0.2.35 的报告把"环境具备 4% 503"写成了"实测处理过"，
实际那轮**零次撞上**。现在这张表的每一行都有脚本与留档，不再靠"环境有这能力"充数。

### 8.11 桥接面：九个工具，与它缺的那一半

`ldv-mcp` 是给 agent 用的最小面（JSON-RPC，零依赖）：

| 工具 | 一句话 |
|---|---|
| `orient` | 我记得：语料/透镜/使用记录/最近动作，会话开始调一次 |
| `ask` | 把问题翻成键，查一支；可带 lens（带理由才冻结） |
| `remember` | 往私人语料写节点（只追加）；`filled_by` 只能记成自己的 actor |
| `drill` | 下钻 = 这一支有用；`verdict=wrong` 只接受 human |
| `derive` | 敲定派生维度（sidecar，删即回退）；必填理由与来源 |
| `remember_answer` | 把一次回答编进树；`unknown=true` 可把"答不出"记成结论 |
| `undo` | 反事实：删一个项看后果，然后原样恢复（指纹比对过才报成功） |
| `next` | 反思：必须/可延后/可忽略；给 `idle=K` 另报议程 + 自问句 |
| `assemble` | 把教过的目标装成装配单（只读，不排先后） |

**缺的那一半**（缺口，详见 §13.2）：桥接**没有** `推演` / `组合` / `后续` / `填` / `结算` / `取` / `验收` 入口。
它们都是内核路由（`App.query`），桥上没有对应工具；`ldv-mcp/core/entry.py` 自 v0.2.28 起
就停在 5 102 行（根目录 `entry.py` 是 7 177 行），推演/组合/端口目录这些代码**没有同步过去**。
这不是本版引入的，但它是"能力已经长出来、外面用不到"的最大一道缝。

### 8.12 生态的规模与生长方式

| 指标 | 当前 |
|---|---|
| `形态: 路由` 节点 | **15** |
| `形态: 推演` 节点（链） | **9** |
| `_xxx_rule()` 授权方法 | **17** |
| 每条路由的判据下限 | 3 条（正向/反向/停手线） |
| 教一条新路由的动作 | 写节点 → `taught` → 加 `_xxx_rule` → 加 3 条判据 → 跑绿 |

生长方式不是"加功能"，是**加一条可移除的路**：
每加一条，既有行为一个字不变；删掉它，行为退回上一版。这是它敢长到 15 条的原因。

⚠️ **更早的能力入口不是七段路由**：端口（393）、Mongo 线协议（396）、接口定义、借阅、
借算（530）、外查、预算受限检索——它们由 `query` 的 `_combo` 分派，身上没有七段。
七段是 v0.2.27 之后的新教法，**不回溯改旧节点**。所以"15 条路由"不等于"15 个组合入口"：
组合入口有 27 个键，七段只是其中较新的一批的写法。

## §9 服务层：三个壳、一套协议、一套并发

### 9.1 三个壳，三种使用者

| 壳 | 给谁 | 形态 | 鉴权 |
|---|---|---|---|
| `entry.py` 的 HTTP | 本机/同机进程、调试 | 8 个 API 路径（9 个方法+路径组合）+ 1 个首页 | **无**，只绑 127.0.0.1 |
| `serve.py` | 多租户部署 | 10 个路径（13 种方法+路径组合）、任务队列、观测 | token + 配额 |
| `ldv-mcp` | agent（Claude/Cursor 等） | JSON-RPC over stdio，9 工具 | 由宿主管 |

三者**共用同一套内核与账本**，差别只在"从哪读请求、怎么管身份"。

### 9.2 入口 HTTP（`entry.py::Handler`）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | 一个单页（人肉试查询） |
| GET | `/api` | 自描述（端点 + 协议 + 返回字段 + 边界） |
| GET | `/api/meta` | 语料规模 + 可用键（facet 来源） |
| GET | `/api/query?require=a,b&forbid=c` | 一条需求 → 一支或 N 支 |
| GET | `/api/suggest?q=出度` | 键建议（**子串**，不涉语义） |
| GET | `/api/examples` | 按数据形状挑的示例需求 |
| POST | `/api/query` | 同上，支持 `queries` 批处理 |
| POST | `/api/drill` | 往下看一层，子节点带覆盖率 |
| POST | `/api/msg` | 对等消息（`ldv-msg/1` 信封） |
| POST | `/api/declare` | 值谓词声明（唯一写入口，且只写用户语料） |

三条边界写在 `api_doc()` 里，不是注释：**只读**（declare 是唯一例外）、**单进程串行**（query 会 expand）、**只绑 127.0.0.1，无鉴权**。

### 9.3 `serve.py`：从"验收壳"到"能给别人用的壳"

| 方法 | 路径 | 谁能用 | 作用 |
|---|---|---|---|
| GET | `/healthz` | 任何人 | **进程活着**（不碰磁盘、不看配置） |
| GET | `/readyz` | 任何人 | **能干活**（语料/策略/调度器），不行 ⇒ 503 |
| GET | `/metrics` | 管理员 | 进程内计数（聚合，**不含租户名**） |
| GET | `/metrics.json` | 管理员 | 同上，JSON（CI 无 prometheus 时用） |
| GET | `/`、`/tenants` | 有 token | 列出租户（只看得到自己的） |
| POST | `/tenants/<名>` | 管理员 | 建（**空库，可跑**） |
| DELETE | `/tenants/<名>` | 管理员 | 删 ⇒ **进回收站**，不是 `rm` |
| GET | `/<租户>/ask` | 该租户 | 查询（agent 面） |
| POST | `/<租户>/drill` | 该租户 | 下钻 |
| GET | `/<租户>/agenda` | 该租户 | 议程 + 自问句 |
| GET/POST | `/<租户>/run` | 该租户 | 同步跑 / 提交任务 |
| GET | `/tasks/<id>` | 该租户 | 轮询（queued/running/done/error） |

四个设计点：

1. **`healthz` 与 `readyz` 分开**。原来的 `readyz` 只查"目录在不在、view_spec 在不在"——
   往语料里放一个重复 id，`/ask` 与 `/run` 全 500，而 `/readyz` 照样 200。
   现在 `readyz` 还查**已知装载失败**，并把"能不能接客"与"能不能干活"分开。
2. **`AppCache` 必须存在，不是为了快**。`entry.App` 里有 `_last_shown` 与 `_tendency` 两处跨请求状态；
   每请求新建 ⇒ `/drill` 拿到的 `_last_shown` 是空的 ⇒ 使用记录**永远记不下来**，
   而返回文案是"这一支不在刚展示的候选里，不记"——**听起来像正常业务判断**。
   缓存失效只看目录 mtime：加/删/改名会重建；**原地改一个文件要 `?refresh=1`**（这是取舍，写在类文档里）。
3. **限流与队列是同一个计数**：`MAX_PER_TENANT = 1`。同一租户同时最多一个进行中任务，
   否则撞"单写者"约定。任务表有上限（原先是无上限地堆内存）。
4. **`metrics` 只存聚合数，不存租户名**——`/metrics` 因此不泄露"谁在用这个服务"。

### 9.4 认证与配额

| 项 | 值/行为 |
|---|---|
| 令牌存储 | 盘上只存**摘要** |
| 默认配额 | 60 次/分（取紧的那侧） |
| 状态码 | 401（没身份）/ 403（没权限）/ 429（超配额）**分开** |
| 契约头 | 每个响应带 `X-Ldv-Protocol` / `X-Request-Id`；错误另带 `X-Ldv-Error` |

`ldv-http/1` 的纪律是**只增不改**：加字段可以，改语义不行。

### 9.5 租户生命周期

```
建：目录 + nodes/ + spec —— 建出来是空库，且**能跑**（空库查询返回 empty_corpus，
    不是"键写错了"）
删：移进回收站（不是 rm），保留可恢复
隔离：一租户一目录；进程间无共享状态 ⇒ 连进程间锁都不需要
```

"空库能跑"这条是端到端抓出来的：空库 `all_keys` 是空集，原来那条"拼错的键"判据
会把**任何**问题都判成"你打错了"——真正的原因（这里还没有材料）一个字都没说。

### 9.6 调度器

```
tick() 自己不幂等；按槽位幂等
重复 tick 会**催熟 k**（把空闲轮次多算）⇒ 调用方必须按槽位对齐
```

这条是"机制层的坑"：一个看起来无害的 `for` 循环调两次 tick，会让议程阈值下降两次，
表现是"待办突然全部到点"。判据钉的是"按槽位"，不是"调了几次"。

### 9.7 `ldv-msg/1`：两个 LDV 直接对讲

**为什么不做自然语言**：LDV 的输出本来就是结构，翻成自然语言是双重有损——
① 丢掉"到底是哪 1 888 项、哪些方向说是、账在哪"；② 丢掉可核验性（收到一句话只能信或不信）。

```
信封六键：proto / type / from / fp / ts / payload     （缺一即拒收）
消息三种：QUERY {require, forbid}（**没有自然语言字段，一个都没有**）
          RESULT  本端 query 返回 + 原查询回声 + fp
          ERROR   {ok:false, error}（不回声对方 payload）
```

**接收方五查**：是 dict · proto 对 · type 已知 · 六键齐 · 无禁词字段。
**结果自检四条**（不依赖发送方诚信）：

```
① n_answer == len(answer_ids)          谎报项数当场露馅
② Σ 各支含答案 == n_answer              不重不漏
③ 每支都有 did                         "这一带"必须落在具体节点上
④ out_of_structure=True ⇒ 必须给 unknown_keys
                                       防"谎报超出结构"当逃避回答的借口
```

④ 必须在 `ok=False` 的 return **之前**查——第一版写在后面，`ok=False` 早就返回了，永远走不到（判据 `[协议] 68c` 守它）。

**两条红线**：① 只换结构不换语义（协议形状上就不可能回自然语言）；② 两个系统之间也不排序
（嵌套禁词 ⇒ 拒收并指出路径）。⚠️ 禁词表有一个实测收窄：第一版含 `rank`/`order`，
结果 `nodes[].rank`（第几层）撞表 ⇒ 每条合法 RESULT 都被拒。**字段名检查分不清"名字像排序"与"真是排序"**——
留下的四个（score/weight/priority/rating）都是只在评分语境出现的词；伪装靠字段名拦不住，那要靠人不发。

**两层传输**：文件（`.jsonl`，可 `git diff`）+ HTTP（`POST /api/msg`），共用内容层。
实测（ext-wiki-vote）：`influence=1-9` 一条 QUERY ⇒ 两层都给 **3 支**（D43 81 项 / D55 / D50），fp 回声一致。

### 9.8 MCP 桥的四个工程点

| 点 | 做法 | 为什么 |
|---|---|---|
| 零依赖 | 手写 JSON-RPC | 与内核同一条纪律 |
| 参数名是契约 | 工具 schema 与实现同名，不做别名 | 别名一多，"传错了"与"没传"分不开 |
| 只读闸 | `assemble` 只读；写工具各自有 actor 校验 | 桥不能替人做判断 |
| **输出纯 ASCII** | `ensure_ascii=True` | Windows 管道默认 GBK，含 `⇒` 会 UnicodeEncodeError ⇒ 单响应丢失 + 主循环死，表象是"server 僵住、全部超时" |

最后一条踩过不止一次（E1/E2/E4 反复撞上的"server 中途死"同根）。

### 9.9 并发与持久化：三件已有机制 + 三件可选项

**已有（服务化直接复用，不重做）**：

| 机制 | 做法 | 服务场景下的角色 |
|---|---|---|
| `commit()` | 临时文件 + `os.replace` + 双侧重试 | 落盘**唯一**入口 |
| 单写者 | 同一租户同时最多一个构建任务 | 由任务队列兑现 |
| 读者重试 | 持柄窗口短（一次读入再关），重试兜底 | 查询请求 |

**可选（默认关或按需开）**：

| 件 | 解决 | 代价/读数 |
|---|---|---|
| `snapshot.py` 跨进程快照 | 每次全量重建 | 7 115 项 6.7 s；3 万 216.6 s；10 万 **3 239 s**（超线性，32.39 ms/项） |
| `session.py` 快照+日志 | 每次加节点重写全量 | 恢复 0.26 s；每行 replay 22.7 ms；每节点成本压成 O(1) |
| `versioning.py` 混合版本 | 访问旧版本 Θ(i) | **O(i/k + k)**，不是 Θ(i) |

**锁沿路径局部化**：改一个方向只需接触它那一个父 ⇒ 锁不会级联到无界个前驱。
若按"子→父"加锁，改一个父要锁住扇出个子的，而扇出不常数 ⇒ 锁集合无界。
根是公共争用点——这是设计承认的。

### 9.10 服务层的边界（缺口，不藏）

- `entry.py` 的 HTTP **无鉴权、只绑本机**；它明说是调试/同机用，不是生产入口。
- `serve.py` 没有 TLS/反向代理/限流外的防护；这些明确交给部署层。
- 没有守护进程：议程、自问、出箱都要被调用才走。
- 任务队列只在进程内，重启归零；没有持久化任务表。
- 每请求一个内核实例是**设计文档**写的；落地的壳用 `AppCache` 复用（mtime 为戳），
  理由见 9.3 第 2 点。两处不一致，以代码为准，文档未同步（记在 §13）。

|---|---|---|
| `docs/`（36 份） | 设计、核验、实测报告；权威是《分层方向视图-设计文档》（2 785 行） | 文档写死 ≠ 已验证 |

## §11 判据与验证：它凭什么说自己成立

### 11.1 三值，跳过不算过

```
红    违约 —— 进退出码
过    本趟真的查了、真的成立
跳过  前提不成立（外部语料不在 / 该方向没内容）—— **不是过**
```

`Report` 连计数都分开：`红 / 过 / 跳过` 三列。理由与"0 和没有"同源：
把跳过计入通过，就是"没查"与"查了没问题"长得一样。

### 11.2 两级套件

| 套件 | 条数 | 跑什么 | 谁在用 |
|---|---:|---|---|
| `run_checks` | **97 断言** | 构建验收：内核不变量、视图、插件、路径、覆盖 | CI / 每次改动 |
| `run_tests` | **1 228 条** | 单元 / 对照 / 守卫 / 注入 / 路由反向判据 | CI / 每次改动 |
| `test_injections` | 71 条 | 故意注入坏形状，证明判据会红 | CI |
| `evidence/` | 166 件 | 慢而全的探针（真实大语料、完整留档） | 不进 CI |

⚠️ 两边**互不替代**：`run_tests` 版不重跑慢任务；运维判据只碰临时挂载副本——
`run_tests` 绝不能获得破坏语料库的能力。

### 11.3 三种角色，不许混

| 角色 | 进退出码？ | 例 |
|---|---|---|
| **判据** | ✅ | §K8 假阴 0、§S7 不删、路由反向对拍 |
| **读数** | ✗，只报告 | 加速比、方向数、叶容量、折叠步数 |
| **证据** | ✗，证明判据会红 | 注入、反向对照、留档脚本 |

反例：把"区分度"当阈值 ⇒ 系统在当裁判；用"标准全绿"当质量证明 ⇒ 绿只说明**没违约**，不说明**好**。

### 11.4 保证矩阵：53 条承诺，零判据 0

`docs/保证矩阵.md` 是**生成物**（勿手改），把每条承诺映射到守它的判据：

```
合计 53 条承诺：有判据 53，零判据 0
零判据（已知缺口）冻结在 evidence/guarantee_gaps.json
```

矩阵还标"三态：直接 / 间接 / 缺"与"反向对照覆盖（读数，不进退出码）"。
它回答的是"这句话有没有人守"，**不回答**"守得对不对"——后者要靠反向对照。

### 13.1 定位边界（不做，不叫缺口）

语义理解 · 内容生成 · 相似度匹配 · "A 意味着 B" · 任务正确性（建树质量对不对）·

### 13.3 三条结构性风险（比单条缺口更值得盯）

1. **双副本漂移**：`entry.py`（7 177）与 `ldv-mcp/core/entry.py`（5 102）已经不同步 11 版。
