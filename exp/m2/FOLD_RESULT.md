## 2. 盲判：48 次调用（8 需求 × 2 呈现 × 3 实例，V15 契约）

| 判据 | 结果 |
|---|---|
| **F1** 折叠版字段提取 == 真实相干字段集合 | **24/24** |
| **F2** 原版字段提取同上 | **24/24** |
| F3 折叠版步数 == 折叠版行数 | 6/24（**期望定义错了**，见下） |

### F1/F2 双满分 ⇒ 折叠无理解劣势，原版也无理解劣势

两种呈现下，agent 都能准确说出"实际用了哪几个字段"。
⇒ 折叠的收益**不在理解层**（V15 契约下原版也不会被读错），**在讲述长度**。

### F3 的 6/24 是**我的期望定义错了**，agent 的读数反而更对

| 需求 | 折叠行数（我的期望） | agent 报的步数 |
|---|---|---|
| C1 | 4（含 1 过路行） | 4 |
| C2 | 5（含 3 过路行） | **2** |
| C3 | 6（含 2 过路行） | 6 |
| C4–C8 | 3–4（各含 1 过路行） | **2** |

agent 报的"分几步"**不是折叠版的行数，而是筛选步骤的个数**——过路行不算步骤。
C2 的 5 行里有 3 行过路 ⇒ 实际筛选 2 步，agent 报 2。**它的语义比我的期望更合理**：
问题问的是"分几步（筛选）"，过路的子类细分不是筛选。

而 C1（报 4 = 行数）与 C3（报 6 = 行数）是**需求含 `标记=重要` 的那两条**——
标记是相干字段，agent 数步时把"过路的子类细分"与"相干筛选"混在一起了。

**修正后重判**（期望 = 折叠版的**相干段数**）：C2/C4/C5/C6/C7/C8 六条一致（18/24），
C1/C3 三次全不一致（报数 = 行数）。

## 3. 三个发现

### ① agent 自发地把"步数"理解成字段决策数

无约束（原版）与有约束（折叠版）下，agent 报的步数都收敛在 **2**（= 相干字段决策数），
而不是链的二元步数（5–8）。⇒ `STOP_PROBE.md` §7 的判断被行为证实：
**"与人可比的步数单位"就是字段决策**——连模型都自发这么数。

### ② 原版有误导风险，但只影响少数需求

原版 24 次里只有 **3 次**（C1 2/3、C5 2/3）被二元步数带偏（报 6/8）。
其余 21 次都报字段级步数。⇒ 原版**不是不能读**，是**偶尔会把讲述长度当成决策数量**。

### ③ 折叠版的行数定义要改

折叠行数含过路行，与"分几步"的直觉不符。若实现进 `chain()`，
`folded` 应区分**筛选步**（相干段）与**过路步**，`步数` 字段只数前者——
这与 V11 的 `attention` 同一个设计原则：**给事实，标注语义，不替人判断**。

## 4. 结论

字段折叠**机械上无损、行为上无劣势、步数语义更贴近人的数法**。
原版的真实缺陷被精确定位：**偶尔（3/24）会让读者把讲述长度当成决策数量**。

呈现层原型（`fold_present.py` 的 `fold()` + `render()`）可以直接作为
`chain()` 输出的第二视图（`chain` 保留全路径 + 新增 `folded` 字段），
但那是内核接口变更，需单独立项。

## 5. 限制

- 单模型 · 每需求 3 实例（修正后 F3 的 6/8 需求一致，但 C1/C3 的不一致未解释）
- 判分用 JSON 字段提取（非语义判分）
- `unable` 0 次——所有任务都在约束下可答，本实验未触发弃答路径
- 未测"人认不认折叠版的讲法"（`ROLES.md` §4.2 的唯一直接判据）——留给人
