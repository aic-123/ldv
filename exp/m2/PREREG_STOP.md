# PREREG：停层判据实验（V1，2026-11-02 18:15，先于任何 V1 数据）

> 接 `STOP_PROBE.md` §4-1：openalex 上判据只压 1.81×，但在 **m2 的 120 条语料**上
> 才有真正的对照——本实验回答：**引入停层判据后，"讲给人听的链"能不能压到人的步数附近。**

## 1. 样本与对照

- 语料：`CORPUS_CARD.md` 重建的 120 条（`relca_probe.py` 同款，8 键走 `declare`）
- 需求：`chains.json` 语义的 8 条等值需求（与 `relca_probe.json` 相同）
- 支：全部答案支（6 条单支 + C2/C6 各 2 支 = **10 支**）
- 对照基线：`chains.json` 里**人给的步数**
  （C1=3, C2=3, C3=3, C4=4, C5=4, C6=3, C7=3, C8=3；多支需求按所属链取）

## 2. 判据（V1，写死，不许中途调）

| ID | 判据 | 说明 |
|---|---|---|
| S1 | 精度满 | 该层成员 **⊆ 答案**（`members_of(层) ⊆ answer_ids`）——再切只是拆分 |
| S2 | 规模可枚举 | 该层成员数 ≤ **K=7**（写死；七±二） |
| S3 | 最后一个相干步 | 它之后所有切分键的字段都不在需求里 |

停点 = 三者中**最靠前**的层。**零相干步的支**（V15 探针踩过的 bug）：
如实记为「全过路」，**不计入停层成功**，也不算 FAIL——单独列一行。

## 3. 判定（先写死）

| ID | 判据 | 阈值 |
|---|---|---|
| **E1** | 压缩后链长 ≤ 人的步数 | ≥ **7/10** 支 ⇒ 判据有效 |
| **E2** | 压缩后链长 ≥ 2 | 停在根（index 0）的支 = 0；有 ⇒ 逐条列为边界 bug |
| **E3** | 精度读数 | 停层处 `|members ∩ ans| / |members|` 全部报出（不判分，供看"停在脏层"的风险） |
| **E4** | 判据来源分布 | S1/S2/S3 各触发几次；若全靠 S3 ⇒ 如实记"退化为讲到最后一个相干步" |

**失败条件**：E1 < 7/10，或压缩后均值 > 4 ⇒ **停层判据 V1 无效**，结论如实写，
不许改 K 或加判据重跑（那要走 V2 增补）。

## 4. 成功后的含义（预判，供对照）

人的 3–4 步里，第 1 步往往是**意愿**（记忆里没有），第 2 步才是**谓词**。
所以压缩后链长**不可能**等于人的步数——树里没有意愿层。合理预期是
**压缩后 = 人的步数 − 1（意愿层）**，即 2–3 层。若实测如此，
结论应写成：**「停层判据把链压到了'纯结构可讲'的下限，与人差的那一层是意愿，
归 agent」** —— 这正是 `ROLES.md` 角色契约的兑现。

## 5. 不许做的事

- ❌ 不许改 K、不许加第四条判据、不许对"人的步数"作任何调整
- ❌ 不许用 openalex 语料（那是规模效应的反例）
- ❌ 多支需求（C2/C6）不许只测一条支
