# LDV 修改方案：从 E1–V17 的证据到改动清单

日期：2026-11-02。每一条修改都标注证据来源；分三层（呈现层 / 轻内核 / 结构层），
按"价值 ÷ 风险"排序。**红线**：`ROLES.md` 三禁令（不许照人的答案改系统 /
不许把 agent 该翻的记成 LDV 缺口 / 不许选择题当题）。

---

## 先说不动什么的（同样来自证据）

| 不动 | 理由 |
|---|---|
| **无假阴（§K8）** | V17 实测：人漏检 3/7 题、LDV 不漏——**完备性是 LDV 对人的核心优势**，绝不为"像人"放弃 |
| **抽象层 `P`/`E` 只随树变** | V11 结论 + §K9/`B14`；使用记录驱动会让 S1 可复现当场红 |
| **attention 不可写** | V13-A 6/6：写入口唯一（drill），显性可读、隐性不可改 |
| **不做"停层"砍层** | V1 判据无效（E1=2/10）：砍层数在错误的量上优化——量应是字段决策数 |

## 第一层：呈现层（已验证，可一次做完）

### 1.1 `chain()` 第二视图 `folded` ★核心改动

**内容**：同字段连续二元切分合并为一个"字段步"，标注相干/过路；
`步数` 只数筛选步（相干段），过路单独一行。

**证据**：
- V16：机械验收 M1–M4 全过（8/8 需求，C5 8→4 步最大压缩）；
  盲判 F1/F2 双 24/24（折叠无理解劣势）；
- V17-H2：人字段决策均值 **1.86**，折叠后的筛选步数即该口径；
- STOP_PROBE §7：链长 5–10 = 2 个字段决策 + 同字段连切——折掉的就是后者；
- Green & Petre 1996：这是治疗 **repetition viscosity** 的 design maneuver。

**形态**（以 C1 为例）：

```
原链（6 步）：标记◆ → type◆ → title· → type◆ → type◆ → type◆
折叠（2+1）：
  1. 标记 = 重要 ◆（1 支，2 项）
  2. 按类型分成 4 支 ◆，答案在「读书」（2 项）
  （另有 1 步过路：子方向细分，未列出）
  检索深度 2 ｜ 到叶深度 6
```

### 1.2 两个深度：检索深度 / 到叶深度

**内容**：`folded` 附 `depth_to_answer`（答案所在分叉）与 `depth_to_leaf`。

**证据**：V17② + PIM 实证——人自己就区分活跃区（1.81–3.7）与归档区（~6±1），
Bergman 2010 检索深度均值 2.86；LDV 链没有此区分，**把归档深度当检索深度讲**。

### 1.3 兄弟分支可见（边界可见性）

**内容**：折叠行附"**另有** `部位=全身`（2 项）不含『背』"——被需求谓词排除的
近邻分支一行带过，不展开。

**证据**：V17③——人花一整段裁决「全身算不算练背」，LDV 零步静默排除；
这是 Cognitive Dimensions 的 **hidden dependencies**（被排除的依赖不可见）。
它不改候选集（n_branches 不变，§X2 合规），只是**把排除变成可见的**。

### 1.4 答案完备性声明

**内容**：答案头部一行：「共 N 条，**无遗漏**（全部列出）」；多支时
「N 条分布在 M 支，已全部覆盖」。

**证据**：V17②——人漏检 3/7 题（C6 5/8、C4 3/4），LDV 不漏。
完备性是 LDV 对人的差异化优势，现在**只在账目里，没在答案里说出来**。

### 1.5 第一刀顺序的**呈现**补丁

**内容**：`folded` 的字段步按"覆盖节点数降序"稳定排序展示（`type` 类大字段
自然排前），**不改树的切分顺序**，只改讲述顺序。

**证据**：V17-H1 7/7 需求人类第一刀 = `type`（基本层级，Rosch）；
LDV 熵选键把 `标记` 排前。此补丁零风险（树不变，S1 不受影响）。
**树本身的选键规则是另一回事（见第三层），不混做。**

## 第二层：轻内核（每项单独预注册，一次一个）

### 2.1 意图槽：需求语句随记录存储

**内容**：`drill`/`query` 的 session 元数据存**自然语言需求原文**
（`qfp` 旁挂 `need_text`），可审计、可读回。

**证据**：V17-H4 红（人不说意愿步）→ 降级结论："意图槽的价值 = 存需求语句本身"；
E2（事实当场写入）+ V8（入口选择不记录）。三个月后"当初为什么这么查"有答案。

### 2.2 完备性声明的账目绑定

若 1.4 要防止"声明与账不符"，需把 `n_answer` 与答案列表的一致性
加进 `run_tests`（一条断言）。轻，但动测试基线，走预注册。

## 第三层：结构层（大变更，独立立项，本轮不动）

### 3.1 多叉 split（根治 viscosity）

一个字段一次切 N 支，替代二叉递归。V16 折叠是它的**呈现层模拟**；
若折叠上线后盲判仍不足（对照 V16 的 F3 教训：问法要避开省略欺骗），
再启动此项。代价：`keyset.py` 核心重写、覆盖性证明重做、全部历史判据重跑。

### 3.2 基本层级优先的选键规则

把 `keyset.py:88` 的"出现率最接近 1/2"改为"基本层级优先"。
**这是"照人的答案改系统"**——虽有 Rosch 理论背书，仍触 ROLES.md 红线。
若要做：预注册必须包含改前/改后的 chain 盲判对照 + S1 复验 + 树签名变化的
完整记录，并写明代价：**"同一语料唯一客观最优树"的叙事不复存在**。
1.5 的呈现层补丁能缓解多少，先量了再决定要不要付这个代价。
