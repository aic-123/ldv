# PREREG_E3 —— CSV 三臂对照（规范 P1，唯一专门打自己的实验）

> 预注册纪律：本文件在 E3 任何数据产生之前写定。跑完只允许追加 RESULTS 节，不许改上文。
> 判分沿用 exp/score.py SCORER v4（sha256 前缀 e6f3c6f2…），与 E1 完全同口径。

## 1. 被打的脸

E1 结论"R-L 0.864 可部分替代 R-R 0.987"存在一个自利解释（DESIGN_V2 §5-T1）：

> R-L 的分数可能不是 ldv **机制**（orient/ask 取回协议）的功劳，而是"规则被
> **预先整理好**放进结构"的功劳。任何人把规则整理成任何形式塞给裸 agent，
> 都能达到同样效果。

如果这个解释成立，ldv 的全部价值收缩为"一个提示词工程工具"，历史宣称
（C 组 1.00、ldv 优于长上下文）须再撤一次。E3 就是专门检验这句话的。

## 2. 三臂设计（信息等价，通路与格式不同）

| 臂 | 规则形态 | 通路 | 窗口内容 | 数据来源 |
|---|---|---|---|---|
| A 结构（R-L） | 结构节点 | ldv 工具取回 | 短引导+材料+工具循环 6 轮 | E1 已有（deepseek N=3） |
| B CSV（E3 新） | **CSV 表** | 直给（无工具） | 短引导+CSV 全文+材料，单轮 | 本实验 |
| C 裸（R-0） | 无 | — | 短引导(仅t1)+材料 | E1 已有（deepseek N=3） |

B 臂构成规则：
- CSV 由脚本从 `e1_store/_data/e1/nodes/` **机械转换**全部节点（rule-e1、
  rule-e1-schema、paper_records），**无人工编辑**。转换脚本 `e3_dump.py`
  与产物 `e3_rule_table.csv` 的 sha256 冻结于本文档 RESULTS 前一节。
- B 臂 prompt = SHORT_GUIDE + "\n\n以下是规则与登记表（CSV）：\n" + CSV 全文
  + "\n\n" + 材料 + TASK_BARE 后缀，与 R-0 同模板；单轮调用，无工具，
  max_tokens/temperature/tries 与 run_R 完全一致。
- B 臂在**每任务重置**窗口下跑（对应 R-L 的 reset 语义）。

## 2.1 产物冻结（生成于任何 B 臂数据之前）

- 转换脚本：`exp/e3_dump.py`
- 产物：`exp/e3_rule_table.csv`，3 节点、19587 字节
- sha256 = `4b88d0ad839f4291ab658b34bf2fd6b6abe6e324b59008b9323f23b536b45361`
- 注：paper_records 节点内登记行为 agent 自己 remember 时的截断标题（忠实导出，
  不清洗）。该表与任务材料无关（E1 矛盾全在材料内），其对 B 臂构成的是
  与 A 臂窗口内容等价的"结构现状"，这正是 E3 要对照的东西。

## 3. 参数（与 E1 冻结值一致）

deepseek-flash（主模型）· N=3 runs × 15 任务 · temperature=0 · max_tokens=MAX_TOKENS_OUT
· 材料爬坡 RAMP_CHARS 不变 · build_task 复用（种子同 E1：run/任务索引决定）·
单任务 ≤150k 硬守卫不变 · B 臂窗口额外含 CSV（约 1.5k token，计预算内）。

## 4. 证伪条件（先写死）

**E3-F1（主）**：B 臂均值 F1 ≥ A 臂（R-L）均值 − 0.05
⇒ "**ldv 的精度可由'预先整理 + 直给'复现，取回机制在 E1 条件下无增值**"
成立。写进 CLAIMS"不能说"首行；历史 C 组撤回声明永久保留。

**E3-F2**：B < A − 0.05
⇒ 意外结果：CSV 直给反而劣于工具取回。须给出机制解释（如：CSV 表头噪声、
注意力稀释），不得粉饰为"ldv 更好"之前先排除判分偏倚与格式伪影。

**E3-F3**：R-R − B ≥ 0.05（R-R 0.987 为参照）
⇒ "**CSV 结构化格式本身损精度**"（散文规则 > 表格规则）。独立于 F1/F2 记录。

## 5. 不得做的事

- 不许因为 B 臂跑分低而改 prompt 重跑（一次定型，改即作废并记录）。
- 不许只报均值不报方差（N=3 全部三值列出）。
- 不许把 B 臂失败 run（格式解析失败）剔除计分——计分母。
- 结果无论正负，写进 RESULTS_E3.md **第一节**。

## V2 增补（写于 B 臂 45 条数据产生之后、B′ 任何数据之前）

**B 臂首轮结果**：N=3 均值 F1 = 0.673（r1 0.692 / r2 0.667 / r3 0.661）。
E3-F1 不触发（B < A−0.05 = 0.814）；E3-F2 方向触发（B < A − 0.05）；
E3-F3 触发（R-R − B = 0.314 ≥ 0.05）。

按 §4 F2 条款要求，触发后**先排除格式伪影**。诊断发现：
446 个报告对中 227（50.9%）是 CSV 内 paper_records 登记行（120 个 W id，
与任务材料同语料池、同标题）与材料行的**跨源配对**——B 臂窗口比 A 臂
（工具 require=["type=规则"] 只取回规则节点）多出了无关登记数据，
信息不等价，B 臂低分不能归因于"CSV 格式"或"直给通路"本身。

**B′ 诊断臂（预注册）**：CSV 仅含两个规则节点（rule-e1、rule-e1-schema），
剔除 paper_records。其余与 B 臂完全一致（prompt 模板、参数、判分）。
定位：**伪影诊断**，不替换 B 臂主结果，两者并列报告。

- B′-F1：若 B′ ≥ A − 0.05（≥0.814）⇒ B 臂低分主因是登记数据伪影；
  "整理+直给可复现 R-L"成立（即 E3-F1 在信息等价条件下成立），
  ldv 取回机制无增值——按 F1 全文表述回填 CLAIMS。
- B′-F2：若 B′ < A − 0.05 ⇒ CSV/表格化规则本身损精度
  （散文规则 > 表格规则），与通路无关；ldv 的优势至少含"规则以散文形态
  存储与取回"这一格式选择。
- B′ 产物冻结：exp/e3_rule_table_rules.csv，sha256 见 RESULTS_E3 §0。

**诚实声明**：B 臂的"全部节点导出"设计使窗口信息超出 A 臂取回内容，
这是预注册时的设计疏漏（§2.1 已注明忠实导出但未预见跨源伪影），
以 V2 增补与 B′ 臂纠正，两份数据全部保留、全部报告。
