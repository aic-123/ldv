原规范：用户 2026-10-30 提供的 E1–E5 设计。评审结论与本文的逐条修复见 §5。
**用户裁定（2026-10-30，两条，优先级最高）**：

> ① **L 组改为每个任务换一个新窗口**（原"单一 messages 累积不裁剪"作废——它会在 1M 窗口的

> ② **引导持久化的载体是结构，不是会话**：引导（含规则）与任务材料一起写进 ldv 结构，

## 1 条件表（V2，替代原 4.1 的 5 组）

窗口策略统一为**每任务一个新窗口**（"换窗"正是真实 agent 的常态：会话结束、进程重启、
上下文压缩——引导要在换窗后仍可用，只能靠结构）。原 R/L 会话轴作废，换成：

| 组 | 引导给法 | 记忆后端 | 窗口 | 作用 |
|---|---|---|---|---|
| **B-0** | 仅任务 1 在窗口内给 | 裸 | 每任务新窗口 | 引导丢失后的基线 |
| **B-R** | 每任务都在窗口内重给 | 裸 | 每任务新窗口 | 上界控制 |
| **M-L** | 仅任务 1 给，随后**写进 ldv 结构** | ldv（工具循环） | 每任务新窗口 | 方案组 |
（压缩轴归 **E2**：污染事件的窗口内做"全史 vs 压缩"对照——每任务新窗口下 E1 没有可压缩的历史，
  硬放会变成无意义的空操作。E1 因此是 **3 组**：B-0 / B-R / M-L。）

压缩操作（确定性，禁 LLM 摘要）：保留 system + 引导 + 当前任务材料，**把此前任务的
助手输出替换为定长摘要行**（"任务 i：报 k_i 处矛盾，命中 h_i"——由判分脚本生成，不是模型生成）。
这模拟真实 compaction 的最常见形态（丢过程留结论），且构造可复现。

## 2 引导 → ldv 结构的映射表（原评审②的修复；PREREG 必含）

| 引导成分 | 进结构的方式 | 工具 | 取回方式 |
|---|---|---|---|
| 任务规则（"同标题同年份=重复不算矛盾"） | `remember` 一条 `type=规则` 节点（`evidence_status=原始记录`，正文=规则原文） | `remember` | `ask require=type=规则` |
| 输出 schema（pairs/ids 形状） | 同上，单独一条 `type=输出约定` | `remember` | `ask require=type=输出约定` |
| 材料事实（逐条登记行） | 逐条 `remember`（`type=登记`，id=记录 sid） | `remember` | `ask require=entity=<id>` / `year=<v>` |
| 年份作为可查询维度 | `derive` 声明 year 维度（sidecar，带 derived_from=原材料） | `derive` | `ask` 键查询 |

⚠️ 声明：M-L 组的"规则进结构"是**人写规则原文、工具收进去**，不是模型自己发明规则——
`filled_by` 记执行者。这条映射表本身接受 E3 同样的质疑（见 §5-T1）。

## 3 任务与材料（修复⑦的规模混淆：窗口独立后不再累计溢出，但保留递增）

- 15 个任务，k=5 固定矛盾 + 10 处同值陷阱（与历史一致）；材料 8k→80k 递增（每任务 ≤ 窗口 35%）。
- **主端点改为逐任务配对差** `Δ_i = F1(B-R, i) − F1(B-0, i)`（同材料、只差引导在不在）；
  "退化斜率"降为次要描述。退化起点 = 第一个 `Δ_i ≥ 0.15` 的任务序号。
- 加压设计：陷阱在 B-0 组（无规则）必然炸精度——这正是"引导携带规则"的测量点，不是噪声。

## 4 E2 重做（按裁定②：污染在**一个任务窗口内**进行 + 压缩对照）

每个污染事件占一个任务窗口，四步全在窗内：植入 2007 → 3 轮 → 更正 2008（勘误）→ 3 轮 → 三问 + 陷阱 Q4。
两组 × 压缩轴：**全史 vs 压缩**（把更正之前的轮次按 §1 同款确定性方式摘要）×（裸 / ldv）。

- 预期：裸+压缩丢 Q2/Q3（历史被摘要覆写）；ldv+压缩无损（记录在结构里，`evidence_status` 可查勘误）。
- **F1-d（修粒度）**：每 run 7 个陷阱机会（15 任务 → 7 次污染），跨 3 run 聚合 21 次，
  粒度 1/21≈0.05，"聚合命中率 < 0.2 ⇒ 污染误用不成立"才有统计意义。
- **F1-e**：压缩条件下 |Q2 准确率（ldv）− Q2 准确率（裸）| < 0.2 ⇒ "版本可追溯是差异点"不成立。
- "污染存量"操作化：= 助手在后续任务回答里**复述已作废值**的次数（判分脚本从 reported 里数），不是设计常数。

## V3 增补（2026-10-31，用户第三次裁定：恢复 5 组 + 150k 预算）

用户原文要点：恢复 R-0 / R-R / R-L / L-0 / L-L 五组原表；**每个 agent 上下文预算 150k token，
超过则按照真实情况压缩上下文**。

- **R-0 / R-R**：每任务重置（与已跑的 B-0 / B-R 协议逐字相同 ⇒ **数据直接沿用改名**，不重跑）。
- **R-L**：每任务重置 + 规则在结构（= 原 M-L，修复后未正式跑）。
- **L-0 / L-L**：**长会话累积**，150k token 预算；超限 ⇒ 确定性压缩（保留最近 ~105k token +
  一行摘要标记；摘要不含任务事实——压掉的就是历史）。L-0 的引导（任务 1 的短引导）会随压缩
  **真的消失**；L-L 的规则在结构里，压缩不触及。
- 预算为何可行：15 任务累计 ≈220k token，第 8–9 个任务触发首次压缩——**压缩事件本身就是测量点**
  （每次压缩记入数据：`compressed` / `compressed_events` / `ctx_tokens` / `guide_in_window`）。
- F1 恢复原规范三条：F1-a（R-0 ≥0.85 ⇒ 引导丢失不成立）/ F1-b（R-L÷R-R <0.85 ⇒ 替代不成立）/
  F1-c（|L-L − L-0| <0.10 ⇒ 生态位不成立）。
- 新增字段：`ctx_tokens`（调用前估算）、`compressed`、`compressed_events`、`guide_in_window`。
