# 实验一预注册：矛盾密度递增

**写下时间**：2026-10-29 18:2x（**在跑任何一组之前**）｜ 模型：`deepseek-flash`（DeepSeek-V4.1-Flash-1017），
上下文 **1M**，非思考模式（`thinking.disabled`），`temperature=0`，`response_format=json_object`。

> 这份文件的作用只有一个：**把「什么结果算失败」写在看到结果之前**。
> 事后改判据是这类实验最常见的作弊方式，所以先钉死。

---

## 0 主张（要被检验的那句话）

> 在「**穷举检出 + 定位**」这类任务上，材料里同类冲突越多，**单趟把整份材料塞进窗口**
> 的做法越容易漏；漏检率随冲突密度上升，而**结构化检索（ldv）不随密度变化**。

⚠️ 注意主张的范围：只针对**穷举型**任务（数清全部 + 指出每一处在哪）。
   不是「长上下文不行」，是「长上下文在**密集合**上不行」。单点问答不在此列。

---

## 1 三组（同一问题、同一判分）

| 组 | 做法 | 关键参数 |
|---|---|---|
| **A** 全塞窗口 | 整份材料一次放进 user message，要求返回 JSON 的 `pairs` | 非思考；`max_tokens=4096` |
| **B** 检索 top-k | 材料切 1200 字符块，字符二元组 BM25 取 **top-8** 块，只把这些块给模型 | 单轮（标准 RAG，不做多轮追问） |
| **C** ldv | 每条事实建成节点（键 = `entity` / `attr` / `value`），按实体做结构查询取候选，脚本比较取值 | 见 §4 的成本说明 |

问题措辞**不给 k**（给了就是泄题）：

> 请找出**全部**矛盾，输出 `{"pairs":[{"a":"S0123","b":"S0456"}],"count":N}`。
> 同一篇论文年份**相同**的重复陈述不算矛盾。

判分：`recall = 命中 / k`；`precision = 命中 / 报告数`；**两个 id 都对**才算命中。
材料里另注入 `traps=10` 处「同值重复」（只按标题重复判就会误报）——precision 靠它才有意义。

---

## 2 证伪条件（**看到结果后不许改**）

设 N=3 次、材料规模 ≥ 100k token（若 100k 上 A 仍无漏检，见 F4）：

- **F1（主证伪）**：A 在 `k=40` 的平均 recall **≥ 0.80** ⇒ 本实验**不支持**「越大越危险」，
  必须如实写成「在 100k 规模、k=40 下长上下文仍然扛得住」。
- **F2（形状证伪）**：A 的 recall 随 k **不下降**（最大 k 的 recall ≥ 最小 k 的 recall − 0.10）⇒
  主张里的「越来越漏」不成立，只能退成「在某个绝对量上会漏」。
- **F3（对照证伪）**：C 的 recall 或 precision **< 0.95** ⇒ 不能说 C 稳；
  要么修实现、要么把这个短板写进结论。
- **F4（规模证伪）**：若 100k 上 A 全对，**允许**再加一档 300k / 600k；
  但**不许**因为「模型更大就能扛」就改口说「实验不成立」——要写清「在多大材料上才失效」。
- **F5（成本证伪）**：若 C 的**端到端墙钟**在 100k 上比 A 还慢（> A 的 p50），
  则「C 更省」这条不能写，只能写「C 更准」。

补充：如果 A 的 recall 不降但 **precision** 明显下降（越报越乱），
结论只能写成「A 变得更不精确」，**不许**写成「A 漏检」。

## 3 公平性约定（写在前面，免得事后争）

1. **材料**：事实来自公开语料（OpenAlex 切片，CC0，4037 篇）；只注入「年份被写成两个值」这一种冲突，
   位置与真假由注入表决定。**不掺任何为 ldv 定制的语料**。
2. **A 不关思考会更准**：默认给非思考，是为了压成本；若 A 在 F1 边缘，**必须**补跑思考模式再下结论。
3. **B 的失败可能是任务类型所致**：单轮 top-k 天然不适合「穷举」。结论里要写明
   「B 输在**任务形态**（聚合/穷举），不是输在检索质量」——不许把它当作 RAG 的一般性结论。
4. **C 的谓词是人命名的**：`entity/attr/value` 三个键由脚本按数据集 schema 给出。
   这是 C 组的**真实成本**，必须单列（§4），不许隐去。
5. **N=3 起步**，报均值与极差；单次结果不下结论。

## 4 C 组的成本（必须一起报，不许只报准确率）

| 项 | 怎么量 |
|---|---|
| LLM token | **0**（C 全程不调模型） |
| 结构查询次数 | 每个实体一次 `ask`，报总数与 p50 耗时 |
| 谓词命名 | 一次性人工成本（本实验由脚本按 schema 生成，**算作人工**） |
| 墙钟 | 端到端：建节点 + 查询 + 比较 |

## 5 预算与止损

- 单价（今天实测，空闲时段）：输入 ¥1/M、输出 ¥4/M、缓存命中 ¥0.02/M。
- 100k token × 6 档 × 3 次 × 2 组 ≈ 3.6M 输入 token ⇒ **≤ ¥4**。
- **止损**：单轮实验累计 > ¥10 就停下报告，不追加。
