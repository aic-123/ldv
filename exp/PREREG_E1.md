## 0 假设与证伪

**H1**：把任务规则与材料写进 ldv 结构后，agent 在**换窗/压缩**后仍能保持任务表现；
裸上下文组则因引导丢失/被压缩而退化——退化集中在精度（规则边界）。

**F1-a**：若 B-0 在任务 2–15 的 F1 均值 ≥ 0.85 ⇒ "引导丢失导致退化"不成立
（备择解释优先级：自条件化 > 任务不需要规则 > 引导不需要）。
**F1-b**：若 M-L 的 F1 均值 / B-R 的 F1 均值 < 0.85 ⇒ "ldv 可追平上界"不成立。
**F1-c**：若 B-C 与 B-R 的 F1 均值差 < 0.10 ⇒ "压缩破坏规则"不成立（压缩对照无差异）。
**F1-d（E2）**：聚合陷阱命中率（跨 3 run × 7 事件）< 0.2 ⇒ "上下文污染导致误用"不成立。
**F1-e（E2）**：压缩条件下 |Q2 准确率（M）− Q2 准确率（B）| < 0.2 ⇒ "版本可追溯是差异点"不成立。
任一触发 ⇒ 对应主张**无条件降级**，不换措辞解释；触发条目写在结果报告第一段。

## 1 条件表

| 组 | 引导 | 后端 | 窗口 | 协议 |
|---|---|---|---|---|
| B-0 | 仅任务 1 在窗口内 | 裸 | 每任务新窗口 | single-shot |
| B-R | 每任务窗口内重给 | 裸 | 每任务新窗口 | single-shot |
| M-L | 仅任务 1 给，随后进结构 | ldv | 每任务新窗口 | tool-loop（≤6 轮） |
| B-C | 每任务重给，窗口**压缩** | 裸 | 压缩后执行 | single-shot |
| M-C | 引导在结构，窗口**压缩** | ldv | 压缩后执行 | tool-loop（≤6 轮） |

- 换窗 = messages 清到只剩 system。压缩 = 确定性摘要行（`score.compression_summary`，
  过程→"报告 x 处、命中 y/z"，禁 LLM 摘要）。
- 工具循环上限 6 轮；工具调用失败重试 1 次，再失败记 `tool_error`，**计入分母**。

## 2 任务序列（预注册写死）

- **15 个任务**；每任务：材料 8k→12k→16k→22k→28k→34k→40k→46k→52k→58k→64k→70k→76k→82k→88k 字
  （≈ token 数的 3.15 倍，单任务 ≤ deepseek-flash 窗口 35%；第二模型按其窗口 35% 另立递增表）。
- 每份材料：**k=5 处矛盾**（同一篇论文年份两个值）+ **10 处同值陷阱**（指令明写不算矛盾）。
- seed：材料生成 seed = 100+task_idx；每 run 的论文池偏移 = 1000×run。
- 引导原文（**逐字，确认后不许改**）：

**短引导**（用户裁定：执行者生成；本稿为定稿，跑前冻结）——只给意图，禁 schema/字段名/规则：

> 材料是一批论文登记记录，其中可能混进了错误。请检查并报告你发现的问题。

**长引导**（定稿；B-R/B-C 每任务给；M 组任务 1 给并写进结构）：

> 材料是论文登记记录，每条形如〔W…〕论文登记：《标题》发表于 YYYY 年，载于 期刊。
> 请找出所有「同一篇论文的年份被写成两个不同值」的矛盾，输出 JSON：
> {"pairs": [{"ids": ["id1","id2"], "year_a": N, "year_b": M}]}
> 判定规则：
> - 同一论文 = 两行的标题完全一致（忽略大小写与首尾空格），id 不同
> - 矛盾 = 同一论文出现两个不同年份
> - 不算矛盾：同标题且同年份的重复登记（这是重复，不是矛盾，不要报告）
> - 两个 id 都要给出，缺一不算命中

短引导校验：不含字面 `year`/`ids`、不含"同标题同年份不算矛盾"、不含 schema（校验脚本化，跑前自动过一遍）。

## 3 模型、N、温度

- 主模型 `deepseek-flash`（**DeepSeek-V4.1-Flash**，context_window=1,048,576，
  max_output=393,216——`/models` 实测，2026-10-30）。`temperature=0`，`thinking=disabled`。
- ⚠️ 偏差记录（2026-10-31 上午）：deepseek API 仅暴露一个模型。
- ✅ **偏差消除（2026-10-31 下午）**：用户提供 GLM API（open.bigmodel.cn），第二模型定为
  **glm-5**（`/models` 实测 11 个候选；窗口实测 **≥290k token**（289,885 输入通过）；非思考默认；
  6.7s 预填 29 万 token）。E1 五组 × 3 run 在两模型上**分别报告**。
- ⚠️ 跨模型口径：150k 预算以 **deepseek 口径估算单位**（字符/3）统一记账——glm 的 tokenizer
  中文更省（实测 ≈1.8 字/token），同预算下 glm 实际装得更多。比较的是「同一预算规则下的表现」。
- **N=3 run/组**（B 组 single-shot 便宜，M 组含工具循环）；报均值 + min/max。
- 判分：`exp/score.py` **SCORER_VERSION=4**，
  sha256 = `e6f3c6f2940faf47ba36eb68274d7db08a8980d66271d901e530feda03129258`。
  版本史：v1 金标准 → v2 去重（重复报告曾把 R 顶到 2.0）→ v3 递归 records（模型自造嵌套，v2 全漏）
  → v4 任意键下 ≥2 个 id 形字符串算一对（related_ids 也出现过）。每次升级都由试点暴露、金标准先行。
  试点数据作废重跑；正式 run 用 v3。改判分 ⇒ 版本 +1 + 全量重放（DESIGN_V2 §5-T4）。
- 数据：`runs/E1-*.jsonl` 只追加；字段含 `protocol/tool_rounds/tool_tokens/format_ok/SCORER_VERSION`。

## 4 E2（与 E1 的 M-L/B-C 共用任务窗，插入式）

- 每 2 个任务 1 次污染（共 7 次）：窗内植入 2007 → 3 轮后更正 2008（出版社勘误）→ 3 轮后三问 + Q4 陷阱。
- 指标：Q1/Q2/Q3 分列 + 聚合陷阱命中率（21 次机会，粒度 1/21）+ 污染存量（后续任务复述已作废值的次数）。
- F1-d / F1-e 见 §0。

## 5 加压设计（如何保证"可能失败"）

- 陷阱在 B-0（无规则）必然炸精度 ⇒ B-0 的高精度只能来自模型真读懂了边界，不是白送。
- 材料递增到 88k 字 ⇒ 末段任务在 97k 级——历史实测该规模默认配置 k=5 F1≈0.7，**有已知的失败区**。
- 压缩组的过程信息被确定性抹掉 ⇒ 裸组 Q2/Q3 只能靠摘要行，历史实验三实测**摘要会覆写历史**。
